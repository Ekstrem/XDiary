# Caddy-конфиги стендов (DO-037)

Здесь лежат **снимки** `/etc/caddy/Caddyfile` с обеих машин — до этого конфиг жил
только на серверах, то есть любой пересоздание VPS воспроизводило дрейф (§5.2).

| Файл | Машина | Роль |
|---|---|---|
| `Caddyfile.dev` | VPS-2 (`77.91.73.67`) | dev = **API-only** (вердикт @AR, DO-036) |
| `Caddyfile.prod` | VPS-1 (`31.192.111.168`) | прод: только API, фронт — GitHub Pages |

## Применение

```bash
sudo cp Caddyfile.dev /etc/caddy/Caddyfile      # или Caddyfile.prod
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

## Проверка

**dev:**

| путь | ожидание |
|---|---|
| `/` | 200, «API-only (dev stand)…» |
| `/health` | 200 |
| `/api/v1/clients` | 200 |
| `/api/v1/partners` (без токена) | 401 |

**prod:**

| путь | ожидание |
|---|---|
| `/health` | 200 |
| `/api/v1/clients` | 200 |
| `/` | 502 — известное состояние (у YARP нет маршрута на `/`); фронт на Pages |

## Правила

- Файлы здесь — **снимок того, что реально работает**, а не «как надо». Если на сервере
  конфиг отличается — это дрейф: сначала снять и закоммитить, потом менять осознанно.
- Секретов в Caddyfile нет: только домены, пути к сертификатам (сами сертификаты
  выдаёт `tailscale cert` и они лежат вне репозитория) и локальные адреса.
- Менять прод-конфиг (например, добавить явный ответ на `/` как на dev) — только
  по решению @TL/@AR: прод трогаем осознанно, не «заодно».
