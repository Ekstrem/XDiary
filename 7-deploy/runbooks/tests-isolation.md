# Ранбук: изоляция тестов (ADR-028)

Правило: **тест, который нельзя собрать и прогнать вместе с компонентом, — не тест компонента.**
Критерий не «где папка», а «чей жизненный цикл».

| Что | Где | Почему |
|---|---|---|
| Домен/агрегат/БД/API одного сервиса, ожидания потребителя | `6-msa/BC-<X>/src/<X>.Tests` | собирается и бежит вместе с сервисом |
| Межсервисные black-box сценарии | `6-msa/E2E` | требует N сервисов, блокирует релиз контура |
| Фронтовые E2E (браузер) | `9-tests/**` + маркер `front-e2e.md` | нужен фронт |
| Гейты/скрипты | рядом со своим кодом | — |

**Запрещено:** каталог `Contract.<A>_<B>` — не собирается без обоих сервисов, «общий тест
ни за кем». Контракт = ожидание потребителя (у потребителя, с HTTP-двойником провайдера)
+ проверка провайдера у провайдера.

## Гейты (машинные)

```bash
python tools/check_test_isolation.py   # б, в, д из комплаенса ADR-028
python tools/check_front_e2e.py        # г: в 9-tests только с front-e2e.md + браузер
```

- **б** — тест в `6-msa/**` не ссылается `ProjectReference` на чужой `BC-*`;
- **в** — `6-msa/E2E` не подключён к сервису (иначе изолированная сборка — фикция);
- **д** — каталога `Contract.<A>_<B>` нет;
- **г** — в `9-tests/**` у каждого проекта маркер `front-e2e.md` **и** браузерная зависимость.

## Пункт «а» — прогонный, не статический

`dotnet test 6-msa/BC-<X>` должен проходить **без** других сервисов. Парсингом это не
проверить: нужен реальный запуск в чистом окружении. Делается отдельной CI-джобой
(после переноса тестов @TE) — по одному сервису за прогон, без поднятия соседей.
