# Runbook — сверить опубликованный секрет с рабочим, не печатая значений

**Когда:** нашёл в репозитории/логах/образе литерал, похожий на ключ (JWT, пароль, токен), и надо
ответить на один вопрос: **это действующий секрет или мёртвая копия**. От ответа зависит приоритет:
совпал → инцидент и ротация; не совпал → чистка литерала, P2.

**Инструмент:** `tools/keycmp.py` (копия из `LoopMaker/tools/`). Он **не печатает значения** —
только `совпадают/нет` и `sha256[:8]`, поэтому его вывод можно класть в чат и в квитанцию.

## Команда (значения не попадают в историю шелла)

```bash
# рабочий секрет — из .env на контуре, кандидат — из файла (литерал выписать в файл, не в командную строку)
python3 tools/keycmp.py \
  --a-file /opt/xdiary/7-deploy/secrets/.env --a-key Jwt__SigningKey \
  --b-file /tmp/literal_key.txt
```

Почему так:

- `--a/--b` **со значением в командной строке не использовать** — попадёт в историю шелла
  (предупреждение есть и в `--help`);
- `--a-file` + `--a-key` читает `.env` по имени ключа, `--b-file` — файл с одним значением;
- `--b-env VAR` — если кандидат уже в переменной окружения контейнера/шелла.

## Как читать результат (норма @AR 2026-11-07 11:05)

| результат | что это значит | что делать |
|---|---|---|
| **совпадают** | опубликован **рабочий** секрет | **инцидент**: ротация обязательна, запись в `ERRATA`; для JWT менять **только подпись** (issuer/claims не трогать, иначе слетят живые токены) |
| **не совпадают** | копия **мёртвая** | ротация **не нужна**; литерал всё равно убрать (репозиторий публичный), приоритет **P2**, закрыть записью «публично лежал нерабочий dev-ключ» |

Печатать в квитанцию оба `sha256[:8]` и длины — иначе два верных замера выглядят как спор
(«у меня совпало / у меня нет»).

## Замер 2026-11-07 (п.4, ключ подписи)

```
keycmp: НЕ совпадают
  a .env Jwt__SigningKey : len=64 sha256:a5784528
  b литерал в git        : len=48 sha256:e34d5cf9
```

- литерал найден в **одном** месте: `6-msa/ApiGateway/docker/docker-compose.single.yml:8`;
- рабочий ключ (64 символа) живёт только в `secrets/.env` и раздаётся **12** контейнерам;
- вывод: **мёртвая копия**, инцидента нет, правка — заменить литерал на `${Jwt__SigningKey:?…}`
  (зона @BE); в `bin/`-копиях те же значения, что и в исходниках, и в git их нет.

## Границы

- Сверка **ничего не меняет** на контуре: только читает `.env` и файл-кандидат.
- Для паролей БД есть отдельный механизм: `DBPW_<SERVICE>` в `secrets/.env` (`DO-111`), сверять
  их тем же `keycmp`, подставляя нужный `--a-key`.
