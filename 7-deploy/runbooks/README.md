# Ранбуки инфраструктуры

> Ранбук отвечает на **«как повторить руками»**. На **«почему так устроено»** отвечает ADR —
> ранбук на него **ссылается**, а не пересказывает. Изменил ADR — обнови ранбук в том же коммите
> (`AGENTS.md` §5.2). Проверяют: `@DO` (владелец), `@AR` (связность с ADR).

## Классы работ

| Ранбук | Когда открывать | Почему существует |
|---|---|---|
| [`ci-workflow.md`](ci-workflow.md) | меняю `paths`/джобы в `.github/workflows/` | `ci-tests.yml` правился 4 раза (DO-030/031/032/035); дважды терялись guard-джобы, один раз — минуты на повторный вывод одних и тех же флагов |
| [`deploy-heal.md`](deploy-heal.md) | 502 на стенде, «образ не обновился», передеплой | образ `clients` 18 ч не обновлялся из-за забытого сервиса в `SVCS`; шлюз полдня ходил без `--add-host clients` |
| [git-incident.md](git-incident.md) | повреждённые метаданные git, «не могу запушить», потеря работы | .git/rebase-merge без head-name, отказ git_sync, пропавшие коммиты |
| [`secrets-rotation.md`](secrets-rotation.md) | ключ утёк, ключ надо добавить/сменить, «значения разъехались» | инциденты 03.11 и 04.11: фрагменты `Jwt:SigningKey` в чате; OTP-ключи в прод `.env` |
| [`release-gate.md`](release-gate.md) | выпускаем релиз: гейт → `smoke` → `deploy-prod` | самый ошибочный класс: «зелёным» считали вытесненный прогон, а образ на проде проверяли глазами |

**Намеренно не заведено:** `board-sync.md`. Доска живёт через `tools/sync_board.py` и
`tools/cleanup_orphans.py`; у них есть `--list` / `--delete` и `--help`. Ранбук продублировал бы
интерфейс скрипта и устарел бы первой же его правкой — источником правды остаётся сам скрипт.

## Кто может запускать

| Ранбук | Кто | Что нужно |
|---|---|---|
| `ci-workflow.md` | `@DO` | push в `.github/` (scope `workflow`) |
| `secrets-rotation.md` | `@DO` | доступ к GitHub Secrets + `.env` на VPS |
| `deploy-heal.md` | `@DO` | SSH на VPS-1/2 (прод — только `@DO`, `@TL` читает результат) |
| `release-gate.md` | `@DO` (запуск и диагностика) | очередь CI, права на `workflow_dispatch` |

Другим ролям SSH не нужен и не даётся: всё, что им нужно, видно в CI-логах и в чате.
Если роль просит доступ к VPS — это повод вынести проверку в CI, а не выдать ключ.

## Общие правила

1. **Один прогон — одно доказательство.** `cancelled` не доказывает ничего; нужен прогон,
   завершившийся сам (`AGENTS.md` §5.1).
2. **Не пушить, пока по группе висит pending** — новый пуш вытесняет ожидающий.
3. **«Дошло» проверять после `fetch`:** `git rev-list --count origin/main..HEAD` = 0.
   Ссылаться на SHA — только после `git merge-base --is-ancestor`.
4. **Секретов в ранбуках нет** — только имена переменных и способ их положить (`AGENTS.md` §6).
5. **Дата ревизии** в каждом файле; пересматривать при изменении ADR.
