> Нормы CI (окно 5 минут, вытеснение, доказательность) — `AGENTS.md` §5.1 и
> [`docs/CI-RULES.md`](../../docs/CI-RULES.md).

- **Класс:** правка `.github/workflows/**` — триггеры, `paths`/`paths-ignore`, джобы, гейты
- **Владелец:** `@DO`
- **Когда применять:** меняешь `paths`, переносишь/добавляешь джоб, правишь concurrency, добавляешь ручной запуск
- **ADR (почему):** `ADR-020`
- **Зависит от ADR (что править при изменении процесса):**
  | ADR | что здесь придётся изменить |
  |---|---|
  | `ADR-020` | меняется схема деплоя → разделы «Гейты» и `release-gate.md` |
  | `ADR-019` | меняются среды (dev/prod) → адреса стендов в шагах |
- **Дата ревизии:** 2026-11-02

## 1. Проверка перед началом

```bash
python tools/check_docs_size.py            # доки не распухли
git fetch origin main && git rev-list --count origin/main..HEAD   # 0 = ничего не висит локально
# очередь по группе, которую трогаешь (подставь имя группы):
gh run list --workflow ci-tests.yml --limit 5
```

Правило: **если по группе есть `pending` — сначала дождаться, потом пушить.** Иначе новый
пуш вытеснит ожидающий прогон, и тот умрёт как `cancelled` без единого шага.

## 2. Шаги

1. **Перечисли джобы до правки** — это твой чек-лист, чтобы ничего не потерять:
   ```bash
   python - <<'PY'
   import yaml
   d = yaml.safe_load(open('.github/workflows/ci-tests.yml', encoding='utf-8'))
   print(list(d['jobs']))
   PY
   ```
2. **Проверь, что guard'ы не задвоены.** Сейчас `check-chat` и `guard-secrets` описаны
   **и** в `chat-guards.yml`, **и** в `ci-tests.yml`. Правя один файл, проверь второй:
   ```bash
   grep -l 'guard-secrets' .github/workflows/*.yml
   ```
3. **Меняя `paths-ignore`, перенеси guard-джобы, а не выключай** (урок DO-032: задачи почти
   сутки не сканировались на секреты, и никто не заметил).
4. **Один джоб за правку**, если переносишь между файлами — так проще найти виновника.
5. **Валидируй YAML до пуша:**
   ```bash
   python -c "import yaml;yaml.safe_load(open('.github/workflows/<файл>.yml',encoding='utf-8'));print('ok')"
   python tools/check_workflow_paths.py      # если менял paths
   ```
6. **Пуш и проверка «дошло»:** `python tools/git_sync.py --role do`, затем
   `git fetch origin main && git rev-list --count origin/main..HEAD` → `0`.

## 3. Гейты (кто и чем проверит)

| Гейт | Команда | Ожидание |
|---|---|---|
| YAML | `python -c "import yaml;…"` | `ok` |
| Линтеры чата/байтов | `python tools/check_nul.py`, `python tools/chat_lint.py --report` | код 0 |
| Доки | `python tools/check_rule_docs.py` | 0 ошибок |
| CI | workflow `ci-tests` / `chat-guards` | зелёный, прогон завершился сам |
| **Негативный тест** | подложить фейковый секрет в файл задачи → пуш → `guard-secrets` должен покраснеть → убрать | гейт **красный** на подлоге |

## 4. Грабли (из реальных случаев)

- **`cancelled` без шагов ≠ «кто-то отменил».** Это вытеснение: GitHub держит один pending на
  группу. Признак — `steps: 0` и пустой `started_at`. Виноват тот, кто пушил.
- **`workflow_dispatch` тоже вытесняется пушем.** Перед dispatch — пустая очередь по группе;
  пока идёт dispatch-прогон — не пушить. За 2026-11-02 на этом сгорели `#977`–`#983`
  (у всех 0 шагов), и «0.65 не проверялся вообще».
- **`--reporter=list,json` + `>` = битый файл.** Оба репортёра пишут в один поток, JSON-парсер
  падает на `Extra data`. Лечится `PLAYWRIGHT_JSON_OUTPUT_NAME=/tmp/report.json` — json в файл,
  list в stdout.
- **`paths-ignore` без переноса guard'ов = тихая дыра.** Симптом: «секреты не проверяются»,
  никакой ошибки нет.
- **Сужение `ci-tests` до чата** убирает и бэкенд-тесты: проверяй, что `test` остался в
  `paths`, а не только в `paths-ignore`.
- **Node 20 deprecated warning** — шум, не падение; шаги на Node 24, но `actions/*@v4` это
  переживают.

## 5. Критерий готовности

- [ ] Список джобов до и после совпадает либо разница объяснена (ни один не потерян).
- [ ] `guard-secrets` существует ровно в одном файле или явно задокументирован в двух.
- [ ] Негативный тест пройден: подлог покраснел, после уборки — зелено.
- [ ] Прогон завершился сам (не `cancelled`), шагов не 0.
- [ ] Коммит в `origin` (`rev-list --count` = 0).

## 6. Откат

```bash
git revert <sha>            # откат правки workflow
python tools/git_sync.py --role do
# если правил paths и потерял guard — восстанови джоб отдельным коммитом, не «заодно»
```

## Синхронизация инструментов: `sync_tools --pull` — только на СОВПАДАЮЩЕЙ копии

Правило (@LM, 02.11, до ретро `D-10`; инцидент @DO того же дня):

**`python tools/sync_tools.py --pull --from ../LoopMaker` не запускать на копии, которая
расходится с манифестом.** `--pull` перезаписывает копию версией источника **молча** — вместе
с локальными правками. Реальный случай: вызов `reach, reach_total, reach_void = metric_ci_reach(...)`
был в `origin` и в `XDiary/tools/health.py`, но не в источнике `LoopMaker/tools/health.py`;
очередной `--pull` вернул файл к версии **без вызова**, то есть вернул бы
`NameError: name 'reach' is not defined` в `health.yml`.

Порядок, пока `D-10` не реализован:

```bash
python tools/sync_tools.py --check                     # 21/21 = копии совпадают
# если НЕ совпадают — НЕ делать --pull; править вручную в ОБОИХ местах:
#   1) источник: LoopMaker/tools/<файл>
#   2) копия:    XDiary/tools/<файл>
#   3) затем --check, чтобы манифест совпал
```

Почему не «просто `--pull`»: копия в `XDiary/tools/` — зона @DO, источник — зона @LM.
Правка одной стороны без другой даёт красный `guard-tools` у всех, а `--pull` на расходящейся
копии стирает как раз ту правку, из-за которой копии и разошлись.

После ретро: `D-10` добавляет отказ с кодом 1 и списком файлов + `--force` для осознанной
перезаписи + негативный тест «правка в копии → `--pull` → код 1 → файл не изменён».
