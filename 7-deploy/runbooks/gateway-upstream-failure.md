# Ранбук: контроль «апстрим недоступен» (B7 — 502/504)

Зачем: проверить, что шлюз отдаёт **502** (быстрый отказ), а не висит и не отдаёт
200/500 — и при этом **не гасить настоящий сервис** (иначе проверка ломает соседей и
оставляет вопрос «а вернули ли»).

## Способ: второй шлюз с мёртвым апстримом

`7-deploy/flaky-gateway.sh` поднимает рядом **копию шлюза** на `127.0.0.1:18080` с копией
конфига, где один кластер (`clients` — маршрут анонимный, токен для пробы не нужен)
смотрит в заведомо мёртвый `http://127.0.0.1:1`. Рабочий шлюз на `8080` не трогается.

**Одна команда** (dev, от `ubuntu`):

```bash
sudo -n bash /opt/xdiary/7-deploy/flaky-gateway.sh up && sleep 8 \
  && sudo -n bash /opt/xdiary/7-deploy/flaky-gateway.sh check \
  && sudo -n bash /opt/xdiary/7-deploy/flaky-gateway.sh down
```

Ожидание: `POST /api/v1/clients -> HTTP 502 за ~0.03s`.
Замер 2026-11-10 на dev: **502 за 0.0259 c**.

## Почему не «остановить контейнер сервиса»

- останавливает живую зависимость (на dev от этого зависят другие роли);
- недетерминированно: сервис может рестартовать по `restart: unless-stopped`;
- портит состояние: `heal-network`/`heal-watch` видят падение и начинают «лечить».

## Отдельно: таймаут по умолчанию слишком долгий

Замер B7 «живым» способом (остановить сервис) давал **504 за 15.01 c** — это таймаут
YARP по умолчанию. Для интерактивного API это UX-дефект: ожидается `ActivityTimeout`
≈ 5 c на кластер (`6-msa/ApiGateway/appsettings.json`, зона @BE).

**Таймаут клиента должен быть больше таймаута шлюза.** Иначе получаешь ложный `000`:
мой первый замер B7 шёл с `curl -m 15`, клиент обрывал запрос ровно на 15-секундном
таймауте шлюза, и вместо `504` я увидел `000` — и почти записал это как «шлюз молчит».
Для замеров B7 — `-m 20` и больше.

## Что проверять при изменении шлюза

1. `check` → 502 и **время < 1 c** (быстрый отказ, не таймаут);
2. рабочий шлюз: `/health` = 200, `POST /api/v1/clients` = 400 (валидация, маршрут жив);
3. `down` → контейнер `xdiary-gw-deadupstream` отсутствует (`podman ps -a | grep deadupstream`).
