# Ранбук: секреты — добавление, сверка, ротация

> «Почему» — [`ADR-020`](../../04-architecture/ADL/adr-020.md) (среды и их секреты),
> `AGENTS.md` §6 (правила секретов). Значения сюда не попадают **никогда** — только имена.

- **Класс:** положить/сменить ключ, сверить ключи между средами, ротация после утечки
- **Владелец:** `@DO`
- **Когда применять:** новый ключ (OTP/JWT/Garmin), «подпись не сходится между сервисами»,
  фрагмент ключа попал в чат/задачу/коммит, плановая ротация
- **ADR (почему):** `ADR-020`, `ADR-021` (OTP)
- **Зависит от ADR (что править при изменении процесса):**
  | ADR | что здесь придётся изменить |
  |---|---|
  | `ADR-020` | меняется схема хранения секретов → разделы 2 и 6 |
  | `ADR-021` | меняется канал OTP → раздел «Добавление ключа OTP» |
- **Дата ревизии:** 2026-11-02

## 1. Проверка перед началом

```bash
# 1) где секреты живут (и не должны коммититься)
git check-ignore -v 7-deploy/secrets/.env
# 2) не утекло ли уже (гейт по пушимому диапазону)
python tools/check_secrets.py --config loop.config.json
# 3) сверка без раскрытия значений: совпадают/нет + sha256[:8]
python tools/keycmp.py --a-env <env-A> --b-env <env-B>
```

Правило: **значение ключа не печатаем, не цитируем и не сравниваем по символам.** Только
«совпадают» / «различаются» и отпечаток.

## 2. Шаги

### Добавление ключа

1. Положить переменную в `.env` **на машине** (`7-deploy/secrets/.env`, `chmod 600`), не в репозиторий.
2. Для CI — в GitHub Secrets, имя заглавными: `DEV_SSH_HOST`, `DEV_SSH_USER`, `DEV_SSH_KEY`.
3. Перезапустить только затронутые контейнеры (`--env-file` читается при создании):
   ```bash
   sudo bash /opt/xdiary/7-deploy/deploy.sh single
   ```
4. Проверить, что сервис **видит** переменную, не печатая значение:
   ```bash
   sudo podman exec <контейнер> sh -c 'printenv | grep -c "^Otp__"'   # ожидаем число переменных
   ```

### Ротация после утечки

1. **Зачистить** рабочее дерево (файл/чат/задачу) — значение остаётся в git-истории навсегда.
2. **Сгенерировать новое** значение у источника (bot-token, JWT-ключ) — не «переставить символы».
3. Положить во все места: GitHub Secrets → `.env` на VPS-1 и VPS-2.
4. Пересоздать контейнеры, которые читают ключ, и проверить поведение, а не значение:
   `curl /api/v1/clients` = 200, OTP приходит.
5. Записать в задачу/чат **факт ротации и дату**, без значения.

## 3. Гейты (кто и чем проверит)

| Гейт | Команда | Ожидание |
|---|---|---|
| Локальный | `python tools/check_secrets.py --config loop.config.json` | код 0 |
| CI (чат/задачи) | `guard-secrets` в `chat-guards.yml` | зелёный |
| CI (код) | `guard-secrets` в `ci-tests.yml` | зелёный |
| Сверка сред | `python tools/keycmp.py --a-env A --b-env B` | «совпадают» |
| **Негативный тест** | подложить фейковый ключ в задачу → пуш | `guard-secrets` **красный** |

## 4. Грабли (из реальных случаев)

- **Фрагмент = утечка.** 03.11 в `chat/be.md` попали хвосты `Jwt:SigningKey`, 04.11 — те же
  хвосты в сообщении координатора об инциденте. Репозиторий публичный: «3 последних символа»
  это тоже разглашение.
- **Путь к хранилищу — тоже подсказка.** Гейт `check_rule_docs.py` ловит абсолютные домашние
  пути в задачах: они говорят, где искать секреты. Писать «личное хранилище роли, вне
  репозитория».
- **`check_secrets.py` в режиме `--range`** сканирует пушимое, включая строки, зачищенные потом
  в рабочем дереве — то есть зачистка после коммита **не спасает**, нужна ротация.
- **`.env` на проде ≠ `.env` на dev.** `CLIENTS__TESTOTP` есть только на dev (нужен
  `seedSession`), на проде его быть не должно: это «универсальный код», обходящий OTP.
- **Ключ в образе не обновляется сам.** Если сервис читает ключ при старте, нужен перезапуск
  контейнера, а не только правка `.env`.
- **PyYAML на сервере отсутствует** — скрипты, которым нужен compose, должны иметь fallback
  (см. `deploy-heal.md`).

## 5. Критерий готовности

- [ ] `check_secrets.py` — код 0; `keycmp.py` говорит «совпадают» для пар, которые должны совпадать.
- [ ] Значение не встречается ни в одном файле репозитория (включая историю пуша).
- [ ] Сервисы, читающие ключ, пересозданы и отвечают 200.
- [ ] Инцидент записан в задаче/чате без значения; ротация помечена датой.

## 6. Откат

Откат секрета — это **новая** ротация, а не возврат старого значения: старое уже скомпрометировано.
Если новый ключ сломал совместимость — положить его во все места одновременно и пересоздать
все зависящие контейнеры одним прогоном `deploy.sh`.
