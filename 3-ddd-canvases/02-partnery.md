# Bounded Context Canvas: Партнёры

## 1. Имя
Партнёры (Partners)

## 2. Назначение
Вести профили партнёров (имя, фото, пол, заметки). Поставляет выбор партнёра в журнал и его пол для гендерно-зависимых типов оргазмов.

## 3. Стратегическая классификация
- [ ] Core Domain (конкурентное преимущество)
- [x] Supporting (поддержка core)
- [ ] Generic (типовой функционал)

## 4. Роль домена
- [x] Execution (исполняет бизнес-операции)
- [ ] Gateway (интеграция с внешними системами)
- [ ] Analysis (аналитика, отчёты)

## 5. Входящая коммуникация (Inbound)
| Кто вызывает | Что вызывает | Формат |
|---|---|---|
| Пользователь (UI) | CRUD партнёра | форма (имя, фото, пол, заметки) |
| Журнал | выбрать партнёра | имя партнёра |

## 6. Исходящая коммуникация (Outbound)
| Кому отправляет | Что отправляет | Формат |
|---|---|---|
| Журнал | список/имя партнёра, его пол | IndexedDB `partners` |
| Каталог (фантазии) | список партнёров для привязки | имена |

## 7. Ubiquitous Language
- **Партнёр** — участник акта (может быть несколько в списке).
- **Пол** — `male` / `female` (влияет на типы оргазмов).
- **Фото** — аватар партнёра.
- **Заметки** — свободный текст о партнёре.

## 8. Бизнес-решения (Business Decisions)
- Пол нового партнёра по умолчанию «женский».
- Пол партнёра определяет набор типов оргазмов на шаге «Оргазмы».
- Фото сжимается до квадрата (512px) перед сохранением.

## 9. Предположения (Assumptions)
- Пол бинарный (мужской/женский).
- Партнёров может быть несколько; в одной записи — один партнёр (пока).

## 10. Зависимости / интеграции
| Контекст | Тип интеграции |
|---|---|
| Журнал | Customer/Supplier (поставщик выбора) |
| Каталог и инвентарь | Customer/Supplier (для фантазий) |
| Приватность и доступ | Gatekeeper |
