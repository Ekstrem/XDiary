# Aggregate Design Canvas: Client (Клиент)

> Bounded Context: Клиент (Client) — идентификация/аутентификация пользователя (ADR-021)
> Агрегат: Client (пользователь)

## 1. Name (Имя)

- **Имя:** Client (Клиент / аккаунт пользователя).
- **Создаётся когда:** `Register(phone)` — регистрация по номеру телефона (`ClientHandlers.cs:27-62`); повтор на существующий номер отдаёт `phone_taken`/`DuplicatePhoneException` (`:60`, `:85`).
- **Завершается когда:** удаления аккаунта в контракте **нет** (ни одна операция индекса не удаляет `Client`) — жизненный цикл `Registered → Verified → Active`.
- Заполнено 2026-11-10 (@AR): раздел отсутствовал, содержимое — из §3 и кода, без новых решений.

## 2. Description
**Идентификатор агрегата (DF):** `<guid, long>` — технический, для быстрого поиска. НЕ входит в сущность.

**Сущность (Entity — корень агрегата):**
- **Client** — аккаунт пользователя:
  - **`phone`** (номер телефона, уникальный) — идентичность
  - **`displayName`** (string) — имя «я» (спрашиваем один раз на онбординге)
  - **`gender`** («male» | «female») — пол «я» (там же)

**VO:** Phone (номер), OtpCode (код), DisplayName (имя), Gender (пол), Photo (опционально).

**Правило формата `phone` (канон, `AR-025`, 2026-11-13) — одно на всех, машинно проверяемое:**

1. **Нормализация** (до валидации, лимитера и проверки уникальности): убрать все символы, кроме цифр и ведущего `+`;
   `8XXXXXXXXXX` (11 цифр, первая `8`) → `+7XXXXXXXXXX`.
2. **Валидность:** E.164 — `^\+[1-9][0-9]{6,14}$` (7–15 цифр, первая не `0`).
3. **Уникальность — по нормализованной форме**: иначе `+7 900 000-00-00` и `+7900000000` создадут двух клиентов.
4. **Невалидный номер** на `Client.Register` → **`400`** с причиной, **до** лимитера (`429`) и отправки OTP.
5. Фронт (`8-front/index.html:49`, `type="tel"`) правило не дублирует: отправляет ввод, сервер нормализует.


> **`gender` — словарь, а не свободная строка.** Допустимые значения: `male`, `female`
> (справочник пола — общий для Журнала, Партнёров и Каталога, см. `00-context-map.md` §Shared Kernel).
> Контракт **валидирует** значение (400 на неизвестное), а не принимает любую строку:
> иначе аналитика по полу и автоподбор органов/типов оргазмов развалятся на «Other»/«other»/«м».
> **Решение владельца (2026-11-03 16:54): «обойдёмся двумя»** — значений ровно **два**, `other` не добавляем.
> Расширение словаря — только новым решением владельца, отдельным коммитом (канвас + контракт + тест).

## 3. State Transitions
```
(нет) → [Register] → Registered
Registered → [VerifyOtp] → Verified
Verified → [CompleteProfile(name, gender)] → Active
Active → [UpdateProfile(name, gender, photo?)] → Active
```

## 4. Enforced Invariants

| Инвариант | Чем держится | Адрес |
|---|---|---|
| `phone` **уникален** | `DuplicatePhoneException` при создании + `phone_taken` при гонке | `ClientHandlers.cs:60`, `:85` |
| OTP имеет **срок и счётчик попыток** | поля `OtpExpiresAt`, `OtpAttempts` в анемодeли агрегата | `AnemicModel.cs:13-14` |
| `Verified` ставится **только** подтверждением кода | `VerifyClientOtpHandler` → `VerifyOtp` в агрегате | `ClientHandlers.cs:91-96` |
| Профиль «я» — **здесь**, не в `Partner` | решение ADR-024, `LinkedPartnerId` удалён | этот файл, §6 (примечание) |

## 5. Corrective Policies

| Политика | Триггер | Поведение |
|---|---|---|
| **Rate-limit OTP** | слишком частые запросы кода | `ClientResults.Fail("Слишком много запросов, попробуйте позже.")` — отказ **без** создания клиента (`ClientHandlers.cs:37`) |
| **Повторная выдача OTP** | регистрация повторно на тот же номер | `ReissueOtp(otp)` перезаписывает код и срок, а не создаёт второй аккаунт (`:56`, `:80`) |
| **Доставка OTP** | канал `Otp:Channel` (log/sms/telegram) | сбой доставки не отменяет регистрацию, но виден вызывающему (`RegisterClientResult.Delivery` — `:62`) |

## Онбординг: продуктовые ответы владельца (по делегации 2026-11-11)

> **Внесено @AR по делегации владельца (2026-11-11); @PO в архиве на итерацию техдолга (`AGENTS` §2.1).**
> Формулировки ниже — **слова владельца**, не мои; в `BC-Client/03-command-api.md` они уже отражены контрактом.

| Шаг | Что спрашиваем | Обязательность | Источник |
|---|---|---|---|
| 1. Телефон | номер + OTP | обязателен | ответ владельца, US-001 |
| 2. «Кто вы?» | **имя** и **пол** — **ровно два значения**, `male`/`female`, третьего нет | **оба обязательны**, кнопка активна только при заполненных | ответ владельца: «имя + пол один раз»; **`ex.md:34` (`2026-11-04 20:12`) → «Только два пола»** |
| 3. Фото | аватар | **опционально** | ответ владельца: «фото опционально» |
| 4. Партнёр | второй человек | **не на онбординге** — отдельным действием позже | ADR-024/E7, `0.88` |

**Следствия, которые нельзя перечитать по-своему:**
- «имя + пол **один раз**» означает: после успешного `POST /clients/me/profile` онбординг **не возвращается** — повторный вход
  идёт сразу в журнал (это и есть критерий `FE-038`, а не «сколько раз показали экран»);
- PIN на онбординге **не спрашивается** (PIN — локальный замок, ADR-021);
- партнёр **не создаётся** на онбординге (онбординг создаёт **профиль клиента**) — проверяется отсутствием шага привязки.

**Garmin — отдельный вход, не онбординг:** подключение живёт в **Настройки → Интеграции**, до готовности импорта кнопка
показывает «скоро». Это подтверждает `BC-GarminGateway` (интеграция — отдельный шаг, не часть аккаунта) и снимает
с онбординга любую зависимость от соматики.


**Пол — ровно два значения (решение владельца).** `ex.md:34`: `- [2026-11-04 20:12] → @AR: Только два пола`
(проверка: `git show origin/main:5-tech-backlog/chat/ex.md | grep -F "Только два пола"`). Следствия, обязательные для кода:
- домен принимает **только** `male`/`female` (нормализация регистра и пробелов — да, расширение словаря — **нет**);
- любое другое значение → **`400`**, а не «сохранили как есть» и не «привели к `male` по умолчанию» (последнее — тихая подмена данных);
- UI: **две** опции, без «другое»/«не указан»; «не указан» существует только как **отсутствие значения до онбординга**, а не как третий вариант;
- это же правило действует для партнёра (`BC-Partners`), потому что словарь один: `GenderEnumValidator.Normalize` (Trim + ToLowerInvariant) + `male`/`female`.
