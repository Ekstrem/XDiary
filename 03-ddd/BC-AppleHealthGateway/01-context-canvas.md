# Bounded Context Canvas: Шлюз Apple Health

## 1. Имя
Шлюз Apple Health (AppleHealthGateway)

## 2. Назначение
Anti-Corruption Layer к Apple Health. Изолирует модель Apple (ручной экспорт `export.xml`/CSV из «Здоровья», HealthKit из браузера недоступен) и отдаёт нормализованную **соматику** (пульс, HRV, сон, пульс покоя). Один агрегат — AppleImport.

## 3. Стратегическая классификация
- [ ] Core Domain
- [x] Supporting
- [ ] Generic

## 4. Роль домена
- [ ] Execution
- [x] Gateway (интеграция с внешними системами)
- [ ] Analysis

## 5. Входящая коммуникация (Inbound)
| Кто вызывает | Что вызывает | Формат |
|---|---|---|
| Пользователь (UI) | импорт файла экспорта | `export.xml` / CSV |
| Соматика (минутные точки / дневные) | запрос нормализованной соматики | метрики за период |

## 6. Исходящая коммуникация (Outbound)
| Кому отправляет | Что отправляет | Формат |
|---|---|---|
| Соматика — минутные точки | точки пульс | нормализованные точки |
| Дневные метрики | пульс покоя / HRV / сон | нормализованные дневные сводки |
| Apple Health (внешний) | чтение экспорта | файл |

## 7. Ubiquitous Language
- **Экспорт** — `export.xml`/CSV из приложения «Здоровье».
- **Соматика** — физиологические метрики (без BB/стресса — это специфика Garmin).

## 8. Бизнес-решения (Business Decisions)
- HealthKit из браузера недоступен → только ручной экспорт файла.
- Метрики, отсутствующие у источника, отсутствуют (Body Battery и «стресс» — только Garmin).

## 9. Предположения (Assumptions)
- Пользователь вручную выгружает файл из «Здоровья».

## 10. Зависимости / интеграции
| Контекст | Тип интеграции |
|---|---|
| Соматика — минутные точки | Customer/Supplier (норм. точки) |
| Дневные метрики | Customer/Supplier (норм. сводки) |
| Apple Health (внешний) | Anti-Corruption Layer |
| Приватность и доступ | Gatekeeper |
