## Известный техдолг

### 1. Fallback расписания Analytics (AR-006) — **страховка несущая, а не «на всякий случай»**
- **Суть:** BE-026 событийный (`ApplyCompleted`/`ApplyDeleted` → `RecomputeLocked`), но `AnalyticsPrecomputeService` (schedule) остаётся fallback-страховкой.
- **Факт 2026-11-07 (проверено @AR по коду):** событийный путь **межсервисный и best-effort по HTTP**, не по шине (шина `EventBus.InMemory` живёт внутри процесса): `Journal.Api/Events/HttpJournalEventPublisher.cs:29-37` — POST в `{analytics}/api/v1/analytics/events` с `Timeout = 2 с` и **пустым `catch { /* best-effort: Analytics MV восстановится fallback-расписанием */ }`**; статус ответа не проверяется. Внутри Analytics обработчики есть (`ApplyCompleted` — 3 файла, `ApplyDeleted` — 3, `RecomputeLocked` — 7, `AnalyticsPrecomputeService` — 4, `BackgroundService` — 1).
- **Следствие, которое надо держать в голове:** «BE-026 событийный» верно **при условии, что HTTP дошёл**; при таймауте/`500`/рестарте Analytics событие теряется **без следа**, и корректность MV держится **на расписании**. То есть fallback — **несущая конструкция**, его отключение = тихая деградация аналитики (и это же причина, по которой `cron`-путь нельзя считать «временным»).
- **Риск:** средний (не «низкий»: незаметная потеря + зависимость корректности от расписания).
- **Приоритет:** P2.
- **Оценка:** оставить как есть **до** появления outbox/ретраев (E5); дешёвый шаг — тот же, что в п.11: `LogWarning` + счётчик вместо пустого `catch` (класс один — «невидимый HTTP-вызов в write-пути»).

### 11. BE-035 — публикация события fire-and-forget без ретраев
- **Суть (уточнено @AR 2026-11-07 по коду):** `RecordPointHandler` публикует событие fire-and-forget (`SomaticSeriesHandlers.cs:16` — `_ = _publisher.PublishPointAsync(..., CancellationToken.None)`), ретраев нет — при сбое доставки событие теряется: из стора его никто не доставит, Outbound Handler отсутствует.
  **Механизм сменился, риск остался и стал тише:** публикация идёт **не через шину**, а по HTTP — `HttpSomaticSeriesEventPublisher.PublishPointAsync` (`SomaticSeries.Api/Events/HttpSomaticSeriesEventPublisher.cs:12-15`): POST в Analytics с `client.Timeout = 2 с` и **пустым `catch { }`**.
  Следствие: сбой доставки **не оставляет следа** — ни исключения наружу, ни строки в логе, ни счётчика. Ранее здесь стояло «`_ = PublishAsync`» (in-memory шина) — эта формулировка устарела: `git grep '_ = PublishAsync'` по `6-msa` даёт **0** вхождений.
  **Дополнено @TL 2026-11-07 (проверено и мной):** невидим не только выброс, но и **HTTP-ответ** — `PostAsJsonAsync` возвращает `HttpResponseMessage`, который **никто не проверяет**: в `HttpSomaticSeriesEventPublisher.cs` (`grep -E 'EnsureSuccessStatusCode|IsSuccessStatusCode|ILogger'` по `BC-SomaticSeries`) **0 вхождений**, то есть `500` от Analytics так же невидим, как таймаут. Минимальная задача без изменения поведения — `catch (Exception ex)` + `LogWarning` + счётчик, и проверка статуса с тем же счётчиком (название согласовать с Analytics: `precompute.non2xx…`), заведена @TL на @BE `09:31`.
- **Риск:** средний (потеря события = рассинхрон MV).
- **Приоритет:** P2.
- **Оценка:** Outbound Handler + ретраи при эволюции шины — это **требования приёмки долга** (`edm-debt-plan.md:35` — E1, `:71` — E5), а не принятое решение: `ADR-029` **отклонён** 2026-11-14.

### 12. do-deploy без версионирования образов — ✅ **закрыто по тегам 2026-11-07, остался digest** (`DO-113`)
- **Суть (было):** деплой (`deploy.yml`) без версий образов (`latest`/пересборка) — откат к конкретной версии невозможен.
- **Факт 2026-11-07 (проверено @AR по коду):** `git grep ':latest' -- 7-deploy .github` → **0 вхождений**; теги берутся из `7-deploy/images.lock` через `tag_of` (`update.sh` — 3 вхождения, `recreate-service.sh` — 2), формат тега — `single-<sha сборки>` + провенанс `commit=<sha>`. **Откат «на тег» теперь возможен.**
- **Что осталось (и это уже другая карточка):** в lock **нет `digest=`**, выкатки по `@sha256` нет ⇒ неизменяемой идентичности образа нет: пересборка того же коммита даёт другой образ под тем же тегом. Это `ADR-027` (частично) и `DO-113`.
- **Риск:** низкий (остаточный — подмена тега в реестре, ловится только провенансом).
- **Приоритет:** P2 → **P3** (остаток закрывается в `DO-113`).
- **Оценка:** ~~теги образов + версионирование~~ → сделано; остаток — `digest=` и выкатка по нему (`DO-113`).

### 14. ADR-008: ссылка «контекст Приватность» — ✅ **снято 2026-11-09; остаток одной фразы 2026-11-07**

### 16. Справочник пола реализован дважды (Client и Partners) — P3

- **Приоритет:** P3 (не мешает; фиксируется, чтобы не выяснять заново).
