> Владелец: архитектор. Каждый пункт: суть, риск, приоритет (P1–P3), оценка. План гашения — согласовать с PO. Задача: **AR-007** (P3, после закрытия фаз).

## Известный техдолг

### 1. Fallback расписания Analytics (AR-006)
- **Суть:** BE-026 событийный (`ApplyCompleted`/`ApplyDeleted` → `RecomputeLocked`), но `AnalyticsPrecomputeService` (schedule) остаётся fallback-страховкой.
- **Риск:** низкий (страховка, не основной путь).
- **Приоритет:** P3.
- **Оценка:** оставить как есть.

### 2. InMemory EventBus (Single-профиль)
- **Суть:** межсервисная доставка событий — Outbound Handler (Saga/HTTP), не настоящая шина.
- **Риск:** средний (потеря/дубликаты событий при сбое доставки).
- **Приоритет:** P2.
- **Оценка:** эволюция профиля Single → Cqrs → Ceqrs (по таблице edm-skill).

### 3. dev-ключи в appsettings (allowlist)
- **Суть:** dev-значения в `appsettings.json` (в allowlist `guard-secrets`).
- **Риск:** низкий (только dev).
- **Приоритет:** P3.
- **Оценка:** держать allowlist узким.

### 4. JWT-ключ только в VPS .env (дисциплина ротации)
- **Суть:** `Jwt:SigningKey` в `.env` на VPS (не в git); ротация вручную через @DO.
- **Риск:** **высокий** (утечка = компрометация; репозиторий публичный).
- **Приоритет:** P1.
- **Оценка:** ротация по инциденту (2026-11-03/04).

### 5. Легаси app/
- **Суть:** старый фронт `app/` (не деплоится; прод из `8-front/`).
- **Риск:** низкий (путаница, не используется).
- **Приоритет:** P3.

### 6. 0-df-issue/ (пробелы DF-фреймворка)
- **Суть:** заметки @BE о пробелах DigiTFactory.Libraries.
- **Риск:** по конкретному issue.
- **Приоритет:** по issue.

### 7. FE-017 — Pearson на клиенте (Фаза 4)
- **Суть:** фронт вычисляет корреляции (Pearson) на клиенте; должен брать из `GET /analytics/correlations` (MV).
- **Риск:** средний (клиент считает бизнес-агрегат, рассинхрон с сервером).
- **Приоритет:** P2 (уберём в Фазе 4 вместе с корреляциями).

### 8. `_dialogue.md` (сводка чата)
- **Суть:** `merge_chat.py` теряет сообщения с двумя адресатами (`@A + @B`); сводка неполна.
- **Риск:** низкий (сводка, не источник).
- **Приоритет:** P3.

### 9. Analytics — глобальный снапшот (tenant-скоуп)
- **Суть:** соматические MV (`analytics_*`) — глобальные (пара = комната), без `clientId`. Per-client аналитика (мой пульс ↔ моя длительность) — будущая multi-tenant фича.
- **Риск:** средний (при мульти-аренде нужен tenant-скоуп).
- **Приоритет:** P3 (MVP = пара, ADR-018).
- **Оценка:** добавить `clientId` в события + per-client снапшот.
