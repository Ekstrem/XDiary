### 9. Analytics — глобальный снапшот (tenant-скоуп)
- **Суть:** соматические MV (`analytics_*`) — глобальные (пара = комната), без `clientId`. Per-client аналитика (мой пульс ↔ моя длительность) — будущая multi-tenant фича.

### 11. BE-035 — публикация события fire-and-forget без ретраев

- **Риск:** средний (потеря события = рассинхрон MV).
- **Приоритет:** P2.
- **Оценка:** outbox (Cqrs-профиль) при эволюции шины.

### 12. do-deploy без версионирования образов

- **Приоритет:** P2.
- **Оценка:** теги образов + версионирование.

### 13. EDM-несоответствие BE (Event Sourcing / IEventBus / MV)
- **Суть:** код `6-msa` не использует инфраструктуру DigiTFactory — вместо Event Store/Event Bus/Read Store сделан **свой слой**: EF Core `SaveChangesAsync` + ручной HTTP-паблишер. Нет Event Sourcing, `IEventBus`, Event Consumer (`IHostedService`), проекции MV (`UpsertAsync`); свои `IRepository`/`IReadRepository`/`IBusAdapter` (запрещено скиллом). Полный разбор — `04-architecture/edm-verification.md`.
- **Риск:** **высокий** (ядро CEQRS не реализовано: «событие = источник истины» отсутствует, query считает на лету).
- **Приоритет:** P1 (отложено: решение владельца 2026-11-06 п.8 = C — после устойчивой работы приложения).
- **Оценка:** системная переделка всех BC (вернуть `AddEventStorePostgres` + `AddEventBus` + `AddReadStore`, Event Consumer, проекции MV).

### 14. ADR-008: ссылка «контекст Приватность» не исправлена — гейт наказывает касание старых ADR
- **Суть:** после ответов владельца (2026-11-09) Privacy входит в `Client`, и в ADR-008 нужна правка **одной ссылки** («на бэке контекст Приватность» → «в `Client`»). Правка не сделана, потому что `check_adr.py --range` считает ADR «изменённым» при **любой** правке, а старые 23 ADR полному шаблону (3 варианта / протокол / комплаенс) не соответствуют → любое касание = красный гейт. Итог: документ **нельзя обновить**, не переписав его целиком.
- **Риск:** средний (прямой стимул «не трогать доки» → расхождение доков и кода — класс, который лечим весь день).
- **Приоритет:** P2 (блокирует правку доменных доков до правила гейта).
- **Оценка:** **СНЯТО 2026-11-09.** Правило гейта принято (@TL 09:20) и реализовано (@LM инструмент, @DO доработка): «новизна» ADR — **дата создания файла в git** (`--diff-filter=AR`, один git-вызов на папку + карта), созданный до `cutoff` (по умолчанию **2026-11-08**) при правке даёт warning вместо error; `--since` — алиас `--cutoff`, но **со значением меньше нормы не принимается** (`rc=2` с объяснением), чтобы случайно не покрасить историю; осознанно строгий прогон — только через `--cutoff`. **Проверки воспроизводимы:** (A) `--range c80f7c92~1..c80f7c92` (правка ADR-008) → `⚠ старый ADR (создан до 2026-11-08)`, «проверено 1, нарушений 0», rc=0; (B) новый ADR без разделов → rc=1, нарушений 1; (C) `--since 2020-01-01` → rc=2 (защита), `--cutoff 2020-01-01 --range …` → rc=1 (штурвал); `--selftest` → rc=0. Правка ADR-008 сделана, поле «Дата» осталось `2026-10-29`. **Переименования** обрабатываются `--diff-filter=AR` с учётом обоих путей (проверено на синтетическом `R100`-логе у @DO; реального переименования ещё не было — подтвердить при первом).
