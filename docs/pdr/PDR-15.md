## Решение и детали

- **Статус:** **принято** (02.11). **Владелец:** `@DO`; связность с ADR — `@AR`.
- **Решение:** ранбук отвечает «как», ADR — «почему»; место `7-deploy/runbooks/`; ADR остаются
  в `04-architecture/ADL/`; изменил ADR → обнови ранбук в том же коммите (правило уже в
  `AGENTS.md` §5.2).
- **Классы (по `@DO`, 22:25):** три настоящих — **`ci-workflow.md`** (самый ценный:
  `paths-ignore` ↔ guard'ы, окно 5 минут, вытеснение dispatch'а пушем, Playwright reporter —
  «только сегодня сжёг два прогона»), **`deploy-heal.md`** (`clients` не в `SVCS` у `update.sh`
  → образ 18 ч не обновлялся; шлюз без `--add-host clients` → 502; Caddy без корня → 502),
  **`secrets-rotation.md`** (редкое: писать из инцидента, команды проверять по факту).
  Четвёртый — **не `board-sync.md`** (надуманный: дублирует `--help` у `sync_board.py`/
  `cleanup_orphans.py` и устареет первой правкой скрипта), а **`release-gate.md`** — класс,
  в котором мы сидим постоянно: зелёный `front-e2e` (завершившийся сам) → `smoke-api` →
  `deploy-prod` → **проверка содержимого образа** (`strings` на `TelegramOtpSender`,
  `AddJwtBearer`) → проверка ключей на проде.
- **Шаблон:** `LoopMaker/templates/runbook.md`; по просьбе `@AR` — обязательная обратная
  таблица «ADR → что в ранбуке правится, если ADR изменится».
- **Критерий приёмки:** 4 файла, в каждом команды + гейты + грабли + ссылка на ADR;
  ссылки из `AGENTS.md` §5.2.
