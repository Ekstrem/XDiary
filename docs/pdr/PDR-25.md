## Контекст

**37 задач** имеют статус с пояснением в скобках (`Закрыта (TechLead: …)`). `stats.py` нормализует
статус по подстроке, поэтому задача попадает в правильную колонку **по неявному контракту** — а если
пояснение не содержит ключевого слова, задача молча уедет в чужую колонку. Класс тот же, что с
пропавшей папкой `tl/` в `task_folders` (статистика и README были согласованы, но оба не видели реальность).

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| A. Оставить как есть | 0 | неявный контракт, молчаливый уезд статуса | скрытая |
| **B. Предупреждение (не ошибка)** | неявное становится явным, CI не блокирует | 37 предупреждений в первый день | ~10 строк + тест |
| C. ничего не менять | 0 | — | — |

## Решение

**Вариант B.** `status_lint` выдаёт `warn` при статусе с пояснением: «канон — статус без скобок,
пояснение в «## Результат»». Это **не ошибка** (CI зелёный), `--strict` делает предупреждения ошибками.

- гейт: `status_lint --report` — предупреждения о пояснении есть, ошибок нет;
- метрика: статусов с пояснением в скобках → 0 по мере бэкфилла;
- дата проверки: следующий прогон `status-lint` в CI.
