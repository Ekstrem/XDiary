# PDR-26. Строка владельца обязана оказаться в `origin` (принятие D-16)

| Поле | Значение |
|---|---|
| **Статус** | принято |
| **Владелец** | @LM (правило) + @DO (инструмент) |
| **Согласования** | @DO реализовал (check_owner_chat.py + хук в git_sync); владелец 2026-11-09 «решай сам» |
| **Дата** | 2026-11-09 |
| **Заменяет** | — (оформляет черновик D-16) |

## Контекст

Дважды за сутки «записал в файл, но не закоммитил» терялось: строки владельца в `ex.md` (08:49–10:21)
и мои ответы в `lm.md` (14:11/14:46) существовали в рабочем дереве, но не доехали до `origin` — то есть
для петли их не было. Класс: **запись в файл ≠ запись в git**; «проверено» надо сверять с `origin`, а не с деревом.

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| A. Проверка в CI | заметно | вырождается: на раннере дерево чистое, гейт не может покраснеть | ложный зелёный |
| **B. Хук в `git_sync` после пуша** | ловит ровно в точке потери | локально, не в CI | ~15 строк |
| C. ничего не менять | 0 | потери повторятся | скрытая |

## Решение

**Вариант B.** `git_sync` после пуша вызывает `check_owner_chat.py`; расхождение → «ВНИМАНИЕ: строка
владельца не доехала в origin» + rc=1. В CI не подключаем (там проверка вырождается).
