# PDR — шаблон решения о процессе (v2)

| Поле | Значение |
|---|---|
| **Статус** | обсуждается |
| **Владелец** | @роль, чья это зона |
| **Согласования** | кто апрувил/возражал (явные строки) |
| **Дата** | 2026-11-09 |
| **Заменяет** | PDR-XX (если пересмотр), иначе — |

## Контекст

Что произошло, какая **цифра или инцидент** заставили это обсуждать (ссылка на коммит/прогон/сообщение).
Без цифры — это не проблема, а мнение.

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| **A. <название>** | | | |
| **B. <название>** (рекомендую) | | | |
| **C. ничего не менять** | | | |

Плюсы/минусы — **исчерпывающие** (не по одному пункту); цена — не только часы: рост CI, риск дефекта,
стоимость поддержки.

## Решение

**Вариант {X}** — обоснование в 1–2 строки. Условия, при которых решение не сработает
(условия отказа/пересмотра).

### Протокол (по ролям, не «все согласны»)

| Роль | Принял | Возразил / условие | Воздержался |
|---|---|---|---|
| @роль | ✅ 2026-11-09 | | |

Бюджет комментариев: **не больше 2 на вариант от роли**; после бюджета без консенсуса решение
принимает владелец зоны.

### Обязательства

| Что | Ответственный | Как проверяется |
|---|---|---|
| {задача / гейт / метрика} | @роль | {команда / строка дашборда} |

### Комплаенс

| Что | Значение |
|---|---|
| Где источник правды | {файл/репо — что считается нормой после принятия} |
| Когда пересматриваем | {дата или триггер} |
| Кто проверяет | @роль |
| Что делаем при расхождении | {гейт красный / задача / откат} |

## Критерий приёмки и метрика

- гейт/проверка: `<команда или workflow>`;
- метрика: `<строка дашборда>` должна сдвинуться в сторону `<цели>`;
- дата проверки эффекта: YYYY-MM-DD.
