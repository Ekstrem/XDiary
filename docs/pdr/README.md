# Process Decision Record — папка решений

Каждое решение — **отдельный файл**. Здесь индекс, правила ведения и шаблон.

Почему папка, а не один файл: решение живёт отдельно, его можно править, ссылаться на него
из задачи/правила и не ломать нумерацию. Одним файлом их стало 20 — читать и обсуждать
по списку неудобно.

## Как ведём (обязательный порядок)

1. **`@LM` пишет варианты и оценку**, а не готовое «делаем так»:
   - минимум **2–3 варианта** (включая «ничего не менять»);
   - по каждому: плюсы, минусы, цена в часах/минутах CI, риски;
   - рекомендация + критерий проверки (метрика или гейт).
2. **Затронутые роли апрувят или предлагают своё.** Апрув — явная строка:
   «согласен» / «согласен при условии …» / «возражаю, предлагаю …». Молчание не считается
   согласием (§18: `RULES.md`).
3. **Владелец зоны решает**, `@TL` оформляет задачи, `@EX` решает продуктовое/денежное.
4. **Статус меняется по факту**, а не по желанию: `обсуждается → принято` только после
   апрува владельца и записанных условий; `отклонено` — с причиной.
5. **Изменилось решение — новая запись** `PDR-NN` со ссылкой «заменяет PDR-MM»; старую не
   переписываем.

## Шаблон v2 (с 2026-11-09)

Требования к записи (проверяет `python tools/check_pdr.py`; для записей **от 2026-11-09**
они обязательны, более старые проверяются по старому минимуму — историю не переписываем):

| Блок | Зачем |
|---|---|
| Контекст **с цифрой** | без числа это мнение, а не проблема |
| Варианты (2–3, включая «ничего не менять») | плюсы/минусы — исчерпывающие, не по одному пункту |
| **Протокол по ролям** (принял / возразил-условие / воздержался) | «согласования» текстом превращаются в «ок»; таблица собирает условия |
| **Обязательства** (что / ответственный / **как проверяется**) | решение без обязательства и проверки — совет, а не решение |
| **Комплаенс** (источник правды, когда пересматриваем, кто проверяет, что при расхождении) | иначе через месяц неясно, что действует |
| Лимит **1 страница** | процессное решение должно стоить дешевле проблемы |

**Бюджет комментариев:** не больше **2 комментариев на вариант от роли**; после бюджета без
консенсуса решение принимает владелец зоны. Встреч и таймингов нет — только файлы.

**Если решение дешевле, чем его оформление** — это не PDR, а строка в чате или черновик
`LoopMaker/retro/drafts/D-xx.md` (там живут идеи до принятия).

## Связь с правилами

- `AGENTS.md` — норма (что делать), PDR — почему и какие варианты отвергли.
- `docs/CI-RULES.md` — процедуры CI и git; PDR фиксирует решения о них.
- `RULES.md` §18 — правило без гейта не принимается: в PDR поле «критерий» обязательно.
