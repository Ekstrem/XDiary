## Контекст

Три разных дефекта гейтов за один день, все три — «гейт есть, а проверять нечего»:

1. **Прогон без шагов.** `#977`–`#983`: пять пушей вытеснили друг друга, ни один прогон не сделал
   ни шага (`cancelled`, `steps: []`). Обсуждать «результат» такого прогона нельзя.
2. **[ЗАКРЫТО @DO, `4be2f59`] Ложное срабатывание `guard-secrets` на типах.** `chat/te.md:533` — описание маскированного
   снимка `{token: bool, tokenLen, clientId: bool, ...}`; сканер увидел `token: bool` (len=4).
   В `tools/check_secrets.py:46` **уже есть** комментарий «имена типов в документации не секреты»
   и `bool`/`number` в `SKIP_VALUES`, но проверка этого не реализует для всех форм.
3. **[ОТКРЫТО] Ложное срабатывание на описании тест-данных.** `chat/do.md:304` — @DO документирует свой же
   негативный тест: `assign token = "ab12cd34ef56"` (12 символов, специально фейковый).
   Сканер честно ловит — это и есть его работа, но CI красный на **документе о проверке**.

## Варианты

| Вариант | Плюсы | Минусы | Цена | Оценка |
|---|---|---|---|---|
| **A. Обойти** (`# noqa`, исключить файл) | 0 | скрывает дефект, оставляет всех без проверки; против §18 | 5 мин | ⭐ |
| **B. Минимальный (@TL, 20:35):** не считать секретом значения-слова типов (`bool`, `number`, `string`, `int`, `length`, `masked`, `true`, `false`, `null`) + отсечь значения **короче 12** символов | простая правка; закрывает случай (2) | **не закрывает случай (3)**: там ровно 12 символов; «12» — магический порог, следующий тест напишут 13-ю символами | 20 мин | ⭐⭐ |
| **C. По энтропии (LM, первый вариант):** длина ≥ 8 + энтропия + слова маскирования | ловит настоящие ключи, терпит прозу | энтропия на коротких строках шумит; «поле-путь» `xdiary.accessToken` может пройти как секрет | 40 мин | ⭐⭐ |
| **D. По форме + подсказкам строки (рекомендую):** для `assign:`-совпадений требовать **форму ключа** (`ghp_`, base64 ≥ 20, hex ≥ 32, JWT из трёх сегментов) **или** высокую энтропию **при** имени из сильного списка; строки с явными подсказками («негативный тест», «пример», «фейковый», «не ловится») **не сканировать** на `assign:` | закрывает все три случая; порог не магический, а по форме | нужна аккуратность: подсказка «пример» в строке с настоящим ключом скроет его — поэтому подсказки **только** вместе с «негативный тест/проверка/фейковый» | 1–1.5 ч | ⭐⭐⭐ |

## Рекомендация

Вариант **D**: сканер секретов должен ловить **форму секрета**, а не слово «token» в прозе.
Дополнительно — **два юнит-примера**, чтобы фикс не откатили:

- позитивный: `password: hunter2secret`, `ghp_`-подобная строка → **красный**;
- негативный: описание сигнатуры `{token: bool, tokenLen: number}` и фраза
  «негативный тест: assign token = "ab12cd34ef56"» → **зелёный**.

Если @DO выберет B (дешевле) — принимаю, но фиксирую в истории, что случай (3) останется
и порог «12» придётся пересматривать.

- **Как проверяется:** `python tools/check_secrets.py --config loop.config.json` на дереве — 0 находок;
  `--range HEAD~3..HEAD` — 0; два юнит-примера зелёные; на настоящем фейковом ключе — красный.
- **Метрика:** доля ложных срабатываний гейтов — цель 0; в дашборде — строка «гейты (stats/chat/wf)»
  должна оставаться `3/3` без ручных исключений.
