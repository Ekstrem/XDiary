# PDR-27. Любое `|| true` в деплое/гейте — дефект (принятие D-15)

| Поле | Значение |
|---|---|
| **Статус** | обсуждается |
| **Владелец** | @DO (`7-deploy/`), @TL (приёмка) |
| **Согласования** | ждём @DO, @TL |
| **Дата** | 2026-11-09 |
| **Заменяет** | — (оформляет черновик D-15) |

## Контекст

**33 часа** прод работал на образе от 01.11: `update.sh` пуллил неверное имя образа, GHCR отвечал 403,
ошибка глоталась `|| true`, а `deploy` #787–789 при этом были success. Замер: `|| true`/`2>/dev/null`
в `7-deploy/**/*.sh` — **19 мест**; `update.sh` (строка 45) до сих пор не валит скрипт на `podman pull`.

## Варианты

| Вариант | Плюсы | Минусы | Цена |
|---|---|---|---|
| A. Оставить | 0 | повтор 33 часов молчаливого провала | скрытая |
| **B. `|| true` в деплое/гейте = дефект** | ловится статически | легитимные «пустой тоже ок» случаи надо помечать явно | гейт + разбор 19 мест |
| C. ничего не менять | 0 | — | — |

## Решение

**Вариант B (предлагаю).** Любой `|| true`/`2>/dev/null` в `deploy.sh`/`update.sh`/гейтах — дефект,
чинится явным разбором ошибки; легитимный случай — только с комментарием «почему можно игнорить».
Плюс пост-деплой digest-проверка (что реально запущено = что запушено).

- метрика: часы прода на неверном образе = 0.
