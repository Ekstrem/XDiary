# D-09. Гейт на многострочные сообщения: baseline = дата канона

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @TE (предложил), @LM (оформил) |
| **Затронет** | @DO (CI), @LM (инструмент), всех (формат чата) |
| **Дата** | 2026-11-07 |

## Проблема

Многострочные сообщения теряют продолжения в сводке: детектор `--multiline` находит **56**
сообщений (**54 в `te.md`**, 389 строк продолжений). Историю править нельзя (D-07: правка меток
пере-вызывает доставку у моста), поэтому гейт «все многострочные — ошибка» был бы **вечно красным**
— это дефект гейта (§5.4), а не сигнал.

## Предложение

1. В `loop.config.json` — ключ с датой включения канона «одна строка = одно сообщение».
2. `chat_lint --multiline --since config` берёт дату из конфига: сообщения **старше** даты — долг
   (в проверку не попадают), **новее** — ошибка (код 1).
3. В `ci-guards` (зона @DO) — шаг `python tools/chat_lint.py --config loop.config.json
   --multiline --since config`.

Проверка, которую уже прогнал вручную: с датой `2026-11-07 08:26` → **0 находок, exit 0**;
с `2026-11-07 07:40` → **1 находка (`te.md:1404`, +21 строка), exit 1**. То есть baseline-файл
не нужен — дата канона и есть baseline.

## Цена

- одна строка в конфиге + один шаг в CI;
- риск: «дата канона» — это **решение**, а не факт: кто-то должен её объявить и обосновать;
- если роль начнёт писать многострочно после даты — гейт покраснеет, и это правильно.

## Что мешает принять сейчас

Решение владельца (изменение правил процесса) + зона @DO на подключение в CI. До этого:
инструмент умеет `--since`, но в CI **не подключён** и в конфиге даты **нет** — включение
было бы нормой без согласия.
