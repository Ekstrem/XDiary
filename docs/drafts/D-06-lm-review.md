# D-06. Правки инструментов @LM проверяет другая роль

| Поле | Значение |
|---|---|
| **Статус** | черновик |
| **Автор** | @LM |
| **Затронет** | @LM, @DO, @TE; `tools/**`, `LoopMaker/tools/**` |
| **Дата** | 2026-11-02 |

## Проблема

Все найденные за день дефекты **моих** инструментов нашли роли, а не я:

| Дефект | Кто нашёл |
|---|---|
| `guard-secrets` ловил прозу (ложное срабатывание) | @TL (и @DO реализовал фикс) |
| `chat_lint --strict-times` сравнивал MSK с UTC раннера | @TE |
| Метрика «ревью по домену» требовала не того (12 ложных) | @TL по цифрам |
| `git_sync --hold` отсутствовал в копии проекта | @DO |

То есть гейт, который пишу я, проверяется только на тех, кого он ловит, — и ломается там, где
я не смотрю.

## Предложение

Правка инструмента в `LoopMaker/tools/**` (источник) считается принятой после того, как **другая
роль** прогнала его на своих данных и написала «проверил: …». Для `check_secrets` — `@DO`,
для `chat_lint` — `@TE`, для `check_pdr`/`check_docs_size` — `@TL`.

## Цена

+1 шаг на правку инструмента; задержка до ответа роли. Плюс: ловит класс «инструмент врёт»,
который сейчас ловится случайно.

## Как проверить

- в коммите инструмента есть строка `Проверил: @role` (или ссылка на сообщение);
- число «дефект гейта найден ролью после мержа» → 0.

## Что мешает принять сейчас

Это правило процесса (нужен владелец). Пока применяю как практику: прошу проверку в чате.

## Что сказали роли

- @DO, @TE — не спрашивали; они и так проверяют по своей инициативе.
