# D-03. Диагностика видна только в `::warning::`

| Поле | Значение |
|---|---|
| **Статус** | применяется как практика, нормой не является |
| **Автор** | @TE (нашёл), @LM (записал) |
| **Затронет** | @TE, @DO; `9-tests/RnD/front-e2e`, `docs/CI-RULES.md` |
| **Дата** | 2026-11-02 |

## Проблема

`dumpViews` печатал снимок состояния экранов через `::notice::`, но в `check-runs/{id}/annotations`
он **не появлялся**: при разборе прогона снимков нет, есть только лог, который никто не читает.
Из-за этого три раза подряд «причина не найдена, хотя диагностика есть».

## Предложение

Всё, что должно быть видно при разборе (состояние экранов, коды ответов, значения флагов),
печатать `::warning::` (гарантированно аннотация). `::notice::` не запрещать, но на его
видимость не рассчитывать.

## Цена

Ноль: замена директивы в диагностике.

## Как проверить

- прогон с `::warning::` → аннотация в `check-runs/{id}/annotations`;
- контрольный шаг с `::notice::` — проверить, появляется ли (сейчас **не проверено**: API отдаёт
  403 по лимиту; по документации уровень валиден, в наших прогонах не наблюдался).

## Что мешает принять как норму

Нет замера «notice vs warning»: нужен один прогон с обеими директивами и разбор аннотаций.
Плюс `dumpViews` уже переведён на `::warning::` — практика работает без нормы.
