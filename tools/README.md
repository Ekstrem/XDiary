# `tools/` — гейты и их самопроверка

Инвентарь на 2026-11-05 (@DO). Правило: **гейт, печатающий числа, обязан иметь `--selftest`
с кейсом на дефект**, и в CI `--selftest` стоит **строкой выше** нормы (@TL).

## Сводка (замер по `origin`, а не по памяти)

| показатель | значение |
|---|---|
| `tools/*.py` всего | **76** |
| вызываются в CI (`ci-guards` + `ci-tests`) | **24** |
| из них с `--selftest` | **19** |
| из них **без** `--selftest` | **5** — см. исключения ниже |
| дублей с `9-tests/scripts/**` (одинаковое содержимое) | **0** |
| `.sh`-скриптов в `tools/` | **0** (только `.py`) |

## Исключения (осознанные, с причиной и датой)

| инструмент | причина | кто решает |
|---|---|---|
| `test_check_secrets.py` | **сам тест** (проверяет `check_secrets.py`); `--selftest` у теста был бы тестом теста | — |
| `test_git_sync.py` | **сам тест** (`git_sync` предохранитель) | — |
| `test_git_sync_state.py` | **сам тест** (классификация rebase-состояния) | — |
| `test_stats_ref.py` | **сам тест** (`stats --ref`) | — |
| `chat_lint.py` | **копия** из `LoopMaker/tools/` (источник правды там), у источника флага `--selftest` нет | **@LM** (процессные линтеры — его зона) |

Четыре `test_*.py` не нуждаются в самопроверке по природе: их «норма» — это и есть проверка
другого инструмента, а красный контроль в них заложен внутри (каждый кейс с ожидаемым провалом).
`chat_lint.py` — единственный, где отсутствие самопроверки является **открытым вопросом**, а не
решением: он 604 строки и правит его @LM в двух местах (копия + источник).

## Что проверено «на дефекте», а не только «на норме»

| гейт | дефект | норма |

| `check_adr_refs` | ссылка на ADR с неверным статусом (класс из DO-094) → `rc=1` с парой «заявлено/факт» | после правки ссылок → `rc=0` |

## Правило «не измерено»

`rc=2` означает **«не смотрел»**, а не «в норме»: файла нет, документов 0, таблицы нет,
ssh недоступен. Такой результат **не считается PASS** и не закрывает задачу.
