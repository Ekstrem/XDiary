## 2. Что это гарантирует

- **Ни один элемент интерфейса с обработчиком не остался без спеки** (64/64): кнопки, поля, чипы, скрытые
  file-входы (проверяются через `setInputFiles`).
- **Каждый экран** покрыт спекой, маркер не врёт (18/18, исключение одно — `view-splash`).
- **Ни одна спека не «молчит»** при падении: есть шаг, тост или лог API (20/20 не-Legacy).
- **Утверждения проверяют поведение**, а не «что-то истинное»: доля слабых 5.1%, порог 30%/15% в гейте.
- **Спеки не ходят мимо контракта**: 14 путей из 14 есть в `api-index.yaml`.
- **Прогон не может быть «зелёным» без исполненных тестов**: страж-репортёр даёт `rc=1`, если все тесты
  ушли в `skip`; квитанция в таком случае возвращает `rc=2` («не измерено»).
- **E2E не может уехать на прод**: предохранитель DO-017 под наблюдением гейта.
- **Локальный прогон не разъезжается с CI**: те же флаги, тот же страж, тот же `globalSetup`.


## 2.1. Инструменты, которые делают числа проверяемыми

- **Пути входа проверяются поведением без браузера** (`login-paths.test.js`, 8/8): браузер в песочнице
  не запускается, поэтому `tests/api.js` загружается с подставным `page` и окружением в `evaluate`.
  Харнесс **нашёл реальный дефект в моей же оптимизации** (в кэш-ветке возврат ссылался на `token`
  вместо `cached.token`) и ещё один класс: `seedSession` при исчерпании попыток бросал голое
  `Failed to fetch` без числа попыток.
- **Триаж падений — одной командой по артефакту** (`e2e_triage.py --input front-e2e-results`):
  таблица `класс | сколько | примеры спек | лечение`, классы `test-timeout` / `wait-timeout` /
  `session-lost` / `stand` / `assert`. Проверено на синтетическом логе формы реального прогона.
- **Цепочка «страж → артефакт → квитанция»** проверяется целиком; гейт нашёл, что при
  «ни один тест не исполнялся» страж не писал файл — то есть самый важный для разбора случай
  не оставлял артефакта. Исправлено.

- **Страж исполнения:** если все тесты ушли в `skip`, прогон не «зелёный» (`rc=1`), а квитанция
  возвращает `rc=2` («не измерено»).
- **Квитанция внутри артефакта:** страж пишет `test-results/receipt.txt`, поэтому числа едут из CI
  вместе с артефактом, а не теряются в логе джобы.
- **Самопроверка агрегатора:** `--selftest` = 12/12, включая **мутации 4/4** (подложенный дефект обязан
  покраснеть у ответственного гейта).
- **Паритет локального прогона с CI:** отдельный гейт; нашёл реальный дефект (адрес двойника
  выставлялся после загрузки `api.js`).
- **Предохранитель DO-017** (E2E не против прода) под наблюдением гейта — и проверен **поведением**:
  прод в адресе → падение, 502-ретрай → успех, stale-image → падение.
- **Локальный стек** (`serve.js` + репортёр аннотаций) проверяется запуском, а не чтением файла.

## 2.2. Первый живой прогон и что сделано по его итогам

**Прогон `2026-11-06` (@DO, REF `73f59ba7`, runs `42124644500` dispatch и `42124604597` push):**
`18 failed, 3 skipped, 8 passed (14.8m)`, 29 тестов. CI-обвязка при этом работала: стенд → очистка →
установка зависимостей → браузеры → **гейты ✅** → тесты ❌ → **артефакт ✅ (5.8 МБ)**.

**Характер падений:** `status: "timedOut"` **до** утверждений, в хуках (`Before Hooks > login по PIN > …`).
Это не «продукт ответил не то», а «не дождались».

**Что сделано по итогам (все правки — про время входа, ни одна не отключает проверки):**

| Правка | Что даёт |
|---|---|
| кэш сессии на процесс (`SEED_SESSION`) | 29 онбордингов → **1** (2 загрузки и 5 запросов на тест заменены одной загрузкой) |
| кэш партнёра (`SEED_PARTNER`) | −28 партнёров за прогон: список `#partners-list` не растёт (раньше доходил до 588 КБ, `DO-044`) |
| без лишнего `reload` | если после засева журнал открыт — страница не перезагружается (экономия загрузки + до 15 с ожидания) |
| повтор входа при `401/404` | «клиента удалили» лечится одним повтором с новым телефоном и `::warning::`, а не падением |
| диагностика | `::notice::login` (фазы: seed/PIN/reload/ожидание), длительности шагов в аннотации падения |
| `e2e_triage.py` | лог → классы падений (`test-timeout`/`wait-timeout`/`session-lost`/`stand`/`assert`) с лечением |

**Найденные при разборе дефекты вне тестов (не моя зона):** три прогона одновременно на одном стенде +
шаг `Очистить E2E-данные`, который удаляет клиентов `+7999…`, — источник класса «вход не завершился».
Предложение: очистка только в dispatch-прогоне либо сериализация группы.

**Пробел покрытия, найденный при разборе пропусков:** `change-pin` (US-11, смена PIN) никогда не выполнялся
в CI. Проверено по коду: сценарий локальный (`window.Pin.*`, ни `fetch(`, ни `/api/`, ни `/privacy`),
исходный PIN возвращается в `finally` — то есть стенду не вредит. Нужна одна строка @DO:
`XDIARY_CHANGE_PIN: "1"` в `env:` джобы. Остальные пропуски — LEGACY (`no-pin`, серверный PIN в
`remove-pin`), они помечены причиной.

## 3. Чего эти числа НЕ доказывают (и почему это важно)

1. **Это не прогон в браузере.** В песочнице @TE браузер не запускается (`spawn EPERM`) и внешняя сеть
   закрыта, поэтому `passed/failed` по спекам здесь нет. Все числа выше — статический и
   «безбраузерный» слой.
2. **Стенд не проверен на живых кодах ответов.** `mock-smoke` доказывает контракт двойника, но не то,
   что dev-стенд отвечает так же (дубликат телефона → 500, `remove` → 400 — это дефекты @BE, а не тестов).
3. **Флейкость не измерена.** Для этого нужен `front-e2e-repeat.yml` (`--repeat-each`), а его шаг
   «Итог по спекам» сейчас не разбирает реальный вывод Playwright (нет ANSI-очистки, требуется префикс
   `tests/`) — замер всегда красный. Замена готова: `e2e_receipt.py --table` (`--selftest` 10/10).

```bash
cd 9-tests/RnD/front-e2e

# 1) 30 гейтов по спекам одной командой (браузер не нужен)
python ../../scripts/check_e2e_all.py

# 2) исполнение тел спек на заглушках (без браузера)
npm run dryrun && npm run dryrun:selftest

# 3) контракт двойника стенда по HTTP (preflight, CORS, 404/405)
npm run mock-api            # в отдельном терминале
node mock-smoke.js

# 4) квитанция по логу/артефакту прогона
python ../../scripts/e2e_receipt.py --input test-results/receipt.txt --ref <sha>
```
