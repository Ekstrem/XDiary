### Переключение входа: «до/после» одним инструментом (2026-11-05)

| Вход / момент | Неизвестный путь | `X-Gravitee-*` | `via=` / вердикт |
|---|---|---|---|
`VPS-1` до правки funnel | `401` (`Server: Kestrel`) | нет | `via=yarp` → `(ii-a)` **не засчитан** |
`VPS-1` после (`Funnel -> Caddy:8081 -> APIM`) | `404 No context-path matches the request URI` | есть | `via=gravitee` → `(ii-a) PASS 74/74` |
`VPS-2` (тест) | `401` (`Server: Kestrel`) | нет | `via=yarp` → `(ii-a)` **не засчитан** |

Три независимых признака поведения на проде после правки (совпали с ожиданием @TL):
`/api/v1/nonexistent-path-xyz` → **404** (`No context-path matches the request URI`),
`/internal/journal/records` → **404**, `/health` → **200** `"ok"`.
Протокол после смены пути: `ИТОГ: (ii-a) PASS 74/74 · (ii-c) PASS 2/2 · знаменатели 74+2=76 из 80 (anonymous 4) · rc=0`.
Смена шлюза **не изменила** закрытость периметра — и это перемерено, а не перенесено.
**Область требования `via=gravitee`** (@AR `05:15`, подтверждено @TL `07:07`): строго только для
`(ii-a)`; `(ii-c)` засчитывается на **любом** входе (`401` на YARP — честный ответ «внутренняя ручка
недостижима»), а `--strict-via` распространяет требование на все условия — режим выбирается осознанно
и виден в выводе (`(ii-c) НЕ ЗАСЧИТАНО` + `::error::` с именем условия).

**Асимметрия площадок:** прод за APIM (`via=gravitee`, `(ii-a)` засчитан), тест на YARP
(`via=yarp`, `(ii-a)` **не засчитан**) — «APIM в пути» верно про конкретный вход, а не про систему.

### Канон `via=` и статус dev — сверено с `ADR-026` (2026-11-05 08:05, @AR)

| Что | Канон (`ADR-026`) | Что делает инструмент |
|---|---|---|
| `(ii-a)` | только снаружи по публичному имени и **обязан** иметь `via=gravitee` | `via=yarp` → `rc=2`, `НЕ ЗАСЧИТАНО` |
| `(ii-c)` | проверяется на **том входе, который есть**; `401` от YARP — честный ответ | засчитывается при любом входе |
| `--strict-via` | опция: распространить `via=gravitee` на все условия, «включается осознанно» | флаг есть, исход виден в выводе |

**Почему нельзя требовать `gravitee` от `(ii-c)`** (формулировка @AR): на стенде без APIM условие
«внутренние ручки недостижимы» стало бы **вечно** `НЕ ЗАСЧИТАНО`, хотя ручки **действительно
недостижимы** — то есть корректная конфигурация стала бы «красной» (тот же класс, что пин `0.88`
на `0.89`).

**Статус dev (позиция @AR):** паритет стенда **не является** условием переключения — протокол
требует `(ii-a)` на проде, где `via=gravitee` доказан извне. Пока APIM на dev нет
(`organizations` → 500, RAM 1963/87, headless-install), `(ii-a)` там `НЕ ЗАСЧИТАНО` — **корректное
состояние, а не дефект**. Если паритет отложен, требуется **одна строка в ранбуке**
`7-deploy/runbooks/apim.md` «dev без APIM, причина: <факт>, `(ii-a)` на dev не засчитывается;
после появления APIM — перемер по тем же командам» (зона @DO). Решение «добиваться ли APIM на dev» —
владелец (ресурсы).

### Асимметрия площадок: dev без APIM (для будущей задачи @DO)

| Площадка | Неизвестный путь | `Server` / `X-Gravitee-*` | `via=` |
|---|---|---|---|
| прод (`VPS-1`) | `404` `No context-path matches the request URI.` | `Via: 1.1 Caddy` + `X-Gravitee-*` | `gravitee` |
| тест (`VPS-2`) | `401` | `Server: Kestrel`, без `X-Gravitee-*` | `yarp` |

На dev APIM не развёрнут (`18082` не слушает), поэтому `(ii-a)` там **не засчитывается** —
это правило `ADR-026`/`@AR 05:15`, а не дефект. **Критерий приёмки симметрии (когда APIM поднимут на dev):**

```bash
python 9-tests/scripts/check_apim_auth.py --all --probe-entry \
       --base https://xdiary-vps2.taile0b6ee.ts.net --where "Funnel->Caddy->APIM, снаружи"
```
Ожидание: `via=gravitee`, `ИТОГ: (ii-a) PASS 74/74 · (ii-c) PASS 2/2 · 74+2=76 из 80 · rc=0`,
проба входа — `404` на неизвестном пути и **наличие** `X-Gravitee-*`; `/internal/**` снаружи — `404`.
До этого `(ii-a)` на тесте останется `НЕ ЗАСЧИТАНО` при `rc=2` — и это честное состояние, а не регресс.

**Протокол переключения — одна команда:** `--all --base <вход>` (при `--direct` добавляется `(ii-b)`);
рядом `--probe-entry --base <вход>`, потому что «переключено» = доказано заголовком/поведением,
а не тем, что команда выполнена.


## История дефектов в самом инструменте (для будущих ревью)

1. **Тождество сходилось по построению.** `passed` считался **вычитанием** из `total`, поэтому
   сумма не могла не сойтись. Исправлено: `protected` — **независимый счётчик** по `401/403`;
   проверено подменой классификатора (прогон 4).
2. **`protected` не инкрементился** (регрессия от правки формата): `401/403` выходили через
   `continue` без счёта → `passed=0` всегда → **гейт не мог дать `PASS` ни на каком контуре**,
   а сумма не сходилась (`неизвестно=0`, `сумма=0/8`). Нашлось на живом прогоне 7, не кейсом:
   в `--selftest` не было случая «все `401` → `rc=0`». Теперь кейс есть (прогон 5).
   Класс: `04-architecture/round-checklist.md` — «контроль, который не может провалиться, — не контроль».

## Что эти прогоны НЕ доказывают

Реальный замер `(ii-b)` на контуре: он делается **изнутри** сети podman
(`--direct --network <net> --images auto --where "podman run --network <net>"`), потому что снаружи
`xdiary-*` не резолвится и гейт честно вернёт `rc=2`. Пока `journal`/`partners` не подняты
(библиотечный `EventStoreDbContext`, зона @BE), `U > 0` — это состояние контура, а не дефект инструмента.
