# Что на самом деле происходит с прогонами (факты из GitHub API, `2026-11-12`)

До этого круга я писал «прогонов нет» — это было **неверно**: я не мог их видеть из песочницы. Проверил
HTTPS-доступ (он **есть**: `https://xdiary-vps2.taile0b6ee.ts.net/health` → `200`, `api.github.com` → `200`)
и снял факты из API. Источник — `https://api.github.com/repos/Ekstrem/XDiary/actions/...`.

## 1. `ci-front` на push — зелёный, но браузерного прогона нет

```
ci-front #1099  push  success  bf5fc002  2026-11-11T18:01:12Z
   job spec-gates   success
   job front-e2e    skipped
```

То есть «CI зелёный» на push означает «статические гейты по спекам прошли», а **браузерный джоб пропущен**
условием `if: github.event_name != 'push'` (`ci-front.yml:50`). Это ровно `DO-103` и объясняет, почему
`REF` браузерного прогона не появляется от пушей.

## 2. `ci-front` по расписанию — **запускается и падает**, а не «не запускается»

```
ci-front schedule: 6 прогонов, все failure
   #1070  failure  b670eb2f  2026-11-11T11:29:32Z
   #1020  failure  27e9c12c  2026-11-10T11:52:57Z
   #938   failure  388fa827  2026-11-09T12:13:27Z
```

Джобы `#1070`: `spec-gates` **success**, `front-e2e` **failure**, причём шаги до браузера прошли
(«Ждать здоровый dev-стенд» ok, «Очистить накопленные E2E-данные» ok, «Install deps» ok,
**«Install Playwright browsers» ok**), а падает шаг **«Front E2E»**. Значит стенд и окружение в порядке,
красный — в самих спеках/поведении. Лог шага из песочницы недоступен (артефакты/логи требуют токена) —
это к @DO.

**Следствие для шести карточек:** ночной прогон **есть**, но он **красный**, поэтому `REF` для приёмки нет.
Следующее расписание — `2026-11-12T04:00Z` (`cron '0 4 * * *'`).

## 3. `ci-backend` на push — зелёный при **нуле** тестов

```
ci-backend #1090  push  success  bf5fc002
   job test success
      «Тесты изменённых BC (без соседей — изоляция ADR-028)»  success
```

Зона считается по `git diff` (`ci-backend.yml:53-75`): если изменений в `6-msa` нет, набор **пуст**,
и шаг «Тесты изменённых BC» проходит, **не запустив ни одного проекта**. Это класс «CI зелёный при
0 проектах / 0 тестов — не доказательство» (AGENTS §5), и именно поэтому квитанция `ci-backend` на
документационном коммите ничего не доказывает.

**Но:** при `workflow_dispatch` тот же шаг выставляет `all=1` (`ci-backend.yml:65-67`) и тестирует **все** BC,
включая `Journal.ApiTests` с `PartnerSoftDeleteTests`. То есть для `TE-050` нужен именно dispatch:

```bash
gh workflow run ci-backend.yml --ref main     # all=1 → все BC
```

## Итог: что теперь можно и нельзя утверждать

| Утверждение | Статус |
|---|---|
| «прогонов нет» | **Отзываю.** Прогонов много (29217 всего), вопрос в том, что в них исполняется |
| «`ci-front` зелёный ⇒ браузер проверен» | **Неверно**: джоб `front-e2e` пропускается на push |
| «ночной прогон не запускается» | **Неверно**: запускается (6 раз) и падает на шаге «Front E2E» |
| «`ci-backend` зелёный ⇒ тесты прошли» | **Неверно** для документационных пушей: 0 проектов |
| «`REF` браузерного прогона есть» | **Нет**: последний — падение; нужен зелёный (ночной или dispatch) |

Квитанций для закрытия карточек эти прогоны **не дают**: `skipped` — не прогон, `failure` — не приёмка,
`0 тестов` — не доказательство. Пути к `REF`: следующий ночной прогон (если позеленеет) или dispatch
`front-e2e-repeat` (зона @DO).
