## Зачем транскрипт

@TL (`23:16`) просил свести квитанцию к «1 поле (place)», опираясь на сообщение @DO, что у `tags` нет сеттера. Транскрипт показывает обратное: `POST /records/{id}/accessories` с телом `{"tags":["tag-a","tag-b"],"costumes":[],"toys":[],"fantasies":[]}` возвращает `200`, и следующее чтение отдаёт `tags` с этими значениями. Поэтому в квитанции теперь указан **источник каждого поля**: `place=/place, tags=/accessories` — чтобы «2 поля» не выглядело как нечто без основания.

## Третий критерий `AR-022` (@AR `2026-11-07 00:45`): тело `/when` — `{startedAt}`

@AR внёс тела команд журнала в контракт (`04-architecture/api-index.yaml`, блок `request` у всех 14 POST-операций
`BC: Journal`) и попросил зафиксировать квитанцию. Прогон на dev (свежая запись, свой клиент):

```
POST /journal/records {"startedAt":"2026-11-10T09:00:00Z"}       → 200   (запись 56c9af9d…)
POST /journal/records/{id}/when {"when":"2026-11-11T10:00:00Z"} → 400   (поля `when` в команде нет — законная валидация)
POST /journal/records/{id}/when {"startedAt":"2026-11-11T10:00:00Z"} → 200
GET  /journal/records/{id}                                      → 200   startedAt = '2026-11-11T10:00:00Z'
```

То есть критерий выполнен: правильное тело даёт `200`, и значение **доезжает до read-модели** (это же было вторым
симптомом в `BE-093`). Неправильное тело даёт `400` — и теперь это не «угадывание», а контракт: у следующего
разработчика в индексе есть `request` с обязательными полями, а у меня — квитанция, что проверка осмысленна.

## Третий критерий `AR-022` в формулировке @TL (`00:21`) — обе строки

@TL: «`POST /records/{id}/when` с `{"startedAt": "2026-11-01T10:00:00Z"}` → ожидаем **200** (не `400`); с `{"when": …}` →
`400` остаётся нормой, потому что поля `when` в команде нет. Приложи обе строки в транскрипт».

```
POST /journal/records/{id}/when  {"startedAt": "2026-11-01T10:00:00Z"}  →  200     ✅ критерий
POST /journal/records/{id}/when  {"when": "2026-11-01T10:00:00Z"}       →  400     ✅ норма (поля нет в команде)
GET  /journal/records/{id}                                              →  200     startedAt = '2026-11-01T10:00:00Z'
```

**Повторяемость (важно, чтобы не было «зелено один раз»):** 3 из 3 прогонов по полному циклу → `/when` `200`;
затем 6 из 6 «сразу после создания, без паузы» → `200`; и 3 из 3 «через 2 с» → `200`. Итого **12 из 12** —
критерий держится.

**Честная деталь:** один раз (первый запуск с этим payload) я получил `404` вместо `200` — и **не воспроизвёл** его
ни в одном из последующих 12 прогонов. Похоже на транзиент во время пересборки/перезапуска `journal` (стенд в это
время обновлялся). Поэтому фиксирую: `404` на `/when` возможен как транзиент, и в гейте `--direct`/основном режиме
такой случай надо отличать от «записи нет».
