# Вложенный worktree внутри репозитория — измеренная причина расхождений в гейтах

**Когда:** 2026-11-06, по просьбе @TL (`23:27`: «свои worktree я создаю вне репозитория… но это не должно быть
„повезло", а должно быть правилом: worktree — только вне дерева репозитория»).

## Что найдено

```
git worktree list
  <repo>                       d8874edd [main]
  ...
  <repo>/origin/main           7b4569c3 (detached HEAD)   ← ВНУТРИ репозитория
```

`XDiary/origin/main` — полноценный worktree (`.git` содержит `gitdir: …/.git/worktrees/main`), при этом для
основного дерева он **не отслеживается** (`git status` → `?? origin/`), то есть это просто каталог с копией
репозитория внутри рабочего дерева.

## Почему это важно (числа, а не рассуждение)

| Способ получить список | Файлов `.md` |
|---|---|
| обход деревом (`rglob("*.md")`) | **1213** |
| `git ls-files` | **638** |
| разница | **575** |
| из разницы — внутри `XDiary/origin/main` | **545** |

Отсюда ровно тот эффект, который описывал @AR: гейт, обходящий дерево, видит **вдвое больше** файлов, чем есть
в репозитории. `check_canon` находил «три копии» канона вместо одной, `check_docs_size` считал бюджет по чужой
копии, `check_rule_docs` — то же. Это не «у автора зелено, у соседа красно» по невнимательности: у них **разные
деревья**, и вердикт зависит от дерева.

## Что теперь делают мои гейты

Все гейты, которые считают файлы, берут список из `git ls-files` (`9-tests/scripts/filelist_source.py`), а
`walk` остаётся фолбэком и **печатается в квитанции** (`git ls-files (N)` / `walk (N)`). Поэтому вложенный
worktree на их вердикт не влияет: квитанции `check_e2e_command_read_path` → `git ls-files (10)`,
`check_e2e_eventsourcing_contract` → `git ls-files (492)`, `check_e2e_ui_coverage` → `git ls-files (6) + git ls-files (22)`.
Мета-гейт `check_e2e_filesource` следит, чтобы новый гейт не начал обходить дерево без источника.

## Что нужно сделать (не моя зона — общее дерево и git-метаданные)

1. Убрать вложенный worktree из репозитория; это git-операция в общем дереве, её выполняет владелец
   (@DO/@TL), а не @TE:
   `git worktree remove --force XDiary/origin/main` (или `git worktree prune`, если путь уже мусорный).
2. Зафиксировать в `AGENTS` норму (@TL уже попросил @LM): **worktree создаётся только вне дерева репозитория**;
   плюс уже согласованная норма про `git ls-files` для гейтов.
3. Пока пункт 1 не сделан, любые числа «сколько файлов» в гейтах, которые ещё обходят дерево, читать с поправкой:
   они могут быть завышены почти вдвое.
