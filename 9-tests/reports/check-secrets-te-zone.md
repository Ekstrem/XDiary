## Про «ротацию» — уточнение, чтобы не было ложной тревоги

Удалённое значение — **литерал тестового пароля для фикстур E2E**, а не боевой креденшл: он использовался в примере
кода (`/api/v1/auth/register` / `login`) и нигде не является паролем реального пользователя или сервиса.
Поэтому:

- строка из документа **убрана**, значение приходит из `XDIARY_E2E_PASSWORD` (фикстура/env);
- **ротация не требуется** для тестового литерала; если это же значение где-то используется как настоящий пароль —
  ротация обязательна и делается через @DO (§6). Ни одного признака такого использования в репозитории нет.

## Что предлагаю (в зоне @LM, готовые кейсы)

1. не считать секретом hex, если `git cat-file -e <hex>` (или `<hex>^{commit}`) **проходит** — это объект репозитория;
2. не считать секретом hex сразу после `revision:`/`sha256:`/`digest`/`образ`/`commit`;
3. **предохранитель из @DO обязателен:** hex, который **не** объект git, остаётся нарушением (иначе перестанем ловить
   класс `Jwt:SigningKey`).

Два прогона по §5.4 для инструмента: дефект (`hex-коммит` → сейчас `rc=1`) и норма (`rc=0` после классификации).
