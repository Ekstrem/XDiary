# AGENTS.md — XDiary

Приватный дневник пары (PWA + микросервисы). Подробности продукта — `README.md`,
путь по инкрементам — `01-user-stories/backlog.md`, домен — `03-ddd/`.

Этот файл читают **все** агенты, которые работают в этом репозитории. Он дополняет
`..\AGENTS.md` (корень воркспейса) и не отменяет прямой просьбы пользователя.

## 1. Роли и зоны записи

Ограничение задано владельцем продукта: **у каждой роли ровно одна «своя» папка (ядро)**.
Плюс минимальный служебный набор, без которого не работает цикл задач и чата.

| Роль | Ядро (пишет только сюда) | Служебные файлы |
|---|---|---|
| **PO** | `01-user-stories/`, `02-cjm/` | `5-tech-backlog/chat/po.md` |
| **Architect** | `03-ddd/`, `04-architecture/` | `5-tech-backlog/arch/`, `chat/ar.md` |
| **BackEnd** | `6-msa/` | `0-df-issue/`, `5-tech-backlog/back-end/`, `chat/be.md` |
| **FrontEnd** | `8-front/` | `5-tech-backlog/front-end/`, `chat/fe.md` |
| **DevOps** | `7-deploy/` | `tools/`, `.github/`, `5-tech-backlog/devops/`, `chat/do.md` |
| **TestEngineer** | `9-tests/` | `5-tech-backlog/tester/`, `chat/te.md` |
| **TechLead** | — (координатор, кода не пишет) | все папки задач `5-tech-backlog/<роль>/`, `chat/tl.md`, `README.md`, `CHANGELOG.md` |
| **LoopMaster** (`@LM`) | — (процессная роль, кода не пишет) | `AGENTS.md`, `loop.config.json`, `5-tech-backlog/chat/lm.md`; правила и шаблоны — `LoopMaker/` |

Служебные файлы — это: **своя** папка задач (править статус и «Результат»), **свой**
outbox в чате, у BackEnd — заметки о пробелах фреймворка (`0-df-issue/`), у DevOps —
инструменты и workflows. Ничего сверх этого.

- `README.md` / `CHANGELOG.md` — общие: правим только разделы про свою зону
  (таблицу статусов правит не рука, а `python tools\stats.py --write`).
- `app/` — легаси, никто не правит; прод деплоится из `8-front/`.
- **Граница тестов (ADR-028 ред. 3):** тест микросервиса — **в папке его сервиса** (`6-msa/BC-<X>/src/*Tests`: `*.Domain.Tests`, `*.IntegrationTests`, `*.ApiTests`) — зона @BE; **тест пары (consumer-driven) — у потребителя:** `<Потребитель>.ApiTests` (пример: `6-msa/BC-Client/src/Client.ApiTests` ждёт от Journal); тесты фронта — `9-tests` (браузер, маркер `front-e2e.md`) — зона @TE; **общих тестовых папок нет**: `6-msa/E2E`, `6-msa/ApiTests`, `Contract.<A>_<B>` запрещены (ADR-028 §1.1, §3.1).
- Проверка: `python tools\check_paths.py` (ядро + служебное) или `--strict`
  (только ядро — так видно, что роль полезла в чужую папку, но и свои задачи/чат
  тогда считаются выходом за зону).

**Выход за зону не делаем молча.** Нужен файл в чужой папке (например тестеру — CI-workflow
или фронту — `pages.yml`): пишешь `→ @TL` в свой outbox, TechLead создаёт задачу владельцу.
Исключение — пользователь попросил прямо.

## 2. Задачи (`5-tech-backlog`)

- Один файл = одна задача, ID: `AR/BE/DO/FE/TE-NNN.md`.
- Обязательные поля: `Статус`, `Приоритет`, `Источник` (трассировка на `US`/`BC`/`ADR`),
  `Зависимости`, затем `## Задача`, `## Критерии приёмки`, `## Результат`.
- **Статусы — только эти восемь** (полная схема: `LoopMaker/STATUSES.md`):

  ```
  Идея → На проработке → ToDo → В работе → На проверке → Закрыта
                          ↑         ↓
                          └── В паузе          (+ Отклонена — терминальный «не делаем»)
  ```

  | Статус | Кто ставит | Обязательные поля |
  |---|---|---|
  | `Идея` | любая роль | `Источник` + 2–3 строки «что и зачем» |
  | `На проработке` | координатор (назначает) | `Прорабатывает:` @роль |
  | `ToDo` | координатор | `Приоритет`, `Критерии приёмки`, `Зависимости` |
  | `В работе` | владелец | `В работе с:` (дата) |
  | `В паузе` | владелец/координатор | `Пауза:` причина + `Разблокирует:` кто/что |
  | `На проверке` | владелец | `Проверяет:` доменный ревьюер (@AR/@DO/@TL) + ссылка на артефакт |
  | `Закрыта` | **владелец** (после вердикта) | `## Результат` |
  | `Отклонена` | координатор/владелец | `Причина:` |

  Синонимы (`Открыта`, `Выполнена`, `Готово`, `Done`, `Пауза`) запрещены: ловит
  `python tools\status_lint.py`. `Идея → ToDo` напрямую разрешено, если проработка не нужна.
  Пауза **не считается** «без движения», но пауза > 7 дней — сигнал обхода.
- **Закрывает владелец задачи.** Ревьюер проверяет и пишет «проверено, можно закрывать» —
  но `Статус: Закрыта` ставит тот, кто задачу делал.
- Закрытие = критерии выполнены + CI зелёный + 1–2 строки в `## Результат` (что и где).
- **Обход гейта при сдаче = дефект постановки.** Если для закрытия задачи нужно действие в обход гейта (ручная выкатка, ручной пуш мимо CI) — задача возвращается на проработку, а не закрывается «руками».
- **Статус меняешь — обнови таблицу:** `python tools\stats.py --write`
  (CI-workflow `Stats` падает, если `README.md` отстал от задач).
- **Смена статуса — строкой в чат (владелец 2026-11-15):** сменил `Статус:` задачи → в **том же коммите** строка `- [YYYY-MM-DD HH:mm] → @TL: <ID> <было> → <стало>` в свой outbox (`chat/<роль>.md`). Статусы молча не меняются — по чату должно быть видно, что роль работает.
- **Спринт не стартует без «продукт однозначен»:** по каждому экрану спринта заполнен чек-лист
  `04-architecture/product-readiness-checklist.md` (PDR-30). Пустой пункт = спринт не стартует.
  Продуктовые вопросы — только `→ @EX` (§4); вопрос, всплывший **в** спринте, — дефект
  проектирования (владелец @AR/@PO), работа по пункту останавливается.

### 2.1. Кто проверяет: домен, а не «всё на TL»

Одна роль не может быть единственным ревьюером 130 задач: она становится горлышком
(это была единственная петля, которая не улучшалась ни на одной итерации). Ревью
распределяется по домену задачи:

| Домен задачи | Ревьюер | Что смотрит |
|---|---|---|
| Архитектура: `03-ddd/`, `04-architecture/`, ADR, границы сервисов, контракты | **@AR** | соответствие ADR, отсутствие дублей и «вторых источников правды» |
| Инфраструктура: `7-deploy/`, `.github/`, `tools/`, секреты, деплой, мониторинг | **@DO** | воспроизводимость, безопасность, стоимость прогонов, отсутствие `cancel-in-progress` |
| Продукт: `01-user-stories/`, `02-cjm/`, формулировки для пользователя | **@PO** — **архив на итерацию техдолга** (владелец 2026-11-11); продуктовые ответы — **@EX** | соответствие замыслу и приватности |
| Всё остальное: код сервисов, фронт, тесты | **@TL** | критерии приёмки, качество, риски |

Правила:

1. **`Проверяет:` = доменный ревьюер**, а не автоматически `@TL`. В задаче пишется
   конкретный тег: `@AR`, `@DO`, `@PO` или `@TL`.
2. **Спор двух ревьюеров** (архитектура против инфраструктуры, продукт против техники) —
   арбитр `@TL`; его решение фиксируется строкой в задаче.
3. **TL не обязан перепроверять** то, что проверил доменный ревьюер: он смотрит только
   вердикт и полноту `## Результат`. Двойное ревью — только при явном риске.
4. **Домен определяется по папке задачи** (см. таблицу выше), а не по желанию.
   Задача про CI в `back-end/` — это инфраструктурный домен для целей ревью.
5. **Закрывает по-прежнему владелец** задачи, кто бы её ни проверял.
6. **Саморевью запрещено.** Если автор задачи — тот же ревьюер её домена (типичный случай:
   `devops/`-задача с автором @DO и `Проверяет: @DO`), ревьюером становится `@TL`
   (для архитектурных — `@AR`). Арбитр правил процесса — `@LM`.

## 3. Артефакт вместо обещания

Агент умеет заканчивать ход планом: «беру TE-015, потом TE-016». Файл при этом не
меняется, и для петли ничего не произошло. Правила (из реального случая 01.11, TE-015):

- **Первый шаг по задаче — два артефакта:** `Статус: В работе` + строка `→ @TL` в outbox. Только потом код.
- **Ход нельзя заканчивать обещанием.** Либо tool call в этом же ходе, либо явное «жду: <чего>».
- **Прогресс = артефакт:** коммит, `Статус:`, строка в чате. Самоотчёт без ссылки не считается.
- **Незакоммиченное — не существует.** Дерево одно: правка может исчезнуть без следа. Сделал правку — сразу коммить (WIP-коммит).
- **Проверяй артефакт в `origin`:** `git show origin/main:<файл>`, а не «у меня в дереве так».
- **Имя ≠ содержимое.** Вывод о содержимом — по `git grep`/чтению, а не по названию.
- **Цитата — дословная, со ссылкой на файл и метку.** Метку `[YYYY-MM-DD HH:mm]`, адресата `→ @X` и текст берём из файла, а не по памяти. Цитата в артефакте приводится **вместе с командой проверки** — `git show <ref>:<файл> | grep -F "<текст>"`; проверяемость встроена в запись, включая отрицательные проверки («этой фразы в файле нет»). Пересказ — источник ложных атрибуций (случаи 2026-11-12: `→ @LM` прочитан как автор; метки `22:30/23:10` придуманы по памяти; «повторы `08:40/09:10`» не подтвердились).
- **Не спрашивать «почему остановился».** Факт: «в прошлом ходе не было tool call — продолжай с шага N».
- Проверка: workflow `Sweep` (движок — `LoopMaker/tools/sweep.py`, конфиг —
  `loop.config.json`). Секция «обещано, но не начато» и есть детектор этого обрыва.

## 4. Чат ролей (`5-tech-backlog/chat`)

- Пишешь **только в свой** файл: `be/do/fe/te/ar/tl/po.md`.
- Формат — одна строка: `- [YYYY-MM-DD HH:mm] → @КОМУ: текст`.
  Многострочные сообщения и сообщения без `→ @КОМУ:` не попадут в авто-сводку.
- Блокер → `@TL`.
- **Продуктовый вопрос — только `→ @EX`** (не решается перепиской ролей). Работа по пункту
  **не стартует** до ответа владельца. Вопрос, возникший в **техническом спринте**, — это
  **дефект проектирования** (продукт не доведён до однозначности до старта), владелец дефекта —
  `@AR`/`@PO` (решение владельца 2026-11-09).
- **Метку времени не выдумываем:** `python tools/chat_lint.py --next-stamp` печатает
  каноническую метку (часы машины + `chat_time.shift_hours`). Шкала чата исторически впереди
  машинных часов — это нормально, важно писать в **одной** шкале и по порядку. `--report`
  показывает уезд за шкалу и нарушения порядка; `--strict-times` сделает их ошибкой.
- **Литералы не цитируем:** вместо значения — «строка вида токена», «12 символов», «фейк без кавычек». Цитата остаётся в истории навсегда (§6).
- **`@LM` — только процесс:** правила, линтеры, миграции статусов, `AGENTS.md`/
  `STATUSES.md`, проверки CI и дашборд. Статусы задач и результаты прогонов `@LM`
  **не адресуют** (решение владельца 06.11): нужен статус для процессного решения —
  попросить точечно.
- Перед работой читаешь **все** outbox'ы и берёшь адресованное себе.

## 5. Git и проверки

- Коммит начинается с роли: `be:`, `fe:`, `do:`, `te:`, `ar:`, `tl:`, `po:`
  (`chat(te):`, `docs(do):` — тоже ок).
- Пушим в `main` сами, но свою зону не расширяем (это проверяет `guard-paths.yml`).
- **Коммит — только своими путями.** Перед коммитом `git diff --cached --name-only`; чужой путь в индексе — `git reset <путь>`. **Запрещено:** `git add .`, `git add -A`, `git commit` без путей, `git commit -a`/`-am` (решение владельца 2026-11-11).
- Не коммитим `bin/`, `obj/`, `.env`, выгрузки Garmin.
- **Маркеры конфликта = ошибка гейта.** `<<<<<<<` / `=======` / `>>>>>>>` в любом `.md` под `5-tech-backlog/` и `04-architecture/` — **rc=1** (гейт `tools/check_nul.py`, `--selftest` 4/4), не предупреждение: это не сообщения, а остатки мержа, сводка/дашборд читают мусор (случай: `chat/tl.md` ~760 в `origin`, 2026-11-12).
- Перед закрытием задачи: тесты сервисов — `dotnet test 6-msa/BC-<X>/src/<X>.*Tests` (unit/интеграция) и `<X>.ApiTests` для пар; фронт — `9-tests` через Playwright (`front-e2e.md`).
- **Бюджет инструкций.** Все `AGENTS.md` воркспейса грузятся вместе, лимит — **64 КиБ**;
  при переполнении файл **молча** перестаёт подхватываться (так этот файл один раз выпал
  из контекста ролей). Гейт — `python tools/check_docs_size.py` (сумма 64 КБ, файл ≤ 32 КБ);
  норма остаётся здесь, истории и подробности — в `docs/CI-RULES.md` и `LoopMaker/RULES.md`.
- **Окно тишины — практика, не норма:** см. `docs/drafts/D-02-branch-by-default.md`
  (ветка `hold/<role>` вместо пуша в `main`, пока очередь занята).
- **Синхронизация с origin — одной командой:** `python tools/git_sync.py --role XX`
  (wip-коммит → fetch → merge → push). **`rebase --autostash` в общем дереве запрещён**
  (три STOP за сутки из одной операции): интеграция — только `merge`.

### 5.1. CI: окно 5 минут и дисциплина прогонов

Полные формулировки и истории — [docs/CI-RULES.md](docs/CI-RULES.md). Нормы:

- **5 минут:** прогон младше 5 минут не отменяет никто; `cancel-in-progress` для
  тяжёлых джобов запрещён (они идут в очередь).
- **`cancelled` ≠ «кто-то нажал отмену»:** нет шагов → вытеснение из очереди новым
  пушем; не пушить код, пока по группе висит pending.
- **Отменённый прогон — не доказательство:** для приёмки нужен прогон, завершившийся
  сам; иначе rerun.
- **Запуск, rerun и диагностика — @DO;** координатор только читает результат.
- **Расширяя `paths-ignore`, переноси guard-джобы, а не выключай.**
- **Прогон без шагов — не прогон** (дефект гейта; подробности — `docs/CI-RULES.md`).
- **Dispatch тоже вытесняется:** перед `workflow_dispatch` дождаться пустой очереди
  по группе; пока идёт dispatch-прогон — не пушить.

### 5.2. Воспроизводимость инфраструктуры

- Серверные скрипты (`deploy.sh`, `update.sh`, `heal-network.sh`) — **в репозитории**;
  списки сервисов генерируются из compose, а не переписываются руками.
- «Починил на сервере» без коммита — не починка, а новый дрейф.
- **ADR — «почему», ранбук — «как».** Ранбук (`7-deploy/runbooks/`) не пересказывает решение,
  а ссылается на ADR; изменил ADR — обнови ранбук **в том же коммите**. Проверяют
  `@DO` (владелец) и `@AR` (связность с ADR).
- **ADR — предусловия вместо моратория (владелец 2026-11-14):** перед заведением обязательны: (1) **сверка с логом** (`git grep` по `ADL/` + `edm-verification.md` + `TECHDEBT.md`); (2) обязательное поле **«Связанные решения»** — если есть ADR того же типа, указать **почему меняется** и **соответствует ли комплаенсу прошлого** (§3.3). **Архитектор свободен — предварительная сверка с владельцем снята.** Исключение: если «Связанные решения» (ссылки на предыдущие ADR с описанием) отсутствует — ADR идёт владельцу.
- **ADR по шаблону** (`04-architecture/ADL/adr-template.md`): минимум **3 варианта**, **протокол по ролям**, обязательства, комплаенс. Гейт `tools/check_adr.py`. **Грандфазеринг по дате создания файла** (`git log --diff-filter=AR`): созданный до 2026-11-08 — предупреждение, позже — ошибка. Границы: ADR — «почему», PDR — процесс, ранбук — «как», D-xx — черновик.

### 5.3. Git-инцидент: STOP и один восстановитель

- **STOP только при потере или повреждении** (конфликт `merge`, «cannot autostash»,
  пропавшие коммиты, чужой force-push). Обычный non-fast-forward — рутина:
  `fetch` + `merge`, без STOP.
- **Сначала объявление, потом действия.** Нашёл повреждённые метаданные git
  (`.git/rebase-merge`, `autostash`, «could not read head-name») — одна строка
  `→ всем` в свой outbox с диагнозом, и только потом лечишь. Не «сначала починил,
  потом расскажу»: параллельные восстановители опаснее самого повреждения.
- **Восстанавливает один — координатор.** Пока не прозвучало «работа возвращена»,
  остальные не трогают `.git/`, не запускают `rebase` и не удаляют стеши.
- **Удаляешь из `.git/` — сначала сохрани SHA в чат**, иначе «стеш был мусором» не проверить.
- **Перед операциями с деревом — `python tools/wip.py --role XX`** (общий каталог).
- **Блокер `untracked would be overwritten` — сначала `git worktree list` + `git status` в конкретном worktree.** У ролей есть свои worktree; файл может быть уже в `origin`, а в чужом worktree — локальная копия. `prunable`-записи игнорируем (путь в `%TEMP%` уже удалён): `git worktree prune` выполняет только владелец, не в общем дереве.

### 5.4. Гейт должен соответствовать тому, что деплоится

- Гейт выбирается по природе изменения (`6-msa/**`, `7-deploy/**` → API;
  `8-front/**` → front; смешанное → оба).
- **Ручной обход гейта запрещён:** он скрывает дефект гейта и делает доставку
  невоспроизводимой.
- Гейт, который блокирует не то, что деплоится, или который постоянно ждут/отменяют, —
  **дефект гейта**, его чинят.
- **Гейт подключён ≠ написан.** Подключённым гейт считается только после **двух прогонов**:
  на **дефекте** (доказывает, что срабатывает) и на **норме, сделанной по инструкции**
  (доказывает, что инструкция не врёт); плюс `--selftest` внутри прогона. Пример: `docs-budget`
  #49 упал на фолбэке → #51/#52 зелёные после фикса. Новый гейт объявляется готовым только
  после обеих сторон (правило из D-12, принято владельцем 2026-11-09).
- **Красный гейт не обходится ручным действием (Left Shifting).** Дефект чинится на самой ранней стадии, где ловится (код → ревью → dev → CI-смоук), и никогда не компенсируется ручным действием на проде. Если гейт блокирует — чинится причина, а не путь доставки.

### 5.5. Пуш: транспорт, одна команда, проверка «дошло»

- **Одна настройка машины** (чинит ssh для всех ролей сразу):
  `git config --global core.sshCommand "C:/Windows/System32/OpenSSH/ssh.exe"`.
  Проверка: `git ls-remote --heads origin main` отвечает без ошибок.
- **Синхронизация — одной командой:** `python tools/git_sync.py --role XX`
  (wip строго по **зоне** роли → `fetch` → `merge` → `push` → проверка).
- **`wip` по зоне, а не по всему дереву:** `wip(be)`, захвативший `AGENTS.md`, уже был.
  Нужны чужие пути — только осознанно: `--paths …` или `--all`.
- **«Дошло» — только после `fetch`:** `git rev-list --count origin/main..HEAD` = 0.
- **Ссылаться на SHA — только после `git merge-base --is-ancestor`** (rebase переписывает коммиты).
- **Запрещено:** `git push --force`, `rebase --autostash` в общем дереве (интеграция —
  только `merge`), пушить код, пока по группе висит pending-прогон
  (§5.1), и хранить в документах пути к хранилищу токена (§6: репозиторий публичный).
  Проверка доков: `python tools/check_rule_docs.py`.

## 6. Секреты

Пароли VPS, `GARMIN_API_KEY`, JWT-ключи, `PROJECT_PAT` — только в `.env` (локально)
или в GitHub Secrets. Не в задачах, не в чате, не в README, не в коммитах:
сообщения агентам сохраняются в транскриптах тредов, а чат — в git-истории.

**Даже фрагменты ключей нельзя.** Не пиши «ключ начинается на …», не цитируй
значение, не сравнивай ключи по символам — только «ключи различаются, сверка/ротация
через Secrets». Репозиторий **публичный**: закоммиченный фрагмент = утёк.

Проверка: job `guard-secrets` — в `chat-guards.yml` (файлы задач и чата, `--range` по
пушу) и в `ci-tests.yml` (код сервисов) — `tools/check_secrets.py`
(в CI режим `--range`: сканируется только пушимое, включая строки, зачищенные потом
в рабочем дереве), пути по умолчанию — `default_paths()` в `tools/check_secrets.py`
(`--config` задаёт `--range`, не пути). Падает на находке; значения в лог
не попадают. Локально: `python tools/check_secrets.py --config loop.config.json`.

`tools/check_secrets.py`, `tools/keycmp.py`, `tools/chat_lint.py` — **копии** из
`LoopMaker/tools/` (источник правды там, в шапке файла это указано). Правка — в обоих
местах. Копии, а не чекаут LoopMaker в CI: репозиторий LoopMaker приватный, а
`GITHUB_TOKEN` чужой репозиторий не читает — чекаут требует отдельного PAT.

Сравнение ключей без раскрытия — `python tools/keycmp.py --a-env A --b-env B`
(«совпадают/нет» + `sha256[:8]`).

При утечке: 1) зачистить в рабочем файле; 2) **ротация ключа** через @DO (Secrets +
`.env` на VPS); 3) из git-истории не убрать без force-push — ротация обязательна.

Инциденты 2026-11-03/04: фрагменты `Jwt:SigningKey` в `chat/be.md`/`chat/tl.md` — зачищено, ключ ротирован @DO; правило и гейт — реакция на оба захода.

## 7. Что спрашивать у владельца, а что — из документов

Прежде чем задать вопрос владельцу, **проверь ADR / канвас / задачу**: если решение уже
принято в документе — реализуй по нему, а не переспрашивай. Переспрашивание принятого
решения читается как «мы не проектировали» и сжигает доверие.

**Решаем сами (не спрашиваем):** всё, что уже есть в ADR/канвасе/`README`; технические
детали (библиотеки, структура кода, имена полей); порядок работы над задачами; как чинить
то, что сломано и мешает (с записью решения в задачу).

**Спрашиваем владельца (не решаем сами):**
- **доступы и ключи** (аккаунт провайдера, бот-токен, домен, платёжные данные) — это не
  архитектура, а ресурсы, которых у агентов нет физически;
- **продуктовые приоритеты**: что делаем сейчас, что откладываем, что вырезаем;
- **изменение уже принятого решения** (в т.ч. правка ADR) — только с его ведома;
- **изменение правил процесса** (как закрываем задачи, как меряем готовность).
