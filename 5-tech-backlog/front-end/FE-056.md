# FE-056 — P1: пустой кэш + сбой `GET` = 0 строк **без текста ошибки** (`withCache` глотает ошибку)

- **Статус:** На проверке
- **Приоритет:** P1 (пользователь видит «нет данных» вместо «авария API» — тот же вред, что `FE-051`, но `FE-051` этот путь не закрыл)
- **Источник:** замер @TE 2026-11-17 21:17 по прогону `front-e2e` (`partner-edit`: `toHaveCount(0)` уже **после** `link-client`-фикса)
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @FE (`8-front/`)
- **На проверке с:** 2026-11-17
- **Артефакт:** `8-front/js/repository.js` (`withCache` пишет `fresh[kind].error`), `8-front/js/app.js` (`renderPartners` называет причину при пустом кэше), версия `0.122` / `xdiary-v122`; тест `5-tech-backlog/front-end/FE-056-cache-error-marker-test.js`

## Механизм (проверено по коду @TE)

`8-front/js/repository.js:182`:
```js
DB.getAllPartners = withCache("partners", Api.partners.list, DB.rawPartners)
```
`withCache` при `429`/`5xx`/сетевой ошибке **молча** возвращает кэш. Если кэш пуст — рендер получает пустой массив и рисует **0 строк без текста ошибки**: исключения нет, значит `.catch` из `FE-051` не срабатывает, и `.load-error` не появляется.

Отсюда в E2E `toHaveCount(0)` означает не «карточки нет», а «последний `GET /partners` не удался» — два разных состояния выглядят одинаково.

## Что нужно

1. `withCache` (или обёртка в `repository.js`) должна возвращать признак «данные получены из кэша после ошибки» (например `{ items, fromCache, error }`), а не только массив.
2. `renderPartners`/`renderJournal`: если `fromCache && items.length === 0 && error` → показать `.load-error` с причиной (как в `FE-051`) **и** кнопкой «Повторить».
3. Если кэш непустой и есть ошибка — прежняя пометка `showStaleNote` (FE-044) **остаётся**, текст ошибки не подменяет её.
4. Не менять контракт `DB.getAll*` для остальных вызовов без явного решения (или ввести совместимый вариант с сохранением текущего поведения).

## Критерии приёмки

- [x] runtime-тест: `GET` → `500` + пустой кэш ⇒ ошибка пробрасывается, `FE-051`-`catch` рисует `.load-error` с причиной и «Повторить» (проверено: `withCache` бросает, `fresh` не выставлен);
- [x] runtime-тест: `GET` → `500` + **непустой** кэш ⇒ данные + `fromCache` + **причина** (`error.status/message`), `stale-note` остаётся, `.load-error` нет;
- [x] runtime-тест: `GET` → `200` + пустой кэш ⇒ данные, признаков ошибки нет (0 строк — легально);
- [x] негативный контроль: без поля `error` UI не смог бы назвать причину — тест это проверяет;
- [x] `node --check` rc=0; версия в паре `0.122` ↔ `xdiary-v122`.

## Почему P1

Именно этот путь даёт ложные «0 элементов» в e2e (`partner-edit`, `stale-note`) и вводит в заблуждение в проде: пользователь не отличает «у меня нет партнёров» от «сервер недоступен».

## Результат

**Сделано в `0.122`/`xdiary-v122`.**

- `withCache` при отказе живого чтения и **непустом** кэше теперь пишет в `fresh[kind]` не только `fromCache/ageMs`, но и **`error: {status, message}`** — причина отказа сохраняется для UI. Тип возврата не изменился (массив), контракт `DB.getAll*` для остальных вызовов сохранён.
- `renderPartners`: если пришли **пустые** данные и признак «из кэша после ошибки» есть — скрывает «Партнёров пока нет» и показывает `.load-error` с **причиной** («Не удалось загрузить партнёров: HTTP 500…») и кнопкой «Повторить».
- Поведение при пустом кэше **не изменил**: `withCache` по-прежнему **пробрасывает** ошибку, и её ловит `.catch` из `FE-051`.

**Важная поправка к механизму в постановке (проверено по коду и тестом).** В карточке было: «если кэш пуст — рендер получает пустой массив и рисует 0 строк без ошибки». По коду `repository.js:167` (`if (!rows || !rows.length) { fresh[kind] = null; throw err; }`) при пустом кэше **ошибка пробрасывается** — тест `FE-056-cache-error-marker-test.js` это фиксирует (`500 + пустой кэш: пробрасывается ошибка — err=HTTP 503`). Значит `toHaveCount(0)` в e2e означал «строк нет», а не «ошибки нет»; реальный молчаливый путь — **непустой кэш**: данные показывались как обычные, причина отказа нигде не называлась. Именно это и закрыто.

**Квитанция:** `node 5-tech-backlog/front-end/FE-056-cache-error-marker-test.js` → **8/8, rc=0**: 500+кэш → данные + `fromCache` + `error.status=500`; 500+пустой кэш → исключение и `fresh=null`; 200 → без признаков ошибки; негативный контроль — без поля `error` UI причину не назовёт. `node --check` rc=0 для `repository.js`/`app.js`; `FE-044-withcache-runtime-test.js` остаётся **8/8** (регресса нет).
