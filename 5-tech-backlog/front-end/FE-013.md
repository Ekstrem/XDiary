# FE-013: Соматика в деталях записи — на API (сейчас локальный `getSomaticRange`)

- **Статус:** Закрыта
- **Приоритет:** P2 (график соматики в детали записи пуст на новом устройстве)
- **Источник:** @FE `chat/fe.md` 2026-11-02 23:30 (продолжение FE-012)
- **Зависимости:** FE-012

## Проблема (по коду)
- `renderSomatic()` (`8-front/js/app.js:1214`) берёт `DB.getSomaticRange(rangeStart, rangeEnd)` — **локальная** соматика, наполняется только CSV-импортом.
- На новом устройстве график в детали записи пустой, хотя `Api.somatic.slice(fromT, toT)` (`8-front/js/api.js:91`) отдаёт данные.

## Задача
- Перевести `renderSomatic` на `Api.somatic.slice(fromT, toT)` (как сделано в FE-012 для корреляций).
- Ошибку API не глотать (пустой график + сообщение, а не тишина).
- Поднять `APP_VERSION`/`CACHE` (`0.33`/`v33`).

## Критерии приёмки
- [x] На новом устройстве график соматики в детали записи показывает серверные данные.
- [x] Версия забампана (`0.33`/`v33`).
- [ ] E2E/CI зелёные (проверит @TE).

## Результат
- `8-front/js/app.js` `renderSomatic`: `DB.getSomaticRange` → `Api.somatic.slice(rangeStart, rangeEnd)`; `DB.getSleep`/`DB.getWeekly` → `Api.daily.series(day, day)`; API-поле `bodyBattery` маппится в `body_battery` (drawChart не менялся). При ошибке API — «Не удалось загрузить соматику».
- Версия: `APP_VERSION` → `0.33`, `CACHE` → `xdiary-v33`.
