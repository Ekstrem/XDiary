## Задача (зона @FE, `8-front/`)

`DB.getAllPartners()` кэширует список на `PARTNERS_MEMO_MS = 2000` мс (`repository.js:172-182`). `DB.putPartner()`/`DB.deletePartner()` сбрасывали мемо **только до** запроса. Если между сбросом и успешным ответом кто-то ещё вызовет `getAllPartners()` (журнал через `getAllRecords`/`getAllJournalData` тоже читает партнёров, плюс сторож и синк), мемо заполняется **старым** списком и живёт ещё 2 с. `renderPartners()` после сохранения попадает в это окно → список без только что созданного партнёра. Это объясняет и «карточек: 1» (только сид «T»), и почему падало 2 из 3 прогонов, а не все.

**Правка:** мемо сбрасывается и **на успехе** мутации (`settle()` в `putPartner`, `.then` в `deletePartner`), а не только до запроса.

## Критерии приёмки

- [x] После `DB.putPartner()` мемо сброшено на успехе: следующий `getAllPartners()` идёт в API и содержит созданного партнёра;
- [x] То же для `DB.deletePartner()` (сброс до и после);
- [x] Воспроизводимый тест на **реальной** функции из `repository.js` (через `vm`), с негативным контролем: старое поведение обязано терять созданного;
- [x] `node --check` rc=0, версия в паре `0.114` ↔ `xdiary-v114`.
