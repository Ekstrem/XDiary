- **Зависимости:** нет (правка в `8-front/js/app.js` + `8-front/js/repository.js`); от `BE-122` не зависит
- **Проверяет:** @TL
- **На проверке с:** 2026-11-17
- **Артефакт:** `8-front/js/app.js` (черновик в `localStorage`, восстановление, классы ошибок), `8-front/js/repository.js` (`DB.onRecordCreated` — id сразу после создания), версия `0.120` / `xdiary-v120`; тест `5-tech-backlog/front-end/FE-055-draft-runtime-test.js`

## Задача (зона @FE, `8-front/`)

Сохранение акта — цепочка вызовов: `POST /journal/records` (`Api.journal.start`) → поля (`when`, `partners`, `place`, `positions`, `accessories`, `contraception`, `duration`, `orgasms`) → `complete`. До этой правки черновик жил **только в памяти**: любой сбой в цепочке → тост «Ошибка: …» → переход в журнал, **введённый текст терялся**. Хуже: если `start()` уже создал запись, а следующий шаг упал, повтор создавал **вторую** запись.

**Правка:**
- черновик пишется в `localStorage` (`xdiary.recordDraft`) **до** отправки;
- как только сервер вернул id созданной записи — id фиксируется в черновике (`DB.onRecordCreated` → `patchRecordDraftId`), поэтому повтор идёт **в ту же** запись (ветка `rec.id` в `DB.putRecord`), а не создаёт дубль;
- черновик **чистится только после** успешной цепочки;
- при сети/`5xx`/`status 0`: остаёмся в визарде, `.load-error` с текстом «Не удалось сохранить акт: … Черновик сохранён — можно повторить» + кнопка **«Повторить»** (перезапускает сохранение), плюс тост «Нет связи с сервером — черновик сохранён»;
- при `4xx`: черновик остаётся, ошибка показывается **как есть** («Сервер отклонил акт: …»), без маскировки под сетевую;
- при открытии визарда без `id` и наличии черновика — он **восстанавливается** (через `loadWizardData`, с тостом «Черновик восстановлен»);
- `showLoadError` для визарда кладёт блок внутрь `.content` (а не над appbar).

## Критерии приёмки

- [x] Черновик сохраняется **до** отправки и переживает перезагрузку;
- [x] Черновик чистится **только** после успешной цепочки (`2xx`);
- [x] Сеть/`5xx` → видимая причина + «Повторить», текст не теряется, пользователь остаётся в визарде;
- [x] `4xx` → черновик остаётся, ошибка показывается как есть;
- [x] Повтор **не создаёт дубль**: id созданной записи фиксируется в черновике и используется при повторе;
- [x] Runtime-тест на **реальных** хелперах: `node 5-tech-backlog/front-end/FE-055-draft-runtime-test.js` → **7/7, rc=0**;
- [x] `node --check` rc=0 для `app.js`/`repository.js`; версия в паре `0.120` ↔ `xdiary-v120`.

## Результат

**Сделано в `0.120`/`xdiary-v120`.** Введён черновик акта в `localStorage`: пишется до отправки, очищается только после успеха; `DB.putRecord` сообщает id созданной записи через `DB.onRecordCreated`, и id сразу фиксируется в черновике — повтор продолжает ту же запись (без дубля). Ошибки разделены: сеть/`5xx` → видимый блок с «Повторить» и текстом причины (пользователь остаётся в визарде), `4xx` → ошибка сервера как есть, черновик сохраняется. При открытии визарда черновик восстанавливается.

**Квитанция:** `node 5-tech-backlog/front-end/FE-055-draft-runtime-test.js` → **7/7, rc=0**: черновик пишется/читается, id созданной записи фиксируется и попадает в `rec.id`, текст не теряется, после успеха черновик очищен; **негативный контроль** — без `patchRecordDraftId` id остаётся `null`, то есть повтор создал бы дубль (тест это ловит).

**Граница:** браузерного прогона на `0.120` не было (в прогонах сейчас красное из-за стендовых `429`/`502`); поведение подтверждено исполнением реальных функций и `node --check`. Живая проверка — при следующем `ci-front`.
