# FE-031: `link-partner` из UI не сохраняется — `me()` отдаёт `linked: false`, журнал не открывается

- **Статус:** ToDo
- **Приоритет:** P1 (блокирует онбординг; два спека E2E красные: `onboarding`, `pin-first-login`)
- **Источник:** `ci-front` #5 (`77b145b`), лог шага (нашёл @DO 2026-11-02 22:20): `views (после привязки): view-lock=hidden, view-onboarding=visible, view-journal=hidden` и сразу `me() после привязки: {"status":200,"verified":true,"linked":false}`
- **Зависимости:** FE-021 (онбординг), FE-025/026 (PIN/лок-гейт), BE-031 (`link-partner` на бэкенде)
- **Проверяет:** @TL (TechLead)

## Что известно по факту (не гипотеза)
1. **Клик по карточке доходит, экран переключается** — но в онбординг, а не в журнал (в логе `view-onboarding=visible`).
2. Причина видна там же: **`me()` возвращает `verified: true`, `linked: false`** — фронт честно смотрит на `linked` и показывает онбординг.
3. **Бэкенд привязку сохраняет:** @DO звал `POST /clients/<id>/link-partner` напрямую → `GET /clients/me` даёт `linkedPartnerId` длиной 36 и держит через 3 с.
4. Значит разрыв — **на участке UI → `link-partner`**: либо запрос не уходит, либо уходит с пустым/неверным `partnerId`, либо ответ обрабатывается как ошибка и `me()` перезапрашивается до сохранения.

## Задача
1. Проверить в `8-front/js/app.js` путь привязки: `renderLinkPartners` → `Api.clients.linkPartner(id, partnerId)` — что именно передаётся вторым аргументом (id партнёра из списка, не `undefined`/`null`).
2. Проверить обработку ответа: при не-2xx не должно быть «тихого» перехода в онбординг; ошибка должна быть видна (toast/лог), иначе пользователь видит «повторную регистрацию».
3. Проверить гонку: если `openJournal()` вызывается **до** ответа `link-partner` (или параллельно с `me()`), журнал не откроется — `me()` вернёт `linked:false`.
4. Не менять бэкенд: он проверен, `linkedPartnerId` сохраняется.

## Критерии приёмки
- [ ] После клика по карточке партнёра `me()` возвращает `linked: true`, `#view-journal` виден.
- [ ] Спеки `onboarding` и `pin-first-login` зелёные (или падают по другой, явно названной причине).
- [ ] Ошибка `link-partner` (не-2xx) не приводит к «тихому» онбордингу — есть видимое сообщение.
