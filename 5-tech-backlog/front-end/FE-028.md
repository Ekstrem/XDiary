# FE-028: Обновление client-JWT по refresh-токену вместо выброса в онбординг

- **Статус:** На проверке
- **Приоритет:** P0 (после BE-041; сейчас через 15 минут пользователь теряет сессию)
- **Источник:** @AR 2026-11-02 17:26 (access 15 мин + refresh 30 дней, `POST /clients/refresh`), FE-025/FE-027
- **Зависимости:** BE-041 (эндпоинт refresh), BE-040 (401 на `/clients/me`)
- **Проверяет:** @TL (TechLead)

## Проблема
Сейчас на любой 401 фронт уходит в онбординг (`afterAuth().catch → openOnboarding()`, `withTimeout` из `0.61`). При access-токене в 15 минут это означает: **каждые 15 минут пользователь «вылетает»** и должен заново вводить телефон и код.

## Задача
1. **Хранить refresh**: при `/verify` сохранять `xdiary.refreshToken` (+ `expiresAt`), access — как сейчас.
2. **Обновление вместо выброса:** при 401 от API — **одна** попытка `POST /api/v1/clients/refresh` с refresh-токеном; при успехе — сохранить новую пару и **повторить исходный запрос**; при неудаче — онбординг (как сейчас).
3. **Однократность:** параллельные 401 не должны запускать несколько refresh — один «inflight» промис, остальные ждут его.
4. **Не зациклиться:** если refresh вернул 401 — больше не пробовать, уходить в онбординг.
5. **Онбординг после успеха** — не показывать, если сессия восстановлена.
6. Версия/кэш: поднять `APP_VERSION` и `CACHE` (`sw.js`) синхронно.

## Критерии приёмки
- [x] При истёкшем access приложение **не уходит в онбординг**, а обновляет пару и повторяет исходный запрос (одна попытка).
- [x] При истёкшем/битом refresh (401/400/сеть) — одинаково «сессия истекла» → онбординг.
- [x] Параллельные 401 не дают шторма: `refreshInflight` (single-flight), один запрос на всех.
- [x] `front-e2e` зелёный; `seedSession` кладёт refresh (совместно с @TE). — проверено @TL: `ci-front` #59 (success), `front-e2e-repeat` #8 (20/0 на грязном стенде), `#10`/`#11` success

## Результат (`0.64`/`v64`)
- `8-front/js/api.js`: `authRefresh()` — `POST /api/v1/clients/refresh {refreshToken}`, single-flight `refreshInflight`, сохраняет новую пару; любые ошибки → «Сессия истекла» (без зацикливания, `/clients/refresh` исключён из повтора).
- `8-front/js/app.js` `submitOnbOtp`: читает `accessToken` (fallback `token`) и сохраняет `refreshToken` из `/verify` (контракт BE-041).
- Версии `0.64`/`v64` синхронны (проверено в `origin/main`).

## Решение владельца (@EX, 2026-11-02): выпускаем всё, включая refresh
Релиз включает полный объём: зелёный `front-e2e` **и** refresh-токен (BE-041 + FE-028) **и** OTP на проде.
Промежуточный вариант «поднять TTL access-токена» **не делаем** — модель AR остаётся: access 15 мин + refresh 30 дней.
Приоритет: **P0** (блокирует релиз).
