# FE-051: 5xx на `/partners` и `/journal` — фронт показывает молча пустой экран

- **Статус:** На проверке
- **Приоритет:** **P1** (при аварии API пользователь видит пустой журнал/пустых партнёров без объяснения — это читается как «данные пропали»)
- **Источник:** живой замер 2026-11-16 11:44 (read-only): `GET https://xdiary-vps1.taile0b6ee.ts.net/api/v1/partners` → **500**, `/api/v1/journal/records` → **500** (при `/health` 200 и `/clients/me` 401); плюс следы того же класса в CI: `front-e2e` на PR #2366 (`43829914785`) — `http 404 /clients/me`, `502 link-partner`, `504 /clients/me/profile`
- **Зависимости:** инфраструктурная причина 500 — зона @DO/@BE (маршруты APIM/`servers: "/"`); эта карточка — про **поведение фронта** при такой ошибке
- **Проверяет:** @TL
- **На проверке с:** 2026-11-16
- **Артефакт:** `8-front/js/app.js` (`showLoadError`/`clearLoadError`, `.catch` в `renderJournal`/`renderPartners`), `8-front/css/styles.css` (`.load-error`), версия `0.116` / `xdiary-v116`; тест `5-tech-backlog/front-end/FE-051-load-error-test.js`

## Задача (зона @FE, `8-front/`)

`renderJournal()` и `renderPartners()` вызывали `DB.getAllRecords()` / `DB.getAllPartners()` **без `.catch`**. Если живое чтение падает (5xx/сеть) и кэш пуст, `withCache` пробрасывает ошибку (`repository.js:158-166`) — она уходит в unhandled rejection, а список остаётся **пустым без единого слова**. Пользователь не отличает «авария API» от «у меня нет записей», а именно в таком состоянии прод сейчас и находится (`/partners` и `/journal` → 500).

**Правка:** видимый блок ошибки вместо пустоты:
- `showLoadError(viewId, listId, message, retry)` — вставляет `div.load-error[role=alert]` с текстом и кнопкой **«Повторить»** (button вызывает тот же рендер); `clearLoadError(viewId)` убирает блок;
- оба рендера: `clearLoadError(...)` в начале, `.catch` — `console.error` + `showLoadError(...)` с текстом «Не удалось загрузить … Проверьте связь и нажмите «Повторить»»;
- успешная загрузка блок убирает (не остаётся «прилипшей» ошибки);
- поведение с **кэшем не изменено**: если данные пришли из кэша, работает прежняя пометка `showStaleNote` (FE-044), а не ошибка.

## Критерии приёмки

- [x] При 5xx/сетевой ошибке и пустом кэше виден текст ошибки (содержит «не удалось») и кнопка «Повторить»;
- [x] Кнопка «Повторить» повторяет загрузку (retry = тот же рендер);
- [x] При успешной загрузке блок ошибки исчезает;
- [x] Кэш-политика не изменена: `showStaleNote` продолжает работать, ошибка не заменяет пометку устаревших данных;
- [x] Воспроизводимый тест с негативным контролем: `node 5-tech-backlog/front-end/FE-051-load-error-test.js` → **16/16, rc=0** (без `.catch` тест падает);
- [x] `node --check` rc=0; версия в паре `0.116` ↔ `xdiary-v116`.

**Сделано в `0.116`/`xdiary-v116`.** Причина — молчаливый путь ошибки: `renderJournal`/`renderPartners` не имели `.catch`, а `withCache` при пустом кэше пробрасывает исходную ошибку, поэтому экран оставался пустым (только `console`). Теперь оба рендера показывают `.load-error[role=alert]` с текстом «Не удалось загрузить журнал/партнёров. Проверьте связь и нажмите «Повторить».» и кнопкой, которая перезапускает тот же рендер; при успехе блок удаляется.
