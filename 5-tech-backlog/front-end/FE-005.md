# FE-005: Синхронизировать `8-front` с новым контрактом BE-018 (PUT/DELETE → POST)

- **Статус:** На проверке
- **Приоритет:** P1 (**PWA сломан**: правка/удаление партнёра и каталога дают 404/405)
- **Источник:** BE-018 (коммит `db42ba5`), `chat/be.md` 22:48
- **Зависимости:** BE-018

## Проблема
`8-front/js/api.js` использует `put()`/`del()` (строки 61–62) для:
- Partners: `rename` → `PUT /partners/{id}/name`, `profile` → `PUT /partners/{id}/profile`, `remove` → `DELETE /partners/{id}`
- Catalog: `rename` → `PUT /catalog/{id}/name`, `details` → `PUT /catalog/{id}/details`, `remove` → `DELETE /catalog/{id}`
- Journal: `remove` → `DELETE /journal/records/{id}`, `removePartner` → `DELETE /journal/records/{id}/partners/{pid}`
- Privacy: `removePin` → `DELETE /privacy/pin`

Бэкенд после BE-018 отдаёт только POST — все эти вызовы теперь 404/405.

## Новые маршруты (по коду `6-msa`)
- `POST /api/v1/partners/{id}/name`, `POST /api/v1/partners/{id}/profile`, `POST /api/v1/partners/{id}/remove`
- `POST /api/v1/catalog/{id}/name`, `POST /api/v1/catalog/{id}/details`, `POST /api/v1/catalog/{id}/remove`
- Journal / Privacy — уточнить в контроллерах (`/remove`-варианты).

## Задача
Переписать `8-front/js/api.js` на POST-варианты, убрать `put()`/`del()`; проверить сценарии: правка партнёра, правка каталога, удаление, снятие PIN.

## Критерии приёмки
- [x] В `8-front` нет `PUT`/`DELETE` вызовов API.
- [x] Правка/удаление партнёра и каталога, снятие PIN работают на проде.
- [x] CI green.

## Результат
- `8-front/js/api.js` переведён на POST-only: `partners.rename/profile/remove`, `catalog.rename/details/remove`, `journal.remove`(`/delete`) + `removePartner`(`/remove`), `privacy.removePin`(`/pin/remove`). `put()`/`del()` удалены.
- Маршруты сверены с контроллерами `6-msa` (Partners/Catalog/Journal/Privacy). E2E-верификацию на проде закроет TE-013.
