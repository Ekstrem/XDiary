# FE-054: `POST /catalog` — клиентский `id` для идемпотентного создания (без дублей при retry)

- **Статус:** На проверке
- **Приоритет:** **P1** (сетевой повтор при создании позиции каталога даёт дубль: сервер принимает клиентский `id`, но фронт его не присылал)
- **Источник:** @BE `2026-11-16 13:35` (из `be.md`): «`POST /api/v1/catalog` принимает опциональный `id` (`{id, kind, name}`) — фронт генерит UUID и переиспользует при retry»
- **Зависимости:** **`BE-122`** (P1, @BE) — `Guid? Id` в `AddCatalogItemCommand` + контрактные тесты (с id, повтор с тем же id, без id)
- **Проверяет:** @TL
- **На проверке с:** 2026-11-17
- **Артефакт:** `8-front/js/api.js` (`catalog.add(kind, name, id)`), `8-front/js/repository.js` (`clientUuid()`, `putCatalogItem` — retry на том же id), версия `0.119` / `xdiary-v119`; тест `5-tech-backlog/front-end/FE-054-catalog-idempotent-test.js`

## Задача (зона @FE, `8-front/`)

`DB.putCatalogItem` создавал позицию через `Api.catalog.add(kind, name)` — **без `id`** и **без повтора**. Если `POST /api/v1/catalog` падал по сети/таймауту, пользователь получал ошибку, а при повторном нажатии создавался **дубль** (сервер не мог отличить повтор от новой позиции). @BE подтвердил, что API уже принимает опциональный `id` — то есть идемпотентность можно сделать на клиенте без изменений бэкенда.

**Правка:**
- `Api.catalog.add(kind, name, id)` — `id` добавляется в тело только если передан;
- `repository.js`: `clientUuid()` (crypto.randomUUID с фолбэком), `putCatalogItem` в ветке создания генерит id **один раз** и делает **один** retry с тем же id при сетевой ошибке/5xx; на `400` повтора нет (иначе спрячем настоящую валидацию).

## Критерии приёмки

- [x] При создании в теле `POST /catalog` уходит клиентский `id`;
- [x] При сетевой ошибке — один retry, и во втором вызове **тот же** `id` (повтор идемпотентен);
- [x] При `400` retry не делается, ошибка проходит наверх;
- [x] Результат содержит id (серверный или, если сервер не вернул, клиентский);
- [x] Runtime-тест на **реальной** функции: `node 5-tech-backlog/front-end/FE-054-catalog-idempotent-test.js` → **9/9, rc=0**;
- [x] `node --check` rc=0 для `api.js`/`repository.js`/`app.js`; версия в паре `0.119` ↔ `xdiary-v119`.
