# FE-003: Миграция данных IndexedDB/CSV → бэкенд

- **Статус:** Открыта
- **Приоритет:** P1
- **Источник:** ADR-011, US-09
- **Зависимости:** BE-011, FE-001

## Задача
Реализовать перенос существующих данных на бэкенд:
- Экспорт текущих данных (записи, каталог, партнёры, соматика) в CSV.
- Импорт CSV в бэкенд через `portability` (идемпотентно по `id`).

## Критерии приёмки
- [ ] Экспорт из IndexedDB → CSV (текущий формат `CSV_HEADERS`).
- [ ] Импорт в бэк без дубликатов (merge по `id`).
- [ ] Сохраняются связи (`startedAt`, `garminId`, списки через `;`).
- [ ] После миграции данные видны в бэке (проверка через журнал).

## Заметки исполнителя (front-end)
- Блокер: «merge по id» и «данные видны в журнале» требуют интеграции portability→journal, которой в коде нет (`portability` хранит CSV-строки, `journal` генерирует новый id). Вопрос @TL (см. `chat/fe.md` 22:30): миграция через portability (после доработки) или через цепочку команд journal.
