# FE-042: этап 1 PIN-легаси — фронт перестаёт вызывать серверный PIN

- **Статус:** Закрыта
- **Приоритет:** P1 (безопасность: 4-значный PIN не может быть серверным креденшлом, ADR-021 §«два PIN — решение (б)»)
- **Источник:** ADR-021 §«Уточнение 2026-11-04: два PIN — решение (б)» + @AR 2026-11-16 01:18 (разделение критериев на три этапа)
- **Зависимости:** `FE-041`/`FE-040` (чтобы не смешивать правки фронта)
- **Проверяет:** @AR (контракт) + @TL (техника) — артефакт: `8-front/js/app.js`, версия `0.90` / `xdiary-v90`

## Задача (зона @FE, `8-front/`)

**Только этап 1** — фронт перестаёт **вызывать** серверный PIN. Обёртки в `api.js` могут остаться: их удаление — этап 3.

Живые вызовы (по факту @AR): `8-front/js/app.js:240` (`applyPin`), `8-front/js/app.js:2243` (сохранение PIN в настройках), `8-front/js/app.js:2260` (снятие) и `/privacy/token` в `8-front/js/api.js:127`.

PIN остаётся **локальным** (устройство); сервер о нём не знает.

## Критерии приёмки

- [x] `git grep -n 'Api\.privacy\.' -- 8-front/js/app.js` → **пусто** (именно это критерий этапа 1; обёртки в `api.js` не считаются).
- [ ] PIN продолжает работать локально: установка/ввод/смена PIN на устройстве. — **требует живого прогона на стенде (@TE/владелец)**, поэтому не закрашен.
- [x] Ни один сетевой вызов `/api/v1/privacy/pin/*` и `/api/v1/privacy/token` не уходит с фронта (проверка `node --check` + grep по `8-front`).
- [ ] Онбординг и вход не ломаются (профиль через `POST /api/v1/clients/me/profile`). — **требует живого прогона**, не закрашен.

## Результат

- **Этап 1 закрыт** @TL по ревью @AR `2026-11-07 00:29`: проверено **по коду**, а не по описанию — `grep 'Api\.privacy'` по `8-front/js/*.js` → **0**; в `app.js` остались только два комментария (`:243`, `:2461`), живых вызовов `privacy/pin` нет. Критерий этапа («фронт не вызывает») выполнен; серверные эндпоинты остаются legacy — их судьба в этапе 3.

Этап 1 выполнен в `0.90`. Все три живых вызова в `app.js` убраны:

- `ensureToken(pin)` — фолбэк «завести серверный PIN, если логин не удался» снят; функция только логинит (`Api.auth.login`), PIN остаётся локальным.
- `applyPin()` — сохранение PIN больше не синхронизируется на сервер: `Pin.setPin(nw)` → `toast("PIN сохранён")`; серверных вызовов и сообщений «сервер ответил» нет.
- `removePinNow()` — снятие только локальное. **Важно:** раньше текущий PIN проверял сервер (`currentPin`), теперь проверка локальная (`Pin.verifyPin(cur)`), иначе после снятия серверного вызова снятие PIN осталось бы вообще без проверки — то есть убрать замок мог бы любой.

Обёртки в `api.js` (`/privacy/pin/*` — `hasPin`/`setPin`/`verifyPin`/`removePin`, `/privacy/token`) **сохранены осознанно**: их удаление — этап 3 (после снятия эндпоинтов), критерий этапа 1 этого не требует.

Проверка: `git grep -n 'Api\.privacy\.' -- 8-front/js/app.js` → **пусто**; `node --check` → rc=0 для `app.js` и `sw.js`; версия `APP_VERSION = "0.90"` ↔ `CACHE = "xdiary-v90"` (парой).

Осталось (этап 2/3, не моя зона в этой карточке): спеки @TE не проверяют серверный PIN; удаление эндпоинтов и device-токена — отдельным ломающим изменением.

**Уточнение 2026-11-11 21:30 (по запросу @TE):** этап 3 **не сделан и карточки на него нет.** Факт из `origin`: в `8-front/js/api.js` остаются **шесть** обёрток — `privacy.hasPin` (`/privacy/pin/has`), `setPin` (`/pin/set`), `verifyPin` (`/pin/verify`), `removePin` (`/pin/remove`), `privacy.token` (`/privacy/token`) и проверка пути `/privacy/token` в обработчике 401; в `8-front/js/app.js` — только **два комментария**, живых вызовов `Api.privacy` — **0** (критерий этапа 1 выполнен). Удаление эндпоинтов — ломающее изменение (фронт-обёртки + `6-msa/BC-Privacy` + спеки), поэтому нужна отдельная карточка от координатора; `TE-055` в паузе ждёт именно её, а не `FE-042`.
