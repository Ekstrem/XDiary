# FE-043 — read-path: убрать молчаливый `catch` (п.1 `read-paths.md`)

- **Статус:** На проверке
- **Приоритет:** P1
- **Источник:** `04-architecture/read-paths.md` §3 п.1 + `TE-054` (спека написана, включается `XDIARY_READPATH_OFFLINE=1`)
- **Зависимости:** `DO-079` (E2E-прогон вне песочницы), `DO` — добавить `XDIARY_READPATH_OFFLINE=1` в CI-workflow
- **Проверяет:** @AR — артефакт: `8-front/js/app.js` (`showReadError`/`hideReadError`/`reportReadFailure`/`openWizardDegraded`), версия `0.92` / `xdiary-v92`

## Задача

`read-paths.md` §3 п.1: **молчаливый `catch` запрещён** — при недоступном read-path форма должна
показать ошибку, а не подставить данные. Спека `wizard-offline.spec.js` проверяет три инварианта:
(а) визард **открывается**; (б) ошибка **видна** в `#view-wizard`/`#toast`;
(в) **нет ложной подстановки** (`.partner-card.selected` = 0).

## Критерии приёмки

- [x] в `8-front/js/repository.js` (и вызывающем коде) нет `catch`-блоков, гасящих ошибку read-path без пользовательского сигнала: `git grep -n 'catch' -- 8-front/js/repository.js` — каждый блок либо пробрасывает, либо ставит состояние ошибки, видимое в UI.
- [ ] при `XDIARY_READPATH_OFFLINE=1` визард открывается, ошибка видна, подстановки нет (проверяет @TE) — **требует прогона `DO-079`**, не закрашен.
- [x] `node --check` по изменённым файлам + строка статуса в чат.
- [x] версия фронта поднята, если поведение меняется для пользователя (`APP_VERSION` ↔ `CACHE`).

## Результат

Реализовано в `0.92`.

**В `repository.js` `catch`-блоков нет вообще** (`git grep -n 'catch' -- 8-front/js/repository.js` → пусто), поэтому молчаливые потери были в вызывающем коде — `app.js`.

Добавлен видимый индикатор сбоя чтения: `showReadError(text)` — красный баннер `role="alert"` сверху экрана с кнопкой закрытия, дублируется в `console.error("read-path:", …)`; `hideReadError()` снимает его при успешном чтении.

Закрыты молчаливые `catch` на read-path:

- `loadWizardData()` — каждый из четырёх источников (партнёры, последняя запись, места, каталог) при сбое попадает в `readError[]`, а не гаснет; отказ промиса тоже возвращает деградированные данные, а не роняет цепочку.
- `reportReadFailure(data)` — если что-то не загрузилось, показывает «Не удалось загрузить: <список>. Данные могут быть неполными.», иначе снимает баннер.
- `openWizardDegraded(e)` — гарантирует инвариант (а): визард **открывается** даже при полном отказе, с пустыми данными и видимой ошибкой; `draft` создаётся через `newDraft()`, то есть `partner` остаётся пустым → **`.partner-card.selected` = 0**, ложной подстановки нет (инвариант в).
- `reopenWizard()`/`openWizard()` получили `.catch` → `openWizardDegraded` (раньше отказ `DB.getAllPartners()` оставлял пользователя без визарда и без сообщения).
- Метрики дня, метрики за 90 дней (экспорт), соматика за период (экспорт), фантазии в каталоге — вместо `return []` теперь `showReadError(...)` с текстом причины.

Осознанно **не** тронуты: пустые `catch` в миграции IndexedDB (`putPartner`/`putCatalogItem` — это запись, а не read-path, ошибки считаются в счётчике пропусков), `serviceWorker.register`, очистка кэшей при сбросе, `self-status` (там уже есть видимое состояние «—»), `somaticFailed` в детали (уже выставляет видимый флаг).

Проверка: `node --check` → rc=0 для `app.js`; `git grep` по `app.js` на `catch(function () { return [] })` и `return null` → **пусто**; версия `APP_VERSION = "0.92"` ↔ `CACHE = "xdiary-v92"`.
