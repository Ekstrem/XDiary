# FE-043 — read-path: убрать молчаливый `catch` (п.1 `read-paths.md`)

- **Статус:** На проверке
- **Приоритет:** P1
- **Источник:** `04-architecture/read-paths.md` §3 п.1 + `TE-054` (спека написана, включается `XDIARY_READPATH_OFFLINE=1`)
- **Зависимости:** `DO-079` (E2E-прогон вне песочницы), `DO` — добавить `XDIARY_READPATH_OFFLINE=1` в CI-workflow
- **Проверяет:** @AR — артефакт: `8-front/js/app.js` (`showReadError`/`hideReadError`/`reportReadFailure`/`openWizardDegraded`), версия `0.93` / `xdiary-v93`

## Задача

`read-paths.md` §3 п.1: **молчаливый `catch` запрещён** — при недоступном read-path форма должна
показать ошибку, а не подставить данные. Спека `wizard-offline.spec.js` проверяет три инварианта:
(а) визард **открывается**; (б) ошибка **видна** в `#view-wizard`/`#toast`;
(в) **нет ложной подстановки** (`.partner-card.selected` = 0).

## Критерии приёмки (переформулированы `2026-11-05 07:10` по @TE: текстовый счётчик — подсказка, критерий — поведение)

- при `XDIARY_READPATH_OFFLINE=1` **визард открывается** (инвариант «не заблокировать форму из-за read-path»);
- **ошибка видна**: `#toast` или баннер с `role="alert"` (признак отказа отличим от «данных нет»);
- **нет ложной подстановки**: `.partner-card.selected` = 0;
- `node --check` по изменённым файлам; версия фронта поднята, если поведение видно пользователю
  (`APP_VERSION` ↔ `CACHE`).
- **подсказка, не критерий:** `git grep -c 'catch' -- 8-front/js/*.js` — там `catch` в `localStorage`,
  а не в read-path; текстовый счётчик не различает storage и read-path, поэтому приёмка — только по поведению.

## Результат

Реализовано в `0.93`.

**Поправка (замечание @AR 2026-11-07 00:31): раньше здесь было записано «в `repository.js` `catch`-блоков нет вообще», и это неверно.** В `origin` их **три**, но **ни один не глотает ошибку чтения**: `:150` — `markSync` (пустой `catch` вокруг `DB.setMeta`, только метка времени, это не read-path); `:156` — `withCache`: при **пустом** кэше `throw err`, иначе отдаёт кэш и ставит `fresh.fromCache`; `:187` — `retryOnce`: пробрасывает всё, кроме `400`/`404`. Значит молчаливого глотания read-ошибки действительно нет — но **не потому, что «`catch` нет»**, а потому что каждый из трёх либо не про чтение, либо пробрасывает. Молчаливые потери были в вызывающем коде — `app.js`.

Добавлен видимый индикатор сбоя чтения: `showReadError(text)` — красный баннер `role="alert"` сверху экрана с кнопкой закрытия, дублируется в `console.error("read-path:", …)`; `hideReadError()` снимает его при успешном чтении.

Закрыты молчаливые `catch` на read-path:

- `loadWizardData()` — каждый из четырёх источников (партнёры, последняя запись, места, каталог) при сбое попадает в `readError[]`, а не гаснет; отказ промиса тоже возвращает деградированные данные, а не роняет цепочку.
- `reportReadFailure(data)` — если что-то не загрузилось, показывает «Не удалось загрузить: <список>. Данные могут быть неполными.», иначе снимает баннер.
- `openWizardDegraded(e)` — гарантирует инвариант (а): визард **открывается** даже при полном отказе, с пустыми данными и видимой ошибкой; `draft` создаётся через `newDraft()`, то есть `partner` остаётся пустым → **`.partner-card.selected` = 0**, ложной подстановки нет (инвариант в).
- `reopenWizard()`/`openWizard()` получили `.catch` → `openWizardDegraded` (раньше отказ `DB.getAllPartners()` оставлял пользователя без визарда и без сообщения).
- Метрики дня, метрики за 90 дней (экспорт), соматика за период (экспорт), фантазии в каталоге — вместо `return []` теперь `showReadError(...)` с текстом причины.

Осознанно **не** тронуты: пустые `catch` в миграции IndexedDB (`putPartner`/`putCatalogItem` — это запись, а не read-path, ошибки считаются в счётчике пропусков), `serviceWorker.register`, очистка кэшей при сбросе, `self-status` (там уже есть видимое состояние «—»), `somaticFailed` в детали (уже выставляет видимый флаг).


**Сверка с `wizard-offline.spec.js` (её прочитал, хотя запустить не могу — Playwright в песочнице недоступен).** Спека ищет признак отказа так: `page.locator('#toast, #view-wizard').filter({ hasText: /(не удалось|ошибк|нет связи|офлайн|offline)/i })`. Первая версия баннера вешалась на `document.body` — под этот селектор она **не попадала**, то есть спека упала бы на утверждении 2 при формально правильном поведении. Исправлено в `0.93`: баннер вставляется в `#view-wizard` (если эта вьюха видима, иначе — в `body`), плюс `toast(text, 6000)` как немедленный сигнал. Дополнительно важен **порядок**: `reportReadFailure()` вызывается **после** `renderWizard()`, иначе `innerHTML` шага сносил баннер. Логика ловится статически: `loadWizardData` собирает `readError[]` из `DB.getAllPartners()` (это `Api.partners.list()`, то есть запрос, который спека и обрывает через `page.route('**/api/v1/partners**')`), `Api.journal.recent()`, `Api.journal.places()`; `.partner-card.selected` остаётся 0, потому что `draft.partner` берётся только из успешно прочитанного `recent.lastPartner`.

Проверка: `node --check` → rc=0 для `app.js`; `git grep` по `app.js` на `catch(function () { return [] })` и `return null` → **пусто**; версия `APP_VERSION = "0.93"` ↔ `CACHE = "xdiary-v93"`.
