## Задача (зона @FE, `8-front/`)

`afterAuth()` вызывал `Api.clients.me()` под таймаутом 2500 мс, и **любой** исход ошибки обрабатывался одинаково:

```js
withTimeout(Api.clients.me(), 2500, null).then(function (c) { … openOnboarding(); })
  .catch(function (e) { console.error("afterAuth/me:", e); openOnboarding(); });
```

Следствия:
1. **таймаут** даёт `c === null` → `openOnboarding()` **молча** (ни тоста, ни причины);
2. **5xx/нет связи** → тот же молчаливый онбординг;
3. **404 на `/clients/me`** → тоже молча (а в E2E это выглядит как «вход не завершился, Тост=""»).

Пользователь с живой сессией видит экран «введи телефон», хотя проблема — сеть/сервер. Для E2E это делало неотличимыми «стенд не готов» и «приложение сломано».

**Правка:** различаем классы ошибок:
- `c === null` (таймаут) → `forceVisibleScreen("afterAuth/me: таймаут")` — видимый экран + сообщение;
- `e.status` нет / `0` / `>= 500` → `forceVisibleScreen("afterAuth/me: HTTP N")` — видимая ошибка, а не онбординг;
- `404` → онбординг **с сообщением** («Профиль не найден на сервере — заполните заново»);
- `401`/остальное — прежний штатный путь (`openOnboarding`).
- Плюс правдивость текста: `forceVisibleScreen` обещал «нажмите «Повторить»», но такой кнопки в UI **нет** (`grep "Повторить"` по `index.html` — 0), текст заменён на «Проверьте сеть и обновите страницу».

## Критерии приёмки

- [x] Таймаут `me()` не открывает онбординг молча — видимый экран и сообщение;
- [x] 5xx/нет связи — видимая ошибка (`forceVisibleScreen`), онбординг не подменяет диагноз;
- [x] 404 — онбординг с явным сообщением пользователю (не пустой тост);
- [x] Штатный путь (нет токена/clientId, 401) не изменён;
- [x] Текст сообщения не обещает элементов, которых нет в UI;
- [x] Тест: `node 5-tech-backlog/front-end/FE-052-afterauth-error-test.js` → **9/9, rc=0**, с **двумя** негативными контролями (убрать ветку таймаута / ветку 5xx ⇒ проверки падают);
- [x] `node --check` rc=0; версия в паре `0.117` ↔ `xdiary-v117`.

## Результат

**Сделано в `0.117`/`xdiary-v117`.** `afterAuth()` больше не сводит все ошибки к молчаливому онбордингу: таймаут и 5xx/сеть дают `forceVisibleScreen` (видимый экран + сообщение), 404 — онбординг с текстом «Профиль не найден на сервере — заполните заново», 401 и отсутствие токена — прежнее поведение. Текст `forceVisibleScreen` приведён в соответствие с UI (кнопки «Повторить» не существует — обещаем «обновите страницу»).
