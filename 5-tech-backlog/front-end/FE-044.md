# FE-044 — read-paths §3 п.2: «данные могли устареть» для кэша партнёров/каталога

- **Статус:** На проверке
- **Приоритет:** P2
- **Источник:** `04-architecture/read-paths.md` §3 п.2 + §5 (п.2 «не покрыто»)
- **Зависимости:** `FE-043` (п.1 — видимые ошибки), `TE-057` (машинная проверка)
- **Проверяет:** @AR — артефакт: `8-front/js/repository.js` (`withCache`, `readFreshness`, `STALE_AFTER_HOURS`), `8-front/js/app.js` (`showStaleNote`), версия `0.94` / `xdiary-v94`

## Задача

`read-paths.md` §1 требует, чтобы **смешанная свежесть была названа**: если данные партнёров или каталога
взяты из кэша и `lastSync` старше N часов, экран обязан показать «данные могли устареть», а не
выдавать кэш за свежие данные.

Сейчас (§5) этот пункт **не покрыт** ни одним тестом — то есть правило заявлено, но не проверяется.

## Критерии приёмки

Порог назван константой: **`STALE_AFTER_HOURS = 24`** (в `repository.js` и `app.js` — `STALE_AFTER_HOURS_UI`).

- [x] при `lastSync` старше порога на экранах, читающих партнёров/каталог, виден признак устаревания — элемент **`id="stale-note"`, `class="stale-note"`, `role="status"`** внутри `#view-wizard` / `#view-partners` / `#view-catalog`; текст «данные могли устареть — синхронизированы N ч назад»;
- [x] при свежих данных признака **нет** — бейдж приходит только при `fromCache` и снимается на свежих live-данных (иначе он станет постоянным шумом);
- [x] `node --check` по изменённым файлам; версия поднята (`0.94` ↔ `xdiary-v94`);
- [x] строка `→ @TL` с id/классом признака — для @TE (см. чат); прогон — за `DO-079`/`TE-054`-**новой** карточкой, здесь не закрашиваю.

## Результат

Реализовано в `0.94`.

**`repository.js`** — источник правды о свежести:
- `STALE_AFTER_HOURS = 24` — порог;
- `markSync(kind)` пишет `syncAt.<kind>` в `meta` при **успешном живым** чтении партнёров/каталога;
- `withCache(kind, live, cached)` — обёртка: при успехе помечает синхронизацию и сбрасывает признак; при отказе живого чтения берёт копию из IndexedDB (`DB.rawPartners`/`DB.rawCatalog`) и запоминает `{ fromCache: true, ageMs }`; если копии нет — пробрасывает ошибку (то есть поведение `FE-043` не ломается);
- `DB.readFreshness(kind)` — точка чтения для UI.

**`app.js`** — наблюдаемый признак:
- `showStaleNote(viewId, kinds)` — бейдж **внутри вьюхи** (`#view-wizard`, `#view-partners`, `#view-catalog`), `id="stale-note"`, `class="stale-note"`, `role="status"`, текст «данные могли устареть — синхронизированы N ч назад»; если данных из кэша нет — бейдж **снимается**;
- вызван после отрисовки в визарде (`openWizard`, `reopenWizard`, `openWizardDegraded`), в `renderPartners` и в `renderCatalog` — то есть на всех трёх экранах, читающих партнёров/каталог.

Осознанное решение: признак привязан к **факту чтения из кэша**, а не к «сегодняшней дате в `meta`». Иначе на уже существующих устройствах `syncAt` отсутствовал бы, бейдж появлялся бы на свежих live-данных и превратился бы в шум — ровно то, против чего второй критерий.

Честная граница: живого кэш-пути до этого фикса **не было** (`getAllPartners`/`getAllCatalog` всегда шли в API), поэтому «данные могли устареть» до сих пор не мог показаться ни при каких условиях — то есть п.2 был не «не покрыт тестом», а **не реализован**. Теперь кэш используется как деградация, и его возраст называется явно.

Проверка: `node --check` → rc=0 для `app.js` и `repository.js`; статически проверены три точки вызова `showStaleNote` и `id`/`class` бейджа; версия `0.94` ↔ `xdiary-v94`.
