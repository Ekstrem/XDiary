# FE-021: Новое устройство уходит на PIN-экран вместо онбординга

- **Статус:** Закрыта
- **Приоритет:** P1 (UX-блокер: новый пользователь не видит «телефон → OTP»)
- **Источник:** @TE 2026-11-04 (находка на `0.50`: `onboarding` — `#view-onboarding` hidden), @TL 23:00
- **Зависимости:** FE-018, FE-020
- **Проверяет:** @TL (TechLead)

## Проблема
На чистом устройстве (нет локального PIN, нет `xdiary.clientId`/`xdiary.legacy`) `lock()` пробовал `Api.auth.login("")`; на стенде с PIN это **401** → `showLockScreen()` → **PIN-экран**. Онбординг «телефон → SMS OTP» недостижим для нового пользователя.

## Задача
- `lock()`: чистое устройство → сразу `openOnboarding()` (без device-токена и PIN-экрана).
- «Пропустить» в онбординге → ставит `xdiary.legacy` + берёт device-токен (если есть) → журнал.

## Критерии приёмки
- [x] Чистое устройство → `#view-onboarding` (`#onb-phone` виден).
- [x] «Пропустить» → `#view-journal`.
- [x] Версия `0.51`/`v51`.

## Результат
- `8-front/js/app.js` `lock()`: `Pin.hasPin()` → PIN-экран (legacy с PIN); нет PIN и нет clientId/legacy → `openOnboarding()`; clientId/legacy → `afterAuth()`.
- «Пропустить»: `markLegacy()` + `Api.auth.login("")` → журнал.
- Версия `0.51`/`v51`.
