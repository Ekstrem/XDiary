# FE-057 — P1: в настройках нет диалога ввода токена Garmin; «Из Garmin» не запускает серверную синхронизацию

- **Статус:** На проверке
- **Приоритет:** **P1** — владелец 2026-11-20: без подключения по токену соматика вводится только CSV-файлом, интеграция с Garmin не работает
- **Источник:** владелец 2026-11-20 (скриншоты настроек/«Импорт Garmin»); **уточнение владельца 2026-11-23:** у пользователя **один токен**, по которому сервис регулярно получает другой; CSV-файлов «не будет вообще»; из настроек убрать «Сменить я», «Сервер» и CSV-упоминания
- **Зависимости:** `AR-163` (канвас: Connect = ввод токена, серверный прокси), `BE-142` (контракт `/api/v1/garmin/connect` + `/sync`; **требуется приём одного токена**), `G-06` (статус-бар синка)
- **Проверяет:** @TL
- **Исполняет:** @FE (`8-front/`)
- **В работе с:** 2026-11-21
- **На проверке с:** 2026-11-23

## Предусловие (контракт в Gravitee)
Работать по **опубликованному контракту** (Gravitee, после DO-155), а не по сообщениям чата: AR-163 (api-index) -> BE-142 (спека) -> DO-155 (публикация). До публикации можно готовить форму по `06-connect-contract.md` @AR, финальные поля/коды сверять с Gravitee.

## Задача
1. **Настройки → Соматика (Garmin):** кнопка/диалог **«Подключить Garmin»** — **одно поле токена** + **опциональная дата экспирации**; `POST /api/v1/garmin/connect` (токен уходит на сервер, в браузере не хранится).
2. **Журнал → кнопка «Из Garmin»:** запускает серверный sync (`POST /api/v1/garmin/sync` → `fetch-activities`) и обновляет журнал, **а не** открывает CSV-диалог.
3. Показать состояние подключения: подключён/истёк токен (`GET /api/v1/garmin/state`, `ReauthOnExpiry`) + статус синка.
4. **Очистка Настроек (владелец 2026-11-23):** убрать блок «Это я» (`Сменить «я»`/`Снять «я»`), блок «Сервер» и **все CSV-упоминания/кнопки**; CSV-импорт не восстанавливать.

## Критерии приёмки
- В настройках диалог с **одним** полем токена и опциональной экспирацией; после сохранения `GET /state` показывает подключение.
- «Из Garmin» вызывает `/garmin/sync` (не `file input`), данные обновляются.
- В настройках нет «Сменить я», «Сервер», CSV-кнопок и слова CSV.
- Истёкший токен даёт понятное сообщение, а не пустой экран.
- Структурный тест падает при возврате второго поля/CSV-кнопки.

## Результат

**Сделано (FE), PR #3286, версия `0.125` / `xdiary-v125`:**

- `garmin.connect/state/sync/fetchActivities` в `8-front/js/api.js`;
- диалог: **одно** поле `garmin-token` (type=password) + `garmin-token-expiry`; payload `{credentials:{oauthToken, tokenExpiry?}}` — без `apiKey` (он серверный, не пользовательский);
- журнал: «Из Garmin» → `sync` → `fetchActivities` → `renderJournal`;
- `requiresReauth` → повторный Connect с текстом об истёкшем токене; коды `validation_error` / `not_connected` / `token_expired` / `upstream_unavailable`;
- из Настроек убраны «Это я», «Сервер», CSV-экспорт/импорт и CSV-кнопка Garmin; экран `view-import` удалён;
- структурный тест: **36/36 OK**, включая негативные контроли (второй токен, CSV-кнопка, отсутствие `requiresReauth`).

**Граница / блокер:** текущий `BE-142` (`CredentialsDto`) требует **и `ApiKey`, и `OauthToken`**; по требованию владельца FE отправляет только `oauthToken`, поэтому до правки @BE (сделать `apiKey` серверным/опциональным) сервер вернёт `validation_error`. Нужна задача @BE на контракт одного токена.
