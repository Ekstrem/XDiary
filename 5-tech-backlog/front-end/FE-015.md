# FE-015: Визард делает 3× `/partners` + 2× `/journal` на одну форму

- **Статус:** На проверке
- **Приоритет:** P1 (перф: открытие визарда — несколько секунд)
- **Источник:** @FE `chat/fe.md` 2026-11-03 11:00 (перф-проблема от PO)
- **Зависимости:** BE-025 (лёгкий эндпоинт)

## Проблема (по коду)
- `app.js:339` `openWizard(null)` → `DB.getAllRecords()` (= `GET /partners` + `GET /journal`);
- шаг «С кем?» (`app.js:398-399`) повторяет — итого **3× `/partners` + 2× `/journal`** на одну форму.

## Задача
- Убрать дубли: кэшировать партнёров/журнал на время визарда, не грузить весь журнал.
- После BE-025 — использовать лёгкий эндпоинт дефолтов (последний партнёр/история мест).
- Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [x] Один визард = ≤1 `/partners` + ≤1 `/journal` (кэш на время визарда).
- [ ] Открытие визарда < 1с на dev (проверит @TE).
- [x] Версия забампана (`0.36`/`v36`); CI — прогон @TE.

## Результат
- `8-front/js/repository.js`: `DB.getAllJournalData()` — 1× `/partners` + 1× `/journal` за один вызов.
- `8-front/js/app.js`: кэш `wizardPartners`/`wizardRecords` на время визарда (`loadWizardData()`); шаги partner/place/positions/marks/contraception читают из кэша и больше не дёргают API на каждый шаг/перерисовку; кэш сбрасывается на save/delete/close.
- Было: ~4× `/partners` + ~5× `/journal` на визард (openWizard + stepPartner + stepPlace + stepPositions + stepMarks + stepContraception). Стало: **1× + 1×**.
- Версия `0.36`/`v36`.
