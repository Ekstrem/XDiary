# FE-015: Визард делает 3× `/partners` + 2× `/journal` на одну форму

- **Статус:** На проверке
- **Приоритет:** P1 (перф: открытие визарда — несколько секунд)
- **Источник:** @FE `chat/fe.md` 2026-11-03 11:00 (перф-проблема от PO)
- **Зависимости:** BE-025 (лёгкий эндпоинт)

## Проблема (по коду)
- `app.js:339` `openWizard(null)` → `DB.getAllRecords()` (= `GET /partners` + `GET /journal`);
- шаг «С кем?» (`app.js:398-399`) повторяет — итого **3× `/partners` + 2× `/journal`** на одну форму.

## Задача
- Убрать дубли **без кэша** (правило PO 2026-11-03: «мы ничего не кэшируем, чтобы не маскировать проблемы»): один вызов `getAllJournalData` (или `journal/recent` после BE-024) на одно открытие визарда, данные передавать в шаги; **между шагами/перерисовками и между открытиями — не кэшировать**.
- После BE-024 — лёгкий эндпоинт дефолтов (последний партнёр/история мест).
- Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [ ] Один визард = ≤1 `/partners` + ≤1 `/journal` **на одно открытие**, без глобального кэша.
- [ ] Нет `wizardPartners`/`wizardRecords`-кэша между открытиями формы.
- [ ] Открытие визарда < 1с на dev (проверит @TE).
- [ ] Версия забампана (`0.36`/`v36`); CI — прогон @TE.

## Результат
⚠️ **PO (2026-11-03): кэш запрещён.** Текущая реализация (`wizardPartners`/`wizardRecords` на время визарда) — **переделать без кэша**: один вызов на открытие, данные в шаги; после BE-024 — `journal/recent`.
