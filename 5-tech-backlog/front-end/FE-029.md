# FE-029: Экран блокировки показывается, когда PIN отсутствует — лок-гейт не сверяется с `hasPin()`

- **Статус:** ToDo
- **Приоритет:** P0 (блокирует релиз: 2 из 5 падений в `front-e2e`)
- **Источник:** @DO 2026-11-02 19:45 — прогон `#951` (`c83989b`): `wizard-record` и `remove-pin`
- **Зависимости:** FE-025/FE-027 (лок-гейт, `withTimeout`), BE-040 (401 на `/me` — устранён)
- **Проверяет:** @TL (TechLead)

## Факт (из `#951`, аннотации `dumpViews`)
1. **`wizard-record`**: `loginWithPin` отработал, но состояние экранов —
   `{"view-lock":true,"view-onboarding":false,"view-journal":false,"view-partners":false,"view-catalog":false,"view-settings":false,"view-wizard":false}` — приложение осталось на экране блокировки.
2. **`remove-pin`**: API-негатив прошёл (`pin/remove` без `currentPin` = **401**, корректно), но `hasPin(page)` вернул **false**, хотя тест ожидал «PIN на месте после неудачного снятия» → `Expected true, Received false`.
3. **Противоречие (1)+(2):** экран `view-lock` показан, хотя `Pin.hasPin()` = **false**. Значит **показ лок-экрана не сверяется с фактическим наличием PIN**.
4. `pageerror` = 0, из UI-потока нет ни одного 4xx/5xx (единственная сетевая ошибка — `somatic-series/slice` `net::ERR_FAILED`, она в других спеках). То есть падения **не из-за ответов API**, а из-за состояния приложения.

## Задача
1. Привести лок-гейт к одному источнику правды: экран блокировки показывается **только** если `Pin.hasPin()` = true; нет PIN — сразу онбординг/журнал (по наличию client-JWT), без промежуточного замка.
2. Проверить путь `init() → showView("lock") → lock()`: синхронный показ замка (страховка FE-022) не должен оставаться финальным состоянием, если PIN нет. Явно логировать в `console` причину, по которой показан замок (`hasPin`, `token`, `clientId`).
3. Снять `dumpViews`-снимок до/после входа **в проде-коде не нужно** — это тестовая фикстура; но состояние экранов должно быть однозначным.
4. Не ломать FE-027 (`withTimeout`) и FE-028 (refresh).

## Критерии приёмки
- [ ] `Pin.hasPin()` = false ⇒ в DOM **никогда** нет видимого `#view-lock` (проверяется спекой `remove-pin`).
- [ ] После `loginWithPin` с валидным PIN и client-JWT открыт журнал (спека `wizard-record`).
- [ ] В консоли при показе замка есть строка-обоснование.
