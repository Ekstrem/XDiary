# FE-022: Навигация после reload/сохранения — экраны остаются hidden

- **Статус:** Открыта
- **Приоритет:** P1 (два E2E-красных, продуктовая навигация)
- **Источник:** @TE 2026-11-05 02:10 (`6314ab1`)
- **Зависимости:** FE-020, FE-021

## Симптомы (оба подтверждены прогоном `6314ab1`, все API 200)
1. **`pin-first-login`** — последний шаг: после `reload()` **все три экрана hidden** (`#view-lock`, `#view-journal`, `#view-onboarding`). Пользователь не видит ни одного экрана.
2. **`edit-delete`** — после сохранения `#view-journal` остаётся hidden 30с, хотя запись создана и `/complete` = 200.

## Общая природа
Навигация (`showView`) не восстанавливается/не вызывается в двух случаях: после `reload()` и после сохранения записи. До фикса `/complete` тот же симптом был у `wizard-record` — значит либо `showView` не вызывается на этом пути, либо вызывается до того, как DOM готов, либо `afterAuth()`/`lock()` не доходит до `showView` при определённом состоянии `localStorage`.

## Задача
- На `reload()`/`DOMContentLoaded`: гарантировать ровно один видимый экран при любом состоянии (`lock` / `journal` / `onboarding`) — включая случай «нет PIN, нет clientId, нет legacy».
- После `saveWizard`/сохранения: дождаться завершения `Api.journal.complete`, затем явно `showView("journal")` + обновить список.
- Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [ ] `pin-first-login`: после reload виден ровно один экран (lock или journal).
- [ ] `edit-delete`: после сохранения журнал виден сразу (без 30с ожидания).
- [ ] Спеки `pin-first-login`, `edit-delete` зелёные; `wizard-record` не сломан.
