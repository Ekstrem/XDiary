# FE-010: Новый рекорд в визарде уходит в ветку редактирования → 404

- **Статус:** На проверке
- **Приоритет:** P0 (ядро: запись журнала через визард не сохраняется)
- **Источник:** @TE `chat/te.md` 2026-11-02 13:30 (коммит `a675fc7`, живой E2E на dev)
- **Зависимости:** —

## Проблема (по коду)
- `8-front/js/app.js` `saveWizard`: новому черновику присваивается `id: uuid()`.
- `8-front/js/repository.js` `DB.putRecord`: при наличии `rec.id` идёт по **ветке редактирования** — не вызывает `Api.journal.start()`, а делает `Api.journal.get(id)` → **404** (записи с таким id на сервере нет).
- Пользователь видит тост «Ошибка: HTTP 404», журнал не показывается.
- Лог @TE: `200 GET /journal/records | 404 GET /journal/records/<uuid> | 200 GET /journal/records`.

## Задача
- Новый рекорд (ещё без серверного id) **не** получает `uuid()`; идёт через `Api.journal.start()` (POST), id возвращает сервер.
- Ветка редактирования (`Api.journal.get` + update) — только для уже существующих записей с серверным id.
- Проверить соседние пути (`putRecord` для partner/catalog уже чинились в FE-004/TE-012 — не должно сломаться).

## Критерии приёмки
- [x] Новый рекорд через визард сохраняется (`POST …/journal/start`), запись видна в журнале.
- [x] Редактирование существующей записи работает (get/update).
- [ ] Живой E2E `wizard-record` (TE-014) — зелёный (проверит @TE).

## Результат
- `8-front/js/app.js` `saveWizard`: новый рекорд создаётся **без `id`** (`apply({ createdAt: nowIso })`) → `DB.putRecord` идёт через `Api.journal.start()` (POST), id возвращает сервер. Ветка редактирования — только при `editingId` (`rec.id = editingId`).
- `repository.js` не менялся: `var startP = rec.id ? … : Api.journal.start()` — без `rec.id` уже корректно создаёт запись.
- `node --check` OK.
