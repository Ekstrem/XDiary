# FE-026: «Пропустить онбординг» (legacy) больше не даёт данных — нет JWT

- **Статус:** Открыта
- **Приоритет:** P1 (после AR-008/FE-025 «Пропустить» ведёт в пустой журнал с 401)
- **Источник:** разбор `0.59` после FE-025; AR-008
- **Зависимости:** FE-025, BE-036, BE-038

## Проблема
После FE-025 (`0.59`):
- `ensureToken(pin)` **определён, но больше не вызывается** (`app.js:193`);
- путь `xdiary.legacy` → `openJournal()` **без каких-либо токенов** (`app.js:214`, `311`);
- а данные журнала/партнёров/каталога читаются **через API** (`repository.js` проксирует `DB.*` → `Api.journal.*`/`Api.partners.*`).

Следствие: если пользователь нажмёт **«Пропустить»** в онбординге (или у него остался `xdiary.legacy` от прошлых версий), он попадёт в журнал, где:
- каждый запрос → **401** (нет JWT);
- список пуст, ошибок пользователю не объясняют.

Раньше «legacy» работал, потому что device-токен выдавался по PIN (`/privacy/token` + `pin`). Теперь этот путь закрыт (PIN = замок поверх client-JWT).

## Задача (нужно продуктовое решение — см. ниже)
Вариант **A**: **убрать** «Пропустить» и legacy-путь совсем — единственный вход = телефон + OTP.
Вариант **B**: оставить «Пропустить» как **локальный режим** — тогда нужен источник данных: работа только с локальным кэшем IndexedDB, явный баннер «офлайн, данные не синхронизируются», и никаких 401 в консоли (не звать API).
Вариант **C**: «Пропустить» = гость с демо-данными (для показа интерфейса).

Технически:
1. Если A — удалить `btn-onboarding-skip`, `xdiary.legacy`, `markLegacy`, ветки в `lock()`/`afterAuth()`; при отсутствии JWT всегда онбординг.
2. Если B — `repository.js`: при отсутствии токена не ходить в API, отдавать локальный кэш; показать статус «локально».
3. В обоих случаях: **не оставлять пользователя в пустом журнале без объяснения**.

## Критерии приёмки
- [ ] После «Пропустить» (если кнопка осталась) пользователь видит понятное состояние, а не пустой журнал с 401.
- [ ] В консоли нет 401-шторма при отсутствии JWT.
- [ ] E2E: спек `onboarding` + новый кейс «пропуск» отражают выбранное поведение.
