# FE-026: «Пропустить онбординг» (legacy) больше не даёт данных — нет JWT

- **Статус:** На проверке
- **Приоритет:** P1 (после AR-008/FE-025 «Пропустить» ведёт в пустой журнал с 401)
- **Источник:** разбор `0.59` после FE-025; AR-008
- **Зависимости:** FE-025, BE-036, BE-038
- **Проверяет:** @TL (TechLead)

## Проблема
После FE-025 (`0.59`):
- `ensureToken(pin)` определён, но больше не вызывается (`app.js:193`);
- путь `xdiary.legacy` → `openJournal()` **без токенов** (`app.js:214`, `311`);
- а данные журнала/партнёров/каталога читаются **через API** (`repository.js` проксирует `DB.*` → `Api.journal.*`/`Api.partners.*`).

Следствие: «Пропустить» (или оставшийся `xdiary.legacy`) → журнал, где каждый запрос **401**, список пуст, ошибок не объясняют. Раньше «legacy» работал через device-токен по PIN — теперь путь закрыт (PIN = замок поверх client-JWT).

## Задача (продуктовое решение — принято, см. ниже)
Вариант **A**: убрать «Пропустить» и legacy-путь — единственный вход = телефон + OTP.
Вариант **B**: «Пропустить» как локальный режим (IndexedDB-кэш + баннер «офлайн», без API).
Вариант **C**: гость с демо-данными.

## Критерии приёмки
- [x] «Пропустить» убран; пользователь не попадает в пустой журнал с 401.
- [x] В консоли нет 401-шторма: без токена API не вызывается (`openJournal()` при отсутствии токена уводит в онбординг).
- [x] E2E: спек `onboarding` (адаптированный @TE) — зелёный. — проверено @TL: `ci-front` #59 (success), `front-e2e-repeat` #8 (20/0 на грязном стенде), `#10`/`#11` success

## Решение TL (2026-11-06 00:10) — вариант A, временный фикс сломанного состояния
Обоснование: (1) @FE и TL независимо рекомендуют A; (2) текущее поведение **сломано** (пустой журнал + 401) — хуже отсутствующей кнопки; (3) C не подходит для приватного дневника, B — вне текущей фазы. Решение **обратимо** (кнопку легко вернуть как офлайн-режим).
