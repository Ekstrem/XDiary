# FE-027: Приложение застревает на экране блокировки, если `Pin.hasPin()`/`clients.me()` не отвечают

- **Статус:** На проверке
- **Приоритет:** P0 (блокирует `front-e2e`: 16 из 18 спеков красные; блокирует прод)
- **Источник:** @DO 2026-11-06 22:55 — `front-e2e` `#919` (`29cdb2e`): 16 failed / 2 passed, «после логина приложение остаётся на экране блокировки»
- **Зависимости:** FE-025 (PIN — замок поверх client-JWT), BE-038 (JWT), TE-032 (`seedSession`)
- **Проверяет:** @TL (TechLead)

## Факт (из логов E2E)
```
wizard-record: виды после логина: {"view-lock":true,"view-journal":false,"view-onboarding":false}
catalog / csv / edit-delete / settings / somatic-detail / trends: #view-journal hidden, toBeVisible() падает 14–44 раза
onboarding / partner-edit / pin-first-login: page.click — Test timeout 90s
```
То есть после установки `xdiary.clientId` + `xdiary.accessToken` (fixtures `seedSession`) приложение **остаётся на `#view-lock`** и никуда не уходит.

## Разбор кода (TL)
`init()` (`8-front/js/app.js:2110`) синхронно вызывает `showView("lock")` — это страховка FE-022 «всегда виден экран». Дальше в конце `init()` вызывается `lock()` (L2259), а он:

```js
function lock() {
  var hasClient = !!localStorage.getItem("xdiary.clientId") && !!Api.config.token();
  if (!hasClient) { openOnboarding(); return; }
  Pin.hasPin().then(function (hasPin) {
    if (hasPin) { showLockScreen(); return; }
    afterAuth();                     // → Api.clients.me() → openJournal()/openOnboarding()
  }, function () { openOnboarding(); });
}
```

Проблема: **весь маршрут «lock → экран» держится на двух промисах, у которых нет таймаута и нет ветки «ничего не ответило»**:
- если `Pin.hasPin()` (`DB.getMeta("pin")`, IndexedDB) не резолвится — экран остаётся `lock` навсегда;
- если `Api.clients.me()` висит — то же самое;
- `afterAuth()` обрабатывает только `then`/`catch`, но не «слишком долго».

Итог: пользователь (и спеки) видят замок, за которым ничего не происходит, без объяснения. Это же объясняет жалобу владельца «в интерфейсе нет идентификации, вижу PIN».

## Задача (фронт, зона @FE)
1. **Таймауты с внятным исходом:** `Pin.hasPin()` и `Api.clients.me()` — обернуть в таймаут (например 5 с). По таймауту: уйти в `openOnboarding()` + показать `toast`/строку статуса («не удалось проверить сессию, войдите заново»), **не оставлять пользователя на пустом замке**.
2. **Страховка в `ensureView()`:** если через N секунд после старта видим только `view-lock`, а сессии нет — перейти в онбординг (аналог FE-022, но для асинхронной ветки).
3. **Диагностируемость:** при ошибке `me()` писать в консоль причину (статус/текст), чтобы E2E-лог сразу показывал «401/500/таймаут», а не «журнал скрыт».
4. Не ломать FE-025/FE-026: PIN остаётся локальным замком **после** client-JWT; без JWT — онбординг.
