# FE-041: «удалённый партнёр» в журнале вместо пустого места (последствие мягкого удаления)

- **Статус:** На проверке
- **Приоритет:** P2 (не блокирует запуск, но пользователь прочитает пустое место как потерю данных)
- **В работе с:** 2026-11-16
- **Источник:** @AR 2026-11-13 13:25 + `03-ddd/BC-Partners/02` §11 (инвариант `HistoryStaysResolvable`): журнал хранит **только `id`** партнёра (`BC-Journal/02` §2.4), имена резолвит фронт через `GET /partners`; после мягкого удаления `GET /partners` удалённого **не отдаёт**, `GET /partners/{id}` → **404** → имя взять неоткуда
- **Зависимости:** `BE-055` (soft-delete), вариант (б) — проекция-справочник в E1
- **Проверяет:** @TL (фронт) — артефакт `de7cd0e1`: `8-front/js/repository.js`, `8-front/js/app.js`, версия `0.89` / `xdiary-v89`

## Задача (зона @FE, `8-front/`)

При отрисовке записи журнала имя участника берётся по цепочке `BC-Journal/02` §2.7 (справочник `partners_directory` → **успешно загруженный** список `GET /api/v1/partners` → заглушка) и различает **три исхода** — они не равны друг другу:

| Что известно | Что показываем | Почему |
|---|---|---|
| строка есть, `deletedAt != null` | **«👤 удалённый партнёр»** | это **факт из данных**, а не догадка |
| строка есть, `deletedAt == null` | имя | нормальный случай |
| нигде не найдено (проекция/список отстали) | **«участник недоступен»** | «не найден» ≠ «удалён»: выдавать удаление там, где мы не знаем, — соврать пользователю и спрятать настоящий дефект |

Правило одной строкой: **«удалён» — это факт из данных, а не значение по умолчанию.** Ни в одном из трёх случаев не показывается пустое место, сырой `id` или «undefined».

## Критерии приёмки

- [x] Запись с партнёром, у которого `deletedAt != null`: вместо имени — **«👤 удалённый партнёр»**, запись не ломается и не «худеет».
- [x] Запись с участником, которого **нет ни в справочнике, ни в списке** (проекция отстала): **«участник недоступен»**, а **не** «удалённый» — иначе UI утверждает удаление, которого не знает.
- [x] Запись с несуществующим `id` (мусор в данных) — тот же фолбэк «участник недоступен», без падения.
- [x] `grep` по `8-front/js` не содержит обращений к `GET /partners/{id}` для резолва имён (только список).
- [ ] Проверено на dev с реально удалённым партнёром (сценарий: создать → записать акт → удалить партнёра → открыть журнал).
