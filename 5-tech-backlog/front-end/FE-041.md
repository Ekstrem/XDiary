# FE-041: «удалённый партнёр» в журнале вместо пустого места (последствие мягкого удаления)

- **Статус:** На проверке
- **Приоритет:** P2 (не блокирует запуск, но пользователь прочитает пустое место как потерю данных)
- **В работе с:** 2026-11-16
- **Источник:** @AR 2026-11-13 13:25 + `03-ddd/BC-Partners/02` §11 (инвариант `HistoryStaysResolvable`): журнал хранит **только `id`** партнёра (`BC-Journal/02` §2.4), имена резолвит фронт через `GET /partners`; после мягкого удаления `GET /partners` удалённого **не отдаёт**, `GET /partners/{id}` → **404** → имя взять неоткуда
- **Зависимости:** `BE-055` (soft-delete), вариант (б) — проекция-справочник в E1

## Задача (зона @FE, `8-front/`)

При отрисовке записи журнала: если `id` участника **не найден** в ответе `GET /api/v1/partners` — показывать **«удалённый партнёр»** (не пустое место, не сырой `id`, не «undefined»). Остальные участники отрисовываются как обычно.

## Критерии приёмки

- [x] Запись с удалённым партнёром: вместо имени — **«удалённый партнёр»**, запись не ломается и не «худеет».
- [x] Запись с несуществующим `id` (мусор в данных) — тот же фолбэк, без падения.
- [x] `grep` по `8-front/js` не содержит обращений к `GET /partners/{id}` для резолва имён (только список).
- [ ] Проверено на dev с реально удалённым партнёром (сценарий: создать → записать акт → удалить партнёра → открыть журнал).
