# FE-002: Аутентификация JWT на фронте

- **Статус:** Закрыта
- **Приоритет:** P0
- **Источник:** ADR-008, US-11
- **Зависимости:** BE-010, BE-012

## Задача
Подключить аутентификацию на фронте:
- Логин → получение JWT (access + refresh).
- Хранение токенов, отправка `Authorization: Bearer` на шлюз.
- Refresh при истечении access.
- Локальный PIN остаётся как доп. слой блокировки приложения.

## Критерии приёмки
- [x] Все запросы к API идут с JWT.
- [x] При 401 — перевыпуск по refresh (без потери сессии).
- [x] PIN (PBKDF2) работает локально как раньше.
- [x] Logout очищает токены.

## Заметки исполнителя (front-end)
- Реализовано: `8-front/js/api.js` (`Api.auth.login/refresh/logout`, `Api.privacy`, `Authorization: Bearer`, refresh-на-401) + `8-front/js/app.js` (`ensureToken` на unlock, синк бэк-PIN на set, `Api.auth.logout()` на removePin/wipe).
- Контракт (BE-014, DDD `03-ddd/BC-Privacy`): `POST /api/v1/privacy/token` `{pin}` → `{accessToken, refreshToken}`; `POST /verify-token` `{token}` → bool. Refresh-эндпоинта нет — при 401 подставляю refresh-токен (30 дней, тоже валидный JWT) как Bearer.
