# FE-002: Аутентификация JWT на фронте

- **Статус:** В работе
- **Приоритет:** P0
- **Источник:** ADR-008, US-11
- **Зависимости:** BE-010, BE-012

## Задача
Подключить аутентификацию на фронте:
- Логин → получение JWT (access + refresh).
- Хранение токенов, отправка `Authorization: Bearer` на шлюз.
- Refresh при истечении access.
- Локальный PIN остаётся как доп. слой блокировки приложения.

## Критерии приёмки
- [ ] Все запросы к API идут с JWT.
- [ ] При 401 — перевыпуск по refresh (без потери сессии).
- [ ] PIN (PBKDF2) работает локально как раньше.
- [ ] Logout очищает токены.

## Заметки исполнителя (front-end)
- Клиентская часть готова в `8-front/js/api.js`: хранение access/refresh (localStorage), `Authorization: Bearer`, refresh-на-401 (перевыпуск + повтор запроса), logout (очистка токенов), `Api.auth.login/refresh/logout`.
- Блокер: в бэке нет выпуска JWT — BE-010 заявлен `POST /token` + `TokenService`, но в коде `6-msa/BC-Privacy` их нет (только PIN). Эскалировано @BE/@TL; контракт refresh уточняется.
