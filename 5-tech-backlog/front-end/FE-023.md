# FE-023: Нет входа в идентификацию с устройства, где уже стоит legacy/clientId

- **Статус:** Открыта
- **Приоритет:** P1 (блокирует ручное тестирование идентификации владельцем)
- **Источник:** владелец 2026-11-05: «обновляю фронт и не вижу идентификации»
- **Зависимости:** FE-020, FE-021

## Проблема
Онбординг (идентификация: телефон → OTP → привязка) открывается **только на «чистом» устройстве** — когда нет локального PIN, нет `xdiary.clientId`, нет `xdiary.legacy` (`lock()` → `openOnboarding()`, `app.js` ~L300-305).

Если на устройстве уже стоит `xdiary.legacy` или `xdiary.clientId` (после прежних прогонов/тестов), приложение уходит в журнал и **никакого способа попасть в идентификацию из UI нет**:
- в Настройках нет «Пройти идентификацию»;
- нет «Выйти / сменить устройство» (сброс `clientId`/`legacy`/токена);
- онбординг-экран существует (`#view-onboarding`, `onb-phone`/`onb-otp`/`onb-link`), но недостижим вручную.

Итог: владелец обновляет фронт, видит журнал/PIN и делает вывод «идентификации нет», хотя она есть — просто недостижима.

## Задача
- В **Настройках** добавить блок «Идентификация»: текущий статус (`clientId`/`phone`, `verified`, `linkedPartnerId` — данные уже есть в `Api.clients.me()`), кнопки:
  - **«Пройти идентификацию»** → `openOnboarding()` (для неидентифицированного устройства);
  - **«Выйти (сбросить устройство)»** → очистка `xdiary.clientId`, `xdiary.legacy`, токена, при необходимости IndexedDB/PIN — с подтверждением, затем `lock()`.
- Показывать «кто я» из `Api.clients.me()` (сейчас в настройках есть `renderSelfStatus()` — использовать его же).
- Не ломать сценарий пары: «Выйти» не должен удалять записи партнёров (только локальное состояние устройства).
- Поднять версию.

## Критерии приёмки
- [ ] На устройстве с `legacy`/`clientId` из Настроек можно открыть идентификацию.
- [ ] «Выйти» сбрасывает устройство и возвращает на онбординг/PIN, не удаляя данные на сервере.
- [ ] На чистом устройстве поведение не изменилось (сразу онбординг).
- [ ] E2E: новый спек «вход в идентификацию из настроек» + существующие `onboarding`/`pin-first-login` зелёные.
