# FE-018: Онбординг «кто я» + опциональный PIN (AR-004, ADR-021)

- **Статус:** Открыта
- **Приоритет:** P1 (Фаза 1: идентификация/аутентификация)
- **Источник:** AR-004 → P1 (@AR 2026-11-04 00:00); ADR-021 (пересмотрен 02:30: многопользовательская, номер телефона + SMS OTP)
- **Зависимости:** BE-029 (BC «Клиент»), BE-028 (self → Partner.clientId)

## Контекст
Фаза 1. **ADR-021 пересмотрен (2026-11-04):** онбординг = **номер телефона + SMS OTP** (BC «Клиент», 11-й), «я» = **`Partner.clientId`** (партнёр с `clientId == текущий Client`). PIN остаётся в Privacy (ADR-008). Старый `view-onboarding` («кто ты = партнёр», `0.43`) — **каркас**, не откатывать.

## Задача
- Первый запуск: онбординг — **телефон → SMS OTP** → JWT клиента (`POST /clients`, `/verify`).
- После верификации — **привязка партнёра-я** (`/link-partner`), «я» = `Partner.clientId`.
- PIN — **опция** (можно пропустить).
- Настройки: профиль клиента / «это я».
- Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [ ] Новый пользователь: телефон → OTP → JWT клиента → link-partner → «я» определяется по clientId.
- [ ] «я» переживает перезагрузку (сервер, не локально).
- [ ] PIN можно не задавать.
- [ ] Версия забампана; E2E (TE-025) зелёный.

## Результат (частично — каркас)
- `0.43`/`v43`: реализован старый онбординг «кто ты = партнёр» (`view-onboarding`, `partners.setSelf`, «Это я»). По пересмотренному ADR-021 **не откатывается** — используется как каркас для шага «телефон + SMS OTP». Переработка — после **BE-029** (BC «Клиент») + **BE-028** (self → `Partner.clientId`).
