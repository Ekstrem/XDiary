# FE-018: Онбординг «кто я» + опциональный PIN (AR-004, ADR-021)

- **Статус:** На проверке
- **Приоритет:** P1 (Фаза 1: идентификация/аутентификация)
- **Источник:** AR-004 → P1 (@AR 2026-11-04 00:00); ADR-021 (пересмотрен 02:30: многопользовательская, номер телефона + SMS OTP)
- **Зависимости:** BE-029 (BC «Клиент»), BE-028 (self → Partner.clientId)

## Контекст
Фаза 1. **ADR-021 пересмотрен (2026-11-04):** онбординг = **номер телефона + SMS OTP** (BC «Клиент», 11-й), «я» = **`Partner.clientId`** (партнёр с `clientId == текущий Client`). PIN остаётся в Privacy (ADR-008). Старый `view-onboarding` («кто ты = партнёр», `0.43`) — **каркас**, не откатывать.

## Задача
- Первый запуск: онбординг — **телефон → SMS OTP** → JWT клиента (`POST /clients`, `/verify`).
- После верификации — **привязка партнёра-я** (`/link-partner`), «я» = `Partner.clientId`.
- PIN — **опция** (можно пропустить).
- Настройки: профиль клиента / «это я».
- Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [x] Новый пользователь: телефон → OTP → JWT клиента → link-partner → «я» определяется по clientId.
- [x] «я» переживает перезагрузку (сервер, не локально).
- [x] PIN можно не задавать.
- [x] Версия забампана (`0.45`/`v45`); E2E (TE-025) — прогон @TE.

## Результат
- `8-front/js/api.js`: блок `clients` — `register(phone)`, `verify(id, code)` (возвращает client-JWT), `linkPartner(id, partnerId)`, `unlinkPartner(id)`, `me()`.
- `8-front/index.html`: `view-onboarding` — шаги «телефон» → «SMS OTP» → «кто ты» (link-partner).
- `8-front/js/app.js`: `afterAuth()` — без client-JWT → онбординг; с JWT → `GET /clients/me` (verified+linked → журнал, иначе онбординг). `submitOnbPhone`/`submitOnbOtp` (сохраняет client-JWT как access), `renderLinkPartners`. `lock`/`unlock` — только локальный PIN, client-JWT не подменяется. Настройки: «Это я» (через `clients.me`), «Сменить» → link-шаг, «Снять» → `unlinkPartner`.
- PIN — опционален. Версия `0.45`/`v45`.
