# FE-012: Тренды читают локальный weekly (CSV), а не API — на новом устройстве «Нет данных»

- **Статус:** Открыта
- **Приоритет:** P1 (тренды не показывают серверные данные)
- **Источник:** @TE `chat/te.md` 2026-11-02 22:00 (живой E2E, TE-018)
- **Зависимости:** —

## Проблема (по коду)
- `renderTrends()` (`8-front/js/app.js:1606`) берёт `DB.getAllWeekly()` / `DB.getAllSleepWeekly()` — это **локальные** IndexedDB-хранилища (`8-front/js/db.js:147,152` → `weekly` / `sleep_weekly`), наполняются **только CSV-импортом** (`importWeekly`).
- Серверные `somatic-series` / `daily-metrics` (`8-front/js/api.js:90-95`) в трендах **не используются**.
- Итог: на новом устройстве (без CSV) тренды всегда «Нет данных», хотя API-данные есть.

## Задача
- Перевести `renderTrends` на `Api.somatic.slice` / `Api.daily.series` (или синхронизировать локальный weekly из API при открытии трендов).
- Сохранить совместимость с CSV-импортом, если он остаётся как источник.
- Поднять `APP_VERSION`/`CACHE` (правило `8-front/AGENTS.md`).

## Критерии приёмки
- [ ] На новом устройстве без CSV тренды показывают серверные данные.
- [ ] E2E TE-018 (`trends`) — зелёный.
- [ ] Версия забампана (`0.31`/`v31`).
