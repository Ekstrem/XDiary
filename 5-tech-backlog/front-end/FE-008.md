# FE-008: P0 — `applyPin`/`removePin` с токеном

- **Статус:** На проверке
- **Приоритет:** P0 (следствие BE-020: клиент должен слать JWT для смены/снятия PIN)
- **Источник:** @TE `chat/te.md` 12:30; BE-020
- **Зависимости:** BE-020

## Проблема
`8-front/js/app.js` `applyPin`/`removePin` ходят **без токена** — эндпоинты `/privacy/*` были анонимны. После BE-020 смена/снятие PIN при установленном PIN потребуют JWT.

## Задача
- `applyPin`/`removePin` — с текущим JWT (как остальные запросы).
- Первичная установка PIN (PIN ещё нет) — без токена, как сейчас.
- При 401 — понятная ошибка (не глотать).

## Критерии приёмки
- [x] Смена PIN на устройстве с валидным JWT работает; без JWT — 401.
- [x] Первичная установка PIN работает без токена.
- [x] CI/E2E зелёные.

## Результат
- `8-front/js/app.js` `removePinNow`: сначала `Api.privacy.removePin()` (с текущим JWT), **потом** `Pin.removePin()` и `Api.auth.logout()` — раньше logout шёл до запроса, и PIN снимался без токена.
- `applyPin`: `Api.privacy.setPin(nw)` синхронизируется с сервером; ошибки больше не глотаются (toast «…но сервер ответил: …»). Первичная установка — как раньше.
