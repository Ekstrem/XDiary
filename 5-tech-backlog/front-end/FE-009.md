# FE-009: Смена PIN — передавать `currentPin` на сервер (после BE-020)

- **Статус:** Открыта
- **Приоритет:** P1 (смена PIN: локально меняется, сервер отвечает 401 → PIN на сервере остаётся старым)
- **Источник:** дефект FE-008 (закрыта, но `applyPin` не шлёт `currentPin`); BE-020 (`c4ae4f7`)
- **Зависимости:** BE-020

## Проблема (по коду)
- `8-front/js/app.js:1978`: `Api.privacy.setPin(nw)` — **без `currentPin`** (текущий PIN проверяется только локально, `Pin.verifyPin(cur)`).
- `8-front/js/api.js:85`: `setPin(pin)` → `{ pin }`.
- BE-020: `SetPinCommand(Pin, CurrentPin)`, при установленном PIN без/с неверным `CurrentPin` → **401**.
- Итог: локальный PIN меняется, серверный — нет; следующий вход с новым PIN → 401.

## Задача
- `api.js`: `setPin(pin, currentPin)` → `{ pin, currentPin }`.
- `applyPin`: передать `cur` (поле «Текущий PIN» в модалке уже есть); при первичной установке (локального PIN нет) — без `currentPin`.
- Ошибку сервера не глотать (toast уже есть — но показывать как ошибку, а не «сохранён локально»).

## Критерии приёмки
- [ ] Смена PIN с валидным JWT: сервер 200, следующий вход с новым PIN работает.
- [ ] Первичная установка PIN — без `currentPin`, работает.
- [ ] E2E/CI зелёные.
