# FE-020: afterAuth — развести PIN-вход (legacy) и онбординг

- **Статус:** Открыта
- **Приоритет:** P1 (UX-блокер: вход по PIN не заканчивается журналом)
- **Источник:** @TE 2026-11-04 (находка на `0.48`, `chat(te)` `9d2bc23`)
- **Зависимости:** FE-019

## Проблема
`afterAuth()` при наличии `xdiary.clientId` + токена идёт в `Api.clients.me()`; если клиент не `verified`/без `linkedPartnerId` — `openOnboarding()`. Поэтому **вход по PIN** на устройстве, где `clientId` есть (или остался от теста/прошлой попытки), но онбординг не завершён, заканчивается онбордингом, а не журналом.

## Задача
Развести два пути:
1. **legacy**: локальный PIN (`Pin.hasPin()`) → PIN-вход → **журнал** (ставить `xdiary.legacy`);
2. **новый**: онбординг (телефон → OTP → client-JWT → link-partner) → журнал.

Правило приоритета: если есть локальный PIN — журнал; онбординг — только когда клиента нет **и** PIN нет **и** legacy-флага нет.

## Критерии приёмки
- [ ] Устройство с PIN: вход по PIN → журнал (не онбординг).
- [ ] Новое устройство без PIN → онбординг.
- [ ] Завершённый онбординг → журнал.
- [ ] Версия `0.49`; спеки `pin-first-login`/`onboarding` зелёные.
