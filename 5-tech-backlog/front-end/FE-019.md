# FE-019: Вход по PIN на новом устройстве — неверный PIN не даёт ошибку

- **Статус:** Закрыта
- **Приоритет:** P1 (UX-блокер входа)
- **Источник:** @TE 2026-11-04 15:50 (находка в `pin-first-login`)
- **Зависимости:** —

## Проблема
На чистом устройстве локального PIN нет → `Pin.verifyPin(любой)` возвращает `true` → `unlock()` идёт в `ensureToken(pin)` → сервер отвечает **401** → `unlock` ловит ошибку как `.then(function () { afterAuth(); })` и **не показывает `#pin-error`**. Пользователь вводит неверный PIN и не понимает, почему не пускает.

## Задача
1. `Pin.verifyPin` — при отсутствии локального PIN **не возвращать `true`** (пусть решает сервер, а не «всегда ок»).
2. `unlock()` — при неудаче `ensureToken` (401/ошибка) **показывать `#pin-error`** и **не звать `afterAuth()`**.
3. Поднять `APP_VERSION`/`CACHE`.

## Критерии приёмки
- [x] Неверный PIN на новом устройстве → видимая ошибка, входа нет.
- [x] Верный PIN → вход работает.
- [ ] Спек `pin-first-login` зелёный (прогон @TE).

## Результат
- `8-front/js/pin.js`: `verifyPin` при отсутствии локального PIN → **`false`** (было `true`).
- `8-front/js/app.js` `unlock()`: `!hasLocal` → `Api.auth.login(pin)`; неудача → `showPinError()` (не `afterAuth`). `hasLocal`: `verifyPin` false → `showPinError()`; `ensureToken` неудача → `showPinError()`.
- Версия `0.48`/`v48`.
