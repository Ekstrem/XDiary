# DO-109: гейт «поля read-модели ⊆ колонки DDL» ищет удалённый источник — красный по дефекту фильтра

- **Статус:** В работе
- **В работе с:** 2026-11-06
- **Приоритет:** P1 — красный `ci-guards` у всех, причина ложная (расхождений нет)
- **Источник:** `@TL 2026-11-06 21:51` («если `check_readstore_mapping` по факту устарел как `check_readstore_ddl` — оформи карточкой, а не тихим отключением»)
- **Проверяет:** @TL (инфраструктура) + @AR (канон полей read-модели)
- **Зависимости:** `DO-099` (DDL переехал в EF-миграции), `DO-105` (тот же класс «гейт устарел»)

## Факт (прогон)

```
$ python tools/check_readstore_ddl.py
  сверено моделей с DDL: 0 | расхождений: 0
  ::error::check_readstore_ddl: ни одной модели с DDL не найдено — фильтр сломан
  rc=2
```

В CI это шаг «Канон «поля read-модели ⊆ колонки DDL» (@AR 15:00)»: он красный **не потому, что поля
разъехались**, а потому что гейт не нашёл ни одного DDL.

## Причина: источник DDL переехал, гейт остался

| что ищет гейт | сколько в `origin` |
|---|---|
| `CREATE TABLE IF NOT EXISTS` в `6-msa/**` | **0 файлов** |
| `migrationBuilder.CreateTable(...)` в `Migrations/ReadStore/*` | **2 файла** |

Таблицы есть, объявлены миграциями:

```
6-msa/BC-Journal/src/Journal.Storage/Migrations/ReadStore/20261105170525_AddReadStores.cs
    name: "journal_read",  name: "partners_directory",
6-msa/BC-Partners/src/Partners.Storage/Migrations/ReadStore/20261105170447_AddReadStores.cs
    name: "partners_read",
```

## Что сделать

1. Научить гейт читать EF-миграции (`migrationBuilder.CreateTable(name: …, columns: …)`), исключая
   `*.Designer.cs` и `*Snapshot.cs` (там дубли).
2. Старый путь (`CREATE TABLE IF NOT EXISTS`) оставить **фолбэком**: два способа объявить DDL — гейт
   обязан видеть оба, иначе снова «ничего не найдено».
3. Квитанция: печатать «источник DDL: EF-миграции (N таблиц) / raw-SQL (M)», чтобы «0 найдено» читалось
   как «не измерено», а не «всё совпало».
4. Проверить на дефекте (§5.4): убрать колонку из миграции → `rc=1` с именем поля; вернуть → `rc=0`.

## Критерии приёмки

- `check_readstore_ddl.py` на `origin` → `rc=0` и «сверено моделей с DDL: ≥ 4»;
- шаг «Канон «поля read-модели ⊆ колонки DDL»» в `ci-guards` — зелёный;
- проверено на дефекте (убрал колонку → `rc=1` с именем поля);
- `--selftest` не вырождается в `0/0`.

## Смежное (проверено, проблемы нет)

`check_readstore_mapping.py` → `регистраций read-store: 4 | немаршенных моделей: 0`, `rc=0`.
