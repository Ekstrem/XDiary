- **Статус:** В работе

- **Приоритет:** P1 — красный `ci-guards` у всех, причина ложная (расхождений нет)
- **Источник:** `@TL 2026-11-06 21:51` («если `check_readstore_mapping` по факту устарел как `check_readstore_ddl` — оформи карточкой, а не тихим отключением»)
- **Проверяет:** @TL (инфраструктура) + @AR (канон полей read-модели)

```

В CI это шаг «Канон «поля read-модели ⊆ колонки DDL» (@AR 15:00)»: он красный **не потому, что поля
разъехались**, а потому что гейт не нашёл ни одного DDL.

| что ищет гейт | сколько в `origin` |

| `CREATE TABLE IF NOT EXISTS` в `6-msa/**` | **0 файлов** |
| `migrationBuilder.CreateTable(...)` в `Migrations/ReadStore/*` | **2 файла** |

Таблицы есть, объявлены миграциями:

```

    name: "journal_read",  name: "partners_directory",
6-msa/BC-Partners/src/Partners.Storage/Migrations/ReadStore/20261105170447_AddReadStores.cs
    name: "partners_read",

## Что сделать

1. Научить гейт читать EF-миграции (`migrationBuilder.CreateTable(name: …, columns: …)`), исключая
   `*.Designer.cs` и `*Snapshot.cs` (там дубли).
2. Старый путь (`CREATE TABLE IF NOT EXISTS`) оставить **фолбэком**: два способа объявить DDL — гейт
   обязан видеть оба, иначе снова «ничего не найдено».
3. Квитанция: печатать «источник DDL: EF-миграции (N таблиц) / raw-SQL (M)», чтобы «0 найдено» читалось
   как «не измерено», а не «всё совпало».
4. Проверить на дефекте (§5.4): убрать колонку из миграции → `rc=1` с именем поля; вернуть → `rc=0`.

- проверено на дефекте (убрал колонку → `rc=1` с именем поля);

### Замер @TL 2026-11-11 20:55 — **гейт подключён, но на `origin` он `rc=2`: фильтр моделей находит 0**

- **Прогон (аргументы — двумя токенами, как в CI):** `python tools/check_readstore_ddl.py --root 6-msa` →
  `сверено моделей с DDL: 0 | расхождений: 0`, затем `::error::check_readstore_ddl: ни одной модели с DDL не найдено — фильтр сломан`, **`rc=2`**.
- **Это не «зелёный на пустом», это хуже для карточки:** гейт честно отказывается мерить (`rc=2`, а не `0`), но значит **проверка не работает**: 0 сверенных моделей при 11 BC. В CI шаг `ci-guards.yml:163` вызывает ровно эту команду ⇒ на `main` это **вторая красная проверка** после `check_secrets`.
- **`--selftest` при этом зелёный: `14/14`.** То есть логика сверки цела, сломан **поиск** моделей (фильтр путей/расширений). Классический случай «инструмент проверен, состояние — нет» (мой же `ERRATA` №43, теперь на чужом гейте).
- **Что нужно:** починить фильтр (найти, где лежат `*ReadModel*.cs` / `*DbContext*.cs` в `6-msa` и почему `--root 6-msa` их не видит), затем §5.4 в обе стороны: дефект (поле модели без колонки) → `rc=1`; норма → `rc=0` и **`сверено моделей > 0`**.
- **Приёмка без этого невозможна:** пока счётчик «сверено моделей: 0», гейт не отличает «всё совпало» от «ничего не смотрел».


### Диагноз @TL 2026-11-11 22:10 — **причина найдена: гейт ищет DDL строкой в `Program.cs`, а DDL больше там не лежит**

| Что проверил | Результат |
|---|---|
| `REG` (регистрации read-store) в `Program.cs` | **4** совпадения: `BC-Journal/src/Journal.Api/Program.cs` (3: `JournalReadModel`, `PartnersDirectoryReadModel`) и `BC-Partners/src/Partners.Api/Program.cs` (1: `PartnersReadModel`) |
| `DDL` (`CREATE TABLE IF NOT EXISTS`) в `Program.cs` | **0** — и не только там: `git grep -F "CREATE TABLE" origin/main -- 6-msa` → **0 файлов** |
| где теперь схема | `6-msa/BC-Journal/src/Journal.Storage/Migrations/ReadStore/20261105170525_AddReadStores.cs` (+ `.Designer.cs`, `ReadDbContextModelSnapshot.cs`) — **EF-миграция**, а не SQL-литерал |
| `*.ReadModel.cs` в коде | **13** файлов (по одному-два в каждом BC) — то есть модели на месте |

- **Механика отказа:** `main()` идёт по `Program.cs`, собирает `tables = ddl_tables(text)` — пусто; затем для каждой найденной модели `resolve_table(model, set(tables))` возвращает `None`, и срабатывает `continue`. Счётчик `checked` остаётся **0**, и гейт честно печатает «фильтр сломан», отдавая `rc=2`.
- **Значит чинить надо не «фильтр моделей», а источник DDL:** читать `migrationBuilder.CreateTable` из `Migrations/ReadStore/*.cs` (или `ReadDbContextModelSnapshot`) вместо `CREATE TABLE` в `Program.cs`. Это ровно тот случай, когда «инструмент отвечает на свой вопрос, а не на твой»: вопрос «есть ли DDL строкой в Program.cs» имеет ответ «нет», и это не дефект кода.
- **Критерий приёмки после починки:** `сверено моделей с DDL` > 0 и равно числу read-model’ей с зарегистрированным контекстом; дефект-плечо: убрать колонку из миграции → `rc=1` с адресом; норма → `rc=0`.
