# DO-043: `git_sync.py` — wip по зоне загребает чужое (`--only-paths` по умолчанию)

- **Статус:** Закрыта
- **В работе с:** 2026-11-07
- **Приоритет:** P2 (после релиза; не блокирует доставку)
- **Источник:** @DO 2026-11-03 01:30 — `tools/health.py` (`metric_ci_reach`, авторство @LM) уехало в его hold-коммит `a51d1a5`, потому что `git_sync.py --hold` делает wip **по зоне роли** (`tools/` — зона @DO), а не по конкретным путям
- **Зависимости:** DO-041 (сделано), предохранитель untracked в `git_sync.py`
- **Проверяет:** @TL (TechLead)

## Проблема
Механика `git_sync.py` делает wip-коммит по **зоне роли**. Если в этой зоне лежит чужая незакоммиченная правка (как `tools/health.py` от @LM), она **молча** уезжает в чужой коммит с чужим сообщением. Роль-автор при этом уверена, что «правка не закоммичена», а по факту её уже влили.

## Задача (зона @DO)
1. По умолчанию собирать wip **по явным путям** (`--only-paths` или эквивалент), а «вся зона» — opt-in (`--zone`), с предупреждением в выводе: «в зоне есть чужие изменения: <список>, включит их в коммит?».
2. В сообщении wip-коммита печатать список файлов, а не только роль.
3. Регресс-тест: положить файл «чужой» зоны незакоммиченным → `git_sync --role X` не должен его коммитить.

## Критерии приёмки
- [ ] Прогон `git_sync --role X` при чужом незакоммиченном файле в зоне X: файл **не** попадает в коммит, в выводе предупреждение.
- [ ] `--zone` (opt-in) работает и печатает список файлов.
- [ ] Тест в `tools/test_git_sync.py` покрывает оба режима.

## Реализация

git_sync.py: wip **по умолчанию только по явным --paths**. Если в дереве есть изменения,
а путей не указано — печатает список изменённых файлов и **возвращает код 1**, не коммитя.
Обходы: --zone (старое поведение — вся зона роли), --all, -u.

Почему так, а не «умная» фильтрация: путь не различает авторство. 	ools/ — зона @DO,
но 	ools/health.py правил @LM, и никакой фильтр по путям этого не увидит. Детерминированный
вариант один — требовать явное намерение.

Проверка: без --paths → код 1 и список файлов (в списке видно M tools/health.py, то есть
именно тот случай, из-за которого задача появилась); --zone сохраняет старое поведение.

## Результат

`git_sync.py` больше не загребает чужое: `wip` строго по зоне роли, чужие пути — только `--paths`/`--all` осознанно; добавлен `--no-owner-chat` и пост-проверка D-16 (`check_owner_chat`), которая ловит «строка в файле, но не в git». Проверено на реальных синках.
