## Задача (зона @DO)
1. **Хеш по каждому образу отдельно** вместо агрегатного (`update.sh:48`): для каждого сервиса — `image@digest`, сравнение с предыдущим состоянием, список «что изменилось».
2. **Пересоздавать только изменённые** контейнеры (compose `up -d <service>`), остальные не трогать; порядок — зависимости (БД → сервисы → шлюз → фронт).
3. **Пост-проверка:** для каждого пересозданного — `verify_running_images`, для всего стека — `/health`; при провале любого шага — **exit 1** и понятный откат.
4. **Миграции:** если изменился образ сервиса с миграциями — прогон миграций **до** пересоздания зависимых; частичный деплой не должен оставить схему и код в разных версиях.
5. **Откат по компоненту:** команда «вернуть предыдущий digest для N сервисов», проверенная один раз на стенде.

## Критерии приёмки
- [ ] Изменение **одного** сервиса пересоздаёт **только его** (подтверждено логом: список «изменено: 1 из 12»).
- [ ] Изменение в фронте не перезапускает бэкенд (негативный контроль: фронт-only коммит → бэкенд не тронут).
- [ ] Если поднялся не тот образ — `verify_running_images` валит деплой (уже есть, проверить в новой схеме).
- [ ] Откат одного сервиса на предыдущий digest выполнен на стенде и описан в `7-deploy/runbooks/`.
