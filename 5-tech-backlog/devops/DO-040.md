## Задача

1. Пустая очередь по группе `ci-front` (иначе ждать — dispatch вытесняется так же, как пуш).
2. Один прогон на текущем `main`; пока идёт — не пушить `8-front/**`, `9-tests/**`.
3. Прислать: цифры (failed/passed/skipped, время), `views (после привязки)`, `me()`,
   **и сетевой notice по `/link-partner`** (был ли запрос, метод/URL/статус).

## Как выполнялось (важно для протокола)

Dispatch **не делался**: в очереди уже стоял `#20` (`c53b82a`), а `a5e209c` — его предок,
то есть `#20` содержит **оба** фикса. `workflow_dispatch` вытеснил бы именно тот pending-прогон,
который нужен, и мы получили бы очередной `cancelled` с нулём шагов. Поэтому прогон взят
из очереди как есть — это ровно «один прогон на текущем `main`», без лишнего запуска.

## Результат

**Ключевой факт, которого не хватало три прогона: `link-partner (после клика по карточке): запросов не было`.**
То есть UI **не отправляет** `POST /api/v1/clients/{id}/link-partner` вообще — не «отправил и получил ошибку».

### Прогон #20 (`c53b82a`, оба фикса) — 2 failed / 17 passed / 2 skipped, 3.3 мин
`onboarding` упал на **шаге 1** (`#onb-otp` остался `hidden` 20 с), потому что
`browser http error: http 500 https://xdiary-vps2.../api/v1/clients`.
Причина 500 — **временная**: `deploy.yml` #732 в это же время пересоздавал dev-стенд
(`deploy-dev` 18:45:00–18:46:08, `smoke-api` **failure** 18:47:10 на `/health`, Expected: OK),
а `front-e2e` #20 стартовал 18:47:23 — через 13 секунд после провала smoke.

### Контрольный прогон #21 (`66cb641`, стенд здоров, очередь пуста) — 2 failed / 17 passed / 2 skipped, 3.0 мин
Те же два падения воспроизвелись, но `onboarding` дошёл до **шага 3** (привязка → журнал):

- `link-partner (после клика по карточке): запросов не было`
- `views (после привязки): view-onboarding=visible, view-journal=hidden`
- `me() после привязки: {"status":200,"verified":true,"linked":false}`
- падение: `onboarding.spec.js` шаг 3, assert на `#view-journal` (строка у assert в конце лога — 85-я, лог `me()`)

`remove-pin` в обоих прогонах **не падает** (переведён на локальный PIN, серверный контур в `skip`) — TE-037 сработал.

### Вывод
Дефект локализован на фронте: обработчик клика по карточке партнёра **не вызывает**
`Api.clients.linkPartner(...)`. Бэкенд при этом исправен — прямой вызов
`POST /clients/{id}/link-partner` на dev даёт 200, а `GET /clients/me` возвращает непустой
`linkedPartnerId` (len=36) и держит его 3 с. Версия «клик не доходит из-за оверлея» снята:
`pointer-events`/`box` в логе не фигурируют, а факт «запросов не было» точнее.
