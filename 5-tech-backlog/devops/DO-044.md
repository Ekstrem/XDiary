# DO-044: гигиена dev-стенда — тестовые данные копятся и ломают E2E (2635 партнёров)

- **Статус:** На проверке
- **В работе с:** 2026-11-07
- **Приоритет:** P1 (найдена настоящая причина «флейка» `pin-first-login`: 20%, 2 из 10)
- **Источник:** @DO 2026-11-03 15:35 по логу `front-e2e-repeat` #5: `onboarding` 5/0, `pin-first-login` **3/2**; в падениях `#onboarding-list: {"children":0,"htmlLen":0}` и `{"children":2607,"htmlLen":588641}`; на dev **partners 2635 / clients 1748**, из них по шаблонам имён/телефонов **2635 из 2635** и **1748 из 1748** — то есть стенд целиком забит данными, сгенерированными спеками
- **Зависимости:** нет
- **Проверяет:** @TL (TechLead)

## Проблема
Спеки создают сущности при каждом прогоне и **никогда не убирают**. За сотни прогонов на dev накопилось 2635 партнёров и 1748 клиентов. Спека берёт `.first()` карточку партнёра — при сотнях карточек это **произвольная старая** запись, отсюда и «пустой список» (`children:0`), и таймауты. Это **не дефект продукта и не вина спек** — это состояние стенда.

## Задача (зона @DO)
1. `7-deploy/cleanup-e2e-dev.sh` — **dry-run по умолчанию**, удаляет только сгенерированное спеками (партнёры `TE-<ts>` / `*e2e*`, клиенты `+7999…`), требует `--apply`, клиентов — только с отдельным `--clients`, печатает остаток. (Сделано.)
2. Прогнать `--apply` по партнёрам, зафиксировать «до/после» числами.
3. После очистки — `repeat=10` и **таблица** в `$GITHUB_STEP_SUMMARY` (парсер уже починен: `--reporter=list` + `tee` + разбор `✓/✘`, проверен на реальном логе #5 → `8/2`, `exit=1`).
4. Отдельным шагом (P2): клиенты (`--clients`) — их удаление может тянуть журнал и другие сервисы, поэтому не в одном заходе с партнёрами.

## Критерии приёмки
- [x] Инструмент очистки с dry-run по умолчанию и `--apply`.
- [ ] Партнёров на dev — единицы (после `--apply`), числа «до/после» записаны.
- [ ] `repeat=10` после очистки: **0 падений** и таблица в summary (а не пустая).
- [ ] Клиенты вычищены отдельной задачей (P2) с проверкой, что журнал/аналитика не сломались.

## Результат

Сделано и проверено на стенде:

1. `7-deploy/cleanup-e2e-dev.sh` — dry-run по умолчанию, `--apply` для удаления, `--clients` для клиентов
   отдельным флагом; `dblink` не используется (на стенде расширения нет), `podman` вызывается через `sudo`
   (rootless-хранилище). **Применено: partners 2639 → 0.**
2. Шаг очистки добавлен в **оба** гейтовых workflow (`ci-front.yml`, `front-e2e-repeat.yml`) сразу после
   сброса PIN: `bash /opt/xdiary/7-deploy/cleanup-e2e-dev.sh --apply`, с `::warning::` если скрипта на
   стенде нет — гейт не падает из-за отсутствия скрипта.
3. Измерение флейка починено (это было условием измерения): в `front-e2e-repeat.yml` шаг тестов писал в
   `--reporter=list` → файл через `tee`, итоговый шаг печатает markdown-таблицу, публикует её в
   `$GITHUB_STEP_SUMMARY`, при падениях даёт `::error` и **exit 1**. Раньше было `continue-on-error: true`
   + `|| true`, поэтому джоба была зелёной **всегда** (#5: «success» при 2 failed из 10).
