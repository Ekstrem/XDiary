## Задача (диагностика по порядку, без догадок)
1. **@DO:** прямой прогон API на проде: `POST /clients` для номера владельца → записать **код ответа и тело** (номер маскировать, код не логировать); затем свежий код → `POST /clients/{id}/verify` с **только что отправленным** кодом → записать **код ответа и тело**. Это отделит «сервер отклоняет» от «фронт не доходит».
2. **@DO:** проверить TTL/одноразовость: повторный `POST /clients` **перевыпускает** код (старый становится невалидным) — если владелец жмёт «получить код» дважды, он вводит устаревший.
3. **@FE:** приложение обязано **показывать** ошибку сервера на шагах register/verify (сейчас молчит) — иначе мы диагностируем вслепую; плюс проверить, что при 409/400 (телефон уже занят) фронт предлагает **ввод кода**, а не «ошибку без выхода».
4. **@BE:** разобрать `ci-backend` #78 — какой тест падает и почему; починить (или вернуть `skip` с причиной, если инфраструктура).
