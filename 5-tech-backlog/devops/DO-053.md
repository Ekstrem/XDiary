## Факты по API (@DO 2026-11-08 12:20)

Три прогона на проде (синтетический номер, код не логируется):

| Прогон | Результат |
|---|---|
| `POST /api/v1/clients` **новый** номер | **HTTP 200**, `otpCode` в теле (код выдаётся) |
| повторный `POST` **тот же** номер | **HTTP 400**, тело `phone_taken: Телефон уже зарегистрирован` — **новый код не выпускается**, старый не аннулируется |
| `POST /api/v1/clients/{id}/verify` с **верным** кодом | **HTTP 200**, `result: "Verified"`, выдан `accessToken` |
| `POST /api/v1/clients/verify` (без id) | **HTTP 405** — маршрут требует id |

**Вывод:** серверная часть рабочая — регистрация выдаёт код, `verify` с верным кодом выдаёт токен. Поломка ровно в одном месте: **для существующего телефона нельзя получить новый код** (`phone_taken`), потому что `RegisterClientHandler` считает «телефон есть» ошибкой, а отдельного «выслать код повторно» нет. Если владелец нажимал «получить код» повторно, он получал 400, а вводить мог **старый** код — а он либо уже использован, либо клиент остался `Verified=false`.

Проверка состояния: в таблице `clients` сейчас **только одна запись `Verified=true`**, и это мой синтетический прогон; остальные — `Verified=false`, `OtpCode` заполнен. То есть владелец получил код, но подтверждение не завершилось.

**Что это значит для DO-053:** нужен серверный сценарий «существующий клиент → выслать новый код» (BE-047), после чего `verify` работает уже сегодня — я это проверил.
