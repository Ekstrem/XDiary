# DO-122: `ci-guards` отменяет сам себя (`cancel-in-progress: true`) — required-чеки навсегда `cancelled`/`failure`

- **Статус:** На проверке
- **На проверке с:** 2026-11-13
- **Артефакт:** `role/do` `543f4ffb9` — `ci-guards:32` и `ci-backend:38` per-PR группы, `cancel-in-progress: false` (проверено @AR 04:24)
- **Проверяет:** @TL
- **Приоритет:** **P0** (ни один PR не может стать зелёным: `check-chat` и `guard-secrets` остаются `failure` **без связи с содержимым PR**)
- **Источник:** @DO `chat/do.md 00:32` («второй блокер required-checks»); подтверждено @TL по аннотациям PR #2174
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @DO (`.github/workflows/ci-guards.yml`)

## Факт (аннотации, а не догадка)

PR **#2174** (`role/tl`, содержимое — карточки + журнал), прогон `ci-guards` `43311603202`:

```
check-chat    [failure] Canceling since a higher priority waiting request for ci-guards exists
guard-secrets [failure] Canceling since a higher priority waiting request for ci-guards exists
```

То есть джобы **не выполнялись**: их вытеснил следующий прогон того же workflow. GitHub оставляет чек в состоянии `cancelled`/`failure`, а required-чек в таком состоянии **не даёт мержить**.

Дополнительно в том же прогоне: `check_adr` → `::warning:: ПРОВЕРЕНО 0 ADR — гейт НЕ СМОТРЕЛ документы`, и `Process completed with exit code 2`. Локально та же команда (`python tools/check_adr.py`) даёт **`rc=0`, «проверено 6, старых пропущено 29, нарушений 0»** — то есть «0 проверено» в CI похоже на **следствие отмены** (прогон оборван), а не на дефект ADR.

## Почему это P0

- `concurrency: cancel-in-progress: true` для **лёгкого** гейта бессмысленно: два пуша подряд (а их в этой сессии десятки) гарантированно отменяют друг друга.
- Пока это так, «красный PR» **не означает ничего** о содержимом PR — а значит и мой круг ревью, и очередь мержа работают вслепую.
- Это тот же класс, что `DO-118` (12 параллельных `sync-board`), только теперь блокирует не раннеры, а **мерж**.

## Задача

1. В `.github/workflows/ci-guards.yml`: `concurrency.cancel-in-progress` → **`false`** (гейт лёгкий: `selftest` + быстрые проверки; вытеснять нечего).
2. Проверить, что при двух пушах подряд **оба** прогона доходят до конца, и чеки приходят в `success`.
3. Если `check_adr` действительно даёт `rc=2` в CI (не из-за отмены) — отдельная строка в `## Результат` с командой и выводом; сейчас локально `rc=0`.

## Критерии приёмки

- [ ] два пуша в одну ветку подряд → **два** прогона `ci-guards` завершаются (нет `Canceling since a higher priority waiting request`);
- [ ] на PR `check-chat` и `guard-secrets` приходят в `success`, а не `cancelled`;
- [ ] `check_adr` в CI печатает «проверено N>0» (как локально: 6) либо объяснено, почему 0;
- [ ] PR с изменением только карточек/журнала **может** стать зелёным (проверка на `#2174`).

## Граница

Содержимое `#2174` к этому отношения не имеет: `status-lint`, `docs-budget`, `guard`, `guard-tools`, `test`, `spec-gates`, `pr` — **все `pass`**; красные только те две джобы, которые были вытеснены.
