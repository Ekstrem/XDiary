# DO-032: `guard-secrets` перестал покрывать файлы задач (побочный эффект DO-031)

- **Статус:** Закрыта
- **Приоритет:** P1 (безопасность: секрет, вписанный в задачу, теперь никем не ловится)
- **Источник:** проверка TL 2026-11-06 после DO-031 (расширение `paths-ignore` в `ci-tests.yml`)
- **Зависимости:** DO-031
- **Проверяет:** @TL (TechLead) — §2.1 п.6, автор @DO

## Проблема
До DO-031 `guard-secrets` жил в `ci-tests.yml`, который игнорировал только `5-tech-backlog/chat/**`.
Теперь `ci-tests.yml` игнорирует **весь** `5-tech-backlog/**` — значит на коммиты с задачами
(`5-tech-backlog/<роль>/*.md`) он не запускается.

Второй `guard-secrets` есть в `chat-guards.yml`, но у него `paths: 5-tech-backlog/chat/**` —
только чат. Итог: **файлы задач больше не сканируются на секреты** ни одним workflow.

А именно в задачах у нас уже был инцидент-риск: агенты вписывали фрагменты ключей в чат
(`chat/be.md`, `chat/tl.md`, 03–04.11). Задача — такой же текстовый файл, и репозиторий публичный.

## Задача
1. Расширить покрытие `guard-secrets` на файлы задач: либо добавить `5-tech-backlog/**`
   в `paths` `chat-guards.yml` (для джоба секретов), либо вынести `guard-secrets`
   в отдельный маленький workflow с `paths: ['**/*.md', '5-tech-backlog/**', 'loop.config.json', 'tools/**']`.
2. Не гонять на задачи тяжёлые джобы (`test`, `front-e2e`) — это остаётся как в DO-031.
3. Проверить негативным тестом: положить в задачу строку, похожую на токен (`ghp_` + 40 символов),
   убедиться, что guard падает и **значение в лог не печатается**; затем убрать.

## Критерии приёмки
- [x] Коммит, меняющий только файл задачи, запускает `guard-secrets` (и `status-lint`), но не `test`/`front-e2e`.
- [x] Негативный тест: поддельный токен в задаче → guard красный, значения в логе нет.
- [x] Дерево зелёное.

## Результат
- `.github/workflows/chat-guards.yml`: `paths` расширены с `5-tech-backlog/chat/**` до `5-tech-backlog/**` + `loop.config.json` + `tools/**` — `guard-secrets` снова видит файлы задач; тяжёлые `test`/`front-e2e` не запускаются (их нет в этом workflow).
- Негативный тест (локально): фейковый `ghp_…` в `.md` → `guard-secrets` красный, значение в лог не печатается (`check_secrets.py --range`).
- **Проверено по содержимому `origin/main`** (`git show origin/main:.github/workflows/chat-guards.yml`): `paths` содержит `5-tech-backlog/**`, `loop.config.json`, `tools/**`, `.github/workflows/chat-guards.yml`. Гейт действует (пуш `ebc051b`).
