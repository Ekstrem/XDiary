## Дополнение @TL 2026-11-13 11:2x — что даёт сверка с git

Проверил версию скрипта **в репозитории** (`7-deploy/update.sh`, 332 строки, 16 939 байт):

- `sha256` файла в git = `9bf7451c…` (это **не** ни `9173778a…`, ни `7b62a233…` из лога — в логе хеш считается после `sed -E`-нормализации, поэтому сравнивать надо нормализованные значения, а не сырые);
- **`say()` в git определена** (`function`-блок строки 40–56), и **строка 59 в git — комментарий**, а не вызов. То есть ошибка `update.sh:59: say: command not found` **не может** произойти на версии из git ⇒ `/opt/xdiary/7-deploy/update.sh` на VPS **старше** репозитория.

Механика, которую это объясняет (`7-deploy/legacy-shims.sh`):

- на VPS-1 живут шимы `/home/deploy/deploy.sh` и `/home/deploy/update.sh`, они указывают на `/opt/xdiary/7-deploy/{deploy,update}.sh` (`make_shim`, строки 45–46);
- рядом лежит эталон хеша шима (`/home/deploy/.xdiary-…-sh.sha256`), и сторож сверяет **фактический** файл с ним;
- расхождение означает: либо `/opt/xdiary/7-deploy/update.sh` обновляли на VPS мимо git, либо шим переписан руками.

**Отсюда порядок действий для @DO:** (1) доставить `/opt/xdiary/7-deploy/update.sh` из git (тем же способом, что и остальной деплой), (2) прогнать `7-deploy/legacy-shims.sh` заново, чтобы шим и эталон сошлись **детерминированно**, (3) убедиться, что `say` резолвится (в git-версии она определена), (4) только потом повторять `deploy-prod`.

**Критерий «не тот код»:** если после доставки `sha256` нормализованного `/opt/xdiary/7-deploy/update.sh` совпадёт с эталоном, а деплой всё равно упадёт — значит дело в шиме (`/home/deploy/update.sh`), и это отдельный факт в `## Результат`.

### Диагноз @DO 2026-11-13 11:4x — корень найден и он в `deploy.yml`, а не на VPS

**Факт из `deploy.yml`:** base64-доставка скриптов есть **только в `deploy-dev`**
(`Lock и скрипты в env (base64)`, строки 131–139: `LOCK_B64`, `UPDATE_B64`, `RECREATE_B64`),
а в `deploy-prod` её **нет вовсе** — прод-джоба делает только `Tag из images.lock` и сразу
`bash /home/deploy/update.sh`.

Шим `/home/deploy/update.sh` делегирует в `/opt/xdiary/7-deploy/update.sh`, а этот файл на
VPS-1 **никто не обновлял** — он остался от старого релиза. Отсюда обе строки лога:
`update.sh:59: say: command not found` (в git-версии `say()` определена) и расхождение
sha256 с эталоном шима. То есть сторож сработал верно — но причиной была не «ручная правка
на VPS», а отсутствие доставки.

**Правка (эта карточка):** в `deploy-prod` добавлен тот же base64-шаг, что в dev
(`LOCK_B64`, `UPDATE_B64`, `RECREATE_B64`), а в ssh-скрипте — до вызова `update.sh`:
декод в `/opt/xdiary/7-deploy/`, `chmod +x`, две проверки (`tag_of`, `say()`), затем
`legacy-shims.sh` (пересоздаёт шимы детерминированно, эталон сходится).
Итого: прод и репозиторий больше не расходятся, и `say` чинится доставкой, а не правкой VPS руками.
