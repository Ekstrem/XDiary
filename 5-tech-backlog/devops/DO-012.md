# DO-012: Публичный HTTPS к API без VPN-клиента (Tailscale Funnel)

- **Статус:** Закрыта (DevOps: Funnel активирован владельцем; `tailscale funnel --bg 8080`, публичный https = 200)
- **Приоритет:** P0 (блокирует реальное использование PWA с телефона)
- **Источник:** прямое требование PO: **никаких новых регистраций** (Cloudflare/DuckDNS/домены отпадают)
- **Зависимости:** DO-004

## Проблема
API доступен только через Tailscale-клиент (`xdiary-vps1.taile0b6ee.ts.net`, ADR-015). С телефона без клиента — `status (null)`. PO не будет ставить VPN и регистрировать сервисы.

## Решение
**Tailscale Funnel** — публичный HTTPS на уже существующем tailnet, без новых аккаунтов.
На VPS-1:
```
sudo tailscale funnel --bg --https=443 http://127.0.0.1:8080
```
(или `tailscale funnel 8080`, затем включить Funnel для узла в админке tailnet, если не включён).
Даёт публичный `https://xdiary-vps1.taile0b6ee.ts.net` — доступен **любому устройству без Tailscale**.

## Ограничения
- Данные чувствительные: доступ — только через JWT (PIN-производный), TLS обязателен, порт 8080 наружу не публиковать.
- Funnel публикует **только 443** (80/10000 при необходимости) — шлюз остаётся на localhost.
- Желателен rate-limit/fail2ban на `/api/v1/privacy/token` (подбор PIN).

## Критерии приёмки
- [ ] `curl https://xdiary-vps1.taile0b6ee.ts.net/health` = 200 **с устройства без Tailscale**.
- [ ] `POST /api/v1/privacy/token` с PIN выдаёт JWT; журнал/партнёры/каталог работают с телефона.
- [ ] `8-front` `DEFAULT_BASE` переключён на этот URL; PWA проверен с телефона.
- [ ] В отчёте: команда и что включено в админке.

## Результат
Funnel настроен: `tailscale funnel --bg 8080` на VPS-1, публичный `https://xdiary-vps1.taile0b6ee.ts.net` отвечает **200** (`/health`). Порт 8080 наружу не открыт, доступ — только через JWT. `8-front` `DEFAULT_BASE` уже указывает на этот URL.
