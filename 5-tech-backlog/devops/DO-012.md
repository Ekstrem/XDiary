# DO-012: Публичный HTTPS к API без Tailscale для пользователя

- **Статус:** Открыта
- **Приоритет:** P0 (блокирует реальное использование PWA с телефона)
- **Источник:** прямое требование PO: пользователь **не должен** логиниться в Tailscale
- **Зависимости:** DO-004, DO-009

## Проблема
API доступен только через Tailscale MagicDNS (`xdiary-vps1.taile0b6ee.ts.net`, ADR-015). С телефона без Tailscale-приложения — `status (null)`. PO отказался: приложение должно просто открываться с телефона.

## Задача
Дать публичный HTTPS-эндпоинт API без VPN-клиента у пользователя. Варианты по убыванию предпочтения:
- **A. Cloudflare Tunnel** на VPS-1 (`cloudflared tunnel`) → `https://xdiary.<домен>` → `127.0.0.1:8080`. Порты наружу не открываются, сертификат автоматический.
- **B. DuckDNS-поддомен + Caddy ACME (DNS-01)** на VPS-1 — без покупки домена.
- **C. Домен + A-запись на IP VPS-1 + Caddy ACME (443/HTTP-01).**

## Ограничения
- Данные чувствительные: доступ только через JWT (PIN-производный), TLS обязателен, порт 8080 наружу не публиковать.
- Rate-limit / fail2ban на `/api/v1/privacy/token` (подбор PIN) — желателен.

## Критерии приёмки
- [ ] `https://<публичный>` → `/health` = 200 **с обычного телефона без VPN**.
- [ ] `POST /api/v1/privacy/token` с PIN выдаёт JWT; журнал/партнёры/каталог работают.
- [ ] `8-front` `DEFAULT_BASE` переключён на публичный URL, PWA проверен с телефона.
- [ ] В отчёте: выбранный вариант и почему.
