# DO-070: гейт `check_adr.py` — «Источник» + «Связанные решения» (норма ADR владельца 2026-11-14)

- **Статус:** На проверке
- **Приоритет:** P2 (процессный гейт: без него норма живёт на памяти архитектора)
- **Источник:** владелец 2026-11-14 (предусловия вместо моратория, `AGENTS §5.2`) + спецификация @AR 2026-11-14 20:40 + канон @LM
- **Зависимости:** нет (гейт уже существует — расширяется)
- **Проверяет:** @AR (норма) + @TL (техника)

## Задача (зона @DO, `tools/check_adr.py`)

Две проверки вместо одной:

1. **`Источник`** — непустой и содержит `\b(AR|BE|DO|FE|TE)-\d{2,3}\b` **или** цитату вопроса владельца с датой.
2. **`Связанные решения`** — **непустое всегда**; если в нём есть `ADR-\d{3}`, обязательны обе части — «почему меняется» и «комплаенс прошлого»; если стоит `— (ADR того же типа нет)`, проверка проходит.

**Сообщения:** `нет поля «Связанные решения» (пусто = ADR не пишется)` и `ссылка на ADR-XXX без «почему меняется»/«комплаенс прошлого»`.

**Грандфазеринг:** проверять только ADR, созданные **после** даты канона (`git log --diff-filter=A --format=%ad`), иначе 29 старых покраснеют и гейт отключат.

## Критерии приёмки

- [ ] Дефект: ADR с пустым «Связанные решения» → **rc=1** с точным сообщением.
- [ ] Норма: ADR с заполненным полем **или** с `— (ADR того же типа нет)` → **rc=0**.
- [ ] `--selftest` включает оба кейса; в отчёте — `REF`.
- [ ] Старые ADR (до канона) не краснеют — проверено списком.

## Результат (2026-11-04)

Обе проверки нормы владельца добавлены в `tools/check_adr.py` и доказаны на реальном ADL.

**Что проверяется (только для ADR, созданных не раньше даты канона `CANON_DATE = 2026-11-14`):**
1. **«Источник»** — непустой и содержит ID задачи (`AR|BE|DO|FE|TE-NNN`) **или** цитату владельца с датой;
   иначе — `нет поля «Источник» (нужен ID задачи вида AR-012 или цитата владельца с датой)`.
2. **«Связанные решения»** — непустое всегда; если в значении есть `ADR-\d{3}`, обязательны обе части —
   «почему меняется» и «комплаенс прошлого»; явное `— (ADR того же типа нет)` проходит.

**Доказательство (§5.4, две стороны + selftest):**
- **дефект**: временный ADR с пустыми полями → `✗ adr-999-tmp-check.md`, две ошибки
  (`нет поля «Источник»…`, `нет поля «Связанные решения» (пусто = ADR не пишется)`), **rc=1**;
- **норма**: те же поля заполнены → `нарушений 0`, **rc=0**;
- **грандфазеринг**: на реальном `04-architecture/ADL` — `проверено 0 (старых пропущено 29)`, **rc=0**,
  то есть 29 старых ADR не покраснели;
- `--selftest`: **5** новых кейсов (`нет «Источник»`, пустые «Связанные решения», `— (ADR того же типа нет)`,
  `ADR-XXX без «комплаенс прошлого»`, полная ссылка) — все `[OK ]`, «самопроверка пройдена».

**Флаг `--no-owner-norm`** — чтобы можно было прогнать гейт по старой норме, не отключая остальные проверки.

**Грабли (для честности):** первый «дефект-прогон» был ложным — падал `AttributeError: no_owner_norm`
(флаг не добавился в argparse), и я чуть не записал это как «rc=1 работает». Отличил по трассировке,
а не по коду возврата: **rc=1 может значить и «гейт нашёл дефект», и «гейт сломался».**
