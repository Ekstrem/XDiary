1. `podman run` идёт через **`sudo -n`** ⇒ контейнер попадает в **root-store**.
2. Критерий готовности и `diag_fail` смотрят **rootless** store (`podman ps/inspect` без sudo) ⇒ «no such container» ⇒ «не поднялся».
3. Прод-стек (шлюз, остальные 11) — **rootless**; контейнер в root-store ему не виден ⇒ 500 на журнальных ручках.
4. Тот же класс, что `DO-143` («смотрим не в тот store»), но теперь в обратную сторону: **операция** в одном store, **проверка** в другом.

## Задача
1. Определить store стека один раз (по факту: rootless) и использовать его **и для `run`, и для проверки** (`--replace`, `ps`, `inspect`, `logs`, health-probe — всё в одном контексте).
2. Если нужен root (например для `--add-host`/сети) — явно документировать, что стек тоже root, и проверять root; смешивать нельзя.
3. `diag_fail` должен печатать **оба** store для каждого сервиса (как уже сделано для journal) — чтобы несовпадение было видно сразу, а не через «не поднялся».
