# DO-080 — «кто проверяет проверку»: монитор входа не должен молча считаться исправным

- **Статус:** ToDo
- **Приоритет:** P1 (молчащий монитор читается как «всё хорошо» — ровно класс «тишина ≠ подтверждение»)
- **Источник:** @AR `09:40` — дыра рядом с `public-probe.yml`; класс дефекта: `restarts=0`, `grep → 0`, «прогон без шагов — не прогон»
- **Зависимости:** `DO-079` (проба уже есть), `ADR-023` (раздел про обнаружение)
- **Проверяет:** @AR
- **Исполняет:** @DO (зона `7-deploy/tools/.github`; правило §1 — задача исполняется владельцем своей папки)

## Задача

`tools/check_public_entry.py` + `public-probe.yml` каждые 15 минут проверяют вход **из интернета**
(`/health` 200, `/api/v1/catalog` 401 + `X-Gravitee-*`, несуществующий путь 404) — это закрыло
«обнаружения не было вообще».

Но если workflow умрёт, расписание остановится или раннер перестанет запускаться, **отсутствие
алертов будет выглядеть как успех**. Монитор обязан уметь говорить «я не знаю», а не молчать
зелёным.

## Критерии приёмки

- проба пишет **время последнего успешного прогона** в машиночитаемое место (артефакт/файл/последняя строка summary — где это дёшево);
- есть правило: **последний успешный прогон старше N минут ⇒ состояние `НЕИЗВЕСТНО`**, а не `ОК`; N задать константой и назвать в карточке (рекомендация: `3 × интервал` = 45 мин);
- состояние видно **без чтения логов**: строка вида `last_ok=<ts> age=<min> state=OK|НЕИЗВЕСТНО` в summary прогона **и** в дашборде/health-странице, если он уже есть;
- `--selftest`: кейс «файл with ts старше N ⇒ `НЕИЗВЕСТНО`» и «ts свежий ⇒ `OK`» — **оба проверяемы локально**;
- правило «прогон без шагов — не прогон» учтено: пустой/отменённый прогон **не обновляет** `last_ok`.

### Замер @TL 2026-11-12 12:30 (ревизия `2fc856d1f`) — **watchdog отсутствует: монитор не проверяется никем**

| Что в карточке | Факт из `origin` |
|---|---|
| «`public-probe` каждые 15 минут проверяет вход» | `.github/workflows/public-probe.yml`: `:15-16` — `schedule: cron: '*/15 * * * *'`, `:31` — `timeout-minutes: 5`, `:35` — selftest пробы, `:38` — проба входа, `:43` — рецепт отката в summary |
| «если workflow умрёт, рядом никого» | **нет** проверки свежести: в файле нет ни «последний успешный прогон», ни dead-man-switch, ни обратной проверки из другого workflow |

- **Следствие:** молчание пробы неотличимо от «всё хорошо»: если workflow отключён/упал на расписании (или GitHub не запустил cron), никто не узнает — ровно то, о чём карточка.
- **Что нужно (зона `@DO`):** отдельный «сторож» с одним критерием — *свежесть последнего успешного прогона* (`gh api …/actions/workflows/public-probe.yml/runs?status=success` → возраст < 45 мин → иначе `rc=1`), запускать его из другого workflow (не из самого `public-probe`), иначе сторож умирает вместе с объектом.
- **Граница:** проверял конфигурацию, а не историю прогонов (`gh` недоступен).
