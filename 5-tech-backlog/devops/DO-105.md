## Что измерено (не оценка)

С моей машины (не из песочницы, не через стенд):

```
GET  https://xdiary-vps1.taile0b6ee.ts.net/health          -> 200 "ok"
POST /api/v1/clients {"phone":"+79001110002"}              -> 200
     тело: {… "otpCode":"<6 цифр>" …}          ← код подтверждения в ОТВЕТЕ
POST /api/v1/clients/{id}/verify {"code":<этот код>}       -> 200
     → client-JWT (237 символов)
GET  /api/v1/partners  с этим JWT                          -> 200
```

**Следствие:** любой, кто знает номер телефона, может зарегистрировать его, прочитать `otpCode`
из ответа API, подтвердить им и получить полноценный client-JWT — то есть **войти в чужой дневник**.
Телефон и Telegram для этого не нужны.

## Почему это появилось

`otpCode` возвращался в ответе как отладочная информация на dev (там `CLIENTS__TESTOTP=000000`,
и код фиксированный). На проде `Otp__Channel=telegram`, но **ответ всё равно содержит код** —
значит отладочное поле не отключено окружением (`ASPNETCORE_ENVIRONMENT=Single` на проде).
