# DO-105: 🔴 P0 — прод отдаёт `otpCode` в ответе регистрации, и этим кодом можно войти под любым номером

- **Статус:** В работе
- **Приоритет:** **P0 (безопасность, прод)**
- **Источник:** владелец пытался протестировать прод `2026-11-06 09:05`, получил «Нет связи с сервером»; при диагностике входа найден дефект
- **Проверяет:** @TL (автор @DO — саморевью запрещено)

## Что измерено (не оценка)

С моей машины (не из песочницы, не через стенд):

```
GET  https://xdiary-vps1.taile0b6ee.ts.net/health          -> 200 "ok"
POST /api/v1/clients {"phone":"+79001110002"}              -> 200
     тело: {… "otpCode":"<6 цифр>" …}          ← код подтверждения в ОТВЕТЕ
POST /api/v1/clients/{id}/verify {"code":<этот код>}       -> 200
     → client-JWT (237 символов)
GET  /api/v1/partners  с этим JWT                          -> 200
```

**Следствие:** любой, кто знает номер телефона, может зарегистрировать его, прочитать `otpCode`
из ответа API, подтвердить им и получить полноценный client-JWT — то есть **войти в чужой дневник**.
Телефон и Telegram для этого не нужны.

## Почему это появилось

`otpCode` возвращался в ответе как отладочная информация на dev (там `CLIENTS__TESTOTP=000000`,
и код фиксированный). На проде `Otp__Channel=telegram`, но **ответ всё равно содержит код** —
значит отладочное поле не отключено окружением (`ASPNETCORE_ENVIRONMENT=Single` на проде).

## Дополнительно найдено (одна причина «код не приходит» на проде)

- Telegram **недостижим с прода**: из контейнера `xdiary-client` `https://api.telegram.org` → «НЕ достижим»;
- но лог печатает `Telegram OTP отправлен на +7…` — то есть **ложный успех**, потому что образ `client`
  на проде старый (`885997ae`, 4 ноября) и не содержит guard'а `BE-037`
  (`if (!resp.IsSuccessStatusCode) throw …`);
- новые образы **не собраны**: `ci-journal #107` и `ci-partners #100` падают на
  `error CS0246: 'IValueObjectJsonConverter' could not be found` (`JournalEventConsumer.cs:59`,
  `PartnerCommandRepository.cs:33`) ⇒ `docker` = `skipped` ⇒ теги из `images.lock` не опубликованы.

## Что сделать (по владельцам)

1. **@BE (немедленно):** убрать `otpCode` из ответа `POST /api/v1/clients` **на всех окружениях**
   (отладка — только через лог при `ASPNETCORE_ENVIRONMENT=Development`, не в DTO);
2. **@BE:** починить `CS0246` в двух BC, чтобы появились образы и `deploy-prod` стал возможен;
3. **@DO (после образов):** выкатить прод, проверить, что `otpCode` в ответе **отсутствует** (негативный
   контроль: тот же `POST` → поля нет), и что Telegram-сбой даёт **ошибку регистрации**, а не «отправлен»;
4. **@DO:** пока фикс не выехал — предупредить владельца, что тестировать на **реальном** номере нельзя
   (код утекает в ответ), и не публиковать скриншоты ответов API.

## Критерии приёмки

- на проде `POST /api/v1/clients` **не содержит** `otpCode` (проверено grep по телу ответа);
- при недоступном Telegram регистрация возвращает ошибку (а не 200 с «отправлен» в логе);
- в `## Результат` — `REF` образа и тела ответов до/после.
