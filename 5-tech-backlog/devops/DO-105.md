# DO-105: `check_readstore_ddl` краснеет «фильтр сломан», потому что DDL больше нет — гейт устарел после BE-072

- **Статус:** ToDo
- **Приоритет:** **P1** (красный `ci-guards`/`check-chat` держит остальные шаги job'а)
- **Источник:** разбор @TL `2026-11-06 08:5x`
- **Проверяет:** @TL

## Факт

```
python tools/check_readstore_ddl.py --root 6-msa
сверено моделей с DDL: 0 | расхождений: 0
::error::check_readstore_ddl: ни одной модели с DDL не найдено — фильтр сломан
rc=2
```

(в CI то же — аннотация в `check-chat`: «`check_readstore_ddl`: ни одной модели с DDL не найдено — фильтр сломан»)

## Причина

Гейт ищет **raw DDL** (`CREATE TABLE …`, `ExecuteSqlRaw`) в read-моделях и сверяет его с моделью. Но после `BE-072`
(«read-схема через миграции, `ExecuteSqlRaw` удалён») в коде **`0`** `CREATE TABLE` и **`0`** `ExecuteSqlRaw` —
схема теперь описывается EF-миграциями. Гейт честно сообщает, что ему **нечего сверять**, и краснеет.

То есть это **не дефект кода**, а **гейт, переживший свой предмет**.

## Варианты (выбрать один)

1. **Вывести из эксплуатации** и оставить `check_readstore_mapping` (он есть и `rc=0`) как единственную проверку соответствия
   read-моделей схеме. В `ci-chat`/`ci-guards` шаг убрать, в `9-tests/AGENTS.md`/`tools/README` — пометку «заменён».
2. **Переориентировать** на новый предмет: сверять **EF-миграции** read-схемы с `ReadDbContextModelSnapshot`
   (то есть ловить «модель изменили, миграцию не создали») — это то, что раньше делал DDL-гейт по смыслу.
3. Оставить как есть и признать `rc=2` «нормой» — **нельзя**: `rc=2` в наших правилах значит «не измерено», а не «зелено».

**Рекомендую (2)**, если время есть: это сохраняет защиту от расхождения «модель ↔ схема». Если времени нет — (1),
но с явной записью, что проверка заменена `check_readstore_mapping`.

## Критерии приёмки

- `ci-guards` job `check-chat` больше не краснеет из-за этого шага;
- в репозитории не остаётся шага, который **по конструкции** всегда `rc=2`;
- если выбран (2) — есть `--selftest` с кейсом «модель изменена, миграции нет» → `rc=1`.
