## Факт 1: триггеры неравномерны

Слушают `6-msa/Shared/**` **8** workflow: `ci-apple-health-gateway`, `ci-catalog`, `ci-daily-metrics`,
`ci-garmin-gateway`, `ci-partners`, `ci-portability`, `ci-privacy`, `ci-somatic-series`.

**Не слушают**: `ci-journal`, `ci-client`, `ci-analytics`, `ci-api-gateway`.

При этом `ci-journal.yml` слушает только:
```yaml
paths:
  - '6-msa/BC-Journal/**'
  - '6-msa/BC-Client/src/Client.ApiTests/**'
  - '.github/workflows/ci-journal.yml'
```

**Следствие:** правка в `6-msa/Shared/**` (например, восстановление `IValueObjectJsonConverter`, которое использует
журнал) **не запускает** `ci-journal` → журнал не собирается → **образ для нового коммита не публикуется**.

## Факт 2: lock уже опережает реестр

`7-deploy/images.lock` после `b0e5ae06` (12:56) указывает:
```
journal   single-e7cf387
partners  single-e7cf387
```
Но:
- `ci-partners` на `5554be29` — **failure** (`Outbox` namespace) ⇒ `docker` = **skipped**;
- `ci-journal` для этого коммита **вообще не запускался** (Shared не в путях).

Значит следующий Deploy может **упасть на `deploy-dev`** при `podman pull … single-e7cf387` (образа нет).

1. **Добавить `6-msa/Shared/**` в `paths:`** у `ci-journal.yml`, `ci-client.yml`, `ci-analytics.yml`,
   `ci-api-gateway.yml` — как это уже сделано в остальных восьми.
2. **Проверить `images.lock` на соответствие реестру** перед деплоем: `podman manifest inspect ghcr.io/ekstrem/xdiary-<svc>:<tag>`.
   Если образа нет — не двигать строку (или откатить на последний опубликованный тег).
3. Подумать про гейт: `check_lock` уже проверяет «lock = git», но **не** проверяет «образ существует».
   Кандидат в `tools/check_images_exist.py` (по списку из `images.lock`, с `podman manifest inspect` на dev) — но это
   отдельное решение, т.к. требует доступа к реестру в CI.
