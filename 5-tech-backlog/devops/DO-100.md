## Найденная причина №2: `Backend tests` падает на **любом** пуше, где не менялся BC (@TL 00:4x, без логов — по коду и diff)

`ci-backend.yml:79-81`:

```bash
bcs=$(printf '%s\n' "$changed" | grep -oE '^6-msa/(BC-[A-Za-z0-9]+|ApiGateway(\.Tests)?)' \
      | cut -d/ -f2 | sed 's/\.Tests$//' | sort -u | tr '\n' ' ')
```

GitHub запускает `shell: bash` как **`bash -eo pipefail`**. Если в пуше **нет** файлов, подходящих под
`6-msa/BC-…`, то `grep -oE` завершается с кодом **1** → `pipefail` делает весь конвейер неуспешным →
присваивание `bcs=$(…)` проваливается → `-e` **прерывает шаг** → «Определить зону» краснеет.

**Проверка на фактах:** оба упавших прогона `Backend tests` — это пуши, где менялись только `9-tests/**` и чат:

```
06d78e0a (base a19583fe): 5-tech-backlog/chat/te.md, 9-tests/README.md,
                          9-tests/RnD/front-e2e/tests/edit-delete-record.spec.js,
                          9-tests/scripts/check_e2e_positional.py      → совпадений с BC: 0
a8ef6234 (base 94f1d73e): 5-tech-backlog/chat/te.md, 9-tests/README.md,
                          9-tests/scripts/check_e2e_all.py,
                          9-tests/scripts/e2e_receipt.py              → совпадений с BC: 0
```

⇒ **Это не «флейк» и не «стенд»: гейт зелёный только тогда, когда менялся BC.** Любой пуш в `9-tests/**`,
`.github/**` или docs ломает job.

**Минимальная правка (одна):**

```bash
bcs=$(printf '%s\n' "$changed" | grep -oE '^6-msa/(BC-[A-Za-z0-9]+|ApiGateway(\.Tests)?)' \
      | cut -d/ -f2 | sed 's/\.Tests$//' | sort -u | tr '\n' ' ' || true)
# и ниже, при пустом списке — NONE (уже есть: ${bcs:-NONE})
```

То есть достаточно `|| true` у конвейера (или `|| echo`), чтобы пустой список стал `NONE`, а не падением.
