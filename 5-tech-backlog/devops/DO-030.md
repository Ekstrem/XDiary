# DO-030: Гейт на NUL-байты в markdown (файлы не должны становиться бинарными)

- **Статус:** ToDo
- **Приоритет:** P3 (гигиена: битые диффы, риск потери строк в чате)
- **Источник:** проверка TL 2026-11-06: `chat/tl.md` (14 NUL), `chat/be.md` (2), `chat/_dialogue.md` (15), `back-end/BE-030.md` (1), `BE-038.md` (1)
- **Зависимости:** —
- **Проверяет:** @DO

## Проблема
В markdown-файлах репозитория встречаются NUL-байты (`\x00`). Источник — команды
`Add-Content`/here-string в PowerShell: при склейке строк попадает нулевой байт.
Последствия:
- git считает файл **бинарным** (`Bin 34573 -> 35211 bytes` в диффах) — изменения не читаются при ревью;
- `tools/chat_lint.py` и генератор `_dialogue.md` могут терять строки (NUL ломает разбор);
- в задачах это прячет реальные правки.

## Задача
1. Добавить в `tools/` проверку: любой `*.md` под `5-tech-backlog/**` (и `README.md`, `CHANGELOG.md`) не должен содержать `\x00`. Сообщение — путь + количество байтов.
2. Встроить в `chat-guards.yml` (или в `guard-paths.yml`) рядом с `check-chat` — дёшево, без сборки.
3. Проверить, что гейт падает на искусственно испорченном файле (негативный тест) и зелёный на текущем дереве.

## Критерии приёмки
- [ ] Чек падает при NUL в md и печатает путь.
- [ ] Зелёный на `main` после очистки известных файлов.
- [ ] В `7-deploy/README.md` — строка про то, почему нельзя писать md через шелл-here-string.
