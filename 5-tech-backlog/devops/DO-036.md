# DO-036: Фронт на dev-стенде не отдаётся — 502 на `/` (нет статики, Caddy без file_server)

- **Статус:** Закрыта
- **Приоритет:** P2 (не блокирует CI/E2E, но «живой» тест-стенд для человека недоступен)
- **Источник:** владелец 2026-11-07 («получается не задеплоился фронт на тест-стенд? остановись обсудить»); факты @DO 07.11
- **Зависимости:** ADR-020 (CD pipeline), ADL; вердикт @AR по вопросам ниже
- **Проверяет:** @AR (архитектура: размещение компонентов, ADR-020/ADL) — по просьбе владельца ревью **до** исполнения

## Факт (проверено на VPS-2)

```
GET https://xdiary-vps2.taile0b6ee.ts.net/        → 502
GET https://xdiary-vps2.taile0b6ee.ts.net/index.html → 502
GET https://xdiary-vps2.taile0b6ee.ts.net/js/app.js  → 502
```

- на VPS-2 **нет каталога статики** `8-front` (`/opt/xdiary/8-front`, `/var/www/xdiary`, `/srv/xdiary` — отсутствуют);
- `Caddyfile` на dev: только `reverse_proxy 127.0.0.1:8080` — **без** `root`/`file_server`;
- API при этом жив: `/health` = 200, `/api/v1/clients` = 200 (и через Caddy, и напрямую).

Причина 502: Caddy отправляет `/` в API-шлюз (YARP), у которого маршрута на `/` нет.

## Почему CI этого не ловил

`9-tests/RnD/front-e2e/playwright.config.js`: `baseURL: http://127.0.0.1:4173` + `webServer` —
UI поднимается **локально** из `8-front`, а на dev идёт только API (`XDIARY_E2E_BASE_URL`).
То есть `front-e2e` проверяет фронт-код, но **не** факт раздачи статики на стенде.

Прод-фронт при этом задеплоен: GitHub Pages, `pages.yml` #1083 (`aea033c`, «FE-027 … 0.61»), success.

## Вопросы к @AR (до исполнения)

1. **Должен ли dev-стенд отдавать UI вообще?** Или целевая схема: фронт — только GitHub Pages (прод), а dev — API-only для E2E/бэка? От ответа зависит, нужна задача или это «так и задумано».
2. **Если должен** — согласовано ли решение `handle /api/* → reverse_proxy 127.0.0.1:8080` + `handle → file_server` с ADR-020/ADL? Сейчас ADR-020 §Инфраструктура описывает «podman + сеть xdiary + 12 контейнеров + Tailscale + caddy → 127.0.0.1:8080» — про статику фронта там ничего нет.
3. **Нужна ли правка ADR-020/ADL** (зафиксировать, где живёт статика на каждой среде), или достаточно раздела в `7-deploy/README.md`?

## Задача (после вердикта @AR)

1. Если UI на dev нужен: положить артефакт `8-front` на VPS-2 (каталог + владелец), Caddy —
   `handle /api/* { reverse_proxy 127.0.0.1:8080 }` + `handle { root * <dir>; file_server }`.
2. Если не нужен: зафиксировать это в ADR/README и **убрать 502 с `/`** (явный ответ «фронт на dev не отдаётся»
   либо редирект на Pages), чтобы стенд не выглядел сломанным.
3. Не менять E2E: `baseURL: 4173` — осознанное решение (UI из локального `8-front`).
