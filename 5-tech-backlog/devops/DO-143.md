- **Статус:** ToDo
- **Приоритет:** P1 — из-за этого фикс `BE-128` не доехал, а `deploy-dev` упал
- **Зависимости:** нет
- **Источник:** прогон `44313211756` (`deploy-dev` failure), инцидент 2026-11-18 16:30–16:40
- **Проверяет:** @TL
- **Исполняет:** @DO (`7-deploy/`)

## Факт

```
run| Error: error creating container storage: the container name "xdiary-catalog"
     is already in use by "fa57b6574dc5…". You have to remove …
run| Error: error creating container storage: the container name "xdiary-client"
     is already in use by "08bc2314f8be…"
##[error]Process completed with exit code 1.
```

**Следствия (проверено на стенде @DO, 16:39):**

```
podman ps: catalog/client/journal/partners -> все single-378a56c (Up 4-6 мин)
images.lock:                                  single-9b7f2fa
```

⇒ `deploy-dev` упал **до** пересоздания контейнеров, они остались на **старом** образе. То есть **новая выкатка не применяется, если контейнеры уже существуют**, и при этом джоб падает.

Побочно: 20 минут стенд был частично недоступен (`/partners` и `/journal/records` → 502), пока контейнеры не пересоздались сами.

## Что нужно

1. В `7-deploy/deploy.sh` (и `recreate-service.sh`) — идемпотентность: `podman rm -f <name>` или `podman run --replace` перед созданием; сейчас `--name` без этого;
2. Явная проверка после `deploy-dev`: `podman ps --format "{{.Names}} {{.Image}}"` и сверка тегов с `images.lock` — если не совпало, джоб **должен падать с внятным сообщением**, а не молча оставлять старые контейнеры;
3. (желательно) шаг «дождаться готовности» — `curl /health` по каждому сервису с ретраями, вместо `sleep`.

## Критерий приёмки

1. Повторный `deploy-dev` на уже работающем стенде — **success**;
2. после него `podman ps` показывает теги **из `images.lock`**, а не прежние;
3. `GET /health` 200 по всем сервисам, `/partners` и `/journal/records` — не 502;
4. `deploy-prod` доходит до конца и `smoke-api`/`smoke-front` зелёные.
