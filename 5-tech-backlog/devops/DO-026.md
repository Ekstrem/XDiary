## Уточнение (владелец 2026-11-06): тестируем НЕСКОЛЬКО аккаунтов
Фиксированная карта «2 телефона» не подходит: владелец будет тестировать несколько аккаунтов. Меняем схему доставки.

### Конфиг
- `Otp__Channel=telegram`
- `Otp__Telegram__BotToken=<токен>` — только `.env`
- `Otp__Telegram__ChatIdMap=+7XXXXXXXXXX:<chat_id>,+7YYYYYYYYYY:<chat_id>` — реальные пользователи (владелец, партнёр)
- **`Otp__Telegram__AdminChatId=<chat_id владельца>`** — fallback: если телефона нет в карте, код уходит **сюда**, а в тексте сообщения указан телефон: «Код для +7… — 123456».

### Поведение
- телефон в карте → код идёт напрямую;
- телефона нет и задан `AdminChatId` → код идёт админу **с телефоном в тексте** (так владелец тестирует сколько угодно аккаунтов);
- телефона нет и `AdminChatId` пуст → **явная ошибка** регистрации (не «успех»): «канал доставки для этого номера не настроен».

### Безопасность
- fallback разрешён только при явном `Otp__Telegram__AdminChatId`; на проде это осознанный режим «тестовый период», записать в `7-deploy/README.md`;
- в лог код не пишем (уже реализовано в `LogOtpSender`).
