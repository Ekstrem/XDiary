# DO-026: Включить OTP-канал Telegram на dev и prod

- **Статус:** Открыта
- **Приоритет:** P1 (без этого онбординг на проде непроходим; владелец делает бота)
- **Источник:** ADR-021 §Решение п.2 (`Otp:Channel = sms|telegram|log`), BE-037, решение владельца 2026-11-06 «могу сделать бота»
- **Зависимости:** BE-037 (`TelegramOtpSender`)

## Что нужно сделать
1. **Приём секрета от владельца** (не в git, не в чат): токен бота → в `.env` на VPS-2 (dev) и VPS-1 (prod):
   - `Otp__Channel=telegram`
   - `Otp__Telegram__BotToken=<токен>`
   - `Otp__Telegram__ChatIdMap=+7XXXXXXXXXX:123456789,+7YYYYYYYYYY:987654321` (2 пользователя: владелец + партнёр)
2. Пересоздать контейнер `clients` (dev и prod) — конфиг читается при старте.
3. **Смоук:** `POST /api/v1/clients` с телефоном из `ChatIdMap` → код приходит в Telegram; `POST /clients/{id}/verify` → client-JWT.
4. Проверить, что `Otp__Channel=log` **не стоит** на проде (иначе код пишется в лог).

## Критерии приёмки
- [ ] На dev и prod `Otp__Channel=telegram`, `TestOtp` не задан.
- [ ] Код приходит в Telegram на телефон из карты; `/verify` выдаёт JWT.
- [ ] Секретов в git нет (`guard-secrets` зелёный), значения только в `.env`.
- [ ] В `7-deploy/README.md` — как добавить телефон в `ChatIdMap` (для партнёра).
