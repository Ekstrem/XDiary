# DO-117: `lock-sync` снова обнулил digest — guard стоит ДО ветки ретрая, а ретрай пишет git-рендер

- **Статус:** ToDo
- **Приоритет:** P1 (регрессия закрытой `DO-113`: `ADR-027` «неизменяемая идентичность образа» снова не выполняется; выкатка по digest невозможна)
- **Источник:** прогон @TL 2026-11-13 23:30, ревизия `d6b17695c`: бот-коммит `d96853ded` («bot: images.lock синхронизирован с git (lock-sync)») → `digest=sha256:` **0**
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @DO — `7-deploy/**`, `.github/workflows/lock-sync.yml`, `tools/gen_images_lock.py`

## Факт

| Замер | Команда | Результат |
|---|---|---|
| digest в lock **до** бота | `git show 7e34e9714:7-deploy/images.lock` (и мой замер 15:40) | **12 из 13** |
| digest **после** бота | `git show d96853ded:7-deploy/images.lock` | **0 из 13** |
| digest сейчас | `git show origin/main:7-deploy/images.lock` | **0** |
| теги при этом валидны | `check_registry_tags.py --available` | «сервисов 13 \| доступно 12 … совпадает с lock», `rc=0` |
| мой прогон `gen_images_lock.py --check` до бота | — | `rc=0`, «подтверждено 12, расхождений 0» |

## Причина (по коду workflow, а не по логам)

`.github/workflows/lock-sync.yml`:

| Строки | Что делает |
|---|---|
| `:78-88` | `python tools/gen_images_lock.py --from-registry --write` — источник **реестр** |
| `:95-112` | **guard**: `--check-digests` → если digest стало меньше, `git checkout -- 7-deploy/images.lock` и `exit 1` (это и есть `DO-113`) |
| `:131-144` | **ветка ретрая**: `for i in 1 2 3; if git push; …` → после `git fetch`/`git merge` вызывает **`python tools/gen_images_lock.py --write`** — то есть **git-рендер**, а `--check-digests` **внутри ретрая не вызывается** |

**Вывод:** guard защищает только «первую» запись. Как только пуш проигран гонкой (а он проигрывается часто — видно по `e059b2f19`/`bdeb3aebd` merge-коммитам), ретрай перегенерирует lock из **git**, где digest взять неоткуда (`merge_digests` сохраняет digest только для **того же тега**, а после merge теги меняются) — и коммитит это без проверки.

## Что сделать (@DO)

1. В ветке ретрая (`:135`) заменить `--write` на `--from-registry --write` — чтобы источником оставался реестр;
2. **перенести guard внутрь цикла** (сразу после записи, до `git commit`), чтобы правило «digest не уменьшился» действовало на **каждую** попытку;
3. если реестр не отдал digest — не терять прежний: `merge_digests` уже умеет сохранять «для того же тега», но в git-рендере тег другой. Значит правильный источник — реестр (п.1), а не «сохранить любой ценой»;
4. `--selftest` плечи: (а) норма — lock из реестра с digest → `rc=0` и 12 digest-строк; (б) дефект — подложить lock без digest → `--check-digests` даёт `rc=1` и запись **откатывается**; (в) неизмеренное (реестр недоступен) → `rc=2`.
