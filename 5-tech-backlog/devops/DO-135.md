## Причина (по @BE, 10:50)

`AddReadStores` вызывает `migrationBuilder.CreateTable`, но в `__EFMigrationsHistory` **нет записей** о двух уже применённых миграциях:

- `20261105170525_AddReadStores`
- `20261105170447_AddReadStores`

При старте EF видит «миграция не применена» → пытается `CREATE TABLE` → таблицы уже есть → **`42P07` (duplicate_table)** → сервис падает → рестарт-петля → APIM 500.

Идемпотентный вариант (`CREATE TABLE IF NOT EXISTS`) @BE **откатил осознанно**: `LoopMaker/Roles/BackEnd/RULES.BackEnd.md` и гейт требуют `grep 'CREATE TABLE IF NOT EXISTS|EnsureCreated' -- 6-msa → 0`; схемой управляют EF-миграции. Заведён gap `0-df-issue/edm-idempotent-migration.md`.

## Что сделать (одна операция БД, обратимая)

```sql
-- 1) что реально в истории (ожидаем НЕ найти эти две строки)
SELECT "MigrationId", "ProductVersion"
FROM "__EFMigrationsHistory"
WHERE "MigrationId" LIKE '2026110517%';

-- 2) что реально есть в схеме (таблицы уже созданы)
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_name IN ('journal_defaults','journal_read','partners_directory','partners_read');

-- 3) отметить как применённые (в БД journal и в БД partners соответственно)
INSERT INTO "__EFMigrationsHistory" ("MigrationId", "ProductVersion")
VALUES ('20261105170525_AddReadStores', '8.0.11')
ON CONFLICT ("MigrationId") DO NOTHING;

INSERT INTO "__EFMigrationsHistory" ("MigrationId", "ProductVersion")
VALUES ('20261105170447_AddReadStores', '8.0.11')
ON CONFLICT ("MigrationId") DO NOTHING;

-- 4) перезапустить сервисы, чтобы Migrate() пропустил CREATE
```

Затем: `podman restart xdiary-journal xdiary-partners` и смотреть логи — `42P07` быть не должно.
