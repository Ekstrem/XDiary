# DO-024: E2E-прогоны уничтожают PIN стенда (DELETE FROM pin_credential)

- **Статус:** Закрыта
- **Приоритет:** P1 (владелец 2026-11-05: «PIN сбросился до 1234 — точно баг»)
- **Источник:** владелец, жалоба на сброс PIN; разбор `7-deploy/reset-dev-pin.sh`
- **Зависимости:** ADR-019/020 (dev-стенд для E2E)

## Факты
`7-deploy/reset-dev-pin.sh` выполняет:
```sql
DELETE FROM pin_credential;          -- без WHERE: удаляет ВСЕ PIN-креденшелы
```
и затем ставит `1234` через `POST /api/v1/privacy/pin/set`.

Скрипт вызывается **автоматически, перед каждым прогоном**:
- `.github/workflows/ci-tests.yml:103` — джоб `front-e2e` (хост `DEV_SSH_HOST`, VPS-2);
- `.github/workflows/deploy.yml:54` — джоб `smoke` (VPS-2, после `deploy-dev`).

Модель `PinCredential` **не имеет** `ClientId`/`TenantId`/`DeviceId` (`6-msa/BC-Privacy/src/Privacy.Domain/Abstraction/IPinCredentialAnemicModel.cs`) → PIN один на всё развёртывание. Значит любой прогон E2E на стенде, которым пользуется человек, **меняет его PIN на 1234** и не восстанавливает.

## Задача
1. **Не трогать общий стенд:** E2E — только выделенный стенд/БД (dev уже отдельный от prod, но и на dev может работать человек — владелец).
2. **Точечный сброс:** если PIN станет per-client/per-device (см. AR-008), сбрасывать только креденшел E2E-клиента; сейчас — минимум `WHERE` по конкретному id, а не `DELETE` без условия.
3. **Восстановление:** перед прогоном сохранять существующий PIN (хэш-запись) и возвращать после; либо явно запрещать прогон, если на стенде есть «человеческий» PIN (проверка + `exit 0` с сообщением, а не удаление).
4. Убрать вызов из `deploy.yml:smoke`, если он не обязателен (сейчас это делает **каждый деплой на dev**).

## Критерии приёмки
- [x] Прогон E2E не меняет PIN, если на стенде уже выставлен «человеческий».
- [x] `reset-dev-pin.sh` не делает `DELETE` без `WHERE`.
- [x] В доке `7-deploy/README.md` — предупреждение: «стенд dev используется и человеком; E2E сбрасывает PIN».

## Результат
- `7-deploy/reset-dev-pin.sh`: `DELETE FROM pin_credential` **убран**. Теперь: PIN уже 1234 → no-op; PIN ≠ 1234 (человеческий) → **отказ `exit 1`** с предупреждением; PIN отсутствует → первичная установка 1234 через `POST /pin/set`. Проверка — через API (`/token` + `/pin/has`), без SQL-стирания.
- `.github/workflows/deploy.yml`: убран шаг «Reset dev PIN» из джоба `smoke` (раньше затирал PIN при каждом деплое на dev).
- `7-deploy/README.md`: раздел «E2E и PIN стенда (DO-024)» — стенд dev используется человеком, PIN один на развёртывание (AR-008).
