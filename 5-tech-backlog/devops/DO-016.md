# DO-016: Funnel для VPS-2 (dev) — внешний доступ для E2E

- **Статус:** Отклонена (дубль — Funnel VPS-2 поднят @DO 19:30, `/health` 200)
- **Приоритет:** P1 (без этого `front-e2e` на dev не прогнать из GitHub-раннера)
- **Источник:** @TE `chat/te.md` 2026-11-01 19:00 (VPS-2 tailnet-only); ADR-020 п.3
- **Зависимости:** DO-010 (Funnel VPS-1 — схема готова)

## Проблема
Dev-стенд VPS-2 (`xdiary-vps2.taile0b6ee.ts.net`) доступен только из tailnet. @TE не может ни из окружения, ни из GitHub-раннера достучаться до `/health` — значит `front-e2e` (в т.ч. деструктивные PIN-сценарии с уборкой) на dev не запустить. Нужен публичный вход, как у VPS-1.

## Задача
1. Tailscale Funnel для VPS-2: публичный `https://xdiary-vps2.taile0b6ee.ts.net` → `127.0.0.1:8080` (шлюз).
2. TLS: `tailscale cert` + caddy (как в `7-deploy/tailscale-tls.sh`).
3. Проверить `/health` = 200 снаружи tailnet.

## Критерии приёмки
- [ ] `https://xdiary-vps2.taile0b6ee.ts.net/health` = **200** снаружи tailnet.
- [ ] @TE может выставить `XDIARY_E2E_BASE_URL` для job `front-e2e`.
- [ ] Секреты/ключи не попадают в репозиторий.

## Результат
Сделано ранее (при подъёме dev-стенда и по запросу @TE 19:00): `tailscale funnel --bg 8080` на VPS-2 (Funnel on, публичный `https://xdiary-vps2.taile0b6ee.ts.net` → `127.0.0.1:8080`), TLS `tailscale cert` + caddy (`bind 100.116.0.20`, активен). `/health` = 200. @TE может ставить `XDIARY_E2E_BASE_URL=https://xdiary-vps2.taile0b6ee.ts.net`.
