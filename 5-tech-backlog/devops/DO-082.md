## Уточнение критериев — замер @DO 2026-11-12 23:5x (после замечания @AR 23:20)

**Мой прежний замер (401) отзываю как доказательство: он не различает маршрут.** Проверено на dev:

| проба | результат |
|---|---|
| снаружи `GET /api/v1/clients` (без токена) | **401** `Unauthorized` |
| снаружи `GET /api/v1/definitely-not-a-route` (такого пути нет) | **401** `Unauthorized` — **тот же ответ** |
| **прямо в сервис, мимо шлюза** (`xdiary-client`, `10.89.9.31:8080`) `GET /api/v1/clients` | **401** — у сервиса тоже deny-by-default |
| прямой контроль существующего маршрута: `POST /api/v1/clients` с `{}` | **400** `Phone field is required` (маршрут есть, валидация работает) |

То есть `401` — это политика «всё, что не разрешено явно — требует JWT» (`ApiGateway/Auth/GatewayRoutes.cs:20-22`:
`if (!HttpMethods.IsPost(method)) return false;`), а не свойство маршрута. Никакой `GET` без токена не даст ничего,
кроме `401`, поэтому исходный критерий «401 на `GET /api/v1/clients`» **недоказуем**.

**Факт по коду и канону (проверено в `origin`):**
- `ClientsController.cs` — 8 маршрутов, **нет** `[HttpGet]` без шаблона: `POST /`, `POST /{id}/verify`, `POST /refresh`,
  `POST /{id}/link-partner`, `POST /{id}/unlink-partner`, `GET /me`, `POST /me/profile`, `GET /{id}`;
- канон `04-architecture/api-index.yaml`: `path: /api/v1/clients` → `operationId: Client.Register` (**POST**);
- маршрут списка удалён коммитом `33a6889e2` («GET /clients убран», 2026-11-03) — **до** создания карточки.

**Предлагаемый честный критерий (по формулировке @AR):** PII закрыт **удалением маршрута**, и доказывается это
кодом + каноном (нет `[HttpGet]` без шаблона; в каноне `Client.Register` — POST; удаление `33a6889e2`), а не кодом
ответа. Всё, что измеримо по HTTP, — `POST /api/v1/clients` с пустым телом → `400` (канон AR-025, phone обязателен).
Если нужен ещё и `404` изнутри контура — он достижим **только с токеном** (без токена любой путь даёт `401`).

## Решающая проба с валидным JWT (@AR 23:58) — выполнена @DO 2026-11-13

Токен добыт штатным путём на dev: `POST /api/v1/clients {phone}` → **200** + `id`; `POST /api/v1/clients/{id}/verify {code}`
→ **200** + `accessToken`.

| проба | ожидание @AR | **факт** |
|---|---|---|
| `GET /api/v1/clients` **с валидным JWT** | `404` | **`405 Method Not Allowed`** — путь существует как **POST-only**, GET к нему не разрешён |
| `GET /api/v1/definitely-not-a-route` **с JWT** | `404` | **`404`** — несуществующий путь действительно даёт 404 |
| `GET /api/v1/clients` **без** токена | `401` | **`401`** (вакуумно, доказательством не считается) |
| `GET /api/v1/definitely-not-a-route` **без** токена | `401` | **`401`** |
| `POST /api/v1/clients {}` | `400` | **`400`** `Phone field is required` (канон `AR-025`) |

Разница `405` vs `404` — не придирка: `405` означает «маршрут `POST /api/v1/clients` есть, а `GET` к нему — нет»,
то есть **GET-маршрута списка не существует**, и видно это с авторизацией, а не через `401` шлюза/сервиса.
`404` на выдуманном пути показывает, что дело именно в методе, а не в том, что 404 не отдаётся никогда.

**Критерий (принимаемая формулировка):** GET-маршрута списка нет — код (`ClientsController.cs`: 8 маршрутов, ни одного
`[HttpGet]` без шаблона), канон (`/api/v1/clients` = `Client.Register`, POST; удалено `33a6889e2`), и **измерено**:
с валидным JWT `GET /api/v1/clients` = **405**, любой несуществующий путь = **404**, `POST {}` = **400**.
