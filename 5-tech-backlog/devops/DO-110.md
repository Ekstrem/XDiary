## Факт: две копии `7-deploy` с разным состоянием

| каталог | `deploy.sh` | `secrets/.env` | чем опасен |
|---|---|---|---|
| `/home/deploy/XDiary/7-deploy` | 8530 Б, 4 ноя | **НЕТ** | `podman run --env-file secrets/.env` → `rc=125` «no such file or directory» |
| `/opt/xdiary/7-deploy` | 8530 Б, тот же | **ЕСТЬ** (было **664**) | рабочий путь; `.env` читался всеми → исправлено на **600** |

То есть канонический запуск (`--env-file secrets/.env`) работает только из `/opt/xdiary/7-deploy`;
из `/home/deploy/XDiary/7-deploy` он падает **до** создания контейнера.

Дополнительно: в строке `xdiary-client` копии `/home/deploy/XDiary/7-deploy/deploy.sh` —
**устаревший пароль БД** (`password authentication failed for user "client"`, SQLSTATE 28P01),
а рабочие строки подключения живут в `env` самого контейнера. Из-за этого пересоздание
«по этой строке» даёт краш-луп, даже когда сеть и образ верные.

## Хронология инцидента (моя ошибка, фиксирую честно)

1. Решил выкатить `client` точечно (не весь `deploy.sh`) с образом `single-766e59e` (содержит фикс `BE-090`).
2. Собрал `podman run` из `podman inspect` — **потерял** `--network xdiary`, `--ip`, `--read-only`,
   строки подключения и `--env-file`; `podman pull`/`run` вернули **125**, контейнер был удалён →
   **`POST /api/v1/clients` отдавал 500 ≈ 20 минут**, `/health` при этом 200 (его отдаёт Caddy).
3. Откат на прежний образ по id — контейнер поднялся, но 500 сохранился: образ старый, а env я
   восстановил из `inspect` (31 переменная) — этого хватило, но `-e` из `deploy.sh` перекрыл
   строки подключения **устаревшим паролем** → краш-луп `28P01`.
4. Рабочее решение: взять строку `client` из `deploy.sh`, заменить тег на `single-766e59e`,
   **убрать `-e ConnectionStrings__*`** и подставить `--env-file` с env исходного контейнера →
   `running restarts=0`, `POST` → 200.

## Что сделать (чтобы это не повторилось)

1. **Один источник правды:** оставить `/opt/xdiary/7-deploy` (там есть `secrets/.env`), а
   `/home/deploy/XDiary/7-deploy` — либо симлинк, либо удалить чек-аут, чтобы не было «двух деплоев».
2. **Строки подключения — только из `secrets/.env`**, не в `deploy.sh`: сейчас пароль в файле
   устарел, а рабочий — в `secrets/.env`.
3. **`secrets/.env` = 600** (сделано), проверку прав добавить в `check_secrets`/ранбук.
4. **Скрипт точечной выкатки** `7-deploy/deploy-one.sh <service> <tag>`: берёт команду из `deploy.sh`,
   подменяет тег, **не теряет** флаги, делает `pull` → `run` → health-чек → **откат по id образа**.
   Ручная реконструкция `podman run` из `inspect` должна быть запрещена ранбуком.
5. **Проверка перед `rm -f`:** если `podman pull` не удался — контейнер не трогаем (сейчас порядок
   действий это нарушил: pull упал, а `rm -f` уже был выполнен).
