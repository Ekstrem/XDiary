# DO-073: миграции БД не применяются — `deleted_at` нет ни на проде, ни на dev

- **Статус:** На проверке
- **Приоритет:** **P0** (E1 «soft-delete» не работает в работающих контурах: код есть, колонки нет)
- **Источник:** @DO 2026-11-14 23:21, проверено на живой схеме: **prod** `partners` rev `b0b1de20a1e1` — колонки `Id, Name, Photo, Gender, Notes, Version, ClientId`, **`deleted_at` НЕТ**, применено только 3 миграции (`InitialCreate`, `AddSelfToPartner`, `AddClientIdToPartner`); **dev** `partners` rev `4c3e03c2b878` — **та же схема и те же 3 миграции**. При этом миграция `20261113120000_AddDeletedAtToPartner` **есть в репозитории** (`5eed2ae1`), и `merge-base --is-ancestor 5eed2ae1` = да для обоих образов → **код с миграцией в образах есть, а в БД её никто не применил**
- **Зависимости:** нет
- **Проверяет:** @TL

## Задача (зона @DO, `7-deploy/` + БД)

1. **Применить миграции на dev**, затем на **проде** (`dotnet ef database update` или стартовый шаг сервиса — выбрать штатный способ и записать его в ранбук).
2. **Проверить фактом:** `deleted_at` присутствует в `partners` на обоих контурах; `Remove()` партнёра ставит `DeletedAt`, запись исчезает из `GET /partners`, `GET /partners/{id}` → 404.
3. **Устранить причину:** миграции должны применяться **автоматически** в контуре деплоя (шаг в `update.sh`/compose или startup-migration с логом), а не «руками когда вспомнили».
4. **Гейт (антирецидив):** проверка «версия схемы соответствует коду» — сравнение применённых миграций с последней миграцией в репозитории; расхождение → **rc≠0** в CI/деплое.

## Критерии приёмки

- [ ] dev и прод: список применённых миграций **совпадает** с репозиторием (число и последняя — в отчёте).
- [ ] `deleted_at` есть в `partners` на обоих контурах (проверка запросом, вывод — «колонка есть/нет»).
- [ ] Soft-delete работает: удаление партнёра → исчез из списка, 404 по id (ручной прогон + ссылка на тест).
- [ ] Миграции применяются **шагом деплоя**, а не вручную (строка в ранбуке + фактический прогон).
- [ ] Гейт «схема = код» написан, дефект/норма по §5.4, `REF` в отчёте.
