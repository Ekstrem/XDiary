# DO-038: Ранбуки инфраструктуры (`7-deploy/runbooks/`)

- **Статус:** На проверке
- **Приоритет:** P2
- **Источник:** `AGENTS.md` §5.2 («ADR — почему, ранбук — как»), `docs/PDR.md` PDR-15, @LM 2026-11-02 19:59/20:01
- **Зависимости:** ADR-019, ADR-020, ADR-021
- **Проверяет:** @TL (автор @DO — саморевью запрещено, §2.1 п.6)

## Задача

Один и тот же класс работ начинался каждый раз с нуля: `ci-tests.yml` правился 4 раза
(DO-030/031/032/035), `update.sh` терял сервис, шлюз полдня жил без `--add-host`, Caddy без
обработчика корня отдавал 502. Нужны ранбуки: точные команды, гейты, грабли, критерий
готовности — со ссылкой на ADR, без пересказа решения.

Классы согласованы с @LM/@AR: **`ci-workflow`, `deploy-heal`, `secrets-rotation`, `release-gate`**.
Вместо предложенного `board-sync` взят `release-gate`: доска управляется скриптами
(`sync_board.py`, `cleanup_orphans.py` с `--list`/`--delete`), ранбук дублировал бы их интерфейс.
`release-gate` — самый ошибочный класс («зелёным» считали вытесненный прогон, образ на проде
проверяли глазами).

## Сделано

- `7-deploy/runbooks/README.md` — индекс классов, **кто может запускать** (SSH только у `@DO`;
  остальным он не нужен — всё видно в CI-логах), общие правила (одно доказательство на прогон,
  не пушить при pending, «дошло» проверять после `fetch`).
- `7-deploy/runbooks/ci-workflow.md` — правка workflow: джобы до/после, дубль guard'ов
  (`chat-guards.yml` + `ci-tests.yml`), негативный тест секрет-сканера, грабли вытеснения
  dispatch'а и `--reporter=list,json`.
- `7-deploy/runbooks/deploy-heal.md` — передеплой и heal: проверка **содержимого образа**
  (`grep -ac AddJwtBearer`/`UseAuthentication`), `--add-host clients`, `gen-hosts.py --check`.
- `7-deploy/runbooks/secrets-rotation.md` — добавление/сверка/ротация: `keycmp.py` без раскрытия
  значений, что «фрагмент = утечка», почему зачистка после коммита не спасает.
- `7-deploy/runbooks/release-gate.md` — Definition of Ready-to-ship: прогон завершился **сам**,
  `smoke-api`/`smoke-front`, проверка образа на проде, вход владельца по коду.

## Критерии приёмки

- [x] Четыре ранбука по шаблону `LoopMaker/templates/runbook.md` (класс, когда, ADR, дата ревизии, шаги, гейты, грабли, критерий готовности, откат).
- [x] Каждый содержит негативный тест — то есть гейт проверяем не только «на зелёном».
- [x] Ссылки на ADR и на инструменты существуют (проверено: `adr-019/020/021.md`, `tools/gen-hosts.py`, `keycmp.py`, `check_secrets.py`, `check_workflow_paths.py`).
- [x] `check_rule_docs` — 0 предупреждений (нет абсолютных домашних путей), `check_nul` — OK.
- [x] Секретов нет: только имена переменных (`Otp__*`), без значений.

## Результат

Ранбуки в `7-deploy/runbooks/` (4 класса + индекс). Каждый — со ссылкой на ADR, а не пересказом;
содержат реальные команды и грабли из инцидентов этой сессии. `board-sync.md` намеренно не
заведён — источник правды остаётся у скриптов доски.
