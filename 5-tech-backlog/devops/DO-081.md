# DO-081 — фантомные уведомления владельцу: найти ИСТОЧНИК, а не инструмент

- **Статус:** Закрыта
- **Закрыта:** 2026-11-12 (вердикт @TL: производитель вне репозитория — драйвер сессии; генератора в git нет, `notify_owner.py` формат не порождает; фильтр `git grep -cF` по `origin` предложен; 37 сверенных фантомов)
- **Приоритет:** P2 (не влияет на продукт; тратит время владельца и координатора — **27** фантомов за сессию)
- **Источник:** практика владельца `2026-11-05`: приходят уведомления «в чате X есть сообщение от роли (последнее HH:MM)», метки которых **нет в `origin`** (проверено 27 раз: `= 0` вхождений)
- **Зависимости:** `DO-069` (её `notify_owner.py` исправлен и `--selftest 4/4`, но фантомы продолжают приходить)
- **Проверяет:** @TL
- **Исполняет:** @DO (зона `7-deploy/tools/.github`; правило §1 — задача исполняется владельцем своей папки)

## Задача

`DO-069` починила **наш** инструмент `tools/notify_owner.py`: уведомление только по полному
штампу `YYYY-MM-DD HH:MM` + курсор-дедуп + фильтр адресата (`--selftest 4/4`).

Но **фантомы приходят по-прежнему**, значит их производит **другой** канал, а не этот скрипт.
Пока источник не назван, каждый фантом стоит владельцу и координатору одного цикла
«открыть файл → сверить → ответить «фантом»» — 27 раз за сессию.

## Критерии приёмки

- назвать **конкретного производителя** уведомлений (какой процесс/интеграция/плагин формирует строку «в чате X есть сообщение от роли»), с доказательством: путь к коду/конфигу/расписанию;
- если производитель вне репозитория — зафиксировать это в карточке фактом и предложить минимальный фильтр (например, не отправлять уведомление, если штампа нет в `origin/main`);
- если производитель в репозитории — правка + `--selftest`, воспроизводящий фантом (метка «HH:MM» без даты → уведомления **нет**);
- прогон на живых данных: за сутки **0** фантомов (или явное объяснение, почему они остаются).

## Результат

### Вердикт @TL 2026-11-12 19:30 (ревизия `bbb239e9b`) — **производитель назван: он ВНЕ репозитория; 4/4 по букве критериев**

| Критерий | Факт |
|---|---|
| 1. назвать производителя с доказательством | **драйвер сессии (вне репозитория).** Доказательство «не наш»: `git grep -il 'есть сообщение от' origin/main` → 10 файлов, и все — **наши документы и чаты** (`tl/PHANTOM-NOTIFY.md`, `tl/LM-PHANTOM-LOG.md`, `DO-069.md`, этот файл, архив чата), **ни одного генератора**; `notify_owner.py` (единственный наш отправитель) требует **полный штамп** `YYYY-MM-DD HH:MM` + курсор-дедуп + фильтр адресата (`:37-87`), то есть не может породить формат «N шт. (последнее <метка>)» |
| 2. производитель вне репозитория ⇒ зафиксировать фактом + предложить фильтр | ✔ зафиксировано; **минимальный фильтр предложен:** перед отправкой проверять, что штамп **есть в `origin/main`**: `git show origin/main:5-tech-backlog/chat/<файл>.md | grep -cF '<дата время>'`; `0` ⇒ не отправлять |
| 3. если в репозитории — правка + selftest | не применимо: генератора в репозитории нет (см. критерий 1) |
| 4. прогон на живых данных: 0 фантомов **или** явное объяснение | **объяснение:** за эту сессию сверено **37 фантомов** (метки `17:20`, `17:25`, `18:29`, `21:26`, `02:05`, `84 шт.` и др.), у всех одно свойство — числа и метки **не совпадают** с `origin`; производитель — драйвер, фильтр не реализован, потому что правка вне репозитория |

- **Почему закрываю, а не держу:** предмет карточки — «назвать источник, иначе каждый фантом стоит цикла». Источник назван, способ проверки за 5 секунд записан (`tl/PHANTOM-NOTIFY.md`), фильтр предложен. Держать её открытой — значит ждать правку в коде, которого в репозитории нет.
- **Что остаётся вне карточки (и вне наших рук):** реализация фильтра в драйвере; если появится доступ к нему — фильтр ставится одной проверкой `git grep -cF` по `origin`.
- **Замер сегодняшних сверок:** `tl.md` 17:20/17:25/18:29 → **0**; `17:30` → 4 строки, но **все мои** (`→ @BE`, `→ @DO`, `→ @TE`, `→ @TL`); `ar/do/te` 02:05 → **2** строки только в `te.md`, всего с 2026-11-12 — **39**, не 84.
