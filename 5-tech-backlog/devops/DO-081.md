# DO-081 — фантомные уведомления владельцу: найти ИСТОЧНИК, а не инструмент

- **Статус:** ToDo
- **Приоритет:** P2 (не влияет на продукт; тратит время владельца и координатора — **27** фантомов за сессию)
- **Источник:** практика владельца `2026-11-05`: приходят уведомления «в чате X есть сообщение от роли (последнее HH:MM)», метки которых **нет в `origin`** (проверено 27 раз: `= 0` вхождений)
- **Зависимости:** `DO-069` (её `notify_owner.py` исправлен и `--selftest 4/4`, но фантомы продолжают приходить)
- **Проверяет:** @TL
- **Исполняет:** @DO (зона `7-deploy/tools/.github`; правило §1 — задача исполняется владельцем своей папки)

## Задача

`DO-069` починила **наш** инструмент `tools/notify_owner.py`: уведомление только по полному
штампу `YYYY-MM-DD HH:MM` + курсор-дедуп + фильтр адресата (`--selftest 4/4`).

Но **фантомы приходят по-прежнему**, значит их производит **другой** канал, а не этот скрипт.
Пока источник не назван, каждый фантом стоит владельцу и координатору одного цикла
«открыть файл → сверить → ответить «фантом»» — 27 раз за сессию.

## Критерии приёмки

- назвать **конкретного производителя** уведомлений (какой процесс/интеграция/плагин формирует строку «в чате X есть сообщение от роли»), с доказательством: путь к коду/конфигу/расписанию;
- если производитель вне репозитория — зафиксировать это в карточке фактом и предложить минимальный фильтр (например, не отправлять уведомление, если штампа нет в `origin/main`);
- если производитель в репозитории — правка + `--selftest`, воспроизводящий фантом (метка «HH:MM» без даты → уведомления **нет**);
- прогон на живых данных: за сутки **0** фантомов (или явное объяснение, почему они остаются).
