# DO-123: `ci-guards` и `ci-backend` делят ОДНУ группу concurrency на все PR → чеки приходят `cancelled`

- **Статус:** ToDo
- **Приоритет:** **P0** (пока группы общие, при ≥2 открытых PR чеки отменяются **механически**, и мерж невозможен независимо от содержимого)
- **Источник:** разбор @TL 2026-11-13 01:16 по фактам: #2169 `test` → `cancelled` (job `131505215083`), ранее #2174 `check-chat` → `cancelled`; 8 открытых PR
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @DO (`.github/workflows/`)

## Факт (аннотации, а не догадка)

```
#2169 (role/be), чек `test` (ci-backend), job 131505215083:
[failure] Canceling since a higher priority waiting request for ci-tests-test exists
→ job: test -> cancelled

#2174 (role/tl), ранее: чек `check-chat` (ci-guards):
[failure] Canceling since a higher priority waiting request for ci-guards exists
```

## Корень: группа без привязки к PR

| Файл | Группа | Что это значит |
|---|---|---|
| `ci-guards.yml:25` | `group: ci-guards` | **все PR и все ветки — одна группа** |
| `ci-backend.yml:36` | `group: ci-tests-test` | **все PR — одна группа** |
| `status-lint.yml:17` | `group: status-lint-${{ github.event.pull_request.number || github.ref }}` | **правильный образец, уже есть в репозитории** |
| `docs-budget.yml:24`, `guard-tools.yml:18` | так же с `pull_request.number` | правильный образец |

`cancel-in-progress: false` (правка `DO-122`) меняет только «отменить **running**» на «поставить в очередь»: GitHub всё равно **отменяет pending-прогон**, если в ту же группу пришёл новый. Поэтому `DO-122` **недостаточен**: он снял вытеснение текущего прогона, но не отмену ожидающего.

При 8 открытых PR и пушах подряд это не теория: отменяются чеки у **разных** PR, а merge queue видит `cancelled` как «не прошёл».

## Задача

1. `ci-guards.yml`: `group: ci-guards-${{ github.event.pull_request.number || github.ref }}`.
2. `ci-backend.yml`: `group: ci-tests-test-${{ github.event.pull_request.number || github.ref }}` (сохранить `cancel-in-progress: false` для тяжёлого).
3. Проверить остальные свои группы на тот же дефект (`git grep "group:" .github/workflows` — группы без `pull_request.number`/`ref` считать подозрительными).

## Критерии приёмки

- [ ] два пуша в **разные** ветки подряд → **оба** прогона `ci-guards` (и `ci-backend`) доходят до конца, оба чека `success`;
- [ ] в аннотациях нет `Canceling since a higher priority waiting request`;
- [ ] `check_workflow_shape` / `check_workflow_paths` → `rc=0`;
- [ ] на `#2169` и `#2174` после правки: `test` и `check-chat` приходят в `success` или `failure` **по содержанию**, но не `cancelled`.

## Граница

Содержимое PR к этому отношения не имеет: у `#2165` те же группы, но его прогоны шли первыми — поэтому там 13 чеков `pass`. Это **не** регресс `DO-122`: тот фикс правильный, но покрывал половину механики.
