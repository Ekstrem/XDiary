# DO-093: гейт проверяет **значения статусов ADR** по закрытому словарю

- **Статус:** На проверке
- **В работе с:** 2026-11-05
- **Приоритет:** P2 (документный гейт; дешёвая проверка, ловит «девятый статус»)
- **Источник:** @AR `2026-11-05 17:45` — `check_adr` печатает «проверено 0, старых пропущено 33» и **не валидирует значения**
- **Норма:** @LM (словарь — правила владельца, `RULES.Architect.md` 13:27)
- **Проверяет:** @AR

## Задача

`tools/check_adr.py` (444 строки) проверяет структуру ADR, но **не проверяет значение статуса**.
Поэтому в документе мог появиться статус вне словаря (случай `ADR-013`: `Заменено`), и гейт этого
не заметил — «проверено 0» при 33 пропущенных по грандфазерингу.

## Словарь (закрытый, семь значений)

| Значение | Требования |
|---|---|
| `Черновик` | в реестр `ADL/README.md` не попадает |
| `Предложено` | — |
| `Принято` | дата |
| `Пересмотрен (дата)` | **дата** + ссылка на ADR, которым заменён (включает бывший `Заменено`) |
| `Отменён (дата)` | **дата** + причина |
| `Отклонено` | **причина** |
| `Отложено` | **причина** + что разблокирует |

## Правило гейта

1. Для ADR, **созданных после канона** (граница грандфазеринга, как у существующего правила):
   значение статуса ∈ словарю выше, иначе **`rc=1`** с именем файла и значением.
2. `Пересмотрен`/`Отменён` **без даты** → `rc=1`. `Пересмотрен` **без ссылки на ADR** → `rc=1`.
   `Отклонено`/`Отложено` **без причины** → `rc=1`.
3. `Черновик` **не должен** появляться в реестре `ADL/README.md` → `rc=1`.
4. Старые ADR (до границы) — `[grandfathered]`, `rc` не красят (как сейчас).
5. `0 ADR в проверке` → **`rc=2`** «НЕ ИЗМЕРЕНО» (не «в норме»).

## Критерии приёмки

- `--selftest` с кейсами: (а) статус вне словаря → `rc=1`; (б) `Пересмотрен` без даты → `rc=1`;
  (в) `Пересмотрен` без ссылки → `rc=1`; (г) корректный словарь → `rc=0`; (д) `Черновик` в реестре → `rc=1`;
  (е) `0 ADR` → `rc=2`;
- прогон на текущем `origin` → **`rc=0`** (`ADR-013` уже нормализован: `Пересмотрен (2026-11-09) — заменён ADR-023`);
- красный контроль — на **фикстуре** (во временном дереве), а не на живом репозитории;
- шаг в `ci-guards` блокирующий, `--selftest` **перед** нормой.

## Результат

**Инструмент:** `tools/check_adr_status.py` — словарь семи значений и пять правил @TL проверяются
как отдельный гейт (структуру по-прежнему проверяет `check_adr.py`; «одно условие — один инструмент»).

**`--selftest 10/10`:** (а) статус вне словаря → `rc=1`; (б) `Пересмотрен` без даты → `rc=1`;
(в) `Пересмотрен` без ссылки → `rc=1`; (г) корректный словарь → `rc=0`; (г2) `Пересмотрен` с датой
и ссылкой → `rc=0`; (д) `Черновик` в реестре → `rc=1`; (д2) `Черновик` вне реестра → `rc=0`;
(е) `0 ADR` → `rc=2`; (ж) старый ADR вне словаря + новый корректный → `rc=0` (grandfathered);
(з) все ADR старше канона → `rc=2`.

### 🔴 Главное: на текущем `origin` гейт проверять **нечего** — и это не его дефект

```
check_adr_status: проверено ADR 0, старых пропущено 33, нарушений 0 (канон 2026-11-08)
::error::check_adr_status: НЕ ИЗМЕРЕНО — 0 ADR после канона, проверять нечего
rc=2
```

Причина та же, что у `check_adr.py` («проверено 0, старых пропущено 33» — цитата @AR): граница
грандфазеринга `2026-11-08` **позже дат коммитов** в репозитории (сегодня 2026-11-05), поэтому
**все** ADR попадают в «старые». То есть граница вакуумна, а не строга.

### Что гейт находит, если грандфазеринг снять (`--canon 1970-01-01`)

```
проверено ADR 33, старых пропущено 0, нарушений 18
rc=1
```

18 нарушений, из них массово: `Принято без даты` (`adr-014, 015, 016, 018, 019, 020, …`) и
`Отложено без «что разблокирует»` (`adr-017`). Это **реальные** расхождения корпуса ADR со словарём,
но их нормализация — зона @AR/@LM, а не DevOps.

### Поэтому критерий «на текущем `origin` → `rc=0`» **недостижим** и шаг в `ci-guards` не включён

Включать блокирующий шаг сейчас можно только в одном из двух состояний: `rc=2` (проверять нечего)
или `rc=1` (18 нарушений). Оба красят `main`, не указывая на **новый** дефект. Предлагаю порядок:
(1) @AR/@LM выбирают фактическую границу канона (или нормализуют 18 ADR), (2) я ставлю границу
в `ci-guards` и включаю шаг блокирующим. Инструмент к этому готов: смена границы — один флаг.
