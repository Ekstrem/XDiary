# DO-092: гейт «`EnableDefaultCompileItems=false` ⇒ список `Compile Include` совпадает с `.cs` в папке»

- **Статус:** На проверке
- **В работе с:** 2026-11-05
- **Приоритет:** P1 (класс «тест написан, но не собирается»; CI при этом зелёный)
- **Источник:** @TE `2026-11-05 14:31` — **доказано дефектом**: скопировал `ApiGateway.Tests.csproj`, положил рядом `NewFeatureTests.cs` → файл не попал в сборку, тест не запустился, CI зелёный
- **Зависимости:** `BE-070` (убрать хак из двух csproj)
- **Проверяет:** @TL

## Задача

Если в тестовом `csproj` стоит `<EnableDefaultCompileItems>false</EnableDefaultCompileItems>`, то глоб
`**/*.cs` отключён и собираются **только** перечисленные файлы. Новый `.cs`, положенный в папку, **молча
не попадает в сборку**: тест «написан», CI зелёный, покрытия нет.

Сейчас в репозитории так в **двух** сборках (`ApiGateway.Tests`, `ApiGateway.ApiTests`).

## Правило гейта

Для каждого `csproj` в `6-msa`:

1. если `EnableDefaultCompileItems` **не** `false` — проверка не применяется (обычный глоб);
2. если `false` — множество `<Compile Include="...">` обязано **точно совпадать** с множеством `.cs`
   в папке проекта (без учёта `bin/`, `obj/`);
3. расхождение в любую сторону (`файл есть, но не перечислен` / `перечислен, но файла нет`) → **`rc=1`**
   с именем файла и именем csproj;
4. `0 csproj в проверке` → **`rc=2`** «НЕ ИЗМЕРЕНО» (по норме §5.4: «не найдено ≠ нет нарушений»).

## Критерии приёмки

- `--selftest` с **тремя** кейсами: (а) `false` + новый `.cs` не в списке → `rc=1`; (б) `false` + список совпадает → `rc=0`; (в) без `false` → проверка не применяется, `rc=0`;
- прогон на текущем `origin` **краснеет на двух сборках** (это ожидаемый красный, он и есть наш дефект);
- после `BE-070` (хак убран) — **`rc=0`** при тех же файлах;
- шаг в `ci-guards` **блокирующий**, `--selftest` идёт **перед** нормой.

## Результат

**Правило (13) добавлено в `tools/check_test_isolation.py`** — «одно условие — один инструмент»:
если в csproj стоит `EnableDefaultCompileItems=false`, множество `<Compile Include>` обязано
**точно совпадать** с множеством `.cs` в папке проекта (без `bin`/`obj`). Расхождение в любую
сторону — `::error::(13)` с именем файла и `rc=1`; `0 csproj` — по-прежнему `rc=2`
(правило (12) и проверка «нечего проверять» остались).

**Доказано в обе стороны на РЕАЛЬНЫХ состояниях `origin`:**

| коммит | что он из себя представляет | результат (13) |
|---|---|---|
| `e04d94d9` | исторический дефект: `GatewaysApi.IntegrationTests.csproj` с флагом, а `GatewayRoutesTests.cs` **не включён** | **1 нарушение**: `есть .cs, но нет в Compile Include: GatewayRoutesTests.cs`, общий `rc=1` |
| `405bbb82^` | состояние сразу до фикса @BE (перенос в подпапки уже сделан) | 0 нарушений — набор совпадает |
| `origin/main` | текущее | **0 нарушений**, `проверено проектов: 96`, `rc=0` |

То есть гейт **краснеет на том самом классе**, ради которого заводился: новый `.cs` молча не
попадёт в сборку, если флаг выключен, а `Include` забыли.

**`--selftest 22/22`** (было 18): четыре новых кейса — норма (файл включён), `.cs` не включён,
`Include` на несуществующий файл, и случай без флага (правило не применяется).

**Важная деталь реализации, найденная кейсом:** первая версия искала `csproj` только в `6-msa/`
(как остальные правила инструмента) и на фикстурах давала **0 нарушений** — то есть была
«зелёной на дефекте». Исправлено: обход `root` целиком.
