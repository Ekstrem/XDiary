## Факты (prod, проверено 19:15)
- `privacy.pin_credential`: **1 строка** (PIN владельца), колонки: `Id, SourceId, Salt, Hash, Iterations, Locked, Version` — **без `client_id`**.
- `client.clients`: **0 строк** — клиент на проде ещё не заведён (single-user, но онбординг не прогоняли).
- Миграция `AddClientIdToPin`: добавляет `client_id` (uuid, `NOT NULL`, default `Guid.Empty`) + уникальный индекс `(ClientId, SourceId)`.

## План
1. **Бэкап `privacy` до деплоя** (до миграции), на VPS-1:
   ```bash
   podman exec xdiary-pg pg_dump -U postgres -d privacy -Fc \
     -f /home/deploy/backups/privacy-pre-be036-$(date +%Y%m%d%H%M%S).dump
   ```
2. **Деплой** (privacy → EF применит `AddClientIdToPin`: существующий PIN получит `client_id = 00000000-...`).
3. **Привязка PIN к клиенту владельца**:
   ```sql
   UPDATE pin_credential SET "ClientId" = '<owner_client_id>'
   WHERE "ClientId" = '00000000-0000-0000-0000-000000000000';
   ```
4. **Проверка**: вход по PIN владельца → 200.

## Блокер выполнения
`<owner_client_id>` пока **не существует** (`client.clients` пуст). Причина: **OTP на проде не доставляется** (нет транспорта — BE-037), поэтому онбординг владельца невозможен. **Клиента вручную НЕ создаём** (решение TL 20:10): ручной клиент не даст вход (нет PIN-привязки к телефону). Ждём решения владельца по каналу OTP → онбординг → берём его id.

## Критерии приёмки
- [ ] Бэкап `privacy` сделан до деплоя и восстановим (`pg_restore`).
- [ ] PIN владельца привязан к клиенту; вход по PIN работает (hash не тронут).
- [ ] Ни один PIN не потерян/не пересоздан без согласования.
