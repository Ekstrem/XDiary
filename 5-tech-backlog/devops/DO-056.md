# DO-056: APIM (Gravitee) как источник правды контрактов + drift-check — ADR-023 (решение B)

- **Статус:** В работе
- **Приоритет:** P2 (после P0 по продукту; начинать после BE-050)
- **В работе с:** 2026-11-09
- **Источник:** ADR-023 пересмотрен **C → B** решением владельца (AR 2026-11-09 00:38: «владелец решил ADR-023 → B (полный APIM, Gravitee): OpenAPI-контракты импортируются в APIM, источник правды»); условие @LM 01:37 («repo → APIM»: спека в git, APIM — рантайм, иначе экспорт+drift-check)
- **Зависимости:** BE-050 (OpenAPI генерируется из кода и коммитится — **остаётся обязательным**, APIM потребляет эти спеки), DO-052 (path-based деплой), ADR-007 (YARP), ADR-013
- **Проверяет:** @TL (TechLead) — саморевью запрещено: автор @DO

## Задача (зона @DO, `.github/`, `7-deploy/`, `tools/`)

1. **Импорт вместо ручного авторинга:** OpenAPI-спеки из `openapi/*.json` (артефакт BE-050) импортируются в Gravitee **идемпотентно по тегу** (`single-<SHA>`), а не вручную в UI и не в `latest`.
2. **Drift-check (обязателен, это ядро решения):** ежедневная сверка «экспорт APIM ↔ git»; расхождение → **красный гейт/алерт**. Ручные правки в APIM запрещены, кроме аварийного хотфикса с обязательным обратным экспортом в git в тот же день.
3. **Локальная разработка без APIM:** профиль dev не требует APIM (сервисы поднимаются как сейчас) — иначе новый компонент остановит работу всех ролей.
4. **Breaking-change детектор** (перенос из прежней редакции): сравнение спеки с версией в `main` (`oasdiff`, версия пинована), нормализация формата, удаление поля/смена типа/новый обязательный параметр → failure с требованием `/v2`.
5. **Версия Gravitee пинована** и записана в задаче; **лицензия проверена** (LM назвал риск: лицензия Gravitee) и зафиксирована в ADR/ранбуке.
6. **Smoke через APIM:** отдельный прогон, который проверяет путь «клиент → APIM → сервис», а не только прямой порт.

## Критерии приёмки
- [ ] Спека из git импортируется в APIM по тегу; повторный импорт идемпотентен (не создаёт дублей).
- [ ] Ручная правка в APIM ловится drift-check в течение суток (негативный контроль: изменил в APIM → красный).
- [ ] Ломающее изменение спеки → failure с перечнем; аддитивное → success.
- [ ] `dev`-профиль поднимается **без** APIM (проверено прогоном).
- [ ] Версия Gravitee и решение по лицензии зафиксированы в ADR-023/ранбуке.
- [ ] Smoke «через APIM» зелёный и покрывает хотя бы один реальный маршрут (`/api/v1/clients`).

## Ресурсы и этапность (TL, решение 2026-11-09 05:40)

**Замер @DO 05:25 (VPS-1):** RAM 5904 МБ, свободно **4234 МБ**, 4 vCPU, диск 102 ГБ свободно; 13 контейнеров ≈ **990 МБ**. Gravitee CE + MongoDB + Elasticsearch ≈ **2.2–2.7 ГБ** → после внедрения остаётся **~1.5–2 ГБ**.

**Решение: два этапа, APIM вводим не сразу в трафик.**

1. **Этап 1 (сейчас, без риска доступности): APIM как control plane.** Gravitee CE поднимается **вне пути запросов**: импорт `openapi/*.json` (BE-050), жизненный цикл версий, портал, drift-check. Трафик идёт **Funnel → YARP → сервисы**, как сейчас. Это ровно то, что просил владелец («API помещать туда»), и при этом **падение APIM не влияет на продукт** — деградация по умолчанию, как и описал @DO.
2. **Этап 2 (после замера на dev): APIM в пути** — только если Caddy/edge умеет активные health-checks (`health_uri`, требует Caddy ≥ 2.5) и если замер RSS за 24 часа на dev показал запас **≥ 1 ГБ** на пике. **Обязательно:** Elasticsearch с ограниченным heap (`-Xms512m -Xmx512m`), иначе ES съест запас и уронит прод по памяти.
3. **Запрет:** поднимать ES/Mongo/Gravitee сразу на проде **без PoC на dev** и без суточного замера RSS. Причина — правило «< 500 МБ свободной RAM на пике → не вводим»: сейчас запас формально есть, но ES растёт с индексами, и оценка «2.2–2.7 ГБ» — это старт, а не пик.

**Негативный контроль (одинаков для этапов):** остановили APIM → `GET /api/v1/clients` отвечает **200** (на этапе 1 — через YARP, на этапе 2 — через переключение edge).

## Постановка после замеров (@TL 2026-11-09 07:35, зафиксировано @DO)

- **PoC на dev снят с требования** — у dev-VPS свободно 93 МБ и нет swap, стек 1.91 ГБ туда не влезает. Апгрейд dev RAM **не просим**, swap 2 ГБ **не добавляем** (числа были бы swap-driven).
- **Этап 1 делаем на VPS-1 как control plane** (трафик не трогаем: `Funnel → YARP → сервисы`), с жёсткими лимитами: ES `-Xms512m -Xmx512m`, `mem_limit` на каждый компонент (gateway/management 512 МБ, Mongo 256–512, ES не более 1 ГБ).
- **Суточный замер RSS — на VPS-1** после включения; по нему решение про этап 2 (APIM в пути).
- **Негативный контроль этапа 1:** остановили APIM → `GET /api/v1/clients` = **200**.
