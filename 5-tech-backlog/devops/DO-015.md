# DO-015: CD pipeline (pull-based: dev авто cron, prod по release-флагу)

- **Статус:** Закрыта (DevOps: вариант B pull-based — dev авто cron, prod по release-флагу `/etc/xdiary/prod-release`)
- **Приоритет:** P2
- **Источник:** ADR-020 (CD pipeline, черновик)
- **Зависимости:** DO-012 (Funnel), ADR-019 (dev-стенд VPS-2)

## Задача
Реализовать CD по ADR-020: автоматическая доставка в **dev** на каждый merge в `main`, продвижение в **prod** по ручному approval.

## Критерии приёмки
- [ ] GitHub Environments `dev` и `prod` (у `prod` — protection rule: required reviewers / approval).
- [ ] Секреты в GitHub: `DEV_SSH_HOST`/`DEV_SSH_USER`/`DEV_SSH_KEY` (VPS-2 `77.91.73.67`/`ubuntu`) и `PROD_SSH_HOST`/`PROD_SSH_USER`/`PROD_SSH_KEY` (VPS-1 `31.192.111.168`/`deploy`).
- [ ] Workflow `deploy.yml`: push/merge в `main` → deploy **dev** (SSH → `update.sh` → `/health` 200) → E2E dev (`XDIARY_E2E_BASE_URL=https://xdiary-vps2.taile0b6ee.ts.net`) → manual approval → deploy **prod** (SSH → `update.sh` → `/health` 200).
- [ ] Продвижение dev→prod **теми же образами** (тег по commit SHA, а не `:single`).

## Результат
Выбран **вариант B (pull-based)** — без SSH-секретов/GitHub UI:
- `update.sh`/`deploy.sh` на обоих VPS принимают тег (`update.sh <tag>`, дефолт `single`).
- **dev (VPS-2)**: cron 15 мин авто подхватывает `single` (latest) — без гейта.
- **prod (VPS-1)**: cron 15 мин деплоит только при наличии release-флага `/etc/xdiary/prod-release` (иначе `skip`), после деплоя флаг удаляется (one-shot).
- `deploy.yml` (push/SSH) удалён как ненужный.

Гейт prod: создать флаг `sudo touch /etc/xdiary/prod-release` → следующий цикл cron задеплоит prod; для релиза конкретным тегом — `update.sh single-<SHA>` вручную на VPS-1.
