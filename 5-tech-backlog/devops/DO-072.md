# DO-072: аудит `ci-*.yml` — гейты, которые «зеленеют на пустоте»

- **Статус:** ToDo
- **Приоритет:** **P1** (зелёный CI без тестов = ложное доказательство готовности)
- **Источник:** два факта за сутки: (1) `ci-client.yml` — **ни одного шага тестов** (только restore+build), правка `BC-Client` тесты не запускала (@DO 2026-11-14 08:13); (2) `ci-backend.yml` — шаг `Run integration tests (9-tests)` искал `find 9-tests -name '*.IntegrationTests.csproj'`, **после ADR-028 таких проектов там нет** → находил **ноль и тихо проходил**, второй шаг гонял жёсткий список из 2 проектов из 29 (@DO 2026-11-14 23:15)
- **Зависимости:** `DO-063` (paths/пуск по зоне) — частично закрывает
- **Проверяет:** @TL

## Задача (зона @DO, `.github/workflows/`)

Систематический проход по **всем** `ci-*.yml` (13 файлов) с тремя проверками:

1. **Есть ли шаг тестов вообще** (а не только restore/build).
2. **Находит ли он что-нибудь:** `find`/`glob`-пути и жёсткие списки проектов должны соответствовать **текущей** раскладке (после ADR-028 тесты живут в `6-msa/BC-*/src/*Tests*`).
3. **Нет ли «тихого зелёного»:** пустой результат поиска должен быть `::error::`/`::warning::`, а не «0 файлов → успех».

## Критерии приёмки

- [ ] Таблица по 13 workflow: `workflow | есть шаг тестов | что запускает | находит ли что-то сейчас` — в отчёте.
- [ ] Ни один шаг не может «пройти на пустом списке» (для каждого — `::error::` при 0 проектов).
- [ ] Слепой контроль: подложить пустой список → **rc≠0**; норма → **rc=0**; `REF` в отчёте.
- [ ] Итог: `grep -c "find .*IntegrationTests" .github/workflows` = 0 (старые пути удалены).
