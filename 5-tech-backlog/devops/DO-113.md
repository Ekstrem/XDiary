## Задача

Довести `ADR-027` от «провенанс по коммиту» до «неизменяемая идентичность»:

1. `tools/gen_images_lock.py` при сборке из реестра пишет в строку **`digest=sha256:…`**
   (GHCR отдаёт `Docker-Content-Digest` в ответе на `manifests` — берём его, не считаем сами).
2. `7-deploy/deploy.sh` / `update.sh` тянут образ по **`@sha256:`**, а тег остаётся для читаемости.
3. `--verify-registry` дополнительно проверяет, что digest в lock **совпадает** с текущим
   digest тега в реестре; расхождение — `rc=1` «тег перезаписан» (это и есть защита от мутации).

## Критерии приёмки

- [x] в `7-deploy/images.lock` **12 из 13** строк имеют `digest=sha256:…`; у `front` — `digest=-` (образа в GHCR нет по построению: фронт едет через Pages, пакет отвечает 403 на анонимный pull-token). Строк с образами 13, digest-ов 12 — расхождение ровно на `front`
- [x] `grep -c 'sha256:' 7-deploy/images.lock` → **12** (было **0**)
- [x] `deploy.sh`/`update.sh` содержат `@sha256` (по 1 вхождению) и функцию `pull_by_digest`: тянет `ghcr.io/ekstrem/xdiary-<svc>@sha256:…` из lock, тег — только для чтения; `bash -n` обоих — OK на dev
- [x] `--verify-registry`: норма → **rc=0**; подменённый digest в lock → **rc=1** с «ТЕГ ПЕРЕЗАПИСАН journal:single-4b90af9 — в lock sha256:000…, в реестре sha256:e75d…»; `--selftest` расширен до **8/8** (кейсы «digest совпал → 0», «digest разошёлся → 1», «digest нет → 0»)
- [x] строка «деплой по digest, тег — только для чтения» добавлена в **существующий** `7-deploy/runbooks/deploy-ledger.md`: файла `runbooks/deploy.md` в репозитории нет (та же причина, что в `DO-110` — вариант A), поэтому правило живёт рядом с правилом точечной выкатки

## Результат

**Сделано @DO 2026-11-12.** `ADR-027` доведён от «провенанс по коммиту» до «неизменяемая идентичность» — по всем трём пунктам задачи.

| что | как |
|---|---|
| digest в lock | `tools/gen_images_lock.py`: `manifest_digest()` берёт **`Docker-Content-Digest`** из ответа реестра (не считаем сами), `lock_digests()` читает поле; новый режим `--fill-digests` (idempotent) дописывает digest в существующий lock |
| lock заполнен | **12 из 13** строк получили `digest=sha256:…` (пример: `journal … digest=sha256:e75d1e5d…`); `front` → `digest=-`, потому что образа в GHCR нет (Pages) |
| выкатка по digest | `deploy.sh` и `update.sh`: функция `pull_by_digest` тянет `ghcr.io/ekstrem/xdiary-<svc>@sha256:…` из lock, тег остаётся для читаемости; `bash -n` обоих — OK на dev |
| защита от мутации | `--verify-registry` сравнивает digest из lock с текущим digest тега: расхождение → **rc=1** «ТЕГ ПЕРЕЗАПИСАН …» |
| ранбук | строка «деплой по digest, тег — только для чтения» — в `runbooks/deploy-ledger.md` (файла `runbooks/deploy.md` нет; то же решение варианта A, что в `DO-110`) |

**§5.4 — обе стороны:** норма `--verify-registry` → **rc=0** (`сервисов 13 | опубликовано 12 | отсутствует 0 | не проверено 1`);
дефект (подменил digest первой строки на `sha256:000…`) → **rc=1** с точным адресом расхождения; `--selftest` → **8/8**.
