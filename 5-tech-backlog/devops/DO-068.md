# DO-068: гейт на маркеры конфликта в `.md`

- **Статус:** В работе
- **Приоритет:** P1
- **В работе с:** 2026-11-12
- **Источник:** @TL 2026-11-12 15:22 — маркеры конфликта в `chat/tl.md` попали в `origin`, и ни один гейт не покраснел
- **Зависимости:** `tools/check_nul.py` (тот же обход `.md`)
- **Проверяет:** @TL

## Задача

Маркеры конфликта (`<<<<<<<`, `=======`, `>>>>>>>`) в `.md` под `5-tech-backlog/` и
`04-architecture/` — **ошибка гейта** (rc=1), не предупреждение.

Почему не поймали раньше: `chat_lint` смотрит только строки, начинающиеся с `- [`, а маркеры
для него «нераспознанные»; `check_nul` искал управляющие байты, а маркеры — печатные символы.

## Критерии приёмки

- [ ] `check_nul` находит маркеры и печатает файл + номера строк, rc=1.
- [ ] Два прогона (§5.4): дефект (файл с маркером) → rc=1; норма (без маркеров) → rc=0.
- [ ] `--selftest` покрывает маркеры обоих видов и BOM-строку.

## Результат

**Сделано в `tools/check_nul.py`:** `PATTERNS` расширены на `04-architecture/**/*.md`;
добавлен `scan_markers()` (учёт BOM), маркер = ошибка; `--selftest` — 4 кейса (чистый файл,
`<<<<<<<`, `=======`, `>>>>>>>`).

**Прогоны (2026-11-12, dev-дерево, @DO):**

- **ДЕФЕКТ:** файл `5-tech-backlog/chat/ZZ-TMP-marker.md` с маркерами → `! … маркеры конфликта:
  стр.3 =======, стр.5 >>>>>>>` → **rc=1**.
- **НОРМА:** после удаления файла → `check_nul: OK (291 md-файлов, управляющих символов и
  маркеров конфликта нет)` → **rc=0**.
- `--selftest` → **4/4**.
