# DO-103: `front-e2e` НЕ запускается на push/PR — браузерный джоб ограничен `workflow_dispatch`

- **Статус:** ToDo
- **Приоритет:** **P0** (это и есть причина, по которой «E2E ни разу не дали чисел»: джоб **всегда skipped** на push/PR)
- **Источник:** разбор @TL `2026-11-06 08:2x` по `ci-front.yml` + факты прогонов
- **Проверяет:** @TL

## Факт

`.github/workflows/ci-front.yml:48-50`:

```yaml
  front-e2e:
    needs: spec-gates
    if: github.event_name != 'push' && github.event_name != 'pull_request'
```

То есть браузерный джоб выполняется **только при `workflow_dispatch`** (ручной запуск). На `push` в `main`
и на `pull_request` он **всегда** в состоянии `skipped`.

Подтверждение из CI (прогон на `c8baa94b`):

```
Front E2E (8-front + 9-tests/RnD)   completed/success
  job spec-gates  -> success
  job front-e2e   -> skipped      ← браузер не запускался
```

## Почему это объясняет всё, что мы искали

- «E2E не дают чисел» — не потому, что падают, и не только из-за вытеснения `pending`: джоб **не запускается по условию**.
- @TE ждал «один прогон `Front E2E`» как естественное следствие пуша — но при пуше он **не появится** никогда.
- Все выводы «E2E зелёные» по `conclusion: success` прогона `Front E2E` **неверны**: `success` здесь означает «spec-gates зелёные», а браузерная часть — `skipped`.

## Варианты (нужно решение: это политика запуска, а не косметика)

1. **Вернуть прогон на push** — убрать `if:` (или `if: github.event_name != 'pull_request'`), оставив `concurrency`
   из `DO-100 №3`. Тогда каждый пуш в `8-front/**`/`9-tests/**` даёт браузерный прогон **и числа**.
2. **Оставить ручной запуск**, но **обязать** триггерить его после каждого изменения фронта/тестов и **зафиксировать это
   в правилах** (`9-tests/AGENTS.md`): «зелёный CI без ручного `front-e2e` не считается доказательством».
   Правило при этом меняется, значит решает **владелец**.
3. **Гибрид:** на push — короткий набор (3 спеки, как в `smoke-front`), полный — по `workflow_dispatch`.

**Рекомендую (1).** Причина, по которой `if:` вообще появился — вытеснение прогонов и стоимость минут (комментарий
в шапке файла) — уже решена `concurrency` и `timeout-minutes: 60`; ручной запуск как **единственный** путь делает
«зелёный CI» недоказательным.

## Критерии приёмки

- пуш в `8-front/**` или `9-tests/**` порождает прогон, в котором `front-e2e` **не** `skipped` (а `success`/`failure` с числами);
- в логе/артефакте есть `test-results/receipt.txt`, и `e2e_receipt.py --input … --table` печатает `passed/failed/skipped` + `REF`;
- `## Результат`: номер прогона и квитанция.
