# DO-083 — гейт: приложение не должно перекрывать регистрацию `DbContext` библиотеки

- **Статус:** На проверке
- **В работе с:** 2026-11-05
- **Приоритет:** P1 (тихий отказ: `Migrate()` «ничего не делает» без ошибки)
- **Источник:** @AR `2026-11-05 18:05` — ловушка для `BE-072`: `MigrationsAssembly` задаёт **библиотека** в своём `AddDbContext<TDbContext>`; если приложение добавит **свой** `AddDbContext<ReadDbContext>` ниже, он перекроет библиотечный и `MigrationsAssembly` потеряется
- **Зависимости:** `BE-072` (миграция read-контекста), `tools/check_eventstore_registration.py` (существующий гейт того же класса)
- **Проверяет:** @TL

## Задача

История уже была: ручной `AddDbContext<EventStoreDbContext>` в `Program.cs` перекрыл библиотечную регистрацию, `DbContextOptions` оказались **не типизированы** → падение при старте (лечили `b9173f09`, затем `BE-066`).

Сейчас тот же класс возможен с read-контекстом: `AddReadStorePostgres` регистрирует `AddDbContext<TDbContext>` **с** `MigrationsAssembly`, а ручной `AddDbContext<ReadDbContext>` ниже — перекрывает. При `Database.Migrate()` это даст **тихий** отказ: миграции не применятся, ошибки нет.

**Факт на `origin` (проверил @AR):** ручного `AddDbContext<ReadDbContext>` в `*.Api/Program.cs` сейчас **нет** (есть только в тестовых `*HostSmokeTest` — это тестовые хосты, не продукт). Условие выполнено, но **удержать его нечем**.

## Критерии приёмки

- гейт (`tools/check_eventstore_registration.py` расширить или новый `check_dbcontext_registration.py`) ловит в `6-msa/BC-*/src/*.Api/Program.cs`:
  любой ручной `AddDbContext<…DbReadContext…>` / `AddDbContext<…EventStoreDbContext…>`, добавленный **после** `AddReadStorePostgres`/`AddEventStorePostgres`;
- `--selftest` с кейсом «дефект: ручной `AddDbContext<ReadDbContext>` ниже библиотечного → `rc=1`» и «норма: только библиотечная регистрация → `rc=0`» — оба прогона в `## Результат`;
- шаг **блокирующий** в `ci-guards` (без `--warn-only`);
- тестовые хосты (`*HostSmokeTest`, `*IntegrationTests`) — вне проверки, но это должно быть **явно** сказано в шапке гейта, а не следовать из случайного пути.

## Результат

**Гейт расширен (а не заведён заново):** `tools/check_eventstore_registration.py` уже проверял
этот класс для `EventStoreDbContext`, поэтому ловушка добавлена туда же — второй гейт на тот же
класс был бы дублем.

**Что добавлено:**

- `manual_after_library()` — ручной `AddDbContext<T>`, стоящий **ниже** `Add*StorePostgres<…, T,…>`
  в `*.Api/Program.cs` → `DBCTX <T>: библиотека на N, ручной AddDbContext на M` + `rc=1`
  («он перекроет библиотечные опции (`MigrationsAssembly`), `Migrate()` станет тихим»);
- **осознанное исключение** `EventStoreDbContext`: там типизированная регистрация **требуется**
  для моста `DbContextOptions` (`b9173f09`/`BE-067`), поэтому «после» — канон, а не дефект
  (записано в шапке функции и покрыто selftest-кейсом);
- **тестовые хосты вне проверки — явно, а не по случайному пути:** сканируются только
  `**/*.Api/Program.cs`; при старой раскладке — все `Program.cs` с отбрасыванием путей,
  содержащих `Tests`/`SmokeTest` (это в шапке гейта, как требовалось);
- шаг в `ci-guards` **блокирующий** (`--warn-only` не используется), с `if: always()`.

**Обе стороны доказаны:**

- **дефект** — во временной копии `Journal.Api/Program.cs` ручной
  `AddDbContext<ReadDbContext>` поставлен после `AddReadStorePostgres`:
  `DBCTX ReadDbContext: библиотека на 42, ручной AddDbContext на 45` → **`rc=1`**, нарушений 2;
- **норма** — текущий `origin`: `проверено файлов: 2 | нарушений: 0`, `rc=0`
  (`Journal.Api` — `ok (DF 38 → typed 39)`, `Partners.Api` — `ok (DF 36 → typed 37)`);
- `--selftest` → **11/11** (включая три новых кейса DO-083: «после» — дефект,
  «до» — не дефект, типизированный `EventStoreDbContext` — не дефект).
