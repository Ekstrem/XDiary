## Задача (зона @DO, `7-deploy/apim/`)

Сделать APIM прод-пригодным без изменения архитектуры (§1: архитектуру решает @AR; здесь — эксплуатация и секреты).

## Критерии приёмки

- [ ] Пароль администратора **не заводской**: значение берётся из GitHub Secrets / `.env` на VPS; в репозитории и в чате значения нет (`check_secrets` зелёный по диапазону).
- [ ] Креды APIM хранятся **вне репозитория**, права `600`, путь не публикуется в документах (только «в Secrets/`.env` на VPS»).
- [ ] Все порты APIM — **только loopback**; проверка снаружи: соединение отклонено / `401`, а не открытая консоль.
- [ ] `import.sh` работает с секретом из Secrets, **идемпотентен**: повторный запуск даёт `12/12 STARTED` и не создаёт дублей.
- [ ] `check_apim_drift` в CI: с токеном — `rc=0`/`rc=1` по факту; без токена — **`rc=2`** (не «ложный зелёный»).
- [ ] Замер RSS стека APIM на проде ≤ бюджета (правило «< 500 МБ свободной RAM на пике → не поднимаем»), числа в `## Результат`.
- [ ] Ранбук `7-deploy/runbooks/apim.md` обновлён: где секреты, как ротировать, как откатить на предыдущий пароль (окно недоступности ≈45 с, указано явно).
