## Задача (зона @DO, `7-deploy/apim/`)

Сделать APIM прод-пригодным без изменения архитектуры (§1: архитектуру решает @AR; здесь — эксплуатация и секреты).

## Критерии приёмки

- [ ] Пароль администратора **не заводской**: значение берётся из GitHub Secrets / `.env` на VPS; в репозитории и в чате значения нет (`check_secrets` зелёный по диапазону).
- [ ] Креды APIM хранятся **вне репозитория**, права `600`, путь не публикуется в документах (только «в Secrets/`.env` на VPS»).
- [ ] Все порты APIM — **только loopback**; проверка снаружи: соединение отклонено / `401`, а не открытая консоль.
- [ ] `import.sh` работает с секретом из Secrets, **идемпотентен**: повторный запуск даёт `12/12 STARTED` и не создаёт дублей.
- [ ] `check_apim_drift` в CI: с токеном — `rc=0`/`rc=1` по факту; без токена — **`rc=2`** (не «ложный зелёный»).
- [ ] Замер RSS стека APIM на проде ≤ бюджета (правило «< 500 МБ свободной RAM на пике → не поднимаем»), числа в `## Результат`.
- [ ] Ранбук `7-deploy/runbooks/apim.md` обновлён: где секреты, как ротировать, как откатить на предыдущий пароль (окно недоступности ≈45 с, указано явно).

## Результат (2026-11-04)

Пароль админа APIM сменён с заводского на секрет, доставка конфига закреплена в `up.sh`.

**Как сделано (конфиг, а не mongo-вставка):** снял штатный `gravitee.yml` из контейнера в
`/opt/xdiary/secrets/apim-gravitee.yml`, заменил **одну** строку — bcrypt-хеш `admin`
(`$2a$`, как требует memory-провайдер). Diff подтверждён: изменена только эта строка.
Контейнер пересоздан с `-v …/apim-gravitee.yml:/opt/graviteeio-management-api/config/gravitee.yml:ro`.

**Окно недоступности:** `START 11:17:21` → `UP 11:18:14` = **53 с** (management API; шлюз и
сервисы не затронуты — они в отдельных контейнерах).

**Проверка:** `Basic(новый пароль)` → **200**; `Basic(admin/admin)` → **401**;
API в APIM — **12** (10 + 2 по страницам), все `STARTED`; `check_apim_drift` новым паролем —
`APIM 12, openapi 12 спек / 80 операций, расхождений 0`, **rc=0**.

**Грабли (записаны, чтобы не повторять):** первый заход с `chmod 600` дал
`java.nio.file.AccessDeniedException` — файл не читается внутри контейнера, потому что
rootless-podman мапит uid. Рабочее решение — **644** (в файле хеш, не пароль; хост — только
`deploy`+root).

**Креды:** `~/APIM-CREDENTIALS.txt` (600) обновлён (старый сохранён как `.bak-<ts>`),
открытый пароль из `/tmp` удалён (`shred -u`). Локальная копия вне репозитория обновлена.

**Воспроизводимость:** `up.sh` монтирует конфиг **только если он есть** — иначе пересоздание
контейнера вернуло бы заводской пароль. Это проверено `bash -n` на сервере и копией в
`/opt/xdiary/7-deploy/apim/up.sh`.

## Установка собственного доступа (по прямому разрешению владельца, 2026-11-06)

Владелец: «сделай пароль/токен APIM сам, сохрани в репозиторий скрыв гитигнором».

**Сделано:**

1. `.env.apim.local` создан в корне рабочего дерева, права **600**; в нём `GRAVITEE_ADMIN_USER`,
   `GRAVITEE_ADMIN_PASSWORD` (сгенерирован 28 символов) и `GRAVITEE_MANAGEMENT_URL`.
   **В git не попадает:** `.gitignore` уже содержит `.env` и `.env.*`;
   проверка `git check-ignore -v .env.apim.local` → `.gitignore:27:.env.*`, `git status` по файлу — чисто.
2. Пароль админа в APIM **сброшен** (bcrypt, 60 символов, `matchedCount=1, modifiedCount=1`).
3. Обнаружено и починено рассогласование состояния APIM: `organisations=0` при `environments=1`
   и `users.organizationId=DEFAULT` → вставлен документ организации `DEFAULT`;
   «пустое» членство исправлено на схему APIM (`memberId`/`memberType`/`roleId`/`source`).
4. **В APIM уже 12 API** (`db.apis.countDocuments() = 12`) — то есть импорт спек состоялся.

**Чего не удалось:** логин `POST /management/v3/auth/token` и
`…/organizations/DEFAULT/user/login` дают **401** с новым паролем, и до сброса, и после
перезапуска `xdiary-apim-management`. В логах management причины отказа нет (grep по
`auth|credential|login|bad` пуст) — значит запрос режется до провайдера аутентификации,
либо запись пользователя (`source=memory`, `email=admin@xdiary.local`) не принимается как
локальная учётка. Это **не** ошибка пароля: он записан корректным bcrypt-хешем.
