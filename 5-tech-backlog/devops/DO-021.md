# DO-021: Таймауты прокси/шлюза в репозитории — 502 на медленных запросах

- **Статус:** Открыта
- **Приоритет:** P2 (скрывает реальные ошибки за 502)
- **Источник:** @DO 2026-11-05 06:50 + аннотации E2E (`POST /somatic-series/points` → 502 при обработчике 10–30 с)
- **Зависимости:** —

## Проблема
Медленный запрос (`POST /somatic-series/points`, 10–30 с) превращается в **502**, и по нему невозможно отличить «сервис упал» от «сервис думает». Конфигурации прокси/таймаутов **нет в репозитории** (`7-deploy` её не содержит) — правки на VPS невидимы, не версионируются и повторяются при пересоздании.

## Задача
- Положить конфиг прокси (Caddy/nginx — что используется на VPS-2) в `7-deploy/` как версионируемый артефакт.
- Явно задать таймауты: `read`/`response_header` ≥ **60 с** для `/api/*`, чтобы медленные, но живые запросы доходили.
- Зафиксировать в `7-deploy/README` (или в задаче), какой прокси стоит перед шлюзом и где его таймауты.

## Критерии приёмки
- [ ] Конфиг прокси в git; таймауты видны и меняются через PR.
- [ ] Запрос 10–30 с доходит без 502 (или даёт честный 504 с понятной причиной).
- [ ] В `7-deploy` есть короткое описание топологии «прокси → ApiGateway → сервисы».
