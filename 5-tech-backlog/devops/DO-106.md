# DO-106: прод НЕ РАБОТАЕТ в браузере — нет CORS на входе через APIM (preflight → 401)

- **Статус:** ToDo
- **Приоритет:** **P0 — блокирует реального пользователя** (владелец не может войти: «Нет связи с сервером»)
- **Источник:** скриншот владельца + проба @TL `2026-11-06 12:2x`
- **Проверяет:** @TL

## Факт (проба снаружи, не догадка)

| Запрос | ПРОД `xdiary-vps1…` (APIM) | DEV `xdiary-vps2…` (YARP) |
|---|---|---|
| `OPTIONS /api/v1/clients` (preflight) | **401**, `ACAO` нет | **204**, `ACAO=*`, `ACAM=POST` |
| `POST /api/v1/clients` | **200**, но **`ACAO` нет** | **200**, `ACAO=*` |
| `GET /health` | 200 | 200 |

`POST` при этом **работает** (сервер создал клиента) — то есть бэкенд жив. Браузер режет ответ, потому что:
1. **preflight отклонён** (`OPTIONS` → 401) — APIM требует auth на сам preflight;
2. в ответе **нет `Access-Control-Allow-Origin`**.

Фронт живёт на `https://ekstrem.github.io` (другой origin), `fetch` к `xdiary-vps1…` — cross-origin ⇒ браузер обязан
получить CORS-разрешение. Его нет ⇒ `fetch` реджектится ⇒ `api.js` показывает свою сетевую ошибку
«Нет связи с сервером (…) — проверьте VPN/Tailscale/сеть». **Ошибка вводит в заблуждение: сеть в порядке.**

## Почему это не ловилось

- CORS включён **только в YARP** (`6-msa/ApiGateway/Program.cs:11-14,23` — `AllowAnyOrigin/Header/Method` + `UseCors()`).
- В `7-deploy` **нет ни одного упоминания CORS** (grep по `7-deploy` → пусто), конфигурация APIM в репозитории отсутствует.
- Канон `check_apim_auth`/`check_public_entry` проверяют **коды** без `Origin` и без preflight — поэтому CORS-дефект
  «зелёный» по всем гейтам. Это дыра в каноне, а не только в конфигурации.

## Что сделать (по возрастанию стоимости)

1. **APIM (Gravitee): включить CORS и разрешить анонимный `OPTIONS`.**
   - CORS-политика на API/плане: `Access-Control-Allow-Origin: https://ekstrem.github.io` (или `*`),
     `-Methods: GET,POST,PUT,DELETE,OPTIONS`, `-Headers: authorization,content-type`.
   - План/путь для `OPTIONS` — **без** JWT, иначе preflight снова 401 (сейчас именно так).
2. **Hotfix на Caddy (прод)** — если APIM быстро не переконфигурировать:
   ```caddy
   @preflight method OPTIONS
   respond @preflight 204 {
       header Access-Control-Allow-Origin "https://ekstrem.github.io"
       header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS"
       header Access-Control-Allow-Headers "authorization, content-type"
       header Access-Control-Max-Age "600"
   }
   header Access-Control-Allow-Origin "https://ekstrem.github.io"
   ```
   Минус: политика CORS окажется в двух местах (Caddy и APIM) — при включении (1) hotfix надо снять.
3. **Гейт, чтобы не повторилось** (@TE/@DO): `check_cors_entry.py` — `OPTIONS` с `Origin` и
   `Access-Control-Request-Method: POST` → ждём `2xx` + `ACAO`; `POST` с `Origin` → ждём `ACAO`.
   Добавить в `ci-guards`/`smoke-api` **после** деплоя. Это ровно тот класс, который не ловится кодами.

## Критерии приёмки

- `OPTIONS /api/v1/clients` с `Origin: https://ekstrem.github.io` → **204/200** и `Access-Control-Allow-Origin`;
- `POST /api/v1/clients` с `Origin` → `200` **и** `Access-Control-Allow-Origin`;
- вход в приложении на проде с телефона проходит (владелец подтверждает);
- в CI появился CORS-гейт (иначе дефект вернётся при следующей правке APIM).
