# DO-069: уведомления о сообщениях ролей не должны матчить «часы без даты»

- **Статус:** ToDo
- **Приоритет:** P3 (не влияет на продукт; влияет на время владельца и координатора)
- **Источник:** владелец, практика: за сутки **29** уведомлений «в чате X есть сообщение от роли (последнее HH:MM)», каждое при проверке давало **0 совпадений** — сопоставление идёт по `HH:MM` **без даты и без файла**, поэтому реальное сообщение любого другого дня выдаётся за новое
- **Зависимости:** нет
- **Проверяет:** @TL

## Задача (зона @DO, `tools/`)

Матчинг уведомлений должен опираться на **полный штамп** `YYYY-MM-DD HH:MM` **и** на конкретный файл outbox, а не на подстроку времени:
1. искать в `5-tech-backlog/chat/<роль>.md` строки, начинающиеся с `- [YYYY-MM-DD HH:MM] → @<адресат>:`;
2. сравнивать **дату и время целиком** (не `HH:MM`);
3. дедуплицировать: не уведомлять о строке, о которой уже уведомляли (курсор по файлу/строке);
4. если адресат — не я, не уведомлять вовсе.

## Критерии приёмки

- [ ] Строка `[2026-11-03 19:39]` **не** вызывает уведомления сегодня (негативный контроль на реальной истории).
- [ ] Строка `[<сегодняшняя дата> <время>] → @TL` вызывает **ровно одно** уведомление.
- [ ] Повторный прогон на тех же данных — **ноль** новых уведомлений (дедуп).
- [ ] Два прогона по §5.4 (дефект/норма) + `--selftest`; в отчёте — `REF`.
