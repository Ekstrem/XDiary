# DO-010: Устранить периодическую потерю iptables-правил rootless podman (DNAT/masquerade)

- **Статус:** Закрыта (DevOps: самовосстановление `heal-network.sh`, вызвано из `update.sh`)
- **Приоритет:** P1
- **Источник:** прод (VPS-1), DO-003 (rootless podman networking)
- **Зависимости:** —

## Проблема

Rootless podman **3.4.4** (штатный в Ubuntu 22.04) периодически **теряет iptables-правила** CNI-сети `xdiary` при redeploy (`deploy.sh` → `podman rm -f` + `podman run`). Проявляется двумя способами:

1. **Портмап шлюза** (DNAT `127.0.0.1:8080` → контейнер) пропадает → `curl localhost:8080/health` = `000` (connection refused), хотя контейнер `xdiary-api-gateway` «Up» и Kestrel слушает `[::]:8080`.
2. **Masquerade** для подсети `10.89.9.0/24` пропадает → контейнеры не могут достучаться до внешнего адреса (наблюдалось ранее с VPS-2, `Network is unreachable`).

Корень — связка CNI-плагинов 0.4.0 (`bridge/portmap/tuning/dnsname` в ручном conflist) + slirp4netns: правила не пересоздаются надёжно при цикле DEL/ADD контейнеров.

## Что уже делалось (обходные меры, не фикс)

- `sudo mount --make-rshared /run` (теряется после перезапуска podman-сервисов).
- Очистка застрявшего IPAM (`/run/user/1000/rootless-cni/var/lib/cni/networks/xdiary/`).
- Ручная пересоздание контейнера шлюза для повторного срабатывания portmap.

## Задача

Сделать так, чтобы сеть переживала redeploy без ручного вмешательства. Варианты:

- **A (правильный):** апгрейд podman до 4.x (netavark + aardvark-dns вместо CNI/slirp4netns). Может потребовать правки `podman-compose.yml`/`deploy.sh` (имена сетей, DNS-имена).
- **B (быстрый):** «самовосстановление» — после `deploy.sh` (и/или по systemd-таймеру) пересоздавать шлюз / досоздавать masquerade+DNAT (idempotent-команды).

## Критерии приёмки
- [ ] После N последовательных redeploy (`update.sh` → `deploy.sh`) `curl localhost:8080/health` остаётся `200` без ручных правок.
- [ ] Контейнеры стабильно держат исходящий доступ (masquerade на месте).
- [ ] Изменения зафиксированы в `7-deploy/` (IaC) + `README.md`.

## Результат
Реализован **вариант B (самовосстановление)** — быстрее и безопаснее апгрейда podman 4.x:
- `7-deploy/heal-network.sh` (в git, без секретов) идемпотентно чинит: rshared-монтирование `/run`, masquerade `10.89.9.0/24`, портмап шлюза (пересоздаёт `xdiary-api-gateway`, если `/health` не отвечает).
- `update.sh` на VPS-1 вызывает `heal-network.sh` после каждого цикла авто-деплоя (каждые 15 мин) — и после redeploy, и при «no changes».
- Проверено на VPS-1: `heal.log` → `gateway /health failed, recreating` → `gateway healed`, `curl /health` = 200.

Критерии выполнены (вариант B). Вариант A (апгрейд podman 4.x) остаётся как долгосрочное улучшение, отдельной задачей при необходимости.
