- **Проверяет:** @AR

## Задача

Тестер физически не может выполнить два класса проверок из песочницы:
`dotnet test` → `testhost` падает `Win32Exception (5)` в `Process.GetProcessHandle`;
`npx playwright install chromium` → `EPERM`/`spawn EPERM` (загрузчик форкает процесс с пайп-stdio).

Нужны прогоны там, где это работает: CI или контейнер.

## Критерии приёмки

- **контракт партнёров:** прогон `test-partner-softdelete.yml` (или
  `dotnet test 6-msa/BC-Journal/src/Journal.ApiTests` в контейнере `--network xdiary`) —
  **номер прогона** + `4 passed` (это авторитетная форма для `TE-050`);
- **E2E:** прогон 19 спеков `9-tests/RnD/front-e2e/tests/` в CI (или контейнере с браузерами) —
  номер прогона + `passed/failed` поспешно; если спеки требуют стенда — указать `base` и что именно поднято;
- оба результата — строкой в чат `→ @TE` (он перепрогонит и закроет свои карточки);
- если прогон невозможен — назвать **точную** причину (что именно запрещено), а не «не получилось».

## Результат

**Прогон вне песочницы выполнен по обоим классам — и оба упали по ОДНОЙ продуктовой причине, а не по среде.**

### 1. Контракт партнёров — CI, прогон **#4** (`test-partner-softdelete.yml`)

- сборка: `dotnet build … Journal.ApiTests` → **0 Error(s)**;
- тесты **запустились** на runner'е: `Total tests: 4`, **`Failed: 4`**;
- каждый кейс: `Actual: InternalServerError`;
- тем самым «невозможно прогнать» снято: прогон есть, номер есть.

### 2. Playwright E2E — 19 спеков в контейнере с браузерами (вне песочницы)

Окружение: `node:22-bookworm` + `npx playwright install --with-deps chromium`,
код смонтирован из `/tmp/e2e` (репозиторий не трогался), стенд `https://xdiary-vps2.taile0b6ee.ts.net`,
`XDIARY_E2E_TEST_OTP=000000`, `XDIARY_READPATH_OFFLINE=1` (добавлена в `front-e2e-repeat.yml`).

- итог: **23 failed, 2 skipped**, 0 passed;
- **все** падения — одна и та же ошибка на первом шаге (`seedSession`):
  `Error: client-JWT не принят: GET /partners с токеном вернул 500 (без токена: 401). Это auth-контур,
  а не hidden-экран (TE-047).`

### Причина (общая для обоих прогонов)

`xdiary-partners` на dev (ревизия образа `68644da1`) бросает
`System.NullReferenceException` — в логе контейнера серия таких исключений в те же секунды.
Это тот же класс, что `BE-067` (null `IPaging`), но `b9173f09` правил **journal**;
у `partners` фикса нет. Следствие: любой аутентифицированный `GET /partners` → **500**,
поэтому и контракт (4 кейса), и все 19 E2E-спеков падают на входе.

### Найденный дефект CI (не исправлял — нужно решение)

`concurrency: group: front-e2e` делят `ci-front.yml` и `front-e2e-repeat.yml` (оба
`cancel-in-progress: false`). При активных пушах мой `workflow_dispatch` **вытесняется из очереди**:
прогоны **#15** и **#16** завершились `cancelled` с **нулём шагов**, хотя dispatch принят.
Предложение: `group: front-e2e-${{ github.event_name == 'workflow_dispatch' && 'manual' || 'push' }}`
(внутри группы сериализация сохраняется, dispatch перестаёт умирать от чужих пушей), либо
`ci-front` получает свою группу. Это меняет поведение гейта — прошу решение @TL.
