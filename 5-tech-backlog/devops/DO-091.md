# DO-091: второе направление в `check_status_chat` — «объявление статуса в чате ⇒ смена статуса карточки»

- **Статус:** ToDo
- **Приоритет:** P2 (закрывает класс «в чате статус, которого нет в файле»)
- **Источник:** @FE `2026-11-05 14:07–14:23` (его случай: в чате «`FE-038` выпущен», в карточке `В работе`) + четыре итерации предиката на реальных данных
- **Зависимости:** `tools/check_status_chat.py` (прямое направление уже есть, `--selftest 2/2`)
- **Проверяет:** @TL

## Задача

`check_status_chat.py` проверяет только **одно** направление: «сменил `**Статус:**` ⇒ строка в чат в том же
коммите». Обратное не проверяется, поэтому в чате можно **утверждать** статус, которого в файле нет.

Добавить второе направление **в тот же инструмент** («одно условие — один инструмент»).

## Спецификация предиката (проверена @FE на 400 коммитах, каждая итерация — на данных)

1. **Каноническая форма:** строка чата содержит `<ID> <СТАТУС_A> → <СТАТУС_B>`.
2. **Закрытый словарь восьми статусов** (`Идея`, `На проработке`, `ToDo`, `В работе`, `В паузе`,
   `На проверке`, `Закрыта`, `Отклонена`) — **оба** статуса из словаря. Без него `<ID> → to_regclass`
   считается объявлением (замер: 54 «объявления» против 11 при словаре).
3. **Отбрасывание перештамповки:** у «добавленной» строки отбросить префикс `- [YYYY-MM-DD HH:mm] `
   и проверить, есть ли **тот же текст** у родителя коммита. Есть ⇒ это фикс метки, не объявление.
   (Замер: коммит `bcc6e822` с 174 перештамповками давал 8 ложных «нарушений».)
4. **Карточка должна существовать:** `<ID>` встречается как файл `5-tech-backlog/*/<ID>.md` в репозитории.
   Иначе цитата примера (`FE-999 ToDo → Закрыта`) читается как объявление — это последний найденный
   ложноположительный класс.

**Если объявление найдено** (все 4 условия), требовать: в том же коммите `**Статус:**` этой карточки
изменён на `СТАТУС_B`. Иначе `::error::` с ID, статусом и коммитом.

## Критерии приёмки

- `--selftest` содержит **4 кейса на ложные срабатывания** (слово статуса без канона; статус вне словаря;
  перештамповка; несуществующий ID) и **1 кейс на настоящий дефект** (объявление без смены статуса → `rc=1`);
- прогон по 400 последним коммитам даёт **0 срабатываний** на текущем `main` (проверено @FE вручную: `ok 1294`, нарушений 0);
- шаг в `ci-guards` **блокирующий**, `--selftest` идёт **перед** нормой;
- в `## Результат` — вывод прогона по 400 коммитам (0 нарушений) и вывод selftest.

## Фикстуры `--selftest` не зависят от живого состояния репозитория (@FE `14:29`)

**Требование:** кейсы `--selftest` строятся на **синтетическом** наборе (свой список карточек + свой diff),
а не на реальных ID. Причина: кейс «объявление `FE-040` `На проверке → Закрыта` без смены статуса» перестаёт
воспроизводиться, как только карточка **закрыта** — то есть тест становится пустым по причине, к логике
не относящейся. ID в фикстурах — вне реальности (`TS-901` и т.п.).
