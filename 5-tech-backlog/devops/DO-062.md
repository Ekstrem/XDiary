# DO-062: включить access-log на краю (Caddy) — чтобы вопрос «были ли обращения» имел ответ

- **Статус:** ToDo
- **Приоритет:** P1 (после инцидента 2026-11-10 PII: «внешние обращения доказательно неизвестно»)
- **Источник:** @DO 2026-11-10 20:00 — «в `Caddyfile` директива `log` не включена, Funnel своих логов не пишет»; `5-tech-backlog/tl/INCIDENT-2026-11-10-PII.md`
- **Зависимости:** нет
- **Проверяет:** @TL (домен инфраструктуры — @DO; саморевью запрещено)

## Задача (зона @DO, `7-deploy/caddy`)

1. Включить `log` в `Caddyfile.prod` (JSON-формат предпочтительно) с ротацией, чтобы файл не рос бесконечно.
2. Убедиться, что **не пишутся секреты/PII**: query-строки с токенами и тела запросов в лог не попадают; заголовок `Authorization` не логируется.
3. Хранить логи **не меньше 14 суток** (время достаточное, чтобы расследовать инцидент), путь и ротация — в ранбуке.
4. Проверка: после включения — обычный запрос появляется в логе; запрос с `Authorization` — **без** значения токена в логе.

## Критерии приёмки

- [ ] `log` включён, ротация настроена, место на диске под него ограничено.
- [ ] В логе есть метод/путь/статус/время; **нет** тел и токенов.
- [ ] В `7-deploy/runbooks/` записано: где лежат логи, сколько хранятся, как искать «кто обращался к маршруту».

## Вердикт TL (@TL 2026-11-11 09:00) — проверено, можно закрывать

Принято по фактам @DO: в `7-deploy/caddy/Caddyfile.prod` добавлена директива `log` (stdout → journald, без отдельных прав и файлов); применение — **бэкап → `caddy validate` (Valid) → `reload`** с **автооткатом** при отклонении любого из трёх контрольных кодов; после применения `/health` 200, `GET /clients` 401, `POST /clients` 400 (вход не сломан). Лог реально пишется: `journalctl -u caddy` → `http.log.access "handled request"` с `remote_ip`/`method` (5 записей за 3 минуты).

**Почему это важно:** при PII-инциденте 2026-11-10 на вопрос «были ли внешние обращения» ответ был «логов нет» — теперь ответ будет фактом. Закрывает @DO (владелец карточки).
