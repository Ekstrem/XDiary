# DO-132 — P0: на проде не работают «Фантазии» и добавление акта (journal API отдаёт 500)

- **Статус:** ToDo
- **Приоритет:** P0 (пользователь не может ни посмотреть фантазии, ни добавить запись)
- **Источник:** баг-репорт владельца 2026-11-15 17:0x: скриншот с «Не удалось загрузить фантазии: HTTP 500 — сервер ответил, повторите» и сообщение «Ошибка при добавлении акта (не появилось на экране)»
- **Зависимости:** `AR-160` (фикс спеков уже в `main`), блокер — креды Gravitee
- **Проверяет:** @TL
- **Исполняет:** @DO (ре-импорт APIM) / владелец (секрет)

## Замер (обе жалобы — одна причина)

| Что нажал пользователь | Вызов приложения | Прод сейчас | Dev сейчас |
|---|---|---|---|
экран «Фантазии» | `GET /api/v1/journal/fantasies` | **500** | 401 (стенд здоров) |
добавление акта | `GET/POST /api/v1/journal/records` | **500** | 401 |
список партнёров | `GET /api/v1/partners` | **500** | 401 |
каталог | `GET /api/v1/catalog` | 401 | 401 |

Ответ прода (заголовки и тело):

```
HTTP/1.1 500 Internal Server Error
X-Gravitee-Client-Identifier: …
X-Gravitee-Request-Id: …
X-Gravitee-Transaction-Id: …
{"message":"Internal Server Error","http_status_code":500}
```

Это **ответ Gravitee**, а не сервиса: APIM не может проксировать запрос к `journal` (и `partners`), потому что в его определении API «битый backend». Причина найдена и доказана в `AR-160`:

- в `openapi/journal.json` и `partners.json` стоял `"servers": [{"url": "/"}]` (в девяти остальных спеках ключа нет);
- `GET /api/v1/journal/nonexistent-xyz` → **500**, при этом `catalog/nonexistent-xyz` → **401** — то есть сломан сам API в шлюзе, а не сервис;
- фикс в `main`: `servers` убран, `import.sh` нормализует `servers`, добавлен шаг деплоя `APIM-REIMPORT` (вход `reimport_apim`).

## Почему до сих пор не починено

Ре-импорт требует админа Gravitee, а он недоступен:

```
APIM-REIMPORT: спек в /opt/xdiary/openapi — 13
APIM-REIMPORT: креды из /opt/xdiary/secrets/apim.env
креды НЕ подошли: и apim.env, и заводские admin/admin дают 401
import.sh: импортировано 0, ошибок 12; API в APIM: ~0
```

`up.sh:83-84` монтирует `/opt/xdiary/secrets/apim-gravitee.yml` — админ кастомный, пароль в файле в виде хеша, для Basic-аутентификации не годится.

## Два пути (нужен @DO или владелец)

1. **Дать актуальную пару** `GRAVITEE_ADMIN_USER`/`GRAVITEE_ADMIN_PASSWORD` в `/opt/xdiary/secrets/apim.env`, затем `deploy` с `reimport_apim=true`.
2. **Сбросить админа APIM** (с ведома владельца): пересоздать `xdiary-apim-management` без монтирования `apim-gravitee.yml` (Gravitee вернётся к заводскому `admin/admin`), затем `deploy` с `reimport_apim=true`, после — задать новый пароль и вернуть монтирование.
