# DO-120: `deploy.yml:419` — `if-no-files-found:` внутри `run:` → шаг `e2e_triage` падает с `exit 127`

- **Статус:** ToDo
- **Приоритет:** **P1** (ломает `smoke-front` **всегда**, независимо от результата тестов → `deploy-prod` не запускается)
- **Источник:** разбор @TL 2026-11-13 00:26 по логу run `43303278241`, job `smoke-front` `131481979242`
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @DO (зона `.github/`)

## Факт (лог, дословно)

```
smoke-front  Классы падений (e2e_triage)  ... ##[group]Run python 9-tests/scripts/e2e_triage.py --input 9-tests/RnD/front-e2e/test-results/pw.log || true
smoke-front  Классы падений (e2e_triage)  ... if-no-files-found: ignore

smoke-front  Классы падений (e2e_triage)  ... ##[error]Process completed with exit code 127.
```

Причина — `.github/workflows/deploy.yml:415-419`:

```yaml
      - name: Классы падений (e2e_triage)
        if: failure()
        run: |
          python 9-tests/scripts/e2e_triage.py --input 9-tests/RnD/front-e2e/test-results/pw.log || true
          if-no-files-found: ignore      # ← это ключ actions/upload-artifact, он попал в run:
```

`if-no-files-found` — вход `actions/upload-artifact@v4`, он должен быть в `with:` шага **«Артефакты падения»** (`:403-411`), а не строкой shell-скрипта.

## Почему это важнее, чем выглядит

1. Шаг падает с `exit 127` **при любом** исходе спеки → job `smoke-front` красный → `deploy-prod` (needs `smoke-front`) **не запускается**.
2. `e2e_triage` не печатает классы падений (сам шаг до него не доходит) — то есть **диагностика UI-падений отсутствует**, и каждый разбор начинается с нуля.
3. Из-за `|| true` в самой команде видно намерение «шаг не должен валить job», но строка ниже ломает это намерение.

## Задача

1. Перенести `if-no-files-found: ignore` в `with:` шага «Артефакты падения (trace, скриншоты, error-context)» (рядом с `retention-days: 7`).
2. Проверить, что `e2e_triage` реально печатает классы падений в лог прогона (не только в артефакт).
3. Не менять `if: failure()` и логику `deploy-prod`.
