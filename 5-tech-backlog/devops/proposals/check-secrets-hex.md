# Предложение @LM: `check_secrets` не должен считать секретом hex, который является коммитом или дайджестом

**От:** @DO, 2026-11-07 00:2x. **Кому:** @LM (правила/линтеры/инструменты — зона @LM,
`AGENTS.md` §1, решение владельца 2026-11-16). **Повод:** `@TL 00:07` — «`check_secrets` `rc=1`,
8 находок, 5 из них ложные: в архивных чатах тяжёлый hex, а это реальные коммиты».

**Почему не правлю сам:** `tools/check_secrets.py` — копия из `LoopMaker/tools/` (источник правды
там, `AGENTS.md` §6), и правка инструментов сейчас за @LM. Ниже — факты, правило и план проверки,
готов к исполнению по твоей команде.

## Факт: 5 находок — это идентификаторы артефактов, а не секреты

Проверил каждую: разбор строки + `git cat-file -e <hex>`.

| файл:строка | длина | `cat-file -e <hex>` | что это на самом деле |
|---|---|---|---|
| `chat/archive/do/…:2069` | 40 | **коммит** | SHA коммита в отчёте о прогоне |
| `chat/archive/do/…:2074` | 40 | **коммит** | `revision образа:` — ревизия Docker-образа |
| `chat/archive/do/…:2918` | 64 | не объект | sha256 файла DLL (`DigiTFactory.Libraries.EventBus.InMemory`) |
| `chat/archive/te/…:2128` | 40 | объект (не коммит) | хеш артефакта при сверке идентичности |
| `chat/archive/te/…:2394` | 40 | объект (не коммит) | «доказал идентичность **хешем**» — сравнение артефактов |

То есть гейт ловит **публичные идентификаторы**, которые мы обязаны цитировать по канону
(«ссылаться на SHA — только после `git merge-base --is-ancestor`», «доехало = `git show origin/main:<path>`»).
Секретов в этих строках нет: коммит и sha256 файла не дают доступа ни к чему.

## Правило (предлагаю в `check_secrets`)

1. **Hex 40** и `git cat-file -e <hex>^{commit}` → это **ревизия**, не секрет: `::notice::`, в
   нарушения не идёт.
2. **Hex 40/64**, который `git cat-file -e <hex>` разрешает в **любой объект** → идентификатор
   артефакта: `::notice::`, не нарушение.
3. **Hex 64** в контексте `sha256:` / `digest` / `revision:` / `DLL` / `хэш` → дайджест: `::notice::`.
4. **Всё остальное** (в т.ч. `assign:password`, токен-подобные строки, base64) — как сейчас:
   нарушение, `rc=1`, значение не печатается.
5. **Квитанция печатает источник классификации**, чтобы вердикт нельзя было получить «на другом
   дереве»: `hex: 5 (коммит 2, объект 2, дайджест 1) | нарушений 0`.

Границы предохранителя: если hex **не** разрешается в объект и **не** имеет дайджест-контекста —
он остаётся нарушением. То есть «просто длинная hex-строка» по-прежнему красная, иначе гейт
перестанет ловить `Jwt:SigningKey`-подобные утечки (инциденты 03/04.11).

## Проверка по §5.4 — две стороны, обе обязательны

| прогон | что должно быть |
|---|---|
| **дефект** | временно добавить в тестовый файл строку вида `apiKey = "<40 hex, не объект git>"` → гейт **`rc=1`**, находка с именем класса |
| **норма** | текущий `origin` → **`rc=0`**, квитанция «hex: 5 (коммит 2, объект 2, дайджест 1) | нарушений 0» |
| **selftest** | новый кейс «hex-коммит не считается секретом» + существующий «токен-подобная строка считается» |
