# DO-013: Приватный канал доступа: устройства пары → nl-vps → VPS-1 (ADR-015)

- **Статус:** Отклонена (выбран Funnel вместо приватного канала через nl-vps; DO-012 закрыта)
- **Приоритет:** P0 (без канала PWA с телефона не достаёт API)
- **Источник:** ADR-015 (частный доступ); PO: VPN на устройствах уже есть; @AR `chat/ar.md` 09:00
- **Зависимости:** DO-004

## Проблема
API живёт за Tailscale на VPS-1. Телефон в tailnet не входит (`tailscale status` — только `xdiary-vps1`). PO не ставит/логинит Tailscale, но у него **уже есть VPN на устройствах** (через `nl-vps`). Публичный Funnel (ADR-017) отложен.

## Задача
Сделать так, чтобы с устройств, уже подключённых к VPN (`nl-vps`), открывался `https://xdiary-vps1.taile0b6ee.ts.net`:
- **A**: на `nl-vps` поднять релей до VPS-1 (Tailscale-узел + subnet router / exit node, либо WireGuard site-to-site);
- **B**: если `nl-vps` уже VPN-выход — добавить маршрут/релей до VPS-1;
- детали (протокол, как `nl-vps` релеит) — за DevOps.

## Ограничения
- 8080 наружу не публиковать; TLS обязателен; данные — только через JWT.
- Не менять модель доступа без @AR (ADR-015 остаётся).

## Критерии приёмки
- [ ] С устройства, подключённого к VPN (`nl-vps`), `curl https://xdiary-vps1.taile0b6ee.ts.net/health` = 200.
- [ ] `POST /api/v1/privacy/token` с PIN выдаёт JWT; журнал/партнёры/каталог работают с телефона.
- [ ] `8-front` `DEFAULT_BASE` корректен; PWA проверен с телефона.

## Результат
Не потребовался: владелец активировал Tailscale Funnel (DO-012) — публичный HTTPS без nl-vps и без VPN на телефоне. Канал «телефон → nl-vps → VPS-1» не нужен.
