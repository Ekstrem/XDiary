# DO-101: `Stats` краснеет от любой смены статуса карточки — сделать обновление README автоматическим

- **Статус:** ToDo
- **Приоритет:** **P2** (не блокирует продукт, но постоянно краснит CI и требует ручной работы от всех ролей)
- **Источник:** наблюдение @TL `2026-11-06 00:50-01:00` (факт: `Stats` красный 6 раз за вечер)
- **Проверяет:** @TL

## Проблема

`stats.yml` запускает `python tools/stats.py --check` и **падает**, если таблица в `README.md` не совпадает
с фактическими статусами карточек. Но статус меняет **каждая роль** на каждом шаге
(`ToDo → В работе → На проверке → Закрыта`). Значит:

- гейт наказывает за **нормальную работу**;
- чтобы он был зелёным, **каждый** автор смены статуса обязан запустить `tools/stats.py --write`
  и включить README в свой коммит — на практике этого не делает никто (я сам забыл дважды);
- в результате `Stats` — самый шумный красный CI: только за вечер 00:36–01:00 он краснел **6 раз**.

## Что предлагается (норма «README = задачи» НЕ меняется)

**Вариант A (рекомендую).** В `stats.yml` заменить «проверить и упасть» на «пересчитать и закоммитить»:

```yaml
permissions:
  contents: write
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-python@v5
    with: { python-version: "3.12" }
  - run: python tools/stats.py --write
  - name: Закоммитить README, если изменился
    run: |
      if git diff --quiet -- README.md; then echo "README актуален"; exit 0; fi
      git config user.name  "xdiary-bot"
      git config user.email "xdiary-bot@users.noreply.github.com"
      git add README.md
      git commit -m "bot: README = задачи (автообновление)"
      git push
```

Плюс `concurrency: group: stats` и `paths:` без `README.md` (иначе бот-коммит снова триггерит workflow).

**Вариант B.** Оставить проверку, но `continue-on-error: true` + отдельный `schedule`-прогон, который чинит README.
Менее честно (гейт перестаёт что-либо гарантировать), но проще.

**Вариант C (не рекомендую).** Ничего не делать и продолжать перегенерировать вручную — это уже съедает время
и у всех ролей, и у @TL.

## Критерии приёмки

- смена статуса любой карточки **не** делает `Stats` красным;
- README **всегда** соответствует доске (проверяется тем же `tools/stats.py --check` в отдельном шаге или в `schedule`);
- в `## Результат` — ссылка на прогон, где статус менялся, а `Stats` остался зелёным.
