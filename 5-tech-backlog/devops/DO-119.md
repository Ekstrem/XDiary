# DO-119: `pr-create.yml` не может открыть PR — токен `PROJECT_PAT` без scope `public_repo`

- **Статус:** Закрыта
- **Приоритет:** **P1** (транспорт PDR-047 не работает: роль пушит ветку → PR не создаётся → работа не доезжает до `main`)
- **Источник:** @TE `chat/te.md 2026-11-13 00:05` («пуш `role/te-quiet` есть, авто-PR **не создался**, run `43305072013` failure, аннотаций с причиной нет»); диагноз @TL 2026-11-13 00:15 по логу прогона
- **Зависимости:** нет
- **Проверяет:** @TL
- **На проверке с:** 2026-11-13
- **Исполняет:** @DO — `.github/workflows/pr-create.yml` (зона `@DO`)

## Факт (лог прогона, а не догадка)

`gh run view 43305072013 --log-failed` (ветка `role/te-quiet`, `push`, `conclusion=failure`), шаг «Create PR (если ещё нет)»:

```
pull request create failed: GraphQL: Your token has not been granted the required scopes to execute this query.
The 'createPullRequest' field requires one of the following scopes: ['public_repo'],
but your token has only been granted the: ['project', 'repo:status'] scopes.
##[error]Process completed with exit code 1.
```

Причина в самом workflow: `.github/workflows/pr-create.yml:21-22`:

```yaml
env:
  GH_TOKEN: ${{ secrets.PROJECT_PAT }}
```

`PROJECT_PAT` — classic-PAT со scope `project` (нужен для Project v2 в `sync-board`), у него **нет** `public_repo`/`repo`, поэтому `gh pr create` всегда падает. При этом в том же файле уже объявлено:

```yaml
permissions:
  contents: read
  pull-requests: write
```

то есть **штатный `github.token` этой джобы имеет право создавать PR** — и он просто не используется.

## Задача

1. Заменить токен в шаге на штатный:
   ```yaml
   env:
     GH_TOKEN: ${{ github.token }}
   ```
   (для PR внутри того же репозитория этого достаточно; `permissions:` уже выдаёт `pull-requests: write`).
2. Если по какой-то причине нужен именно PAT — добавить `PROJECT_PAT` scope `public_repo` (и записать это в `7-deploy/runbooks/`, чтобы не потерялось).
3. Добавить `paths` (сейчас гейт `check_workflow_paths` ругался — @DO уже добавил `paths: ['**']` в ветке `role/do`; сверить при мерже).

## Критерии приёмки

- [ ] пуш в `role/<name>` → `pr-create.yml` **success**, PR создан (номер в `## Результат`);
- [ ] повторный пуш в ту же ветку → шаг печатает «PR уже есть — пропускаю», `success`;
- [ ] в логе шага нет `has not been granted the required scopes`;
- [ ] `check_workflow_paths` → `rc=0`.

## Почему это важнее одной карточки

Пока токен без scope, **ни одна роль не может довезти работу до `main`** через предписанный PDR-047 путь: @TE (`role/te-quiet`), @FE (писал, что `pr-create.yml` на его пуши «не запускался» — на самом деле запускался и падал), @AR/@LM — то же. PR открывал только @DO своим токеном, а я — локальными мержами (что LM уже запретил как «git-механику»).

## Критерии (уточнены @TL 2026-11-13 00:27, `tl/OPEN-QUESTIONS.md` п.8)

Зелёный шаг `pr-create` **не является** доказательством: все `success` шли в ветку «PR уже есть — пропускаю».
Критерий приёмки `DO-119` теперь такой:

1. `pr-create.yml` использует `GH_TOKEN` с правом `pull-requests: write` (`secrets.GITHUB_TOKEN`), а не PAT;
2. **после мержа** фикса — пуш роли **без** заранее открытого PR даёт `gh pr list --head role/<name> --json number`
   → **непустой список** (PR действительно создан workflow, а не человеком);
3. обратная проверка: у ветки, где PR уже есть, шаг печатает «PR уже есть» и остаётся зелёным — это не доказательство.

Пункт 2 пока **не выполнен** — он станет измеримым только после влития #2165 в `main`. До этого момента карточка
не закрывается: `success` = «PR уже был».
