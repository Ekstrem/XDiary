## Зачем

Компилятор не видит строковые URL, канон `(ii-a)` проверяет **периметр**, а `gen_openapi`/`check_api_index` сверяют **спеку**, а не строки `HttpClient`-вызовов. Поэтому путь, которого нет ни у одного сервиса, спокойно доезжает до `main`.

Живой случай (`@AR` `14:31`, замер на dev с валидным токеном):
```
BffController.cs:39   $"{journalBase}/api/v1/journal"        → 404 (пустое тело)
Journal на самом деле  GET /api/v1/journal/records            → 200 []
                       GET /api/v1/daily-metrics/series?…      → 200 []
```
`404` апстрима → `HttpRequestException` → шлюз отдавал **`500`** (после фикса @BE — `502`), и только канон на проде это заметил.

## Задача

Тул `tools/check_api_call_paths.py` (имя — на усмотрение @DO):
1. Собрать из `04-architecture/api-index.yaml` множество `(method, path)` реальных операций;
2. Найти в `6-msa/**/*.cs` строковые литералы вида `"/api/v1/…"` (в т.ч. интерполяции `$"{base}/api/v1/…"`, собирать префикс до `?`);
3. Сравнить: путь без совпадения по шаблону → **ошибка**; вывод — файл:строка + путь + ближайшие похожие операции;
4. `--selftest` (как у остальных гейтов) + регистрация в общем прогоне гейтов;
5. Осознанные исключения — только явным списком в конфиге с комментарием-причиной.

## Критерии приёмки

- `python tools/check_api_call_paths.py --selftest` — зелёный (включая кейс «интерполяция с базой»);
- на текущем `main` гейт **красный ровно на одном** месте — `BffController.cs:39` (`/api/v1/journal`); после фикса `BE-141` — `rc=0`;
- гейт добавлен в CI и в `9-tests/scripts/check_*`-общий прогон (если такая практика есть);
- ложных срабатываний на `GatewayRoutes.cs` (там пути-строки без вызова) нет — либо заведены в исключения с обоснованием.
