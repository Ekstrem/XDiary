# DO-023: Политика отмены CI — гарантированное окно для `front-e2e`

- **Статус:** Открыта
- **Приоритет:** P2 (из-за отмен прогонов теряется приёмка; повторялось 2 раза за сутки)
- **Источник:** владелец 2026-11-05: «есть ли метрика, сколько надо гарантированно дать тестам отработать?»; факты сессии — `front-e2e` на `09262c7` отменён через 111 с новым пушем
- **Зависимости:** fix CI (`9b58f6f` — `paths-ignore` для чата), DO-021

## Проблема
`concurrency: ci-tests / cancel-in-progress: true` рубит **любой** идущий прогон при новом пуше. Метрики/бюджета прогона нет, поэтому:
- `front-e2e` не доходит до конца при активной работе команды → **нет приёмки** FE-017/020/021/022, TE-031;
- при этом сам `test` дешёвый (по фактам: 69 с зелёный, 24 с на падении сборки), а E2E — единственный дорогой прогон.

## Факты (для бюджета)
| Джоб | Лимит в workflow | Факт |
|---|---|---|
| `test` | `timeout-minutes: 20` | зелёный **69 с**, падение сборки 15–24 с |
| `front-e2e` | `timeout-minutes: 30` | **зелёного прогона в сессии нет** — все либо отменены, либо красные; известный прогон отменён на 111 с |

Вывод: текущие лимиты (20/30 мин) сильно больше реального времени, а отмены происходят на 1–2 минуте — то есть отмена бьёт не по «зависшему», а по нормально идущему прогону.

## Предлагаемая политика (решает @DO, это его зона)
1. **`test`** — оставить `cancel-in-progress: true` (дёшево перезапустить), но добавить бюджет: не отменять прогон, которому < **3 мин** (p95 зелёного 69 с × ~2.5).
2. **`front-e2e`** — **никогда не отменять** по `cancel-in-progress`: отдельная группа `front-e2e` с `cancel-in-progress: false`. Пусть копится максимум один ожидающий run (с `paths-ignore` для чата очередь не раздувается). Мы уже видели 21+ queued — но там причина была в чат-пушах, теперь закрыта.
3. **Гарантированное окно:** E2E обязан получить **полные 30 мин** (его `timeout-minutes`) без внешней отмены. Прогон считается валидным для приёмки, если завершился сам (success/failure), а не был отменён.
4. **Метрика, которую ведём:** для `test` и `front-e2e` — p50/p95 длительности за последние 20 зелёных прогонов (из API `check-runs`), хранить в `7-deploy/RESOURCE-USAGE.md` или отдельном разделе; пересматривать бюджеты при изменении набора спек.
5. **Правило приёмки (TL):** результат отменённого run'а **не считается** доказательством — ни зелёным, ни красным.

## Критерии приёмки
- [ ] `front-e2e` в отдельной группе, `cancel-in-progress: false`.
- [ ] В workflow/README зафиксирован бюджет: `test` ≥ 3 мин, `front-e2e` ≥ 30 мин без отмены.
- [ ] Таблица p50/p95 по двум джобам (минимум 3 зелёных прогона E2E).
- [ ] В `5-tech-backlog/chat/README.md` (или AGENTS §5) записано: отменённый прогон ≠ доказательство.
