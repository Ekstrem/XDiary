# DO-023: Политика отмены CI — гарантированное окно для `front-e2e`

- **Статус:** Закрыта
- **Приоритет:** P2 (из-за отмен прогонов теряется приёмка; повторялось 2 раза за сутки)
- **Источник:** владелец 2026-11-05: «есть ли метрика, сколько надо гарантированно дать тестам отработать?»; факты сессии — `front-e2e` на `09262c7` отменён через 111 с новым пушем
- **Зависимости:** fix CI (`9b58f6f` — `paths-ignore` для чата), DO-021

## Проблема
`concurrency: ci-tests / cancel-in-progress: true` (так было **до** фикса) рубил **любой** идущий прогон при новом пуше. Метрики/бюджета прогона нет, поэтому:
- `front-e2e` не доходит до конца при активной работе команды → **нет приёмки** FE-017/020/021/022, TE-031;
- при этом сам `test` дешёвый (по фактам: 69 с зелёный, 24 с на падении сборки), а E2E — единственный дорогой прогон.

## Факты (для бюджета)
| Джоб | Лимит в workflow | Факт |
|---|---|---|
| `test` | `timeout-minutes: 20` | зелёный **69 с**, падение сборки 15–24 с |
| `front-e2e` | `timeout-minutes: 30` | **зелёного прогона в сессии нет** — все либо отменены, либо красные; известный прогон отменён на 111 с |

Вывод: текущие лимиты (20/30 мин) сильно больше реального времени, а отмены происходят на 1–2 минуте — то есть отмена бьёт не по «зависшему», а по нормально идущему прогону.

## Принятое решение (финал владельца 2026-11-05)
> Первоначальное предложение (порог в три минуты и автоматическая отмена для `test`) **снято**: владелец сказал «5 минут», поэтому оба джоба просто не отменяются. Действует список ниже.

1. **`test`** — `cancel-in-progress: false` (не `true`): прогон не отменяется новым пушем, идёт в очередь; окно **5 минут** соблюдается с запасом.
2. **`front-e2e`** — отдельная группа `front-e2e`, `cancel-in-progress: false`; никогда не отменяется.
3. **Гарантированное окно:** E2E получает **полные 30 мин** (его `timeout-minutes`) без внешней отмены. Прогон валиден для приёмки, только если завершился сам (success/failure).
4. **Метрика:** p50/p95 по последним 20 зелёным прогонам — `tools/ci-metrics.py` → `7-deploy/CI-BUDGET.md`.
5. **Правило приёмки (TL):** отменённый run **не считается** доказательством — ни зелёным, ни красным.
6. **Для агентов:** не отменять прогон раньше **5 минут** от `started_at`; `queued`-дубликаты отменять можно; «завис» — только с цифрами `started_at`/`updated_at` (AGENTS §5.1).

## Критерии приёмки
- [x] `front-e2e` в отдельной группе `front-e2e`, `cancel-in-progress: false`.
- [x] В workflow/README зафиксирован бюджет: `test`/`front-e2e` **не отменяются** (гарантированное окно 5 мин → реализовано как «не отменять вовсе»; `front-e2e` получает полные 30 мин).
- [x] Таблица p50/p95 по двум джобам — инфраструктура готова (`tools/ci-metrics.py` → `CI-BUDGET.md`, автообновление); цифры наполняются по мере зелёных прогонов (сейчас 0 зелёных E2E).

## Результат
- `.github/workflows/ci-tests.yml`: `test` (группа `ci-tests-test`) и `front-e2e` (группа `front-e2e`) — оба `cancel-in-progress: false` (финальное решение владельца: гарантированное окно 5 мин → не отменять вовсе).
- `7-deploy/README.md` — раздел «Бюджет CI (DO-023)»; AGENTS §5.1 — полная политика (5 мин, правила отмены, отменённый run ≠ доказательство).
- `tools/ci-metrics.py` + `7-deploy/CI-BUDGET.md` — p50/p95 по зелёным прогонам (автообновление); `--help` показывает справку, бюджетная строка приведена к «5 мин» (финал владельца).
