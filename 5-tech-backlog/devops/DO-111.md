## Задача

Убрать второй источник правды для строк подключения. Сейчас:

1. `7-deploy/deploy.sh` (версия из репозитория) содержит `-e "ConnectionStrings__CommandDb=…"`
   с **устаревшим паролем**;
2. `7-deploy/secrets/.env` содержит актуальные значения и передаётся через `--env-file`;
3. `-e` **перекрывает** `--env-file` → сервисы падают `28P01: password authentication failed`.

Из-за этого на dev рабочим оказался **бэкап старого `deploy.sh`**
(`deploy.sh.bak-do-212641`), а не версия из репозитория: «починил на сервере» ≠ «в репозитории»
(`AGENTS.md` §5.2). На проде тот же класс уже приводил к 500 на `POST /api/v1/clients`
(`DO-110`), там фикс тоже был ручным.

## Критерии приёмки

- [ ] строки подключения берутся **только** из `secrets/.env`; в `deploy.sh` нет `-e ConnectionStrings__*`
- [ ] `grep -c 'ConnectionStrings__' 7-deploy/deploy.sh` → `0`
- [ ] на dev `bash update.sh` поднимает все 12 сервисов без `28P01` (квитанция: `podman inspect` + `/health`)
- [ ] в `7-deploy/runbooks/deploy.md` записано правило: секреты только в `secrets/.env`, `-e` для них запрещён
- [ ] бэкап-скрипт `deploy.sh.bak-*` на VPS-2 удалён после проверки (иначе снова станет «источником»)
