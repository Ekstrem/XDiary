## Что произошло на самом деле (и почему «старый образ» — неверная версия)

В прогоне `43303278241` шаг «Квитанция BE-092 на dev» дал:

```
check_be092_delivery: занятый номер: ожидали `409` + `clientId`, получили `200`,
`clientId` нет, `delivery` нет, ключи: [id, otpExpiresAt, phone, verified, version]
```

`200` с новым `id` — это ответ **создания** клиента, то есть вторая проба увидела номер как **новый**.

**Код в образе корректен.** Проверил по коммиту образа `33c226c` (`images.lock`, `client single-33c226c`):

```
33c226c:6-msa/BC-Client/src/Client.Api/Controllers/ClientsController.cs
  40|  if (r.Existing)
  42|  // 409: номер уже зарегистрирован, код переотправлен — клиенту нужен реальный clientId.
  43|  return Conflict(delivery is null
  44|      ? new { error = "Номер уже зарегистрирован", clientId = m.Id } …
```

Путь `Existing → 409 + clientId` появился **2026-11-07** (`3e3600981`, «be: BE-092 — delivery/409/429»), то есть **есть** в образе от 2026-11-10. Версия «на dev старый образ без 409» — **опровергнута чтением коммита образа**.

## Настоящая причина: две джобы пишут в одну базу одновременно

| Джоба | Что делает | Телефоны |
|---|---|---|
| `receipt-be092` | POST `/clients` с **одним** номером `+7999{time%1e7}` три раза: новый → занятый → третий | `+7999…` |
| `smoke-front` (шаг «Очистить накопленные E2E-данные на dev (DO-044)») | `bash cleanup-e2e-dev.sh --apply --clients` | `CLIENT_PATTERN="("Phone" LIKE '+7999%')"` → **удаляет всех `+7999…`** |

Обе джобы в `deploy.yml` имеют `needs: deploy-dev` и **ничем не упорядочены между собой** → идут параллельно. Между первой и второй пробой `receipt-be092` очистка может удалить только что созданного клиента → вторая проба создаёт нового → `200` вместо `409`.

Это объясняет и то, почему аннотация предлагала «ждать 70 с и повторять»: ожидание не помогает, если строка удалена, а не «не создана».

## Варианты (выбрать один, @DO и @TE согласуют)

1. **Порядок (предпочтительно, правка в `.github/workflows/deploy.yml`):** `receipt-be092: needs: [deploy-dev, smoke-front]` — тогда очистка уже завершена и пробы никого не пересекают.
2. **Диапазон проб (правка в `9-tests/scripts/check_be092_delivery.py`, @TE):** проба на префиксе, который очистка не трогает (например `+7998…`), с обновлением `--phone`.
3. **Оба** — предпочтительно: порядок убирает гонку, отдельный диапазон делает пробу устойчивой к будущим очисткам.

## Критерии приёмки

- [ ] `receipt-be092` на следующем прогоне: **`409`+`clientId` (+`delivery`) на занятом номере**, номер прогона в `## Результат`;
- [ ] в логе нет `занятый номер: ожидали 409 … получили 200`;
- [ ] номер пробы **не** попадает под `cleanup-e2e-dev.sh` (`LIKE '+7999%'`), либо `receipt-be092` идёт строго после `smoke-front`;
- [ ] `deploy-prod` перестаёт быть `skipped` (при зелёных остальных гейтах).
