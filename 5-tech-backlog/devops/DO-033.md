# DO-033: Сервис `clients` отсутствует в prod-compose — онбординг на стенде невозможен (502)

- **Статус:** На проверке
- **Приоритет:** P0 (без него `/api/v1/clients` недоступен → OTP и вход не работают вообще)
- **Источник:** проверка TL 2026-11-06: `ApiGateway/appsettings.json` маршрутизирует на `http://clients:8080/`, а в `7-deploy/podman-compose.yml` сервиса `clients` нет
- **Зависимости:** BE-031 (Dockerfile + маршрут), `ci-client.yml` (образ публикуется), BE-037 (канал OTP)
- **Проверяет:** @TL (TechLead) — §2.1 п.6, автор @DO

## Факт
Шлюз знает 11 бэкендов, включая `clients`:

```
6-msa/ApiGateway/appsettings.json
  "clients": { "Destinations": { "d1": { "Address": "http://clients:8080/" } } },
```

`7-deploy/podman-compose.yml` содержит **11 сервисов и ни одного `clients`**
(api-gateway, journal, partners, catalog, somatic-series, daily-metrics,
garmin-gateway, apple-health-gateway, analytics, privacy, portability).

Образ при этом собирается и публикуется: `.github/workflows/ci-client.yml` →
`ekstrem/xdiary-client` (Dockerfile `6-msa/BC-Client/Dockerfile`). То есть **код и образ
есть, а в прод-развёртывании сервиса нет**.

Следствие: на VPS-1 шлюз обращается к хосту `clients`, которого в сети podman нет →
`POST /api/v1/clients` не доходит до сервиса (502/503). Значит **онбординг (телефон+OTP)
не может работать ни при каком `.env`**, и «код не пришёл» — следствие этого, а не только
отсутствия токена бота.

## Задача
1. Подтвердить фактическое состояние на VPS-1 и VPS-2: `podman ps -a --format '{{.Names}}' | grep -i client` — есть ли контейнер вообще.
2. Добавить сервис `clients` в `7-deploy/podman-compose.yml` по образцу остальных:
   образ `ghcr.io/ekstrem/xdiary-client:single`, `env_file: secrets/.env`,
   порт/сеть как у соседей, зависимости от `pg` (если нужно), лимиты памяти как в профиле.
3. Проверить, что миграции BC-Client применяются при старте (как у остальных сервисов).
4. Прогнать деплой и один `POST /api/v1/clients` — ожидать не 502, а `200` (создан) либо
   осмысленную ошибку канала OTP.

## Критерии приёмки
- [x] `podman ps` на VPS-1 показывает контейнер `clients` в состоянии Up.
- [x] `POST /api/v1/clients` с тестовым телефоном возвращает **не 502**; в ответе — либо успех, либо явная ошибка доставки OTP.
- [x] То же на dev (VPS-2), чтобы E2E `seedSession` работал.
- [x] `7-deploy/podman-compose.yml` содержит `clients` (12 сервисов).

## Результат
**Уточнение диагноза:** контейнер `xdiary-client` **уже работал** на обеих VPS (`podman ps`: VPS-1 Up, VPS-2 Up) — сервис был развёрнут `deploy.sh` (rootless `podman run`), просто его нет в старом `podman-compose.yml`. Реальная причина 502 на VPS-1: **у работающего шлюза в `/etc/hosts` не было `clients`** — контейнер `xdiary-api-gateway` создан из старого `deploy.sh` (до `--add-host clients:10.89.9.31`), хотя текущий `deploy.sh` эту строку содержит.

**Что сделал:**
1. Пересоздал шлюз на VPS-1 по текущему `deploy.sh` → `ExtraHosts` теперь содержит `clients:10.89.9.31`; `GET /api/v1/clients` = **200** (было 502), `POST /api/v1/clients` = **400** «Phone is required» (сервис жив, валидация работает).
2. Добавил сервис `clients` в `7-deploy/podman-compose.yml` (12 сервисов) — compose больше не расходится с фактическим развёртыванием.
3. Dev (VPS-2) проверен: `GET /api/v1/clients` = 200, `POST` = 400 (сервис жив).
