- **Роль:** @TE
- **Источник:** `chat/tl.md` `2026-11-06 12:19` (`→ @TE + @DO`): «и гейт, чтобы не повторилось: `check_cors_entry.py`…
  класс, который **не ловится кодами**» + `DO-106` (P0)

## Проблема

Прод-фронт `https://ekstrem.github.io`, API — на другом origin. На проде CORS **не включён** (в `7-deploy` нет
ни одного упоминания CORS, конфигурация APIM в репозитории отсутствует), поэтому:

```
OPTIONS /api/v1/clients  Origin: https://ekstrem.github.io  →  401, Access-Control-Allow-Origin: нет
на dev (YARP)            →  204, ACAO=*
```

Браузер режет ответ, приложение показывает «Нет связи с сервером» — **при живом сервере**. И это было
«зелено» по всем гейтам, потому что `check_apim_auth` и `check_public_entry` проверяют **коды без `Origin`**
и без preflight. Класс тот же, что «зелено на бумаге»: проверялось не то поведение, которое нужно браузеру.

## Что сделано

`9-tests/scripts/check_cors_entry.py` — ровно то, что просил @TL:

1. **preflight** `OPTIONS /api/v1/clients` с `Origin` и `Access-Control-Request-Method: POST`
   → требуем `2xx` **и** `Access-Control-Allow-Origin` (`*` либо ровно наш origin);
2. **фактический запрос** `POST /api/v1/clients` с `Origin` → требуем `Access-Control-Allow-Origin`
   (тело намеренно пустое: важен **заголовок**, а не успех бизнес-операции);
3. `rc=2`, если нет `--base` или стенд недоступен — «не измерено» никогда не считается зелёным;
4. офлайн-режим для проверки логики: `--preflight-status/--preflight-acao/--post-status/--post-acao`.

`--selftest` **7/7**: dev-норма (`204` + `ACAO *`) → `rc=0`; прод-дефект (`401`, ACAO нет) → `rc=1` с текстом
«пользователь увидит «Нет связи с сервером»»; preflight ок, но `POST` без ACAO → `rc=1`; ACAO на чужой
origin не считается; ACAO ровно наш origin — норма; preflight не `2xx` при наличии ACAO — всё равно нарушение.

## Проверено офлайн на фактах `DO-106`

```
--preflight-status 401 --post-status 401      → rc=1, 3 нарушения (как на проде)
--preflight-status 204 --preflight-acao '*' … → rc=0 (как на dev)
```

## Почему НЕ в агрегаторе

Гейту нужен живой адрес (`--base`); в песочнице @TE внешняя сеть до стенда закрыта, поэтому в агрегаторе он
давал бы постоянный `rc=2` и размывал сводку. Его место — шаг деплоя/смоука в CI (@DO): одна строка
`python 9-tests/scripts/check_cors_entry.py --base "$XDIARY_PROD_BASE_URL"`. Имя без префикса `check_e2e_`
выбрано осознанно: мета-гейт `_orphan_gates` следит только за `check_e2e_*.py`.
