# TE-101. `POST /journal/records/{id}/when` принимает **любую строку** как дату: `"не дата"` сохраняется и отдаётся

- **Статус:** Закрыта
- **Приоритет:** P1 (данные дневника: невалидная дата сохраняется как есть → сортировка/тренды/метрики считают мусор)
- **Роль:** @TE (замер), **исправление — @BE** (`6-msa/BC-Journal`), контракт — @AR
- **Проверяет:** @TL
- **Источник:** `chat/fe.md` `2026-11-07 00:27` (`→ @TE + @TL`): «фронт может отправить **пустую строку** `startedAt` —
  `rec.startedAt || ""` (`repository.js:127`) при импорте записи без даты; если сервер на `""` отвечает `400`, это
  законно, но тогда в отчёте стоит указать, что тест с `""` — не „сломанное поле“, а „пустая дата отклонена“».
  Проверка показала третье: сервер не отклоняет **ничего**.

## Измерено на dev (`2026-11-07 09:3x`, контур `https://xdiary-vps2.taile0b6ee.ts.net`)

Цикл: `POST /clients` → `verify(000000)` → `POST /journal/records` (черновик) → `POST /records/{id}/when` → чтение
`GET /records/{id}`.

| Тело `when` | Ответ | `startedAt` после чтения |
|---|---|---|
| `{"startedAt": "2026-11-07T10:00:00Z"}` | 200 | `2026-11-07T10:00:00Z` (норма) |
| `{"startedAt": ""}` | **200** | `''` — пустая дата сохранена |
| `{"startedAt": "не дата"}` | **200** | `'не дата'` — **сохранено как есть** |
| `{"startedAt": "1234567890"}` | **200** | `'1234567890'` — сохранено как есть |
| `{"startedAt": null}` | 400 | — (это отказ **биндинга**, а не валидации) |

## Почему это дефект, а не «строка и есть строка»

- Канон (`04-architecture/api-index.yaml`, `Journal.SpecifyWhen`) объявляет `types: {startedAt: "string (ISO)"}` и
  `400: "доменная ошибка (validation/invariant)"` — то есть не-ISO обязан отвергаться.
- Домен/хранилище хранит значение **дословно**: любая строка проходит, попадает в read-модель и отдаётся наружу.
- Следствия: сортировка и «последняя запись» по `startedAt`, тренды и корреляции, CSV-экспорт получают мусор;
  пользователь видит запись без даты там, где ожидается время.
- Фронт здесь **не виноват** и менять его не нужно: `rec.startedAt || ""` — разумный фолбэк, если сервер отклоняет
  пустую строку `400`. Дефект в том, что сервер её принимает.

## Повторный прогон после выкатки `journal` (`2026-11-07 11:2x`) — **валидация работает**

Тот же контур, тот же цикл; значение в записи читается после каждого вызова:

| Тело `when` | Ответ | В записи |
|---|---|---|
| `2026-11-07T10:00:00Z` | 200 | `2026-11-07T10:00:00Z` |
| `""` | **400** | не изменилась (`…10:00:00Z`) |
| `"   "` | **400** | не изменилась |
| `"не дата"` | **400** | не изменилась |
| `"1234567890"` | **400** | не изменилась |
| `2026-11-07T09:00:00+03:00` | 200 | `'…09:00:00+03:00'` |
| `2026-11-07T06:00:00Z` | 200 | `'…06:00:00Z'` |

То есть мусор отвергается, **и** отказ не портит запись (значение остаётся прежним) — это важнее, чем просто `400`.

**Осталось одно:** нормализация — `+03:00` и `Z` дают **разные** строки (`git grep "ToUniversalTime|ParseExact"` →
0 вхождений). Критерий про равные моменты **не выполнен**, карточка поэтому `На проверке`, а не `Закрыта`.

## Критерии приёмки

- [x] `{"startedAt": ""}` → **400** (проверено `11:2x`, запись не испорчена)
- [x] `{"startedAt": "не дата"}`, `"   "`, `"1234567890"` → **400**
- [x] `{"startedAt": "2026-11-07T10:00:00Z"}` → 200, чтение отдаёт то же значение
- [ ] тест в `6-msa/BC-Journal/src/Journal.*Tests` (зона @BE), с негативным контролем на «принимает всё»
- [→] **нормализация вынесена из этой карточки** (`@TL 11:21`): `2026-11-07T09:00:00+03:00` и
      `2026-11-07T06:00:00Z` пока дают разные строки (`git grep ToUniversalTime|ParseExact` → 0), и это
      **отдельная карточка @BE** со ссылкой на `TE-101`. Здесь критерий снят, чтобы приёмка данных не висела
      на маленьком хвосте — но факт не спрятан: он записан и в разделе прогона выше.
- [ ] прогон, который реально собрал тесты (REF), а не «локально прошло»
