# TE-066. «Забыли PIN?» нажимался вне экрана замка

- **Статус:** На проверке
- **Проверяет:** @TL
- **Роль:** @TE
- **Источник:** реальные прогоны Front E2E (аннотации `##[error]` и артефакт `front-e2e-results`)

## Проблема

`pin-fallback.spec.js` кликал `#btn-pin-forgot` **после** успешной разблокировки. Кнопка живёт только внутри `#view-lock` (`8-front/index.html:34`), поэтому `page.click` ждал её появления до общего лимита теста: в прогоне #770 — `Test timeout of 100000ms exceeded`. Снимок `error-context.md` подтверждал: приложение показывает журнал, замка нет.

**Правка:** перед шагом «Забыли PIN?» спека возвращает замок (`reload` + `expectScreen('#view-lock', 20 с)`) и только затем кликает; после клика ждёт `#view-onboarding` (20 с).

**Проверено:** `node --check` rc=0; `e2e-dryrun` 22 теста / 0 падений; гейты 34/34. В прогоне #774 тест `pin-fallback → «локальный PIN есть → замок…»` из списка падений исчез (`passed 12 → 13`).

## Результат

Правка в `9-tests/RnD/front-e2e/tests/pin-fallback.spec.js:123-129`: перед `#btn-pin-forgot` спека
возвращает замок (`reload` → `expectScreen('#view-lock', 20000)` → клик) — контрол, который живёт только
внутри `#view-lock`, больше не ищется на экране журнала.

Квитанция (`2026-11-07`, рабочее дерево, `HEAD` `9caffd67`): `node --check` `rc=0`; `check_e2e_all.py` —
**гейтов 43 | зелёных 43 | красных 0**, `rc=0` (счёт вырос с 34 — это норма, а не перепроверка); `e2e-dryrun.js --all-flags` — **тестов исполнено 28 | упало 0 | утверждений 307**, `rc=0`; `check_e2e_reload_lock.py` — «со «слепым» reload 0 | нарушено: 0».

Граница (честно): браузерного `passed/failed` нет — прогон на стенде за @DO (`front-e2e`), до него
карточка держится не на «проверено в CI», а на исполнении тела спеки и на исчезновении класса падения в #774.
