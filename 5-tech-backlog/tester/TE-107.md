## Факт

Прогон **#27** (`failure`, sha `f465e4735`) в аннотациях печатает **пять раз**:

```
{"title":"views (ПОСЛЕ ПАДЕНИЯ: E2E: FE-046 — ошибка API на старте: сплэш уходит за 2 с, экран или ошибка видны)","views":{}}
```

По коду `9-tests/RnD/front-e2e/tests/api.js:74-89` `dumpViews` делает:

```js
const views = await page.evaluate(() => {
  const out = {};
  document.querySelectorAll('[id^="view-"]').forEach((el) => {
    out[el.id] = el.classList.contains('hidden') ? 'hidden' : 'visible';
  });
  return out;
});
```

Значит `views:{}` — это **ноль элементов** с `id`, начинающимся на `view-`, а не «все скрыты» (тогда было бы 13 ключей со значениями `hidden`). Два взаимоисключающих объяснения, и различить их сейчас нечем:

| Гипотеза | Что должно быть в отчёте |
|---|---|
| **A. Документ не загрузился** (не тот URL, 404/500 от статики, пустой `body`) | `url`, HTTP-статус документа, `document.body.innerHTML.length` |
| **B. Документ есть, но разметка экранов не создана** (ранняя ошибка JS до вставки `#view-*`) | те же поля + список первых 5 `id` в `body` |

## Задача

Расширить `dumpViews` (и вызовы в спеках) так, чтобы при **пустом** результате печаталось:

- `page.url()` — фактический адрес (после редиректов);
- статус ответа на документ (через `page.on('response')` для `main`-запроса);
- `document.body ? document.body.innerHTML.length : -1` и первые 5 `id` в документе;
- по-прежнему `views` — карта экранов, когда они есть.

## Критерии приёмки

- [ ] `dumpViews` печатает `url`, `status`, `htmlLen`, `ids` (первые 5) **всегда**, а не только при пустом `views`;
- [ ] норма: на зелёном прогоне (`front-e2e-repeat`, `specs=wizard-offline`) аннотация содержит `views` с 13 ключами и `url` стенда;
- [ ] дефект: прогон с `specs=startup-api-error` печатает либо `views` с ключами (гипотеза B), либо `ids:[]` + `htmlLen` (гипотеза A) — то есть строка однозначна;
- [ ] `--selftest` у стенда/линтера не ломается (`check_ci_artifacts --strict` → `rc=0`).

## Почему это карточка, а не «догадаемся»

`FE-046` невозможно закрыть, пока `views:{}` читается двояко: если документ не грузился — это дефект спеки/стенда (зона @TE), если грузился, а экранов нет — дефект продукта (зона @FE). Сейчас обе трактовки выглядят одинаково, и именно на этом разборе мы уже теряли круги.
