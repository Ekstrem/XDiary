# TE-056 — условие `(ii-c)`: `/internal/**` не достижим снаружи

- **Статус:** Закрыта
- **Приоритет:** P0
- **Источник:** ADR-026 §«Квитанция (ii-b)» + решение @AR `02:30` (компенсация за исключение `anonymous-inside`)
- **Зависимости:** `TE-050` (партнёрский стенд), `BE-067`
- **Проверяет:** @AR
- **В работе с:** 2026-11-05
- **Закрыта:** 2026-11-05 (вердикт @AR `04:45`: «проверено, можно закрывать»)

## Задача

`anonymous-inside` — операции, которые **не проверяются токеном** и доступны только внутри контура.
Исключение их из `(ii-b)` создаёт риск: если они достижимы **снаружи**, это публикация внутреннего API,
что серьёзнее открытой ручки.

Нужен машинный гейт `(ii-c)`: через **публичный** вход (`Funnel`/YARP/APIM) запрос к `/internal/**`
обязан давать **`401`/`404`** и **никогда `2xx`**.

## Критерии приёмки

- в `9-tests/scripts/check_apim_auth.py` режим проверки `(ii-c)` по базе публичного входа
  (`--public-only` или аналог) для операций `auth=anonymous-inside` из `api-index.yaml`;
- вердикт: все `/internal/**` → `401/404` ⇒ `rc=0`; любой `2xx` ⇒ **`rc=1` с именем операции**;
- `--selftest`-кейс «`/internal` отдаёт `200` снаружи ⇒ `rc=1`» (красный без проверки, зелёный с ней);
- прогон на тесте и на проде с `REF`/`where` в `## Результат`.

## Результат

Реализовано в `9-tests/scripts/check_apim_auth.py` (режим **`--ii-c`**, а не `--public-only`: имя
совпадает с условием `ADR-026`, чтобы квитанцию нельзя было спутать с `(ii-b)`).

- `internal_ops()` берёт операции **из `api-index.yaml`** по признаку `auth=anonymous-inside`
  или пути `/internal/**` — сейчас 2: `Journal.ListAll` (`GET /internal/journal/records`),
  `Journal.IngestPartnerEvent` (`POST /internal/partners/events`). Захардкоженного списка нет,
  поэтому новая внутренняя ручка попадёт в гейт автоматически.
- `verdict_internal()`: `401/403/404` → ok (недостижим снаружи), **любой другой полученный код**
  (`2xx`, `400`, `405`, `5xx`) → нарушение с именем операции, нет ответа → `unknown`.
- Квитанция `(ii-c)` печатается тем же форматом, что `(ii-a)/(ii-b)`, включая `сумма=`, `where=`,
  `images=`, `network=`, `tool=`.
- `--selftest` = **25/25**; кейс проверяет три исхода (`200` → нарушение, `401`/`404` → норма,
  нет ответа → `unknown`) и то, что внутренних операций в индексе ровно две.
- Локальная приёмка (настоящий HTTP, два контура): «всё `200`» → `REF=… | (ii-c) FAIL
  защищено=0/2 | нарушителей=2 | rc=1`; «всё `401`» → `(ii-c) PASS защищено=2/2 | rc=0`.
- Побочно: знаменатель `(ii-b)` приведён к решению @AR `03:14` — `anonymous-inside` исключён,
  целей **74**; `--dry-run` печатает `целей 74 (в индексе 80, без токена: 4 anonymous + 2 anonymous-inside)`.

### Прогон на публичном входе (выполнено @TE)

Оба входа проверены снаружи, TLS через Python `http.client` (без прокси; `curl.exe` в этой среде
не работоспособен — `SEC_E_NO_CREDENTIALS`, см. `@DO 03:06`):

```
(TEST) REF=6e1cec53 | (ii-c) PASS защищено=2/2 | нарушителей=0 | contract=0 | неизвестно=0
       | rc=0 | сумма=2/2 | where=Funnel/VPS-2 public entry, TE sandbox, http.client
(PROD) REF=6e1cec53 | (ii-c) PASS защищено=2/2 | нарушителей=0 | contract=0 | неизвестно=0
       | rc=0 | сумма=2/2 | where=Funnel/VPS-1 public entry, TE sandbox
```
Поимённо: `GET /internal/journal/records [Journal.ListAll]` → **401**, `POST /internal/partners/events
[Journal.IngestPartnerEvent]` → **401** на обоих входах. Внутренние ручки **не опубликованы наружу** ⇒
условие `(ii-c)` выполнено, блокер Funnel со стороны гейта снят.

Важно: `(ii-c)` не маскирует продуктовый дефект `BE-067` — `Journal.ListAll` даёт `500` **изнутри**
контура, это остаётся багом @BE; снаружи он был бы виден как `500`, то есть как нарушение `(ii-c)`.

### Вердикт @AR (`04:45`) — «проверено, можно закрывать»

Проверено по существу: (1) `(ii-c)` **PASS 2/2** на обоих входах, `rc=0`; (2) классификация
ровно как в `ADR-026` — допустимы только `401/403/404`, любой другой полученный код = нарушение
(включая `400`/`405`); (3) операции берутся **из индекса**, захардкоженного списка нет;
(4) `--selftest` покрывает обе стороны — красный на «всё `200`», зелёный на «всё `401`»;
(5) `--all` печатает ИТОГ с одним `tool=`/`where=`; (6) тождество `74 + 2 = 76` из `80` с `rc=2`
при непокрытии сделало норму проверяемой в прогоне.

**Замечание по области действия (важно для протокола):** `(ii-c)` измеряет **публичный вход**, а не
конкретный шлюз. Поэтому закрытие не зависит от открытого спора «APIM в пути или YARP»
(`--probe-entry`: `Server: Kestrel`, без `X-Gravitee-*`, несуществующий путь → `401`). Если после
подтверждённого переключения на APIM поведение входа изменится, `(ii-c)` перемеряется теми же
командами — это отдельный прогон, а не переоткрытие задачи.
