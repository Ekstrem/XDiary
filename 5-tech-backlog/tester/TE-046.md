# TE-046: `reportStep` называет «тост ошибки» любой тост — на зелёном прогоне это ложный красный

- **Статус:** На проверке
- **В работе с:** 2026-11-07
- **Приоритет:** P3 (гигиена сигналов; на доставку не влияет)
- **Источник:** @DO 2026-11-04 00:05 — в прогоне `front-e2e-repeat` **#12** на шаге 4 в логе стоит `##[warning]тост ошибки (шаг 4: «я» с сервера после перезагрузки): Это ты: e2e-aut…`, но прогон **зелёный**: это **информационный** тост («Это ты: <партнёр>»), а не ошибка
- **Зависимости:** TE-045 (имена шагов в `onboarding` — сделано), TE-032 (диагностика)
- **Проверяет:** @TL (TechLead)

## Проблема
`reportStep` печатает `##[warning]тост ошибки: …` для **любого** видимого тоста. На зелёном прогоне это читается как предупреждение о дефекте: люди привыкают игнорировать warning — ровно тот класс, который мы весь день устраняли (`|| true`, `continue-on-error`, ложный `success`).

## Задача (зона @TE, `9-tests/`)
1. Нейтральная формулировка: `тост (шаг N): <текст>` вместо «тост ошибки».
2. Если во фронте есть классы тостов (`toast-error` / `toast-info` / `toast-success`) — различать их и писать уровень честно: `::warning::` только для ошибочного тоста, `::notice::`/`console.log` для информационного.
3. Поведение спеки не менять: это только текст/уровень лога.

## Критерии приёмки
- [x] На **зелёном** прогоне в логе нет `::warning::` про тосты (информационный тост идёт как `::notice::`).
- [x] Если тост действительно ошибочный — он виден как `::warning::`.
- [x] `node --check` = 0.
- [ ] Прогон `front-e2e-repeat` с этими спеками после правки — зелёный (за @DO).

## Результат
Правка в `9-tests/RnD/front-e2e/tests/api.js`, `reportStep`:
```
было:  console.log('::warning::тост ошибки (' + where + '): ' + text)  ← для ЛЮБОГО тоста
стало: const isError = /error|danger|fail/i.test(state.cls) || /^(ошибк|error)/i.test(text);
       const line = 'тост (' + where + '): ' + text;
       console.log((isError ? '::warning::' : '::notice::') + line);
```
- **Формулировка нейтральная** — `тост (шаг): <текст>`, без «ошибки».
- **Уровень по признаку ошибки:** сначала класс тоста (`toast-error`/`error`/`danger`/`fail` — задел на будущее), иначе текст: ошибочные тосты во фронте начинаются с `«Ошибка:»` (`8-front/js/app.js:279, 320, 327, 336, 341`). Всё остальное — `::notice::`.
- **Почему не по классам только:** `toast()` во фронте (`8-front/js/app.js:106`) ставит лишь `hidden`, классов `toast-error`/`toast-info` в разметке нет (проверено: `index.html:357` — `<div id="toast" class="toast hidden">`), поэтому класс проверяется как задел, а рабочий признак — текст.
- **Проверка логики без браузера** (`node -e` по тем же регуляркам):
```
'Это ты: e2e-auto-123'    → ::notice::   ← это и был ложный warning в #12
'Ошибка: привязка'        → ::warning::
'Введите номер телефона'  → ::notice::
класс 'toast error'       → ::warning::
```
`node --check` для `api.js`, `onboarding.spec.js`, `pin-first-login.spec.js` = 0.

**Осталось:** критерий про зелёный `front-e2e-repeat` — за прогоном @DO (поведение спек не менялось, менялся только уровень/текст лога).
