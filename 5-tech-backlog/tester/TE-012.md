# TE-012: front-e2e падает — `showView()` спотыкается об удалённый `#view-garmin`

- **Статус:** В работе
- **Приоритет:** P2 (CI-quality-gate, не блокер релиза)
- **Источник:** DO-011 (job `front-e2e`); первичная гипотеза @TL; уточнено @TE по логу CI
- **Зависимости:** DO-011, FE-004

## Настоящая причина (по логу CI — проверено)
Лог `front-e2e` (run #78, аннотация check-run):

```
pageerror: Cannot read properties of null (reading 'classList')
dom: { lock: false, journal: true, tabbar: false }
```

1. `8-front/index.html`: коммит **FE-004** (`bee7e8a`) удалил `<section id="view-garmin">`.
2. `8-front/js/app.js`: `showView()` по-прежнему перебирает список, включая `"garmin"`:
   `["lock","journal",…,"garmin","detail"].forEach(v => $("view-"+v).classList.toggle(…))`.
3. `$("view-garmin")` → `null` → `null.classList` → **исключение**.
   Оно прерывает `showView("journal")` в `lock()`, поэтому `#tabbar` остаётся `hidden`
   и любой клик по вкладке падает.

**Это реальный регресс фронта, а не тест** — UI-автотест его и поймал. Гипотеза про
`pin/has` (`{}` вместо `false`) **не подтвердилась**: `app.js` `lock()` использует
**локальный** `Pin.hasPin()` (`pin.js` → IndexedDB), а `Api.privacy.hasPin` не вызывается.

## Задача (@FE — зона `8-front`)
- Убрать `"garmin"` из списка в `showView()` (и мёртвый garmin-код), либо вернуть `#view-garmin`.
- Проверить, что вкладки переключаются.

## Задача (@TE)
- Держать `front-e2e` красным до фикса (это корректно), затем подтвердить зелёный.

## Критерии приёмки
- [ ] `showView()` не падает на отсутствующем `view-garmin`.
- [ ] `front-e2e` зелёный на push.
- [ ] Сценарий «Добавить партнёра» проходит.
