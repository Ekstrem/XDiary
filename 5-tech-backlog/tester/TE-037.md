- **Статус:** Закрыта
- **Приоритет:** P1 (единственный способ убрать третье падение гейта: `remove-pin` красный на серверном assert)
- **Источник:** @TE 2026-11-02 19:17 — `change-pin.spec.js` построен на серверном PIN (`POST /privacy/pin/set`, `POST /privacy/token {pin}`); канон MVP — **локальный** `window.Pin`, серверный `/privacy/pin/*` = legacy. Подтверждено вердиктом **AR-009 = B (legacy)** и ADR-021, раздел «PIN: серверный vs локальный»
- **Зависимости:** AR-009 (решён), ADR-021, FE-025/FE-029 (локальный замок), FE-031 (0.66)
- **Проверяет:** @TL (TechLead)

- **Артефакт:** `9-tests/RnD/front-e2e/tests/change-pin.spec.js`, `remove-pin.spec.js` (оба активны, `node --check` = 0)

## Задача — два спека, оба переводятся на локальный PIN
### 1. `change-pin.spec.js`
Смена **локального** PIN через UI Настроек (`window.Pin.setPin` / экран смены), проверить:
1. новый локальный PIN пускает в журнал (`unlockIfLocked` с новым значением);
2. старый локальный PIN больше не пускает;
3. после смены `Pin.hasPin()` = true; в `finally` возвращается исходный PIN (чистота стенда).

### 2. `remove-pin.spec.js`
1. **Серверный assert `pin/has` убрать из гейта:** серверный блок — `describe.skip` с причиной «серверный PIN — legacy (ADR-021 / AR-009), вне MVP».
2. Проверять **локальное** состояние: `window.Pin.hasPin()` = true до снятия и **false после** снятия через UI; журнал после снятия открывается без PIN-экрана.
3. Серверные вызовы `/privacy/pin/*` не должны быть условием прохождения спека.

## Критерии приёмки
- [x] Ни `change-pin`, ни `remove-pin` не проверяют серверный `/privacy/pin/*` как продуктовый контракт.
- [x] `remove-pin` проверяет локальный `window.Pin.hasPin()` до/после снятия.
- [x] Пометки `legacy` в шапках сняты там, где спека снова проверяет MVP-путь; где остаются — указана причина и ADR.

## Результат

**Оба спека переписаны на локальный PIN и снова в гейте.**

| Спек | Было | Стало |
|---|---|---|
| `change-pin.spec.js` | весь спек под `test.describe.skip('legacy: серверный PIN (ADR-008)')` | активный тест: смена через UI (`#btn-pin-open` → `#pin-current/new/confirm` → `#btn-pin-set`), `Pin.verifyPin(NEW)` = true и `Pin.verifyPin(OLD)` = **false**, `Pin.hasPin()` = true, reload снимается **новым** PIN; в `finally` исходный PIN возвращается через `Pin.setPin` |
| `remove-pin.spec.js` | серверный assert `pin/has` был **условием прохождения** | серверный контур (негативы `/privacy/pin/remove` → 401, `pin/has`, device-токен) вынесен в `test.describe.skip('legacy: серверный PIN (ADR-021 / AR-009) — вне MVP')`; активный тест проверяет **локальное** состояние |

**Активный сценарий `remove-pin`:** `loginWithPin` → `Pin.hasPin()` = true → Настройки → модалка PIN → «Удалить PIN» → `#confirm-yes` → `expect.poll(Pin.hasPin())` = **false** (условие прохождения — локальное состояние, а не ответ сервера) → reload → `#view-lock` **hidden**. В `finally` локальный PIN возвращается.

**Проверки:** `node --check` = 0 для обоих; все обращения к `/privacy/*` лежат внутри `describe.skip` (строки 21–58 в `remove-pin`), активный тест начинается со строки 60.

**Почему это разблокирует гейт:** третье падение (`remove-pin`) было на серверном assert, который по AR-009 = B вне MVP. Теперь серверный контур не влияет на результат, а MVP-путь (локальный PIN) проверяется по-настоящему.

**Решение, на котором это стоит (AR-009 = B, legacy):** источник правды для PIN — **локальный** `window.Pin` (IndexedDB), см. ADR-021, раздел «PIN: серверный vs локальный». Серверный `/privacy/pin/*` остаётся только для device-токена (ADR-008) и продуктом в MVP **не используется**. Поэтому:
- `BE-045` (починка серверного `pin/has`) **отклонена** — правится спека, а не сервер;
- серверные негативы в `remove-pin` сохранены как `describe.skip` с причиной, чтобы история BE-021/BE-034 не потерялась;
- гейт (`front-e2e`) больше не зависит от серверного контура PIN.
