## Проблема

@TL 01:06 решил три вопроса по карте покрытия: `#btn-partner-delete` и `#btn-catalog-delete` **входят в MVP**,
`#btn-import` — **вне MVP-спеки** (импорт уже покрыт через `#import-file`, кнопка лишь триггер выбора файла).
Решение было только в чате, а гейт `check_e2e_ui_coverage.py` продолжал держать `btn-import` в `MVP_CRITICAL`:
карта показывала долг там, где его по решению нет, и следующий человек снова поднимал бы тот же вопрос.

## Что изменено

1. `btn-import` убран из `MVP_CRITICAL` и добавлен в новый `OUT_OF_MVP` **с причиной и ссылкой на решение**:
   «вне MVP (решение @TL 2026-11-06 01:06): триггер выбора файла, импорт покрыт через #import-file».
2. Квитанция гейта дополнена счётчиком `вне MVP N`; в `--list` элемент помечается `(вне MVP)`.
3. `#btn-partner-delete` и `#btn-catalog-delete` остаются в `MVP_CRITICAL` и **покрыты**:
   `partner-edit.spec.js:114,124` и `catalog-archive.spec.js:101,129`.

## Измерено после правки

```
квитанция: элементов с обработчиком 64 | трогают спеки 64 | не покрыто 0 |
           критичных без покрытия 0 | вне MVP 0 | нарушено: 0
```
То есть карта покрытия сейчас **полная** (64 из 64), а не «64/38/26», как было на момент решения @TL.
