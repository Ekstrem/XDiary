## Задача
1. **API-уровень (можно писать сразу, сейчас):** `9-tests/scripts/probe_garmin_connect.js` (или `.py`): `POST /api/v1/garmin/connect` без токена -> **401**; с пустыми/битыми credentials -> **400 validation_error**; `GET /api/v1/garmin/state` без подключения -> **404**; `POST /api/v1/garmin/sync` без подключения -> **400 not_connected**; после connect с будущим `tokenExpiry` -> `state` **200** и в ответе **нет** `apiKey`/`oauthToken`; с прошлым `tokenExpiry` -> `requiresReauth=true`. Режим `--check-class-only` по образцу TE-111 (rc=0 жив, rc=1 нарушение, rc=2 «не измерено»).
2. **E2E (после FE-057):** сценарий `9-tests/e2e/garmin-token.spec` (Playwright): Настройки -> «Подключить Garmin» -> три поля (`API key`, `OAuth token`, `Token expiry`) -> Сохранить -> `GET /state` показывает `connected` и `lastSync`; кнопка «Из Garmin» на журнале вызывает серверный `sync` (в сети виден `/garmin/sync`, не `<input type=file>`); CSV-кнопка остаётся отдельной.
3. **Регрессионный якорь (то, что просил владелец):** тест **обязан падать**, если поля токена в настройках нет (проверка наличия трёх полей и кнопки). До мержа FE-057 — `skip` с явной причиной `FE-057 not merged` (не ложный pass, §5).
