# TE-016: E2E — снятие PIN (pin/remove с текущим PIN)

- **Статус:** Закрыта
- **Приоритет:** P1
- **Источник:** @FE 18:02 (не покрыто: «только смена»); PE 18:10 — «всё надо покрыть»
- **Зависимости:** BE-021, FE-009, FE-011
- **Результат:** `front-e2e` на `e97c667` — **success** (run `41310549082`). Сценарий `tests/remove-pin.spec.js`: логин по PIN → **негативы API** (`pin/remove` без `currentPin` → 401, с `0000` → 401, `pin/has` = true) → **снятие через UI** (Настройки → «Удалить PIN» → `#confirm-modal` **поверх** `#pin-modal` → «Да») → `pin/has` = false, device-токен (`pin:''`) → 200. В `finally` PIN возвращается через `pin/set` + проверка. Попутно закрыт **FE-011** (клик по «Да» перехватывался pin-модалкой) и подтверждён **BE-021**.

## Задача
Живой E2E, **безопасно для стенда**: на тестовом инстансе (или с тестовым PIN) снять PIN через `removePin(currentPin)` → проверить через API `pin/has` = false и что device-токен снова выдаётся → в `finally` вернуть исходный PIN.

## Критерии приёмки
- [x] `pin/remove` без/с неверным `currentPin` → 401 (проверка BE-021).
- [x] `pin/remove` с верным `currentPin` → 200, PIN снят, device-токен работает.
- [x] `finally` возвращает PIN; API-E2E и прод не ломаются.

## Ход работы
- Найден **UI-баг** → **FE-011**: клик по `#confirm-yes` перехватывался `#pin-modal` (stacking модалок) — «Удалить PIN» из настроек было невозможно. После фикса (`#confirm-modal { z-index: 130 }`) UI-путь добавлен в сценарий как регресс-защита.
- Проверка «старый PIN → 401» **некорректна** при снятом PIN: сервер выдаёт device-токен (BE-019) на любой `pin`. Заменена на `pin/has = false` + работоспособность device-токена.
- Проверено по коду: `PrivacyController.Remove` → `RespondAuth` → 401 при неверном `CurrentPin`.
