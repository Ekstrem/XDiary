# TE-059 — спека индикатора `busyRun`: появляется на задержке, не появляется на быстром ответе

- **Статус:** Закрыта
- **Приоритет:** P2 (покрытие: `busyRun` **0 спек**; компенсирован только юнит-тестом таймеров)
- **Источник:** @TE `2026-11-05 08:58` (аудит покрытия) + `FE-040` (юнит-тест таймеров `7/7`, браузерной проверки нет)
- **Зависимости:** `FE-040` (`busyStart`/`busyStop`/`busyRun`, пороги 300/3000 мс)
- **В работе с:** 2026-11-05
- **Проверяет:** @TL (код фронта; тест уже принят по артефакту `FE-040-timers-test.js`)

## Задача

Индикатор загрузки проверен **юнит-тестом таймеров** (`node 5-tech-backlog/front-end/FE-040-timers-test.js`
→ 7/7), но **в браузере** его не проверяет ни одна спека.

## Критерии приёмки (сформулированы @TE)

- при задержке ответа **1000 мс** индикатор **появляется** (порог показа **300 мс**);
- при быстром ответе **100 мс** индикатор **не появляется** (иначе он мелькает и мешает);
- после завершения операции (успех и ошибка) индикатор **исчезает**;
- при задержке **> 3000 мс** появляется текст «дольше обычного» и кнопка «Повторить» (если передан `retry`).

### Вердикт @TL 2026-11-07 11:43 — **принято по артефакту, с одним условием**

- Спека есть: `9-tests/RnD/front-e2e/tests/busy-indicator.spec.js`, внутри `const BANNER = '.busy-banner'`, порог **300 мс** и задержка **1000 мс** — то есть проверяются оба критерия карточки (не мелькает на быстром ответе; появляется на медленном) и исчезновение после завершения.
- **Условие, которое фиксирую:** спека включается только при `XDIARY_BUSY=1`, иначе `skip`. Значит в обычном прогоне CI покрытия `busyRun` **нет** — это не дефект карточки, но и не «покрыто». Либо спека входит в обязательный набор, либо в отчёте пишем «покрыто условно».

## Результат

Спека: `9-tests/RnD/front-e2e/tests/busy-indicator.spec.js` (включается `XDIARY_BUSY=1`, иначе `skip`).

**Что проверяет (критерии карточки):**
- задержка **100 мс** → баннер `.busy-banner` **не появляется** (порог 300 мс соблюдён, индикатор не мелькает);
- задержка **1000 мс** → баннер **появляется**, `role="status"`, текст `Считаем тренды`;
- после завершения баннер **исчезает** (нет «вечного спиннера»);
- задержка **4000 мс** → появляется текст «дольше обычного» и кнопка «Повторить» (`retry` передан).

**Факты, снятые с фронта (а не предположенные):** тренды читают `**/api/v1/daily-metrics/series**`
(`8-front/js/api.js:147`), вызов идёт из `renderTrends()` → `busyRun("Считаем тренды", …)`
(`app.js:2064`), вкладка — `#tab-trends`; баннер — `.busy-banner` (`app.js:1986`), порог показа 300 мс,
«дольше обычного» через 3000 мс. Первая версия ловила `**/api/v1/analytics/**` — **не тот эндпоинт**,
такая спека проверяла бы пустоту.

**Прогон:** `node --check` rc=0. Браузерный прогон — за `DO-079` (`XDIARY_BUSY=1`).

**Закрыто владельцем `2026-11-11 06:55`** — вердикт @TL получен. Условие вердикта (`XDIARY_BUSY=1`) зафиксировано честно: покрытие **условное** — спека включается флагом и в обычном наборе `skip`. Это записано в `## Результат` выше, чтобы «покрыто» не читалось как «покрыто всегда».
