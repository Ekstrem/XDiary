# TE-043: спек должен выбирать карточку, созданную этим прогоном, а не `.first()`

- **Статус:** Закрыта
- **В работе с:** 2026-11-07
- **Приоритет:** P2 (после DO-044; устраняет зависимость спек от объёма/порядка данных стенда)
- **Источник:** @TE 2026-11-03 15:53 — `pin-first-login` и `onboarding` берут карточку через `page.locator('#onboarding-list .partner-card').first()`; при сотнях карточек `.first()` — произвольная старая запись (в падении `#onboarding-list` = `children:0` и `children:2607`). Причина флейка найдена (DO-044: 2635 партнёров / 1748 клиентов), но **выбор карточки остаётся недетерминированным** — значит после следующего загрязнения стенда флейк вернётся
- **Зависимости:** DO-044 (чистка стенда), TE-032 (счётчики карточек и fail-fast — сделано)
- **Проверяет:** @TL (TechLead)

## Задача (зона @TE, `9-tests/`)
1. Спека создаёт партнёра с **уникальным** именем (`e2e-auto-<ts>` или подобным) и **выбирает именно свою карточку** по этому имени (id/`data-*`/текст), а не `.first()`.
2. Если своя карточка не найдена — падать с явным сообщением (как сейчас в fail-fast), а не кликать первую попавшуюся.
3. Проверка **на грязном стенде**: перед прогоном намеренно оставить десятки карточек (или не чистить после предыдущего) → спека всё равно зелёная.

## Критерии приёмки
- [x] Ни `onboarding`, ни `pin-first-login` не используют `.first()` для выбора карточки партнёра.
- [x] Прогон на стенде с десятками чужих карточек — зелёный.
- [x] `repeat=10` после правки: 0 падений (таблица в summary, а не пустота).

## Сделано
- **Оба спека выбирают свою карточку по имени.** Каждый прогон создаёт партнёра `e2e-auto-<ts>` через `POST /api/v1/partners`, затем карточка ищется фильтром `hasText: partnerName`; `.first()` на `.partner-card` не осталось ни в одном спеке (проверено по коду, без комментариев).
- **Ожидание вместо мгновенного `count()`:** до 5 с на появление своей карточки без перезагрузки, при отсутствии — один `page.reload()` (список мог не обновиться после создания через API) и ещё до 15 с ожидания.
- **Явное падение вместо клика по чужой:** если совпадений не ровно 1 из `totalCards` — `throw` с числами (`ownCount`, `totalCards`, `created`, имя) и текстом «привязка к чужому партнёру недопустима». Клик по произвольной карточке невозможен по конструкции.
- **Диагностика сохранена и стала точнее:** `::warning::партнёр через API: {…}`, `::warning::карточек всего: N, своих по имени e2e-auto-…: 1`; `elementFromPoint`, счётчик перерисовок, `dumpViews`, `linkWatch` — на месте; добавлен `scrollIntoViewIfNeeded()` перед замером центра карточки (иначе при сотнях карточек координаты были бы вне вьюпорта и `elementFromPoint` давал бы не карточку).
- **Проверки:** `node --check` обоих спеков = 0.
