# TE-033: Починить `test` и `front-e2e` под новую модель (SetPin +4-й аргумент, PIN не нужен в globalSetup)

- **Статус:** В работе
- **Приоритет:** P0 (оба джоба красные → `smoke` красный → прод не обновляется)
- **Источник:** CI run **893** (`b773e9b`), аннотации `test` и `front-e2e`
- **Зависимости:** BE-036 (SetPin получил `clientId` + `iterations`), FE-025/BE-038 (PIN перестал быть первичным входом)
- **В работе с:** 2026-11-06
- **Проверяет:** @TL

## Факт 1 — `test` падает на компиляции (16 с)
```
9-tests/Analytics.Privacy/AnalyticsPrivacy.IntegrationTests/PrivacyTests.cs:37
9-tests/Analytics.Privacy/AnalyticsPrivacy.IntegrationTests/PrivacyTests.cs:48
There is no argument given that corresponds to the required parameter 'iterations'
of 'Aggregate.SetPin(Guid, string, string, int)'
```
Подпись сейчас: `SetPin(Guid clientId, string salt, string hash, int iterations)` (`BC-Privacy/Aggregate.cs:21`). В тестах вызовы на 3 аргумента:
- L37 `SetPin(salt, hash, iter)`;
- L48 `SetPin("salt", "", 100_000)`.
Нужно передавать `clientId` первым (`Guid.NewGuid()`) и `iterations` последним (в тестах — маленькое значение, например `1000`, чтобы не замедлять прогон).

## Факт 2 — `front-e2e` падает в globalSetup (5 с)
```
globalSetup: PIN на стенде https://xdiary-vps2.taile0b6ee.ts.net не 1234 и не
восстанавливается известными остатками — нужен серверный сброс PIN на dev (@DO)
```
`9-tests/RnD/front-e2e/tests/global-setup.js` требует, чтобы PIN стенда совпадал с `XDIARY_E2E_PIN`. По новой модели **PIN вообще не нужен для входа**: `seedSession` получает client-JWT по телефону+OTP, а PIN — локальный замок, который спеки ставят сами через `Pin.setPin`.

Нужно: убрать из `globalSetup` требование PIN на стенде; заменить на проверку живости API/сессии (например, `POST /api/v1/clients` доступен и `/health` отвечает). Проверки PIN оставить только в спеках про PIN (`pin-first-login`, `change-pin`, `remove-pin`), где PIN ставится внутри спека.

## Критерии приёмки
- [ ] `dotnet build 9-tests` зелёный (или `dotnet test` проходит сборку).
- [ ] `front-e2e` не зависит от PIN стенда: `globalSetup` зелёный на свежем dev.
- [ ] Оба джоба дают **самостоятельно завершившийся** зелёный прогон (`test` + `front-e2e`).
- [ ] `smoke` в `deploy.yml` зелёный → `deploy-prod` доезжает до VPS-1.
