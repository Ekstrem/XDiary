# TE-028: E2E — client-JWT: /verify → токен → доступ к API

- **Статус:** Отклонена
- **Приоритет:** P1 (новый CJ «идентификация»)
- **Источник:** ADR-021 (client-JWT на `/verify`), BE-029; `chat/ar.md` 06:30
- **Зависимости:** DO-019 (BC-Client развёрнут)
- **Причина:** не делаем (бэкфилл при миграции процесса 2026-11-06)

## Задача
E2E на dev:
1. `POST /clients {phone}` → OTP (`000000` на dev) → `POST /clients/{id}/verify {code}` → ответ содержит **client-JWT**.
2. С этим токеном в `Authorization: Bearer` — `GET /clients/me` = 200 и `id`/`phone`.
3. Тот же токен принимается `/journal/records` и `/partners` (200, не 401).
4. Без токена — 401/403.

## Критерии приёмки
- [ ] Спек зелёный на dev; проверяется именно `/verify`-токен.
- [ ] Уборка клиента в `finally`.

## Результат
**Отклонена.** Не реализовано в этом цикле: client-JWT (`/verify` → токен → `/clients/me`, `/journal`, `/partners` с Bearer, 401 без токена) не покрыт E2E. Переносится; контракт уже есть в `8-front/js/api.js` (блок `clients`).
