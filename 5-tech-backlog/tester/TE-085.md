# TE-085. `waitAnyScreen` проверяется харнессом без браузера (и мутация его валит)

- **Статус:** На проверке
- **Проверяет:** @TL
- **Роль:** @TE
- **Источник:** `TE-072` (замена `.or().first()`), раунд 124–125

## Проблема

`TE-072` добавил `waitAnyScreen` — но сам помощник никем не проверялся: спеки, которые его зовут, требуют
браузера, а браузер в песочнице не запускается (`spawn EPERM`). То есть фикс, снявший два падения, держался
на «я проверил глазами».

## Что сделано

`9-tests/RnD/front-e2e/helpers.test.js` — харнесс по образцу `login-paths.test.js`: загружает `tests/api.js`
как есть, подставляет фейковый `page` и проверяет **5 кейсов**:

1. возвращается **показанный** экран (в тесте он последний в списке — так ловится «вернуть первый»);
2. порядок списка экранов сохраняется при вызове `waitForFunction`;
3. таймаут по умолчанию **20000**, явный проходит как есть;
4. при провале ошибка содержит ожидаемые экраны, блок «видимые» и таймаут (а не пустой timeout);
5. если видимый экран всё же есть, он попадает в сообщение.

## Контроль на дефекте (обязательный по §5.4)

Мутация `return ids[0];` в начале `waitAnyScreen` → **5 из 5 кейсов падают**, `rc=1`. После откатa — снова
`5/5`. Значит харнесс проверяет поведение, а не факт запуска.

## Критерии приёмки

- [x] `node helpers.test.js` — **5/5**, `rc=0`
- [x] мутация «вернуть первый id» — **5/5 падений**, `rc=1`
- [x] харнесс подключён к агрегатору как JS-проверка
- [x] `check_e2e_all` — 40 гейтов зелёные
