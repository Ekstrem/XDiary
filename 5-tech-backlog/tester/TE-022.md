# TE-022: Smoke-набор для dev-этапа CD (ADR-020)

- **Статус:** Открыта
- **Приоритет:** P1
- **Источник:** ADR-020 (CD), @AR 2026-11-02 10:00, @TL 2026-11-02 10:40
- **Зависимости:** ADR-020, DO-015 (CD pipeline), TE-014

## Задача
Определить и поддерживать smoke-набор, который гоняется после авто-деплоя **dev** (VPS-2)
и является условием пропуска в **prod** (VPS-1).

## Blocking (prod — только на зелёном smoke, ~2–3 мин)
1. `GET /health` = 200 (шлюз жив).
2. **API-E2E** `9-tests/E2E` — все 9 (auth 4, journal 2, somatic/analytics 3) против dev.
3. **UI `front-e2e`** на dev — `add-partner`, `wizard-record` (ядро — запись журнала), `change-pin` (auth/PIN).

## Non-blocking (полный набор — по расписанию / на релиз)
`catalog` ×4 (костюм/игрушка/фантазия/контрацепция), `no-pin`, сценарии TE-015…TE-021.

## Правила
- Тесты **чистят за собой** в `finally`; данные — только на **dev**.
- `XDIARY_E2E_PIN` — секрет Environment `dev`.
- `change-pin` **деструктивный** — на dev допустим, **в prod-smoke не включать**.
- `no-pin` требует dev **без PIN** (иначе `test.skip` с причиной).
- Тесты в `front-e2e` идут **последовательно** (`workers: 1`) — PIN на стенде общий.

## Критерии приёмки
- [ ] Job `smoke-dev` в CI (после `deploy dev`); его результат — условие `deploy prod`.
- [ ] Все blocking-сценарии зелёные на dev.
- [ ] В `finally` убирается всё созданное (проверено: после прогона списки пусты).
- [ ] `change-pin` не входит в prod-smoke.
