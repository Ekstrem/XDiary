# TE-093. `check_registry_tags.py`: сколько из 13 тегов `images.lock` реально есть в реестре

- **Статус:** На проверке
- **Проверяет:** @DO (инфраструктура), вердикт @TL
- **Роль:** @TE
- **Источник:** `chat/tl.md` `2026-11-06 22:00` (`→ @DO`): «`client single-0dd2b57` **опубликован**, но
  `lock-published` требует **все 13** тегов, а **10 отсутствуют**» + собственный прогон по GHCR

## Проблема

`deploy-prod` стоит, потому что шаг `lock-published` требует **все** образы из `7-deploy/images.lock`. Сам lock
генерируется **из git** (`gen_images_lock.py`), а не из реестра, поэтому он указывает на коммит, чьи образы могли
не публиковаться (красная сборка → job `docker` = `skipped`). В результате «почему прод не обновился» выясняется
руками, а числа «сколько не хватает» нигде не было.

## Что сделано

`9-tests/scripts/check_registry_tags.py` — читает `images.lock`, спрашивает GHCR по каждому сервису и печатает:

- `::warning::` на каждый отсутствующий тег (с причиной: сборка красная / `docker` = skipped);
- `::notice::` на пакет, недоступный анонимно (403) — это **«не проверено»**, а не «нет»;
- квитанцию: `образов в lock N | опубликовано X | отсутствуют Y | не проверено (403) Z`.

`--selftest` **5/5** (разбор lock, все на месте, один отсутствует, 403 не считается «нет», текст квитанции);
без сети/без lock — `rc=2`.

## Режим `--available`: что реестр реально может дать (`DO-108`, по просьбе @AR `22:44`)

@AR: «сначала прогнать `--verify-registry` по **всем** 13 (число опубликованных), потом `--write` из реестра».
Обычный режим отвечает на вопрос «теги из lock существуют ли», а `--available` — на вопрос «что можно записать,
если выводить lock **из реестра**»: для каждого сервиса берётся самый свежий опубликованный `single-*`, чей коммит
есть в истории `origin/main`.

**Практический вывод для `DO-108`:** lock из реестра соберётся **12 из 13** (front — особый случай: 403 на
анонимный pull-token, деплой идёт через Pages). И `client` в нём будет `single-766e59e` — тот самый образ с
фиксом утечки, то есть ручная правка lock (`single-0dd2b57`) **не нужна**: реестр даёт правильный тег сам.

**Две ловушки, найденные при реализации** (записаны, чтобы не повторять):

1. `git log --format=%h` в этом репозитории отдаёт **8** символов (коллизии в 7772 коммитах), а тег в реестре несёт
   **7**-символьный префикс — при точном сравнении «доступно 0» на всех 13. Ключ кладётся и полный, и 7-символьный.
2. Имя удалённой ветки различается между клонами (`origin/main` vs `gh/main`) — реф пробуется по порядку, а не
   зашит: иначе квитанция врёт «0 доступно» при живом реестре.
