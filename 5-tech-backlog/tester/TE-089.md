# TE-089. Гейт ловит «используется, но не определено» — это и есть CS0246, который держит выкатку

- **Статус:** На проверке
- **Проверяет:** @TL
- **Роль:** @TE
- **Источник:** `chat/tl.md` `2026-11-06 12:53` (`BE-089`: `CS0246 IValueObjectJsonConverter` → `docker` skipped → образы не публикуются) + собственная проверка `origin`

## Проблема

`@TL` описал блокер выкатки: в `ci-partners` и `ci-journal` шаг `Build` падает с
`error CS0246: The type or namespace name 'IValueObjectJsonConverter' could not be found` → job `docker` = `skipped`
→ образы не публикуются → `images.lock` некуда двигать → `deploy-prod` не запускается. Это объясняет **12 из 12
`deploy-prod` = skipped**, которые я мерил ранее.

**Проверил сам в `origin` (`dc0b859b`):**

| Что | Результат |
|---|---|
`6-msa/Shared/XDiary.Contracts/IValueObjectJsonConverter.cs` | **нет** (в `6-msa/Shared` 8 файлов, ни одного с `IValueObject`) |
`class IValueObjectJsonConverter` где-либо в `6-msa` | **нет определения** |
файлы, которые его **используют** | **4**: `JournalEventConsumer.cs`, `PartnerEventConsumer.cs`, `OutboxDispatcher.cs`, `PartnerCommandRepository.cs` |

То есть тип вынесен в `Shared`, но сам файл не закоммичен — компиляция невозможна ни в одном сервисе, который
его использует. Мой гейт `check_e2e_eventsourcing_contract` проверял только **использование конвертера** и был
зелёным, потому что «использование есть» — а определение отсутствовало.

## Что сделано

Гейт расширен проверкой **определения**:

- если `IValueObjectJsonConverter` упоминается, где-то в `6-msa` должен быть `class IValueObjectJsonConverter`;
- иначе — `rc=1` с текстом «ошибка компиляции CS0246: сборка сервиса красная, образы не публикуются»;
- пока файл не закоммичен, случай объявлен в `KNOWN_UNDEFINED` («BE-089, владелец в курсе») и печатается
  **предупреждением с числом** в квитанции, а не скрывается.

`--selftest` **4 → 7** (три кейса детектора: без `class` → issue с CS0246; с `class` → молчит; без `6-msa` → молчит).
