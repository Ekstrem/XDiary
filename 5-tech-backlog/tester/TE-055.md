## Факт, который надо знать до этапа 3 (проверено `git grep`, `REF=d274362f`)

Формулировка «спеки не проверяют серверный PIN» **неточна**: локальный `window.Pin` — да, основа
(`change-pin`, `remove-pin`), но `remove-pin.spec.js` **проверяет и серверный**:

| Файл:строка | Что делает | Судьба на этапе 3 |
|---|---|---|
`remove-pin.spec.js:23` | `POST /privacy/token {pin}` — получает device-токен для запросов `pin/has` | **сломается**: device-токена не будет |
`remove-pin.spec.js:32` | `fetch /api/v1/privacy/pin/has` (скоуп по устройству) | **сломается**: эндпоинта не будет |
`remove-pin.spec.js:44` | `POST /privacy/pin/remove {}` → ждёт 401 (без `currentPin`) | **сломается** (404 вместо 401) |
`remove-pin.spec.js:47` | `POST /privacy/pin/remove {currentPin:'0000'}` → ждёт 401 | **сломается** |
`remove-pin.spec.js:50-51` | `pin/remove {PIN}` + assert `pin/has = false` | **сломается** |
`remove-pin.spec.js:55-56` | `pin/set {PIN}` + assert `pin/has = true` | **сломается** |
`pin-fallback.spec.js:20` | проба стенда `POST /privacy/token {pin:''}` → 401/200 | **сломается**: применимость сценария определялась по этому ответу, нужен другой внешний признак |
`no-pin.spec.js:16` | тот же probe, но спека уже `describe.skip` (legacy) | удалить вместе с этапом 3 |

Итого: **две живые спеки** (`remove-pin`, `pin-fallback`) держатся на серверном контуре.

## Задача (после этапа 3 `FE-042`)

1. `remove-pin.spec.js`: убрать серверный блок (5 вызовов + 2 assert'а) — оставить проверки
   **локального** `window.Pin` (hasPin true → снятие через UI → hasPin false → восстановление).
   Историю `BE-021` сохранить комментарием со ссылкой на этот файл, а не мёртвыми запросами.
2. `pin-fallback.spec.js`: заменить признак применимости. Сейчас — `POST /privacy/token {pin:""}`;
   после этапа 3 нужен **внешний** признак, не зависящий от удалённого эндпоинта: например,
   `GET /api/v1/privacy/pin/has` (если останется) либо `XDIARY_STAND_HAS_PIN=1` (env, по образцу
   `XDIARY_READPATH_OFFLINE`/`XDIARY_PARTNER_OWNERSHIP`). Выбор — за @AR/@FE: нужен признак
   «на стенде PIN задан», и он не должен читаться из поведения UI.
3. `no-pin.spec.js`: удалить целиком (сейчас `describe.skip`, после этапа 3 смысла нет).
4. Прогнать `pin-first-login`, `change-pin` — они локальные и должны остаться зелёными.
