# TE-095. Гейт на `X-Correlation-Id` у любого `5xx` (норма @AR `trace_rule`)

- **Статус:** На проверке
- **Проверяет:** @AR (норма его), вердикт @TL
- **Роль:** @TE
- **Источник:** `chat/ar.md` `2026-11-06 00:26` (`→ @TE`): «если возьмёшь это в гейт — проверка одна: в smoke на любой
  `5xx` искать заголовок `X-Correlation-Id`; отсутствует ⇒ дефект (`rc=1`)»; и `api-index.yaml` → `trace_rule`

## Проблема

`500` на `POST /partners/{id}/remove` и `/link-client` (дефект `23505 PK_outbox`) отдавал **пустое тело и ни одного
идентификатора**. Поэтому «запрос → строка в логе» восстанавливался **вручную**: без корреляции непонятно, какое
именно исключение из 57 за окно относится к твоему запросу. Норма @AR: тело `5xx` по-прежнему без подробностей (не
течём внутренностями), но **`X-Correlation-Id` обязателен**.

## Что сделано

`9-tests/scripts/check_5xx_correlation.py`:

1. делает пробы к стенду (здоровье, анонимные ручки, команды партнёра/журнала) и для **каждого `5xx`** требует
   заголовок `X-Correlation-Id` (принимаются также `X-CorrelationId`, `X-Request-Id`);
2. `4xx` не проверяются — нормой корреляция там не требуется (иначе гейт краснел бы на валидации);
3. `--require-5xx` переводит «ни одного `5xx` не встретилось» в **`rc=2`** — чтобы гейт не был «зелёным на пустоте»;
4. `--status 500 [--has-correlation yes|no]` — офлайн-режим для проверки логики без стенда.

`--selftest` **6/6**: `5xx` без заголовка → `rc=1`; с заголовком → `rc=0`; `4xx` не требуют корреляции; смесь (один с
id, один без) → `rc=1`; «`5xx` не встретилось» → `rc=0` с явной строкой в квитанции; текст квитанции.

## Измерено на dev (2026-11-07)

```
GET /health → 200 | GET /partners (anon) → 200* | GET /partners → 200 | GET /journal/records → 200
POST /partners/{id}/name → 200 | POST /partners/{id}/remove → 200 | POST /partners/{id}/link-client → 404
квитанция: запросов 7 | из них 5xx 0 | с X-Correlation-Id 0 | нарушено: 0
```

**Важно:** `5xx` в этот прогон **не встретилось** — то есть заголовок проверить было не на чем, и это честно видно
в квитанции («из них 5xx 0»). С `--require-5xx` такой прогон даёт `rc=2` («не измерено»), а не «зелено».

## Побочно: критерий @TL по идемпотентности на dev сейчас выполняется

```
link-client #1 → 200 | link-client #2 → 200 (тот же id)
remove #1      → 200 | remove #2      → 404 (записи уже нет)
```

То есть **`500` не воспроизводится**: повторные команды дают `200`/`404`, а не `500` и не `23505`. Класс дефекта
(идемпотентность вставки в outbox) закрыт на dev — гейт `check_5xx_correlation` остаётся как страховка на будущее.

**Две честные границы, обе остаются в карточке:**
1. на dev в прогоне `5xx` **не встретилось** («из них 5xx 0») — способность поймать живой `5xx` на стенде **не показана**;

2. `trace_rule` — требование **@AR**, а не подтверждённая владельцем норма (`08:06`: «если владелец скажет „лишнее“ —
   гейт припарковать»). Поэтому **в блокирующие шаги CI гейт не ставится** до ответа @EX; вопрос задан `08:14`.
