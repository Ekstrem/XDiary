# TE-106: `check_registry_tags --available` без реестра **молча падает в git-историю и даёт `rc=0`** — ложное зелёное

- **Статус:** На проверке
- **Приоритет:** P1 (гейт `lock-published` в `deploy.yml` — первый в цепочке релиза; его ложное зелёное означает «выкатываем ссылки на несуществующие образы»)
- **Источник:** @TL 2026-11-13 12:30, ревизия `108477dae` — прогон гейта в песочнице
- **Зависимости:** нет (правка в `9-tests/scripts/check_registry_tags.py`)
- **Проверяет:** @TL
- **На проверке с:** 2026-11-12
- **Исполняет:** @TE (`9-tests/scripts/**` — его зона)

## Факт (прогон, а не рассуждение)

```
python 9-tests/scripts/check_registry_tags.py --available
::notice::check_registry_tags: история из origin/main
   journal   последний доступный: single-4b90af9   (в lock single-ae29f58) —
   partners  последний доступный: single-2003cf5   (в lock single-ae29f58) —
   …
квитанция (from-registry): сервисов 13 | доступно 12 | без образа 1
rc=0
```

При этом **в CI тот же гейт красный**: `deploy.yml` запуск **#1970** (run `43090151275`) — `lock-published` **failure** на шаге «Что реестр реально может дать (не-front без образа → красный)», сообщение «образ из lock недоступен в реестре».

## Дефект

1. **Фолбэк неотличим от измерения.** Когда реестр недоступен, инструмент берёт «историю из origin/main» и **возвращает `rc=0`**, печатая лишь `::notice::`. То есть «не смог проверить» выглядит как «всё опубликовано» — ровно тот класс, который в `check_canon` и `check_readstore_ddl` уже починен: фолбэк/неизмеренное → **`rc=2`**.
2. **Следствие для релиза:** локальный прогон создаёт ложное впечатление, что lock консистентен. В реальности `images.lock` ссылается на **один тег `single-ae29f58` для 11 сервисов**, а последние доступные теги в реестре **разные у каждого** (`journal single-4b90af9`, `partners single-2003cf5`, `catalog single-4d9b2f5`, `client single-33c226c`, `privacy single-c47ac4c`, …). Синтетический общий тег в реестре не публиковался.

## Критерии приёмки

- [ ] без доступа к реестру (аналог: неверный `XDIARY_REGISTRY_HOST`) → **`rc=2`** с печатью «НЕ ИЗМЕРЕНО: реестр недоступен», а не `rc=0`;
- [ ] с доступом и отсутствующим тегом → **`rc=1`** и список отсутствующих (как сейчас в CI);
- [ ] с доступом и полным набором → `rc=0`;
- [ ] в квитанции печатается **чем** считали: `from-registry` / `НЕ ИЗМЕРЕНО`;
- [ ] `--selftest` с тремя кейсами (0/1/2), `0/0` недопустим.

## Почему карточка, а не «поправить по ходу»

Это тот же дефект, что `DO-115` (`check_canon` считал вложенные копии) и `ARD-024` (`YAML` терял ключ): **инструмент отвечает «ок» там, где он не мерил**. Разница в цене: здесь от этого зависит, выкатим мы ссылки на несуществующие образы или нет.

## Результат

### Исполнено `2026-11-12` (круг 28), правка в `9-tests/scripts/check_registry_tags.py`

1. **Новая чистая функция `available_rc(errors, missing, allow_fallback=False)`** — решение о коде вынесено
   из `main`, поэтому его можно проверить самопроверкой: отказ реестра ⇒ **`2`**, иначе `registry_rc(missing)`.
2. **Ошибки `front` не считаются «не измерено»** — `front` в GHCR не публикуется (Pages), его 403 —
   архитектурное исключение (@DO `2026-11-11 16:17`). Иначе гейт краснел бы всегда.
3. **В `--available` при частичном отказе реестра** печатается
   `::error::… НЕ ИЗМЕРЕНО: реестр недоступен для N сервис(ов): …` и квитанция
   `квитанция (НЕ ИЗМЕРЕНО): реестр недоступен | сервисов 13 | ошибок N`, возврат **`2`** — до расчёта по
   git-истории (то есть «фолбэк» больше не выглядит измерением).
4. **Осознанный выход для отладки:** `--allow-git-fallback` — считает как раньше, но печатает
   `::warning::… считаю по git-истории по флагу … (это НЕ измерение реестра)`.

### Квитанции

| Проверка | Результат |
|---|---|
| `--selftest` | **7/7** (было 6/6): добавлен кейс «0/1/2 и 0 при `--allow-git-fallback`» |
| частичный отказ реестра (`registry_tags` для `journal` бросает `OSError`) | **`rc=2`**, текст `НЕ ИЗМЕРЕНО: реестр недоступен для 1 сервис(ов): journal: OSError…` |
| полный отказ | `rc=2` (ветка была и раньше, проверено подменой) |
| норма | `rc=0`, квитанция `(from-registry): сервисов 13 | доступно 12 | без образа 1 | 1 без образа: front — пакет 403 …` |

**Как проверял:** подменой `registry_tags` в импортированном модуле. Первая попытка через
`XDIARY_REGISTRY_HOST='registry.invalid'` **не сработала** — скрипт эту переменную не читает, прогон шёл к
настоящему реестру и дал `rc=0` с реальным 403 у `front`; поэтому способ замера записан честно.
