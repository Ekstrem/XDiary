# TE-023: E2E — первый вход на устройстве без локального PIN (FE-007)

- **Статус:** Закрыта
- **Приоритет:** P1
- **Источник:** @PO через @FE 2026-11-03 00:45 (PO не может войти: PIN `1234` не подходит, PIN он не ставил)
- **Зависимости:** FE-007

## Задача
Покрыть путь FE-007: на стенде PIN **установлен**, а на устройстве **локального** PIN нет.
1. Устройство без локального PIN → `login("")` → 401 → **экран PIN** (`#view-lock`).
2. Неверный PIN → `#pin-error` «Неверный PIN», JWT не появляется.
3. Верный PIN → `login(pin)` → JWT + журнал (+ локальный PIN ставится).

## Критерии приёмки
- [ ] Пункты 1–3 покрыты отдельным кейсом.
- [ ] Не зависит от `no-pin` (тот skip-ается на стенде с PIN).
- [ ] CI `front-e2e` зелёный.

## Ход работы
- Проверено по коду: `lock()` (`app.js:194`) — без локального PIN вызывает `Api.auth.login("")`, при 401 → `showLockScreen()` (FE-007). `unlock()` — без локального PIN → `Api.auth.login(pin)`; успех → `Pin.setPin(pin)` + журнал, ошибка → `#pin-error`.
- Сценарий `tests/pin-first-login.spec.js`: чистый контекст (локальный PIN **не** ставим, только `apiBase`) → `#view-lock` → неверный `0000` → `#pin-error` + нет JWT → верный PIN → JWT + `#view-journal`.
- Пробел, который нашёл @FE: `no-pin` skip-ается при PIN на стенде, а `loginWithPin` сначала ставит локальный PIN — путь «новое устройство + серверный PIN» тестами не покрывался.

## Результат
**Закрыта.** Спек `tests/pin-first-login.spec.js` написан и в CI; адаптирован под FE-021 (`0.51`/`0.54`): чистое устройство → онбординг, PIN-экран — только при пройденном онбординге.
