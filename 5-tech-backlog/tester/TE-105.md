## Дефект 1 (доказан по YAML и статусам шагов)

Шаг «Артефакты падения (trace, скриншоты, error-context)» стоит **до** шага, который обнаруживает падения:

```
:159  - name: Артефакты падения (…)     ← if: failure()  (:160)
:161    uses: actions/upload-artifact@v4
:171  - name: Классы падений (e2e_triage)  ← if: always()
:176  - name: Итог по спекам               ← if: always()
```

На шаге `:159` падений ещё нет (`Repeat run (list)` вернул success), поэтому `if: failure()` → **skipped**;
падения обнаруживает `:176`, когда шаг артефактов уже пройден. На этом пути артефактов **не бывает
никогда** — что и подтверждают пять прогонов с нулём артефактов.

**Правка:** шаг артефактов — **после** «Итог по спекам», условие `if: failure()`; либо `if: always()` с
проверкой `if-no-files-found: warn`.

## Дефект 2 (гипотеза, требует лога)

Разбор вывода list-репортёра (`:188`): `pat = ^\s*([✓✗✘×\-»›])\s+\d+\s+(tests/[\w./-]+)`. Строка
Playwright в repeat-режиме выглядит как `✘  1 [chromium] › tests/foo.spec.js:12:3 › …` — между номером и
`tests/` стоит `[chromium] ›`, поэтому шаблон может не совпасть, `agg` остаётся пустым, и шаг печатает
«не разобрал ни одного результата» + `exit 1` (`:215-217`) — то есть **красный из-за разбора, а не из-за
тестов**. Проверить это можно только логом; в карточке фиксирую как гипотезу, а не как факт.

## Критерии приёмки

- [ ] Красный прогон (`repeat-each=5` на заведомо флейкующей спеке) оставляет артефакт `front-e2e-results`
      (в списке артефактов прогона — **не 0**), то есть диагностика доступна без токена.
- [ ] «Итог по спекам» на **зелёном** прогоне (`repeat-each=1`, любая стабильная спека) — green.
- [ ] На прогоне с падением «Итог по спекам» красный **и называет** спеки/тесты (в логе есть имена).
- [ ] Если `/tmp/repeat-list.txt` непуст, но не разобран ни один результат — шаг печатает `::warning::`
      и **не** валит прогон (иначе снова «красный не из-за того, что проверяет»); если файла нет вовсе —
      валит (это «измерение не состоялось»).
- [ ] §5.4 в обе стороны: дефект (шаблон не совпадает / шаг артефактов до итога) → красный или warning;
      норма (зелёный прогон) → green.

## Почему это мешает закрывать задачи

`TE-053`, `TE-054`, `TE-104` (и `BE-044`) ждут `REF` браузерного прогона. Пока красный прогон не оставляет
ни лога, ни артефакта, квитанцию собрать нечем: `check_run_receipt.py` требует **лог**, а лог недоступен
анонимно. Починка шага артефактов — предусловие для закрытия этих карточек.
