# TE-104. Критерий `FE-046` «API 500 на старте» не был проверен ни одной спекой

- **Статус:** На проверке
- **Приоритет:** P2 (критерий карточки `FE-046` требует отдельного теста; сейчас он не проверяется)
- **Проверяет:** @TL
- **Источник:** `FE-046` критерий 3 («отдельный тест: подменить API на 500 →
  `#view-onboarding` / `#view-journal` показываются (или видимая ошибка), сплэш не висит»)
- **Зависимости:** прогон `front-e2e` (браузер) — зона @DO

## Задача

`FE-046` («приложение висит на сплэше, если API отвечает ошибкой», 8 из 19 падений E2E) требует отдельного
теста на **ошибку сервиса при старте**. Проверено: ни одна спека этого не делает.

- `onboarding.spec.js:47-55` проверяет, что `#view-splash` уходит, но на **здоровом** стенде и с лимитом
  **20 000 мс** — это про медленный ответ, а не про необработанную ошибку;
- подмена на `5xx` есть только в `stale-note`/`wizard-offline`/`somatic-detail` и **после** входа, не на старте.

То есть критерий 3 карточки `FE-046` держался на слове.

## Критерии приёмки

- [x] спека `9-tests/RnD/front-e2e/tests/startup-api-error.spec.js`: все `**/api/v1/**` → `500`
      (сеть есть, сервис сломан), затем `goto('/')`;
- [x] утверждение 1: `#view-splash` скрыт за **2 000 мс** (иначе «вечная загрузка»);
- [x] утверждение 2: виден `#view-onboarding` **или** `#view-journal` **или** видимая ошибка
      (`/не удалось|ошибк|нет связи|повторить/i`) — «пусто и тихо» критерий не проходит;
- [x] при провале печатается состояние **всех** экранов (`dumpViews`), а не только текст ассерта;
- [x] явная проверка `#view-lock` отсутствует не «по умолчанию»: свежее устройство не имеет PIN,
      поэтому замок обязан быть скрыт — это утверждение, а не предположение (`FE-036`);
- [ ] прогон `front-e2e` (браузер) — зона @DO; до него `e2e-dryrun` исполняет тело спеки на заглушках
      (29 тестов / 0 падений), то есть структурно спека исполнима.

## Результат

Спека добавлена, три контракта моего же набора гейтов пройдены **не подгонкой, а по существу**:

| Гейт | Что требовал | Что сделано |
|---|---|---|
| `check_e2e_traceability` | в шапке спеки `TE-NNN` | эта карточка (`TE-104`), ссылка в шапке спеки |
| `check_e2e_coverage` | спека объявлена в маркере `front-e2e.md` | строка в таблице покрытия |
| `check_e2e_reload_lock` | 2 000 мс сразу после `goto` — «ложные падения на медленном стенде» | исключение с причиной: 2 с — **требование карточки** (`FE-046`), а не догадка о времени; плюс явная проверка `#view-lock` скрыт |

Квитанция набора: `check_e2e_all` — **43/43** (спек 23), `e2e-dryrun --all-flags` — 29 тестов / 0 падений /
309 утверждений. Браузерный прогон остаётся за @DO: без него «зелёный» по этой спеке не заявляется.
