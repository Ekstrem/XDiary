## Задача

`FE-044` добавил признак устаревания кэша, но **ни одна из 20 спек его не проверяет**. Значит «зелёный E2E»
не означает «правило §5 п.2 подтверждено».

## Критерии приёмки (сформулированы @TE, проверить исполнением)

- бейджа **нет** при живом ответе API (данные не из кэша);
- бейдж **есть** при чтении из кэша с `lastSync` старше порога (**24 ч**);
- текст соответствует `данные могли устареть|синхронизированы N ч назад`;
- спека включается отдельным признаком (по образцу `XDIARY_READPATH_OFFLINE`), чтобы не влиять на остальные
  прогоны; при недоступности стенда — `skip`, а не `fail`.

## Результат

Спека: `9-tests/RnD/front-e2e/tests/stale-note.spec.js` (включается `XDIARY_STALENOTE=1`, иначе `skip`).

**Что проверяет (критерии карточки):**
- при живом API бейджа `#stale-note` внутри `#view-wizard` **нет** (шум на свежих данных исключён);
- при отказе живого чтения (abort `**/api/v1/partners**` и `**/api/v1/catalog**`) и кэше старше 24 ч бейдж **есть**;
- текст соответствует `/(данные могли устареть|синхронизированы .* ч назад)/i`, и у бейджа `role="status"`.

**Механика, которую пришлось выяснить по коду (иначе спека была бы ложно-зелёной):**
`syncAt.<kind>` хранится **в IndexedDB** (`8-front/js/db.js` store `meta`, `DB.getMeta/setMeta`), а не в
`localStorage`; признак `fromCache` — in-memory (`repository.js:167 DB.readFreshness`). Поэтому возраст
кэша сдвигается через ту же `DB`, что и приложение (`ageCache`), а не через `localStorage` — первая версия
делала именно так и **ничего не сдвигала** (была бы вечно-зелёной).

**Прогон:** `node --check` rc=0. Браузерный прогон — за `DO-079` (`XDIARY_STALENOTE=1`).
