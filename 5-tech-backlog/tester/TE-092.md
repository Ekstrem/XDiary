# TE-092. `AddPartner` не должен затирать поля записи (`BE-093`) — проверка «за 2 минуты»

- **Статус:** На проверке
- **Проверяет:** @TL
- **Роль:** @TE
- **Источник:** `chat/tl.md` `2026-11-06 21:37` (`→ @DO + @TE`): «и это стоит проверить на стенде, когда будет образ:
  запись с заполненными `Place`/`Tags` → `AddPartner` → чтение; результат — либо «поля на месте», либо «пусто»»;
  сам дефект — `BE-093` (`JournalEventConsumer.cs:75-77`)

## Проблема

`BE-093`: консьюмер журнала делал **полную замену строки**
`var read = JournalProjection.Project(domainEvent); if (read is not null) await _readStore.UpsertAsync(read);`
— а `Project` заполняет **4 поля** (`Id`, `ClientId`, `Partners`, `StartedAt`) из ~20 в `JournalReadModel`
(`DurationMin`, `Place`, `Positions`, `Tags`, `Costumes`, `Toys`, `Fantasies`, `Contraceptives`, `Orgasms`,
`Garmin`, `GarminId`, `CreatedAt/UpdatedAt`, `Deleted`).

Следствие: любое событие, меняющее `Root` (`AddPartner`), затирает остальные поля дефолтами. Это «зелёный путь,
который теряет данные» — ошибок в логах нет, и именно это делало `BE-077` нерасследуемым.

Проверка «глазами» тут не годится: нужен факт, воспроизводимый одной командой.

## Что сделано

`9-tests/scripts/check_be093_stale_fields.py` — ровно сценарий @TL:

1. `POST /api/v1/journal/records` с `place` и `tags`;
2. чтение до (`GET /api/v1/journal/records/{id}`);
3. `POST /api/v1/journal/records/{id}/partners` (`AddPartner`);
4. чтение после — сравнение `place`/`tags` (нормализация: регистр, порядок тегов);
5. `rc=1`, если поле было заполнено и стало пустым/другим — с текстом «событие затирает чужие поля
   (полная замена строки вместо патча, BE-093)»;
6. `rc=2`, если нет `--base`/`--token`/`--partner-id` или стенд недоступен — «не измерено» ≠ зелено;
7. офлайн-режим `--before-json/--after-json` — проверка логики без стенда.

`--selftest` **7/7**: «поля на месте» → `rc=0`; «затерты» → `rc=1` (2 нарушения); «затерты только `tags`» → `rc=1`;
вложенный вид ответа (`record`: `…`) → находит; поля не были заполнены → проверять нечего (`rc=0`); разный регистр и
порядок тегов **не** дают ложного красного; текст квитанции.

## Измерено офлайн

```
--before-json '{"place":"Дом","tags":["a","b"]}' --after-json '{…те же…}'
  → rc=0  «проверено полей 2 (place, tags) | сохранились 2 | затерто 0 | нарушено: 0»
--after-json '{"place":null,"tags":[]}'
  → rc=1  «сохранились 0 | затерто 2 | нарушено: 2»
без --base/--token → rc=2 «не измерено»
```
