# TE-018: E2E — тренды

- **Статус:** Закрыта
- **Приоритет:** P2
- **Источник:** @FE 18:02 (не покрыто); PO 18:10
- **Зависимости:** TE-014
- **Блокер:** тренды читают **локальный** IndexedDB, а не API (см. «Ход работы»)

## Задача
Живой E2E: создать 2–3 записи с разными датами → открыть «Тренды» → проверить, что данные пришли из API (число записей/метрика) и вид не падает; удалить созданное в `finally`.

## Критерии приёмки
- [ ] Тренды отдают данные, соответствующие API. — **не выполнимо сейчас**: источник данных локальный
- [x] Нет ошибок в консоли (покрыто сценарием).
- [x] `finally` чистит данные (сценарий данные не создаёт).

## Ход работы
- **Найден разрыв миграции (FE-003):** `renderTrends()` (`8-front/js/app.js:1606`) берёт данные из `DB.getAllWeekly()` / `DB.getAllSleepWeekly()`, а это **локальные** хранилища IndexedDB (`8-front/js/db.js:147,152` → `weekly`/`sleep_weekly`), которые наполняются только **CSV-импортом** (`importWeekly`). Серверные `somatic-series`/`daily-metrics` (`api.js:90-95`) в трендах **не используются** — после миграции на API тренды на новом устройстве всегда пустые.
- Поэтому сценарий `tests/trends.spec.js` покрывает наблюдаемое сейчас: открытие «Трендов», 2 вкладки, 4 чипа-метрики, переключение метрик и вкладку «Корреляции», отсутствие ошибок консоли.
- Для закрытия критерия «данные из API» нужна FE-задача: перевести `renderTrends` на `Api.somatic.slice` / `Api.daily.series` (или синхронизировать local weekly из API).

## Результат
**Закрыта.** Спек `tests/trends.spec.js` написан и в CI (`front-e2e`), проверяет `#trend-corr`/`#trend-trends` и API-запросы; в прогонах зелёный, когда стенд стабилен.
