## Замер @TL 2026-11-13 11:4x — причина названа: **транзиентный 502 от dev-стенда**

Прогон `43395691243` — `front-e2e-repeat` на `main` (`7b6caaca0`), `specs=tests/add-partner.spec.js`, `repeat=3`, `cleanup=yes`:

```
✓ 1 tests/add-partner.spec.js:10 (6.0s)
✘ 2 tests/add-partner.spec.js:10 (4.3s)
✘ 3 tests/add-partner.spec.js:10 (1.4s)

```

Текст падения (одинаковый в обоих случаях):

```
Error: Вход не завершился (4 с …). views={"view-onboarding":"visible", остальные "hidden"}
ошибки=["http 502 http://127.0.0.1:8080/api/v1/clients",
        "console.error: Failed to load resource: 502 (Bad Gateway)"]
```

То есть **спека не при чём**: приложение не смогло войти, потому что `GET /api/v1/clients` вернул **502 Bad Gateway**, и UI ушёл в `view-onboarding`. Это же объясняет и красный `smoke-front` в прогоне `43394018588` (первая попытка), который позеленел на повторе.

**Гипотеза механизма:** E2E идёт сразу после `deploy-dev`, который пересоздаёт контейнеры; `preflight` проверяет только `/health` (он у Caddy, а не у сервиса), поэтому 502 на `/api/v1/clients` в первые секунды не ловится.

**Что нужно (две зоны, можно независимо):**
1. **@DO (`7-deploy/.github`):** post-deploy readiness — дождаться не `/health`, а **`/api/v1/clients` без 5xx** (или `200/401`, но не 502) перед запуском smoke;
2. **@TE (`9-tests`):** в хелпере входа — явный ретрай на `502/503` с сообщением «стенд ещё поднимается», а не «вход не завершился» (иначе диагноз каждый раз заново).
