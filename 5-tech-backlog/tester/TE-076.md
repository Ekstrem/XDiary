# TE-076. Шаг «чистое устройство → онбординг» падал по лимиту без диагностики (95 с)

- **Статус:** На проверке
- **Проверяет:** @TL
- **Роль:** @TE
- **Источник:** прогон Front E2E #775 (REF `e8f5ba00`), аннотация `##[error]` теста
  «онбординг E7 → телефон → OTP → Кто вы?»

## Проблема

Шаг `чистое устройство → экран онбординга` занял **95.0 с** — весь бюджет теста, и упал с
`Test timeout of 95000ms exceeded` плюс единственная зацепка
`page.addInitScript: Target page, context or browser has been closed`. То есть тест дождался лимита,
после чего контекст закрылся, — а **что было на экране**, в лог не попало.

В шаге три ожидания подряд (20 с `expectScreen('#view-onboarding')`, проверка скрытости замка, 20 с
скрытости `#view-splash`), и любое из них могло «съесть» время. Загадка была не в продукте, а в
отсутствии данных: диагноз по логу поставить нельзя.

## Что изменено

Оба ожидания обёрнуты так, что при провале сначала печатается состояние **всех** экранов
(`dumpViews`), и только потом пробрасывается ошибка:

```js
try {
  await expectScreen(page, '#view-onboarding', 'чистое устройство → онбординг', 20000);
} catch (e) {
  await dumpViews(page, 'onboarding шаг 0: экраны при провале (ждали #view-onboarding)');
  throw e;
}
```

То же для залипшего `#view-splash`. Проверки не ослаблены: требования те же, добавлена только
диагностика на путь провала.
