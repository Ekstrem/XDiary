- **Статус:** В работе
- **Приоритет:** P1 (поднят @TL 16:06: `smoke-api` зелёный, но **8 из 9 тестов в `skip`** — гейт проверяет меньше, чем должен; единственный приоритет @TE после отклонения TE-042)
- **В работе с:** 2026-11-07
- **Источник:** @DO 2026-11-03 09:00 — `deploy` #752 (`15b56ce`): 8 из 9 падают через `E2EInfra.LoginAsync`; проверено по коду: `E2EInfra.cs:25` и `AuthE2ETests.cs:14` ходят в `POST /api/v1/privacy/token {pin}`; вердикт **AR-009** (legacy, ADR-021 п.3): источник правды для PIN — локальный `window.Pin`, серверный контур `/privacy/*` — вне MVP
- **Зависимости:** AR-009 (решён), BE-041 (client-JWT + refresh — сделано), TE-037 (та же логика для фронт-спек)
- **Проверяет:** @TL (TechLead)

## Проблема
`smoke-api` (гейт перед `deploy-prod`) построен на **device-токене по PIN**: `E2EInfra.LoginAsync` → `POST /api/v1/privacy/token {pin}`. По AR-009 этот контур — legacy, продукт на него не опирается. Итог: гейт проверяет **то, что мы намеренно вывели из MVP**, и блокирует доставку зелёного фронта.

## Задача (зона @TE, `9-tests/E2E`)
1. **Немедленно (разблокировать доставку):** 8 падающих тестов пометить `Skip` с причиной, ссылающейся на AR-009/ADR-021 — так же, как это сделано для `no-pin.spec.js`/`change-pin.spec.js`. Тесты **не удалять**: они остаются исторической регресс-защитой legacy-контура.
2. **Затем (реальная замена):** перевести `E2EInfra.LoginAsync` на клиентский контур, который работает: `POST /api/v1/clients` → `POST /api/v1/clients/{id}/verify {code}` → `accessToken` (+ `refreshToken`), и вернуть эквивалентные проверки:
   - логин выдаёт пару и `expiresAt`;
   - доступ с токеном → 200, без токена → 401 + `WWW-Authenticate`;
   - `refresh` продлевает пару;
   - журнал: создание записи → чтение → деталь;
   - аналитика: summary/correlations/somatic-slice отвечают 200.
3. `run-e2e-vps.sh` — убрать шаг с `POST /privacy/token` (он тоже legacy).

## Критерии приёмки
- [ ] `smoke-api` зелёный **на клиентском контуре**, а не за счёт `Skip` всего набора (п.2 выполнен).
- [x] Ни один тест гейта не ходит в `/privacy/token` и `/privacy/pin/*`.
- [x] Помеченные `Skip` (если останутся) имеют причину со ссылкой на AR-009.

## Ход
- **Шаг 0 — блокер доставки снят (`a4358ac`, в `origin`):** введён атрибут `E2EFactLegacy` с причиной «AR-009 / ADR-021 п.3: серверный PIN — legacy, `/privacy/token` вне MVP; миграция `LoginAsync` на client-JWT — TE-041»; помечено ровно **8** legacy-тестов (Auth 3, Journal 2, Somatic 3), тесты **не удалены**, `Anonymous_IsRejected_401` оставлен активным как отрицательный контроль.
- **Шаг 3 (уточнение):** в `run-e2e-vps.sh:34` `/privacy/token` стоит **внутри `echo`** — это печатаемая подсказка, а не исполняемая команда.

## Сделано (миграция на client-JWT)
- **`E2EInfra.LoginAsync` переведён на клиентский контур:** `POST /api/v1/clients {phone}` → `POST /api/v1/clients/{id}/verify {code}` → `accessToken` + `refreshToken`; возвращает `E2ESession(AccessToken, RefreshToken, ClientId)`. Добавлен `RefreshAsync` → `POST /api/v1/clients/refresh {refreshToken}`.
- **`E2EFactLegacy` удалён полностью** — `Skip` больше не нужен: 8 тестов снова в гейте на рабочем контуре.
- **Проверки восстановлены/добавлены:** `Login_ReturnsAccessAndRefresh`; `Anonymous_IsRejected_401_WithWwwAuthenticate` (401 + `WWW-Authenticate`, BE-044); `ValidToken_AllowsAccess` (`/clients/me`); **`Refresh_ReturnsNewPair`** (новый пункт); `Logout_ClearsTokens_ThenAnonymous401`; `Journal_Anonymous_IsRejected_401`; `Journal_WithClientToken_AllowsAccess`.
- **`run-e2e-vps.sh`:** `XDIARY_E2E_PIN` → `XDIARY_E2E_OTP`, подсказка для нагрузки переписана на `clients` → `verify`; `/privacy/token` остался только в комментарии.
- **Проверки:** `dotnet build` = **0 ошибок / 0 предупреждений**; `git grep` по `9-tests/E2E` — обращений к `/privacy/token` и `/privacy/pin/*` в коде **нет** (только комментарии). `dotnet test` локально недоступен (testhost в песочнице падает на именованных каналах) — приёмка по `smoke-api`.

**Риск, о котором предупреждаю честно:** тест `Anonymous_IsRejected_401_WithWwwAuthenticate` требует `WWW-Authenticate` на 401. По сообщению @TL 16:16 правка `BE-044` (`GatewayRoutes.IsAnonymous` + `WWW-Authenticate`) **ещё не в `origin`**. Если на стенде заголовка нет — покраснеет именно этот тест, и это **дефект BE-044**, а не теста; тогда его надо либо дождаться, либо временно ослабить проверку до 401 (решение за @TL).

**Старт был после `deploy-prod`** (@TL 10:06), приоритет P1 поднят @TL 16:06.
