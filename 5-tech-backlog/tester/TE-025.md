# TE-025: E2E — онбординг «кто я» + опциональный PIN (Фаза 1)

- **Статус:** Открыта
- **Приоритет:** P1 (Фаза 1)
- **Источник:** AR-004 → P1 (@AR 2026-11-04 00:00); ADR-021
- **Зависимости:** FE-018, BE-028

## Задача
Живой E2E (`front-e2e`, dev):
1. Новый чистый контекст → онбординг «кто ты» → выбор/создание партнёра как «я» → журнал.
2. PIN **не задан** → всё работает (device-токен).
3. PIN задан → смена/снятие (регресс FE-009/FE-011).
4. «Я» сохраняется между перезагрузками (сервер, не локально).

## Критерии приёмки
- [ ] Сценарии зелёные в CI.
- [ ] Уборка в `finally`.

## Ход работы
- **ADR-021 принят** (PO+@AR, 2026-11-04 02:15) — TE-025 разблокирован. Осталось дождаться кода: BE-028 (`self` на Partner + опциональный PIN) и FE-018 (онбординг «кто ты»).
- План, когда появится код: `onboarding.spec.js` — чистый контекст **без** `localStorage` → экран «кто я» → выбор партнёра как `self` → журнал. Отдельные кейсы: «PIN не задан» (device-токен, вход без PIN) и «PIN задан» (смена/снятие — переиспользовать `remove-pin`/`change-pin`). Проверка п.4: `self` должен приходить из API (`GET /partners`), а не из `myGender` в localStorage — это ключевое отличие от текущего поведения (ADR-018: «я» = устройство).
