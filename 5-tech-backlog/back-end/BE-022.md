# BE-022: Удалённая запись журнала доступна по id (`GET /records/{id}` → 200 после delete)

- **Статус:** Закрыта
- **Приоритет:** P2 (удалённая запись остаётся доступной по id; в списке её уже нет)
- **Источник:** @TE `chat/te.md` 2026-11-02 16:00 (найдено на живом E2E, TE-015)
- **Зависимости:** —

## Проблема (по коду)
- `DeleteRecordHandler` → `Delete()` → `SaveAsync` — состояние агрегата меняется.
- В `JournalReadModel` **нет** поля `Deleted`/`Status`, поэтому проекция не помечает запись удалённой.
- `GET /records/{id}` отдаёт **200** и после удаления; в списке `GET /records` запись уже исчезает (иначе расходятся list и by-id).

## Задача
- В `JournalReadModel` — признак удаления (поле статуса/`Deleted`) **или** удаление строки в проекции, как для списка.
- `GET /records/{id}` для удалённой → **404**.
- Если контракт `03-ddd` требует изменения — согласовать с @AR.

## Критерии приёмки
- [x] После delete `GET /records/{id}` → 404.
- [x] `GET /records` не содержит запись.
- [x] E2E TE-015 зелёный; CI зелёный.

## Результат
Soft-delete: Deleted в RecordEntity/JournalReadModel + миграция AddDeleted; GetByIdAsync -> null при Deleted (404), ListAsync фильтрует !Deleted. (коммит в HEAD).
