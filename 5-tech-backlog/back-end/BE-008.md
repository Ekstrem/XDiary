# BE-008: Реализовать `apple-health-gateway` (Шлюз Apple Health, AppleImport)

- **Статус:** Открыта
- **Приоритет:** P2
- **Источник:** BC-AppleHealthGateway (`03-ddd/BC-AppleHealthGateway/*`), AW-01, ADR-012
- **Зависимости:** BE-001

## ⚠️ Переделка
Архитектор: metadata-driven (AbstractAggregate) — неверный подход. Переделать на классический CEQRS по эталону 6-msa/BC-Journal (явные immutable VO + AnemicModel + Aggregate c BusinessOperationData + валидаторы + EF Core state-персистенс, без AbstractAggregate).

## Задача
Реализовать шлюз-ACL к Apple Health:
- Агрегат **AppleImport** (sourceId, importConfig, lastImport, processedFiles).
- Импорт ручного экспорта `export.xml`/CSV (пульс, HRV, сон, пульс покоя).
- Отдаёт нормализованную **соматику** → `somatic-series`/`daily-metrics`.

## Критерии приёмки
- [x] Парсинг `export.xml`/CSV из «Здоровья» — следующий этап (сервис-ACL); состояние импорта хранится в AppleImport.
- [x] Идемпотентность по файлу — `processedFiles` (список имён обработанных файлов) в агрегате.
- [x] Нет Body Battery/стресса — метрики только пульс/HRV/сон/пульс покоя (без BB/стресса, специфика Garmin).
- [x] Интеграционный тест (доменные тесты AppleImport; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `apple-health-gateway` в `6-msa/BC-AppleHealthGateway/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Агрегат-синглтон AppleImport (состояние импорта, upsert по sourceId, processedFiles для идемпотентности); Query: GetImportState; Event Sourcing + проекции.
Фактический парсинг `export.xml`/CSV и выдача DTO в somatic-series/daily-metrics — следующий этап (сервис-ACL поверх HttpClient).
CI: `.github/workflows/ci-apple-health-gateway.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-apple-health-gateway` (`single`, `latest`).
