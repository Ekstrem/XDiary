# BE-136 — P2: `ChangedValueObjects` отдаёт ТОЛЬКО ОДИН ключ на событие (дефект diff библиотеки) → `Verified` не доезжает проекцией

- **Статус:** ToDo
- **Приоритет:** P2 — обойдено workaround-ом `#2892` (`VerifyClientOtpHandler` пишет `Verified=true` напрямую), но проекция в общем случае теряет часть изменений
- **Источник:** замеры @DO (`v1 → {Root}`, `v2 → {OtpCode}`, `v3 → {Gender}`) + анализ @FE (`AnemicModel.GetValueObjects()` содержит все 8 полей, включая `Verified`)
- **Зависимости:** `#2889` (LegacyTimestampFloor), `#2892` (workaround) — в `main`
- **Проверяет:** @TL
- **Исполняет:** @BE (+ библиотека `DigiTFactory.Libraries.SeedWorks`)
- **Результат:** —

## Факт
На каждое событие в `domainEvent.ChangedValueObjects` приходит **ровно один** ключ, хотя менялось больше полей:
```
RegisterClient: {"Root"}          (менялись Root, Phone, OtpCode, OtpExpiresAt, Verified)
VerifyOtp:      {"OtpCode"}       (менялись OtpCode, Verified)
UpdateProfile:  {"Gender"}        (менялись Gender, DisplayName)
```
Следствие: `ClientProjection.ApplyVos` видит только один ключ, остальные поля read-модели не обновляются; `Verified` не приходит никогда.

## Задача
Установить, где теряются ключи (библиотечный `GetChangedValueObjects`/`Invariants` diff), и починить так, чтобы дифф отдавал **все** изменённые VO. До этого — workaround `#2892` остаётся.

## Критерии приёмки
- на событии `VerifyOtp` в `ChangedValueObjects` есть **и** `OtpCode`, **и** `Verified`;
- проекция `ClientEventHandler` без workaround-а ставит `verified=true`;
- `BE-131`-подобные сценарии (несколько изменённых полей) проходят без ручных апдейтов;
- запись в `04-architecture/edm-debt-plan.md` закрыта.
