# BE-128 — P1: партнёр не появляется в `partners_read` (дубль `SaveEventAsync` в консьюмере)

- **Статус:** На проверке
- **Приоритет:** P1 (блокер выкатки: `RegisterPartnerContractTests` красный, `smoke-api` «Контракт журнала» падает)
- **Источник:** замеры @DO 2026-11-18 (`partners_read` 0 строк по свежим id, событие `CommandToAggregate` в `Commands.DomainEvents` есть) + воспроизведение @BE на живом Postgres
- **Зависимости:** BE-127 (миграции `AddVersionToPartnersRead`)
- **Проверяет:** @TL
- **Исполняет:** @BE (`6-msa/BC-Partners`)
- **На проверке с:** 2026-11-18
- **Артефакт:** PR #2688 (`role/be-be128` → `main`)

## Корень (проверен кодом и на живой БД)

`BusAdapter.cs:33-34` уже делает `SaveEventAsync(result)` **до** `PublishAsync(result.Event)`. А `PartnerEventHandler.HandleAsync` повторно вызывал `_store.SaveEventAsync(entry)` для **того же** события ⇒ INSERT по тому же `Id` ⇒ исключение уходило в отброшенную задачу `_ = HandleAsync(e)` ⇒ проекция **не доходила** до `UpsertAsync` ⇒ 0 строк в `partners_read`.

Это объясняет все факты: `[handle] entered` × 100 (консьюмер входит), событие в `DomainEvents` есть, строк нет, логи «чистые» (исключение глушится).

**Опровергнуто:** гипотеза «`UpsertAsync` падает». Проверено на живом Postgres: и прямой `INSERT`, и реальный `UpsertAsync` через DI — строки пишутся; после удаления дубля `HandleAsync` пишет строку корректно.

## Критерии приёмки

- [ ] свежий партнёр появляется в `partners_read` (1 строка);
- [ ] `GET /partners` непустой;
- [ ] `link-client` → 200;
- [ ] `RegisterPartnerContractTests` зелёный.

## Результат

Убран дубль `SaveEventAsync` из `HandleAsync` (событие сохраняет только `BusAdapter`). Фикс в PR #2688; проверен локально на живом Postgres (строка пишется с корректными `Name`/`ClientId`).
