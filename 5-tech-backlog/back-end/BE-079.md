## Почему это P0, а не «потом» (добавлено @TL 20:21)

`6-msa/BC-Partners/src/Partners.Api/Program.cs:60` вызывает **при старте**:

```csharp
scope.ServiceProvider.GetRequiredService<CommandDbContext>().Database.Migrate();
```

То есть **следующий перезапуск контейнера partners** (и любая выкатка) попытается применить ожидающую
`20261105165235_AddOutbox`, чей первый шаг — добавление колонки `DeletedAt` в `partners`, при том что колонка **уже есть**
(её создала применённая `20261113120000_AddDeletedAtToPartner`).

**Последствие:** падение миграции при старте ⇒ сервис не поднимается ⇒ `/api/v1/partners` ложится.
Сейчас этого не видно только потому, что образ на dev (`b9c2f066`) собран **до** появления `AddOutbox`.

⇒ **До фикса partners не перевыкатывать.** Это не «уборка», это условие следующего деплоя.

## Точный патч и одна тонкость, без которой фикс будет неполным (@TL 20:24)

### Порядок ID объясняет, почему падает именно dev

`20261105165235_AddOutbox` (**1**) → `20261113120000_AddDeletedAtToPartner` (**2**).

- **Чистая база:** (1) добавляет `DeletedAt`, (2) пытается добавить его снова ⇒ падение на (2).
- **dev:** (2) уже применена, а (1) — нет ⇒ EF применит только (1) ⇒ падение на дубле.

То есть «просто удалить из (1)» лечит **оба** случая, но семантическим владельцем колонки остаётся (2)
(`AddDeletedAtToPartner` — так и называется).

### Патч

**`Migrations/20261105165235_AddOutbox.cs`** — в `Up()` удалить блок:

```csharp
migrationBuilder.AddColumn<DateTime>(
    name: "DeletedAt",
    table: "partners",
    type: "timestamp with time zone",
    nullable: true);
```

в `Down()` удалить:

```csharp
migrationBuilder.DropColumn(
    name: "DeletedAt",
    table: "partners");
```

Оставить только `CreateTable("outbox")` / `DropTable("outbox")`.

### ⚠️ Тонкость: `AddOutbox.Designer.cs`

В нём останется `b.Property<DateTime?>("DeletedAt")` (строка 37) — это **снимок модели** на момент миграции.
Если оставить как есть, следующая сгенерированная миграция будет считать, что колонка появилась в `AddOutbox`,
и разъедется с фактическим состоянием. Поэтому:

- в `AddOutbox.Designer.cs` **убрать** свойство `DeletedAt` (модель на тот момент его не содержит);
- `CommandDbContextModelSnapshot.cs` (**строка 34**) **не трогать** — это актуальная модель, где `DeletedAt` есть.
