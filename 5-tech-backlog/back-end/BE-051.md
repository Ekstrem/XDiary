# BE-051: Идемпотентность создания в каталоге — дубль «костюмчика» при добавлении

- **Статус:** В паузе
- **Приоритет:** P1 (владелец воспроизвёл; возможен системный класс — повтор запроса/двойной тап → дубль)
- **Пауза:** ретро владельца (объявлена 2026-11-09) — работы не ведутся
- **Разблокирует:** решение владельца после ретро
- **Источник:** владелец 2026-11-09 03:5x: «в списке костюмчиков продублировался один при добавлении. Если это проблема повторителя, то вопрос есть ли идемпотентность операций (и тесты на неё?)»
- **Зависимости:** FE-036 (повторы на сетевой сбой), BE-016 (dedup в `/me`), ADR-006 (REST)
- **Проверяет:** @TL (TechLead)

## Проблема
При добавлении «костюмчика» в каталоге появилась **дублирующая запись**. Наиболее вероятная причина — **повтор запроса** (retry на сетевой сбой со стороны клиента или двойной тап) при **неидемпотентном** `POST`. Владелец прямо спросил: есть ли идемпотентность и тесты на неё.

## Задача (зона @BE, `6-msa/BC-Catalog`)
1. **Диагноз:** воспроизвести — два одинаковых `POST /api/v1/catalog` подряд; зафиксировать, что создаётся 2 записи. Проверить, отдаёт ли фронт два запроса на один тап (лог @DO/@FE).
2. **Идемпотентность:** поддержать **`Idempotency-Key`** (или `clientRequestId` в теле) на создание: повтор с тем же ключом в течение окна (например 10 минут) возвращает **ту же** запись и `200/201` без создания новой. Ключ хранить с привязкой к `clientId`.
3. **Альтернатива, если ключ не подходит:** уникальный индекс «(`ClientId`, нормализованное имя, тип)» + идемпотентный upsert — но только если продукт допускает «одинаковые элементы нельзя».
4. **Тесты:** unit/интеграционные: «два одинаковых POST с одним `Idempotency-Key` → одна запись, оба ответа 2xx с тем же `id`»; «два POST с разными ключами → две записи» (законное поведение); негативный контроль: без ключа поведение прежнее и задокументировано.

## Критерии приёмки
- [ ] Воспроизведение до/после зафиксировано в задаче (2 записи → 1).
- [ ] Тест на идемпотентность в `9-tests` есть и падает при её отсутствии.
- [ ] Фронт при retry переиспользует ключ (согласовать с @FE).
- [ ] Владелец не видит дублей при обычном добавлении.
