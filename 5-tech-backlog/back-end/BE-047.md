# BE-047: P0 — повторный вход невозможен: `register` для существующего телефона отдаёт 400 и НЕ отправляет код

- **Статус:** В работе
- **В работе с:** 2026-11-08
- **Приоритет:** **P0** (владелец зарегистрировался один раз и больше не может войти)
- **Источник:** владелец 2026-11-08 10:30 «Не могу войти»; `ex.md` 09:35 — первый вход **удался**; после него `POST /api/v1/clients` для того же номера возвращает `400 phone_taken` (`ClientHandlers.cs:20`), код **не отправляется**, а `verify` вызывать не на чем
- **Зависимости:** BE-046 (маркер `phone_taken`), TE-041 (client-JWT), DO-053 (диагностика входа)
- **Проверяет:** @TL (TechLead)

## Проблема
В контуре **нет входа**, есть только регистрация. Фронт получает код через `POST /api/v1/clients`, и для **уже существующего** телефона этот вызов теперь честно отдаёт `400 phone_taken` — то есть **второй и последующие входы невозможны**, хотя это штатный сценарий (человек возвращается на следующий день).

## Задача (зона @BE, `6-msa/BC-Client`)
1. `RegisterClient` должен работать как **register-or-login**: если телефон уже есть —
   - **выпустить новый OTP и отправить его** (тот же `IOtpSender`);
   - вернуть **`200`** и `clientId` существующего клиента (плюс, как обычно, `verified`/`linkedPartnerId`, если есть);
   - **не** создавать дубликат и **не** отдавать `phone_taken` в этом сценарии.
2. `400 phone_taken` оставить только для случая, когда регистрация действительно запрещена (например явный флаг/админский путь), либо убрать совсем — но тогда обновить тесты BE-046.
3. Проверить, что при повторных запросах **старый код инвалидируется**, а новый — единственный валидный (иначе «ввожу старый код» будет воспроизводиться).
4. `ci-backend` #78: разобраться, какой тест падает после правок `TestOtpPolicy`/warning, и починить **тест**, не ослабляя проверку.

## Критерии приёмки
- [ ] Повторный `POST /api/v1/clients` с существующим телефоном → **200**, код уходит в Telegram, возвращается `clientId`.
- [ ] Владелец входит **второй раз** (подтверждено им же).
- [ ] Тест: «второй register для того же телефона → 200 и отправка кода» в `Client.IntegrationTests`.
- [ ] `ci-backend` зелёный (самостоятельно завершившийся прогон).
