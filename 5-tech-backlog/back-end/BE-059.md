## Задача (зона @BE, `6-msa/`)

1. Публикация событий — через outbox-таблицу в той же транзакции; доставка — фоновым воркером (`IHostedService`) с ретраями.
2. Гарантия «хотя бы один раз» + идемпотентный обработчик.

## Критерии приёмки

- [ ] Событие переживает падение процесса: `INSERT` в `outbox` (та же транзакция) → `OutboxDispatcher` доставляет после рестарта. «Остановить брокер» неприменимо: внешнего брокера нет (шина in-memory `EventBus.InMemory`, @AR 08:14), а «остановить БД» ломает условие самого теста.
- [ ] Дубли не ломают проекции (идемпотентность).

## Оценка

**2 человеко-дня** (@AR, `edm-debt-plan.md`).

## Результат

- `OutboxMessage` + таблица `outbox` (миграция `AddOutbox`, только `CreateTable`);
- `SaveAsync` dual-write: `INSERT` (Payload с `$type`-дискриминатором) + текущий `PublishAsync`;
- `IValueObjectJsonConverter` (полиморфная сериализация `IValueObject`) + `PartnerRoot [JsonConstructor]`;
- `OutboxDispatcher` — `SELECT` непроцессированных → реконструкция `DomainEvent<IPartners>` → `PublishAsync` → `ProcessedAt`/`Attempts`;
- re-delivery несёт **id агрегата**: `OutboxMessage.AggregateId` (миграция `AddOutboxAggregateId`) → `DomainEvent(AggregateId, …)`, а не PK строки outbox;
- идемпотентность — `SaveEventAsync` по `Id` (DF) + read-модель через read-modify-write; «остановить брокер» неприменимо (шина in-memory) — снято @AR 08:14;
- Partners зелёная.
