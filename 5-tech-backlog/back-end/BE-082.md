# BE-082: `partners_directory` никто не заполняет — в журнале вместо имён партнёров идентификаторы

- **Статус:** ToDo
- **Приоритет:** **P0** (пользователь видит UUID вместо имени партнёра — прямой дефект экрана журнала)
- **Источник:** проверка @TL по коду `2026-11-05 23:5x`
- **Проверяет:** @TL

## Факт 1 — приёмник есть

`6-msa/BC-Journal/src/Journal.Api/Controllers/PartnersEventsController.cs`:

```csharp
[Route("internal/partners")]
[AllowAnonymous]
public sealed class PartnersEventsController : ControllerBase
{
    [HttpPost("events")]
    public async Task<IActionResult> PostEvent([FromBody] PartnersEventDto dto, CancellationToken ct)
        => Ok(new { ok = await _store.UpsertAsync(new PartnersDirectoryReadModel { PartnerId = …, Name = …, … }) });
}
```

Он — единственный способ наполнить `partners_directory` (read-модель справочника имён).

## Факт 2 — отправителя НЕТ

```
git grep "internal/partners" -- 6-msa   →  только сам контроллер
git grep "HttpClient|PostAsync|internal/" -- 6-msa/BC-Partners/src →  пусто
```

То есть **Partners не публикует события в Journal** — ни через HTTP, ни через шину. Значит `partners_directory` пуст.

## Факт 3 — что видит пользователь

`JournalReadRepository.ResolveNamesAsync()` (`JournalReadRepository.cs:29-42`):

```csharp
m.PartnersNames = m.Partners
    .Select(id => Guid.TryParse(id, out var g) && byId.TryGetValue(g, out var n) ? n : id)   // ← fallback = id
```

Если справочник пуст, `byId` пуст ⇒ `PartnersNames` = **сырые идентификаторы**. На экране журнала это выглядит как набор GUID вместо имён.

## Задача

1. **Связать Partners → Journal:** при создании/переименовании/удалении партнёра публиковать событие в `internal/partners/events`
   (через `HttpClient` с внутренним адресом `journal:8080`, либо через шину, если она уже прокинута между сервисами).
2. **Закрыть `[AllowAnonymous]`** на этом эндпоинте: это **внутренняя запись** в read-модель; анонимный доступ к ней —
   возможность испортить справочник. Нужен сервисный секрет/подпись (ADR-008), а не «доверенная сеть» по умолчанию.
3. Прогнать проверку на **новых** данных: создать партнёра → запись с ним → убедиться, что `PartnersNames` содержит **имя**.

## Критерии приёмки

- `partners_directory` содержит строку для созданного партнёра (`SELECT count(*) … WHERE "PartnerId" = …` = 1);
- `GET /api/v1/journal/records` для записи с партнёром отдаёт **имя**, а не UUID (`PartnersNames` не содержит `-`-формат GUID);
- тест, который это фиксирует (unit или ApiTests), а не ручная проверка;
- `(ii-c)` по `/internal/**` снаружи остаётся 401/403/404 (2xx = нарушение) — проверить после закрытия авторизации.
