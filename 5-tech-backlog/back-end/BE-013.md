# BE-013: Сервисы не создают схему БД (нет миграций и EnsureCreated) — 500 на запросах

- **Статус:** Открыта
- **Приоритет:** P0
- **Источник:** 6-msa/BC-* (рефакторинг «классический CEQRS», BE-002…BE-011); найден DevOps на проде
- **Зависимости:** BE-002…BE-011

## Диагноз (DevOps, на проде VPS-2)

После рефакторинга «классический CEQRS» каждый сервис **подключается к своей БД, но не создаёт таблицы**:

1. В `Program.cs` сервиса НЕТ ни `Database.Migrate()`, ни `Database.EnsureCreated()`.
2. Папки `*/Storage/Migrations/` **пустые**; файлов `*Migration*.cs` во всём `6-msa/` — 0.
3. В итоге на проде (PostgreSQL VPS-2) БД созданы, но **пустые** → запросы падают:
   ```
   Npgsql.PostgresException 42P01: relation "pin_credential" does not exist
   HTTP 500 (напр. GET /api/v1/privacy/pin/has)
   ```

Строки подключения на проде уже выровнены (в контейнеры передаются `ConnectionStrings__CommandDb`/`ReadDb`), то есть до БД сервисы доходят — не хватает только схемы.

## Задача (бэкендеру)

Обеспечить создание схемы при старте сервиса. Варианты:

- **Минимальный (Single-профиль):** в `Program.cs` после `var app = builder.Build();` и до `app.Run();`
  ```csharp
  using (var scope = app.Services.CreateScope())
  {
      scope.ServiceProvider.GetRequiredService<CommandDbContext>().Database.EnsureCreated();
  }
  ```
- **Правильный:** вернуть EF-миграции (`dotnet ef migrations add InitialCreate` для `CommandDbContext` и `ReadDbContext`) и вызывать `Database.Migrate()` на старте.

Учесть: в профиле Single `CommandDb` и `ReadDb` указывают на **одну и ту же БД**, а `CommandDbContext` и `ReadDbContext` мапят **одну таблицу** (напр. `pin_credential`) — создание должно быть идемпотентным, чтобы не было конфликта «table already exists».

## Критерии приёмки
- [ ] После старта контейнера в БД сервиса есть таблицы (для privacy — `pin_credential`).
- [ ] `GET /api/v1/privacy/pin/has` возвращает **200** (JSON), а не 500.
- [ ] Аналогично для остальных 9 сервисов (их таблицы создаются при старте).
- [ ] CI green; образы в GHCR обновлены (`single`/`latest`).

## Дополнительно (низкий приоритет)
- `app.UseHttpsRedirection()` в сервисах за шлюзом даёт в логах `Failed to determine the https port for redirect` (HTTPS терминирует шлюз/caddy, а не сам сервис). При желании — убрать/настроить.
