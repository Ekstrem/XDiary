# BE-006: Реализовать `daily-metrics` (Дневные метрики, DailyMetrics)

- **Статус:** Закрыта (TechLead: классический CEQRS, CI green, соответствует исправленному канвасу) (классический CEQRS, CI green, образ ghcr.io/ekstrem/xdiary-daily-metrics)
- **Приоритет:** P1
- **Источник:** BC-DailyMetrics (`03-ddd/BC-DailyMetrics/*`), G-02
- **Зависимости:** BE-001, BE-007/BE-008

## ✅ Переделано (классический CEQRS, без AbstractAggregate)
Архитектор: metadata-driven (AbstractAggregate) — неверный подход. Переделать на классический CEQRS по эталону 6-msa/BC-Journal (явные immutable VO + AnemicModel + Aggregate c BusinessOperationData + валидаторы + EF Core state-персистенс, без AbstractAggregate).

## Задача
Реализовать микросервис `daily-metrics`:
- Агрегат **DailyMetrics** (date, stress, resting_hr, hrv; sleep: score/duration/deep/light/rem/awake).
- Получает нормализованные дневные сводки от шлюзов.
- Query API: тренды по датам.

## Критерии приёмки
- [x] Хранит `weekly` (стресс/пульс покоя/HRV) и `sleep` (сон) — единая проекция `daily_metrics`.
- [x] Метрики, отсутствующие у источника, отсутствуют — поля опциональны (0 = нет данных).
- [x] Интеграционный тест Command → Query → Assert (доменные тесты DailyMetrics; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `daily-metrics` в `6-msa/BC-DailyMetrics/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Append-only: ImportDaily (upsert по date, детерминированный Guid из date); Query: GetDailySeries (тренды по диапазону дат); Event Sourcing + проекции.
CI: `.github/workflows/ci-daily-metrics.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-daily-metrics` (`single`, `latest`).
