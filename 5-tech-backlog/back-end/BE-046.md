# BE-046: `POST /clients` с существующим телефоном отдаёт 500 + EF-стек вместо 409/400

- **Статус:** На проверке
- **В работе с:** 2026-11-03 00:30
- **Приоритет:** P1 (утечка внутренностей наружу + ложный «сервер упал» в E2E)
- **Источник:** @DO 2026-11-03 17:45 — при коллизии телефона `POST /api/v1/clients` возвращает **500** с `Npgsql.PostgresException` (EF-стек уходит наружу); в E2E это выглядит как «сервер упал», а не как «номер уже занят»
- **Зависимости:** BE-041 (client-JWT — сделано), TE-041 (`smoke-api` на рабочем контуре)
- **Проверяет:** @TL (TechLead)

## Проблема
Дубликат телефона — **ожидаемая бизнес-ситуация** (человек уже регистрировался), а обрабатывается как необработанное исключение БД:
- наружу уходит текст `Npgsql.PostgresException` (внутренности БД, имена констрейнтов);
- HTTP-код **500** вместо 4xx → клиент не может отличить «номер занят» от «сервер сломан»;
- в E2E это маскирует реальные падения (наш случай: 5–20% «флейков» были коллизиями, а выглядели как нестабильность UI).

## Задача (зона @BE, `6-msa/BC-Client`)
1. Обработать нарушение уникальности телефона **на уровне приложения**: проверка перед вставкой и/или перехват `DbUpdateException`/`PostgresException` с `SqlState 23505`.
2. Вернуть **409 Conflict** (или 400 с кодом `phone_taken`) и **человеческое** сообщение; тело — без стеков, без имён констрейнтов, без деталей БД.
3. Добавить тест: повторный `POST /clients` с тем же телефоном → 409/400 и тело без `Postgres`/`constraint`.
4. Проверить, что лог приложения при этом пишет **warn**, а не error-стек (иначе шум в мониторинге).

## Критерии приёмки
- [x] Повторный телефон → **4xx**, тело без внутренних деталей.
- [x] Тест на это в `Client.IntegrationTests` (и он попадает в CI через DO-045).
- [x] В логах — предупреждение, не стек исключения.

## Результат
`RegisterClientHandler`: проверка `GetByPhoneAsync` перед вставкой + `try/catch` на `SaveAsync` (гонка) → `Fail("phone_taken: Телефон уже зарегистрирован")` → 400, без EF-стека. Тест `RegisterClientHandlerTests` (дубликат → `phone_taken`, без `Postgres`). Маркер `phone_taken` поддержан спекой @TE (`IsPhoneCollision`).
