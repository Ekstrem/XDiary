# BE-012: API Gateway (YARP) + BFF-агрегация

- **Статус:** Закрыта (TechLead: соответствует ADR-006/007/008, CI green, Docker в GHCR)
- **Приоритет:** P0
- **Источник:** ADR-006, ADR-007
- **Зависимости:** BE-001, BE-010

## Задача
Реализовать шлюз **YARP**:
- Единая точка входа `/api/v1/...`.
- Маршрутизация на 10 микросервисов.
- Проверка JWT (stateless).
- BFF-агрегация для сводки аналитики (данные из `journal` + `daily-metrics`).

## Критерии приёмки
- [x] Все запросы PWA идут через шлюз — единая точка входа `/api/v1/...` (YARP).
- [x] Маршруты соответствуют Command/Query API — по одному префиксу на микросервис (`03-ddd/*/03/04-*-api.md`).
- [x] JWT проверяется на шлюзе; аноним отклоняется — middleware HS256 (stateless), 401 без валидного Bearer (кроме `/api/v1/privacy/*` и `/health`).
- [x] BFF-агрегация сводки работает — `GET /api/v1/bff/analytics-summary` (journal + daily-metrics).

## Результат
Шлюз в `6-msa/ApiGateway/` (YARP 2.2.0, .NET 8, профиль Single).
ReverseProxy: 10 маршрутов → 10 кластеров (journal, partners, catalog, somatic-series, daily-metrics, garmin-gateway, apple-health-gateway, analytics, privacy, portability).
JWT (HS256) проверяется stateless (тот же signing key, что у privacy); BFF-агрегация `analytics-summary`; CORS.
CI: `.github/workflows/ci-api-gateway.yml` — build + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-api-gateway` (`single`, `latest`).
