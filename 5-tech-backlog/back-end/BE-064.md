# BE-064: deny-by-default в сервисах — `[Authorize]` на всех неанонимных операциях + явный `[AllowAnonymous]`

- **Статус:** ToDo
- **Приоритет:** **P0** (безопасность: сейчас deny-by-default держится **только на YARP**; прямой вызов сервиса без токена отдаёт `200` — доказано замером @DO `2026-11-04 20:58`)
- **Источник:** решение @AR `2026-11-04 15:40` (`ADR-026` §«Ревизия 20:58»): симметричный `Jwt__SigningKey` (HMAC, 64 символа без PEM) не может быть проверен APIM-JWT-планом; канон авторизации — **в сервисах**
- **Зависимости:** `BE-063` (gender-канон), DI-фикс `journal`/`partners` (тот же код)
- **Проверяет:** @AR (контракт/ADL)

## Задача (зона @BE, `6-msa/`)

1. **`[Authorize]`** в контроллерах: `Catalog`, `Analytics`, `DailyMetrics`, `SomaticSeries`, **`Portability`** (5 BC, auth-stack = 0 у всех; в `Client` уже есть; `Privacy`/`Partners`/`AppleHealth`/`Garmin` — `401` подтверждены).
2. **Явный `[AllowAnonymous]`** на **4** анонимных операциях (`POST /clients`, `POST /clients/{id}/verify`, `POST /clients/refresh`, `POST /privacy/verify-token`) — чтобы «нет атрибута» больше **не** было способом случайно открыть ручку.
3. Deny-by-default fallback-политика в каждом BC (как в `ADR-026`).

## Критерии приёмки

- [ ] Для **каждой** операции `api-index.yaml` с `auth ≠ anonymous` (**76 из 80**) прямой запрос **в сервис** без токена → **`401`**; `2xx` = дефект. Проверка — скриптом по индексу, вывод в `## Результат`.
- [ ] Четыре анонимные операции доступны без токена (`200`/`400` по контракту) и помечены `[AllowAnonymous]` **явно**.
- [ ] `dotnet build` + прогон `*.ApiTests`/`*.IntegrationTests` этих BC зелёные; в `## Результат` — числа (сколько тестов, какие проекты).
- [ ] `check_api_index` зелёный (индекс ↔ код сходится).
