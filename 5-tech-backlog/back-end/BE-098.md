# BE-098: тесты `BC-DailyMetrics` и `BC-Catalog` не компилируются после `clientId` в агрегатах — `ci-backend` dispatch красный

- **Статус:** На проверке
- **На проверке с:** 2026-11-12
- **Приоритет:** P1 (блокирует `TE-050`: любой `ci-backend` dispatch красный на шаге тестов, `REF` не появится)
- **Источник:** @TL 2026-11-13 01:00 — из **публичных аннотаций** прогона `ci-backend` #1097 (run `43078918968`, sha `caae6d07c`, `conclusion=failure`)
- **Зависимости:** проявилось благодаря `BE-087` (тестовые проекты внесены в `.sln` → стали компилироваться); до этого класс был невидим для CI
- **Проверяет:** @TL
- **Исполняет:** @BE — обе тестовые папки в зоне `6-msa/**`

## Задача (зона @BE)

Догнать тесты за изменением сигнатур агрегатов: в `RecordStress` / `RecordRestingHr` / `RecordHrv` / `RecordSleep` и `AddItem` добавлен обязательный параметр **`clientId`** (`Guid`), а тесты зовут старые сигнатуры.

| Файл | Строки | Вызов | Ошибка |
|---|---|---|---|
| `6-msa/BC-DailyMetrics/src/DailyMetrics.ApiTests/SomaticDaily.IntegrationTests/DailyMetricsTests.cs` | 25, 26, 27, 28, 50, 57, 64 (и 72) | `RecordStress(date, …)`, `RecordRestingHr(date, int)`, `RecordHrv(date, int)`, `RecordSleep(date, …)` | `CS7036`: нет аргумента для `clientId` |
| `6-msa/BC-Catalog/src/Catalog.ApiTests/PartnersCatalog.IntegrationTests/CatalogTests.cs` | 17, 44, 51 (helper — `:15`) | `AddItem(kind, name)` | `CS7036`: нет аргумента для `clientId` |

**Проверено на `origin` (`315b3c864`):** вызовы по-прежнему без `clientId` — `grep` по файлам показывает `clientId: НЕТ` в каждой из перечисленных строк. То есть дефект живой, а не «был когда-то».

## Критерии приёмки

- [ ] `dotnet build 6-msa/BC-DailyMetrics/src/DailyMetrics.sln` и `dotnet build 6-msa/BC-Catalog/src/Catalog.sln` — **`Ошибок: 0`** (в логе видны оба тестовых проекта);
- [ ] `gh workflow run ci-backend.yml --ref main` → шаг «Тесты изменённых BC» **success**, прогон `conclusion=success` (это и даст `REF` для `TE-050`);
- [ ] в `## Результат` — номер прогона и `sha`, а не «локально собирается».

## Почему карточка, а не «поправить по ходу»

Это ровно тот класс, ради которого закрывался `BE-087`: **тесты не входили в solution ⇒ не компилировались ⇒ устарели молча**. Ошибка не в одной строке, а в том, что сигнатуры агрегатов и тесты разъехались без единого сигнала CI. После правки сигнал появится: `BE-087` уже внёс проекты в `.sln`.
