# BE-088: command-репозитории читают READ-модель — из-за лага проекции `when` даёт 404, а `remove`/`link-client` — 400

- **Статус:** Закрыта
- **Закрыта с:** 2026-11-11
- **В работе с:** 2026-11-06
- **Приоритет:** **P0** (это причина, по которой `smoke-api`/`smoke-front` красные в **каждом** прогоне и `deploy-prod` не запускается)
- **Источник:** разбор @TL `2026-11-06 08:4x` по коду + симптомы из прогонов Deploy `0139fe60`, `30c6df98`
- **Проверяет:** @TL

## Симптомы (одни и те же в двух прогонах подряд)

```
POST /api/v1/journal/records/{id}/when        → 404
POST /api/v1/partners/{id}/link-client        → 400
POST /api/v1/partners/{id}/remove             → 400 "Partner not found." (smoke-api, контракт)
```

## Причина (по коду, а не по догадке)

**1. `JournalCommandRepository.GetByIdAsync` читает read-модель и БД больше не имеет:**

```csharp
// 6-msa/BC-Journal/src/Journal.Storage/JournalCommandRepository.cs
:12  private readonly IJournalQueryRepository _readRepo;

:16  public async Task<IJournalAnemicModel?> GetByIdAsync(Guid id, CancellationToken ct = default)
:18      var read = await _readRepo.GetByIdAsync(id, ct);
```

**2. То же в Partners:**

```csharp
// 6-msa/BC-Partners/src/Partners.Storage/PartnerCommandRepository.cs
:15  private readonly IPartnersQueryRepository _readRepo;
:19  public async Task<IPartnerAnemicModel?> GetByIdAsync(Guid id, CancellationToken ct = default)
:21      var read = await _readRepo.GetByIdAsync(id, ct);
```

**3. `EnsureOwns` в контроллере журнала тоже смотрит в read-модель:**

```csharp
// 6-msa/BC-Journal/src/Journal.Api/Controllers/JournalController.cs:30-35
var rec = await _mediator.Send(new GetRecordByIdQuery(id));   // → JournalReadRepository → read model
if (rec is null) return NotFound();
```

`GetRecordByIdHandler` (`JournalQueries.cs:16-21`) **не имеет** fallback — просто `_repo.GetByIdAsync`.

## Механизм отказа

Read-модель наполняется **проекцией** (асинхронно, fire-and-forget). Запись создана секунду назад ⇒ её ещё нет в
`journal_read`/`partners_read` ⇒:

- `EnsureOwns` → `null` → **404** (`when`, и любая мутация записи);
- `remove`/`link-client` → `GetByIdAsync` → `null` → `Fail("Partner not found")` → **400**.

Это тот же класс, что раньше лечили в **запросах** Partners: `PartnerQueries.cs:22-27` — «сначала read-модель,
затем fallback в command-store». Но теперь **хуже**: command-репозитории сами стали читать read-модель и потеряли
доступ к command-store, поэтому fallback делать нечем.

## Что сделать (в порядке)

1. **Вернуть command-репозиториям доступ к источнику истины:** `CommandDbContext` (для Partners/Journal) **или**
   event-store пересборку агрегата по `id` — тогда `GetByIdAsync` = «read-модель → при промахе источник».
2. **`EnsureOwns`/guards** не должны отдавать `404` из-за лага: при промахе read-модели — проверять агрегат.
3. Не менять поведение там, где лаг допустим (списки/чтения) — там fallback уже есть (`PartnerQueries`).
4. Тест: «создать запись/партнёра → **сразу** вызвать `when`/`remove` в том же тике» — оба 2xx, без ожидания проекции.

## Важно: просто `git revert` вернёт 504 — не делать

Вернув событийную пересборку **без** кэша, мы получим медленный `GetByIdAsync` (пересборка всех событий на каждый
запрос) — а это ровно та причина, по которой, судя по всему, и перешли на read-модель (`e1b3f828`: «504 — consumer
`HandleAsync` + fire-and-forget»). Поэтому правка — **гибрид**, а не откат:

```csharp
public async Task<IPartnerAnemicModel?> GetByIdAsync(Guid id, CancellationToken ct = default)
{
    var read = await _readRepo.GetByIdAsync(id, ct);      // быстрый путь
    if (read is not null) return read;
    var events = await _repo.GetById(id, ct);             // источник истины при промахе
    return events.LastOrDefault();
}
```

Так: свежие данные находит пересборка, «старые» — read-модель, и `POST` не ждёт проекцию.

**Плюс** отдельная задача по латентности (если пересборка всё же дорога): снапшоты агрегатов — тогда `GetById` не
читает все события.

`_repo` — это `IRepository<IPartners, IPartnerAnemicModel>`, то есть `PartnerCommandRepository`, у которого

## Про журнал: fallback в `EnsureOwns` УЖЕ есть — значит 404 оттуда не должен идти

```
eae62589 (11-06 04:58) Journal EnsureOwns — fallback command-store (read-after-write 404)
JournalController.cs:36-39   // @TE 04:32 — fallback: read-модель материализуется с лагом
var agg = (await _anemic.GetById(id, CancellationToken.None)).LastOrDefault();
if (agg is null) return NotFound();
```

И этот коммит **входит** в образ-тег `8ca25cf` (проверено `git merge-base --is-ancestor`). Значит для `when` 404
осталось два кандидата, и оба проверяются фактом, а не чтением:

1. **образ на dev старее тега** (тогда 404 — старое поведение) → `podman inspect` даёт ответ;
2. **событий нет в event store** ⇒ `_anemic.GetById` возвращает пусто ⇒ `NotFound` даже с fallback
   (проверка: `[handle] entered` в логах журнала + `count(*)` по таблице событий после создания записи).

**Второй вариант правдоподобен:** `JournalEventHandler.OnNext` → `_ = HandleAsync(e)` (fire-and-forget). Если
`HandleAsync` падает (`/journal` событие не сохранилось), ошибка не видна ни в ответе, ни в логе, а `when`
закономерно даёт 404 — и это же объясняет, почему `journal_read` содержал 52 записи при 2481 в `records`.

## Готовый патч (paste-ready, оба файла) — @TL 08:4x

`IAnemicModelRepository<…>` **уже зарегистрирован** в DI обоих сервисов (им пользуются `JournalController:19-20`
и `PartnerQueries:18-19`), поэтому новых регистраций не нужно — только параметр в конструктор.

### 1. `6-msa/BC-Partners/src/Partners.Storage/PartnerCommandRepository.cs`

```csharp
private readonly IPartnersQueryRepository _readRepo;
private readonly IAnemicModelRepository<IPartners, IPartnerAnemicModel> _events;   // + добавить
public PartnerCommandRepository(CommandDbContext db,
                                IPartnersQueryRepository readRepo,
                                IAnemicModelRepository<IPartners, IPartnerAnemicModel> events,  // +
                                IEventBusProducer bus) { _db = db; _readRepo = readRepo; _events = events; _bus = bus; }

public async Task<IPartnerAnemicModel?> GetByIdAsync(Guid id, CancellationToken ct = default)
{
    var read = await _readRepo.GetByIdAsync(id, ct);
    if (read is not null) return read;                    // быстрый путь
    var events = await _events.GetById(id, ct);           // источник истины при промахе
    return events.LastOrDefault();
}
```

### 2. `6-msa/BC-Journal/src/Journal.Storage/JournalCommandRepository.cs`

То же самое, с `IJournal`/`IJournalAnemicModel` и `IJournalQueryRepository` (сейчас у него **нет** `CommandDbContext`,
поэтому fallback — именно `IAnemicModelRepository`, как было до `8ca25cf5`).

### Почему это, а не `revert`

Полный откат вернёт событийную пересборку **на каждый** запрос — то есть 504-латентность, ради которой и делали
read-модель. Гибрид оставляет быстрый путь и закрывает лаг.
