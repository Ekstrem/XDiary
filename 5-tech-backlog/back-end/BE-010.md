# BE-010: Реализовать `privacy` (Приватность, PinCredential + JWT)

- **Статус:** Закрыта (TechLead: классический CEQRS, CI green, соответствует исправленному канвасу) (классический CEQRS, CI green, образ ghcr.io/ekstrem/xdiary-privacy)
- **Приоритет:** P0
- **Источник:** BC-Privacy (`03-ddd/BC-Privacy/*`), US-11, ADR-008
- **Зависимости:** BE-001

## ✅ Переделано (классический CEQRS, без AbstractAggregate)
Архитектор: metadata-driven (AbstractAggregate) — неверный подход. Переделать на классический CEQRS по эталону 6-msa/BC-Journal (явные immutable VO + AnemicModel + Aggregate c BusinessOperationData + валидаторы + EF Core state-персистенс, без AbstractAggregate).

## Задача
Реализовать микросервис `privacy`:
- Агрегат **PinCredential** (PBKDF2-SHA256: salt + hash).
- Выпуск/проверка **JWT** (2 пользователя, один issuer).
- Локальный PIN остаётся на устройстве (доп. слой).

## Критерии приёмки
- [x] PBKDF2-SHA256 хранение PIN (не открытым текстом) — `PasswordHasher` (Rfc2898DeriveBytes, 100000 итераций, соль + hex-хеш).
- [x] Краткоживущий access + refresh токен — `TokenService` (HS256): access 15 мин, refresh 30 дней.
- [x] Шлюз проверяет JWT (stateless) — эндпоинт `POST /api/v1/privacy/verify-token`.
- [x] Интеграционный тест (доменные тесты PinCredential; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `privacy` в `6-msa/BC-Privacy/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Агрегат PinCredential (userId, salt, hash, iterations — открытый PIN не хранится); Command: SetPin (PBKDF2-SHA256), RemovePin; Query: HasPin, VerifyPin.
JWT (HS256, issuer `xdiary`): `POST /token` (выпуск после проверки PIN), `POST /verify-token` (stateless для шлюза); signing key из `Jwt:SigningKey`.
Event Sourcing + проекции; доменные тесты PinCredential.
CI: `.github/workflows/ci-privacy.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-privacy` (`single`, `latest`).
