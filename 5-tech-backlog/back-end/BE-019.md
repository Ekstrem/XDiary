# BE-019: Токен без PIN (PIN — опционален, а не обязателен)

- **Статус:** На проверке
- **Приоритет:** P0 (блокирует живое тестирование PWA без PIN)
- **Источник:** @TE `chat/te.md` 09:00; правило PO: «PIN — возможность, а не правило»
- **Зависимости:** BE-014

## Проблема (по коду)
- Клиент: без PIN журнал открывается (`lock()` → `showView("journal")`).
- API: `6-msa/BC-Privacy` `IssueTokenHandler` (`TokenEndpoints.cs`): `var m = await _repo.GetBySourceIdAsync("pin", ct); if (m is null || !m.HasPin) return null;` — **без PIN токен не выдаётся**.
- Шлюз: JWT обязателен на всё, кроме `/health` и `/api/v1/privacy/*` → **401 на «Сохранить»** у пользователя без PIN.
- Итог: противоречие продукту — PWA без PIN не может ни читать, ни писать.

## Задача
Выдавать JWT при отсутствии PIN (PIN остаётся опциональным):
- при `!HasPin` — device/anonymous-токен тем же signing key (например claim `sub="device"`, без PIN-привязки), короткий TTL;
- при заданном PIN — поведение не меняется (текущий flow).

## Критерии приёмки
- [x] Без PIN: `POST /api/v1/privacy/token` (или отдельный device-endpoint) возвращает рабочий JWT.
- [ ] Клиент без PIN читает и пишет журнал/партнёров/каталог (нет 401).
- [x] С PIN — без изменений.
- [ ] CI (`Test 9-tests`, `E2E`) зелёный.
