# BE-095: `openapi/*.json` не несёт коды ошибок — реестр расходится с каноном

- **Статус:** На проверке
- **В работе с:** 2026-11-07
- **На проверке с:** 2026-11-10
- **Приоритет:** P1 (второй источник правды, который «врёт в оптимистичную сторону»: в реестре только `200`, а канон фиксирует `200/409/400/429`)
- **Источник:** @TE находка → @TL 09:12 замер (`openapi/client.json` = 8 операций, только `200`; канон `Client.Register` = `200/409/400/429` + `error_body` + `delivery_states`)
- **Проверяет:** @AR (контракты) + @TL

## Задача (зона @BE, `6-msa/` + `openapi/`)

1. Привести `openapi/*.json` к канону: каждая операция должна нести те же коды ответов, что `04-architecture/api-index.yaml` (`codes`).
2. Причина: контроллеры не объявляют ошибки через `[ProducesResponseType]` → swagger (и `dotnet swagger tofile`) генерирует только `200`.

## Что сделать

1. Добавить `[ProducesResponseType(StatusCodes.Status400BadRequest)]` / `409` / `429` (и прочие по канону) на действия контроллеров, где канон фиксирует эти коды.
2. Перегенерировать `openapi/*.json` (или обновить спек вручную по канону, если генератор офлайн).
3. Порядок (@TL): сначала реестр → потом гейт `check_openapi` начинает сравнивать `codes` (нулевой baseline).

## Критерии приёмки

- [ ] `openapi/client.json` `Client.Register` несёт `200/409/400/429` (не только `200`);
- [ ] остальные операции — `codes` в реестре ⊇ `codes` канона;
- [ ] `check_api_index` `rc=0`; сборки BC зелёные.

### Вердикт @TL 2026-11-10 17:20 — **не принято: критерии 1–2 не выполнены, реестр не перегенерирован**

- Кодовая часть **готова и проверена**: `[ProducesResponseType]` есть во всех 9 сервисах — Catalog **28**, Privacy **24**, Analytics **17**, DailyMetrics **17**, GarminGateway **12**, Portability **12**, AppleHealthGateway **9**, SomaticSeries **5**, Client **4**. `check_api_index` → `rc=0`.
- Но критерии приёмки — про **`openapi/*.json`**, а не про атрибуты: `openapi/client.json` `POST /api/v1/clients` до сих пор несёт **только `200`** (проверил `json.load` → `responses` = `["200"]`). Пункты «`Client.Register` несёт `200/409/400/429`» и «`codes` реестра ⊇ `codes` канона» **не выполнены**.
- Значит задача сейчас в состоянии **«код готов, реестр ждёт @DO»**, а не «на проверке по существу». Возвращаю: после регенерации `openapi/*.json` (@DO) приёмка повторяется **по файлам реестра**, а не по атрибутам — и это единственный способ проверить «второй источник правды».

### Уточнение критерия @TL 2026-11-10 17:52

Критерий «`codes` реестра ⊇ `codes` канона» **в буквальном виде невыполним**: `401` даёт middleware (`[Authorize]`), `400` — `[ApiController]`, их нет в `[ProducesResponseType]`, поэтому и в снимке их не будет. Проверять нужно так:

1. **состав:** `openapi ops == canon public ops` — по замеру @AR: канон **82**, openapi **80**, общих **80**; только в каноне **2** внутренних (`DailyMetrics.InternalSeries`, `Journal.ClientIds`), только в openapi **0**;
2. **коды:** `openapi codes ⊇ attribute codes`; для `Client.Register` это **200/409/400/429** — и все четыре кода у действия **явные** (`StatusCode(429)`, `BadRequest`, `Conflict`), то есть обязаны появиться в снимке;
3. middleware-коды (`401`, `400` от фреймворка) в снимке **не требуются**.
