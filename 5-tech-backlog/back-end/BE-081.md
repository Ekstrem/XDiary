# BE-081: у `Analytics` нет `/health` — единственный сервис, который отвечает 401 на health-проверку

- **Статус:** Закрыта
- **Приоритет:** P1 (ломает **любую** проверку стенда «по сервисам»; в CD/ранбуках аналитика выпадает из здорового контура)
- **Источник:** @DO `2026-11-05 22:36` (три уровня проверки стенда) + проверка @TL по коду `22:4x`
- **Проверяет:** @TL

## Факт

На dev: `analytics /health` → **401** с `WWW-Authenticate: Bearer`, тогда как у остальных **11** сервисов `/health` → **200**.

## Причина (проверено по коду, а не по догадке)

Все сервисы объявляют health явно и **анонимно**, например:

```csharp
// 6-msa/BC-Catalog/src/Catalog.Api/Program.cs:38
app.MapHealthChecks("/health").AllowAnonymous();
```

То же есть в `BC-AppleHealthGateway:47`, `BC-Client:58`, `BC-DailyMetrics:43`, `BC-GarminGateway:47`, `BC-Journal:75`,
`BC-Partners:70`, `BC-Portability:38`, `BC-Privacy:49`, `BC-SomaticSeries:42` и в `ApiGateway/Program.cs:65`.

**В `BC-Analytics` вхождений `MapHealthChecks` — 0.** Значит `/health` не маршрутизируется, запрос попадает в
цепочку авторизации и возвращает `401` — то есть **не «health закрыт», а «health отсутствует»**, и это маскируется под 401.

## Задача

1. Добавить в `6-msa/BC-Analytics/src/Analytics.Api/Program.cs` ту же строку, что у остальных:
   `app.MapHealthChecks("/health").AllowAnonymous();` (при необходимости — `AddHealthChecks()` в DI).
2. Проверить, что `analytics /health` изнутри сети → **200** без токена.

## Критерии приёмки

- `analytics /health` с dev-хоста → **200**, тело — стандартный ответ health-checks;
- остальные 11 сервисов — по-прежнему 200 (**не сломать AllowAnonymous**);
- в `## Результат` — вывод по **всем 12** сервисам (12 × 200), а не только по аналитике.

## Результат

- в `Analytics.Api/Program.cs` добавлены `builder.Services.AddHealthChecks()` (`:29`) и `app.MapHealthChecks("/health").AllowAnonymous()` (`:37`) — как у остальных 11 сервисов;
- сборка `Analytics.sln` зелёная; @TL `23:37` принял код (строки совпадают с эталоном);
- runtime «12 × 200» с dev-хоста — сверка @DO (dev-прогон), вывод дополню после прогона.
