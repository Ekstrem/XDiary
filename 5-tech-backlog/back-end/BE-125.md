# BE-125 — P0: свежий образ `BC-Partners` не стартует — нет регистрации untyped `DbContextOptions` (workaround BE-075)

- **Статус:** ToDo
- **Приоритет:** **P0** — образ из `release` падает на старте, из-за этого `deploy-dev` красный, `deploy-prod` не выполняется, квитанция `FE-054` невозможна
- **Источник:** CI `deploy.yml` `run 44173877420`, джоб `deploy-dev` (`134362295021`), после мержа свежего lock `single-b536455`; найден @TL 2026-11-18 00:0x
- **Зависимости:** нет (правка в `6-msa/BC-Partners`)
- **Проверяет:** @TL
- **Исполняет:** @BE

## Симптом (дословно из лога контейнера)

```
Unhandled exception. Autofac.Core.DependencyResolutionException:
  An exception was thrown while activating DigiTFactory.Libraries.CommandRepository.Postgres.EventStoreDbContext.
  ---> System.InvalidOperationException: The DbContextOptions passed to the EventStoreDbContext constructor
       must be a DbContextOptions<EventStoreDbContext>. When registering multiple DbContexts ...
  at Program.<Main>$(String[] args) in /src/BC-Partners/src/Partners.Api/Program.cs:line 60
```

Следом: `recreate-service: ОШИБКА: xdiary-partners не поднялся`.

## Причина (сверка двух BC, не догадка)

Библиотечный `EventStoreDbContext` имеет конструктор `(DbContextOptions)` — **не** generic. Рабочий обход — зарегистрировать untyped `DbContextOptions` как singleton, ссылающийся на generic (комментарий `BE-075` в коде так и говорит).

| BC | `AddEventStorePostgres` | регистрация `AddSingleton<DbContextOptions>` |
|---|---|---|
**BC-Journal** | да | **ЕСТЬ** (`Program.cs`, строка ~52) |
**BC-Partners** | да | **НЕТ** |

Это **единственные** два сервиса, использующие `AddEventStorePostgres` (проверено `git grep` по `6-msa/**/Program.cs`), поэтому дефект ровно в одном месте.

## Что нужно

В `6-msa/BC-Partners/src/Partners.Api/Program.cs` добавить **ту же** регистрацию, что в `BC-Journal` (после `AddEventStorePostgres`, до первого `GetRequiredService<EventStoreDbContext>` в `line 60`):

```csharp
builder.Services.AddSingleton<Microsoft.EntityFrameworkCore.DbContextOptions>(
    sp => sp.GetRequiredService<Microsoft.EntityFrameworkCore.DbContextOptions<EventStoreDbContext>>());
```

Регистрация должна идти **до** `scope.ServiceProvider.GetRequiredService<EventStoreDbContext>()` (строка 60), иначе контейнер снова соберётся без неё.

## Критерии приёмки

- [ ] образ `BC-Partners`, собранный из текущего `main`, стартует: в логе нет `InvalidOperationException ... must be a DbContextOptions<EventStoreDbContext>`;
- [ ] `deploy-dev` → success (контейнер `xdiary-partners` поднялся);
- [ ] после `release` + lock — `deploy-prod` → success (сторож «образ старше кода» пропускает);
- [ ] `node 9-tests/scripts/probe_catalog_idempotency.js` → `exit=0` (это уже квитанция `FE-054`, снимает @TE).
