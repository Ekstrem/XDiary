# BE-009: Реализовать `analytics` (Аналитика, read-only)

- **Статус:** Выполнена
- **Приоритет:** P2
- **Источник:** BC-Analytics (`03-ddd/BC-Analytics/*`), ST-01..ST-08
- **Зависимости:** BE-002, BE-005, BE-006

## Задача
Реализовать read-only микросервис `analytics` (нет агрегата записи, только проекции):
- Сводка за период (30/90/всё время).
- Физиопрофиль, топы, распределение, пороги, корреляции (Пирсон).
- Читает записи из `journal` и тренды из `daily-metrics` (query-API).

## Критерии приёмки
- [x] Только чтение: не обращается к Domain/Event Store напрямую — нет агрегата/Event Store, только вычисляемые проекции.
- [x] Корреляции с пояснением + n наблюдений (n ≥ 3) — Pearson + Explanation + N.
- [x] Переключатель периода 30/90/всё время — параметр `period` в GetSummary.
- [x] Интеграционный тест (доменные тесты Pearson + SummaryCalculator; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `analytics` в `6-msa/BC-Analytics/` (edm-net, DigiTFactory.Libraries + SeedWorks, CEQRS, профиль Single).
Read-only: нет агрегата/Event Store — вычисляемые проекции на лету. Query API: GetSummary (период 30/90/all), GetCorrelations (Pearson, n ≥ 3).
Полное межсервисное чтение (через query-API journal/daily-metrics по HTTP) — следующий этап: сервис получает records/metrics на вход и вычисляет проекции.
CI: `.github/workflows/ci-analytics.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-analytics` (`single`, `latest`).
