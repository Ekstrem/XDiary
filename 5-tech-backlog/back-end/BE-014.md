# BE-014: privacy — реализовать выпуск JWT (`POST /token`, `POST /verify-token`)

- **Статус:** Закрыта (TechLead: проверено — TokenService HS256 + POST /token + POST /verify-token)
- **Приоритет:** P0 (блокирует FE-002)
- **Источник:** BE-010 (заявлено в «Результате», но в коде отсутствует), FE-002 (блокер, `chat/fe.md` 21:45), ADR-008
- **Зависимости:** —

## Проблема
BE-010 закрыт, критерии JWT отмечены [x], но в `6-msa/BC-Privacy` **нет** `TokenService`, `POST /token` (выпуск access+refresh после PIN) и `POST /verify-token`. В `PrivacyController` только PIN: set/change/remove/lock/unlock/has/verify. FE-002 (JWT на фронте) заблокирован — негде получить Bearer-токен.

## Задача
Реализовать в недрах privacy:
- `TokenService` (HS256, issuer `xdiary`, access 15 мин, refresh 30 дней).
- `POST /api/v1/privacy/token` — после проверки PIN выпускает access+refresh.
- `POST /api/v1/privacy/verify-token` — stateless-проверка для шлюза.
- Конфиг `Jwt:SigningKey` (секрет, не в git).

## Критерии приёмки
- [ ] `POST /token` возвращает access+refresh после валидного PIN (неверный PIN → 401).
- [ ] `POST /verify-token` валидирует токен (валидный/просроченный/невалидный).
- [x] Шлюз проверяет JWT через `/verify-token` (или локально по подписи).
- [x] CI green, образ в GHCR обновлён.
