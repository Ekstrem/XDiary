# BE-016: JWT отклоняется шлюзом — рассинхрон кодировки signing key

- **Статус:** Открыта
- **Приоритет:** P0 (блокирует E2E/релиз)
- **Источник:** E2E (TE-007..009, вариант B на VPS-1, 6/9 fail); `6-msa/ApiGateway/Program.cs`, `6-msa/BC-Privacy/src/Privacy.Application/Security/TokenService.cs`
- **Зависимости:** BE-014

## Проблема
- `TokenService` (privacy) подписывает JWT ключом `Encoding.UTF8.GetBytes(_key)`.
- Шлюз (`ApiGateway/Program.cs`) проверяет `Convert.FromBase64String(config["Jwt:SigningKey"])`.

Для одного и того же `Jwt__SigningKey` это **разные байты** → подпись не сходится → **401** на `/api/v1/journal/**` и `/api/v1/analytics/**` (auth-эндпоинты проходят).

## Задача
Привести к одной кодировке. Ключ генерируется как base64 (`openssl rand -base64 48`, `.env.example`) — значит **обе стороны должны декодировать base64**:
- `TokenService`: `Convert.FromBase64String(_key)` вместо `Encoding.UTF8.GetBytes(_key)`.
- Шлюз — оставить `Convert.FromBase64String`.

## Критерии приёмки
- [ ] privacy и gateway используют одинаковые байты ключа.
- [ ] Валидный токен проходит шлюз (200), просроченный/чужой — 401.
- [ ] E2E auth/journal проходят; CI green.
