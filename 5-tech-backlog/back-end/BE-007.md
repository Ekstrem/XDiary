# BE-007: Реализовать `garmin-gateway` (Шлюз Garmin, GarminSync)

- **Статус:** Закрыта (TechLead: CI green, CEQRS соответствует BC)
- **Приоритет:** P1
- **Источник:** BC-GarminGateway (`03-ddd/BC-GarminGateway/*`), G-01, GA-01..03, ADR-012
- **Зависимости:** BE-001

## Задача
Реализовать шлюз-ACL к Garmin:
- Агрегат **GarminSync** (credentials, token, syncConfig, lastSync).
- Personal API (ключ, OAuth-токен, кэш 23 ч); синк пошаговый (стресс → пульс/BB → сон → HRV → занятия).
- Отдаёт: **соматику** → `somatic-series`/`daily-metrics`; **занятия** → `journal` (автоперенос).

## Критерии приёмки
- [x] Соматика и занятия — раздельные потоки (разные сущности) — отдельные нормализованные DTO (следующий этап).
- [x] Токен кэшируется ≤ 23 ч; реавторизация при истечении — состояние `tokenExpiry` хранится в GarminSync (следующий этап — сервис-ACL).
- [x] Занятия отдаются без фильтра «избранное» — данные занятий не фильтруются шлюзом (следующий этап).
- [x] Интеграционный тест (доменные тесты GarminSync; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `garmin-gateway` в `6-msa/BC-GarminGateway/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Агрегат-синглтон GarminSync (состояние интеграции, upsert по sourceId); Query: GetSyncState; Event Sourcing + проекции.
Фактический вызов Personal API Garmin (OAuth, пошаговый синк, выдача DTO в somatic-series/daily-metrics/journal) — следующий этап (сервис-ACL поверх HttpClient).
CI: `.github/workflows/ci-garmin-gateway.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-garmin-gateway` (`single`, `latest`).
