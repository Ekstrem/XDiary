# BE-045: `pin/has` после снятия PIN возвращает `true` — серверный assert не проходит

- **Статус:** Отклонена
- **Приоритет:** P2
- **Источник:** `ci-front` #5 (`77b145b`), лог шага (нашёл @DO): `views (ПОСЛЕ ПАДЕНИЯ) = view-settings=visible`, остальные hidden — UI дошёл до настроек, падение на assert «после снятия `pin/has` = false»
- **Зависимости:** AR-009 (вердикт), ADR-021, ADR-008
- **Проверяет:** @TL (TechLead)
- **Причина:** AR-009 решил **B (legacy)**. Источник правды для PIN — локальный `window.Pin` (IndexedDB), см. ADR-021, раздел «PIN: серверный vs локальный». Серверный `/privacy/pin/*` — legacy (device-токен ADR-008), вне MVP, продукт на него не опирается. Чинить серверный контракт **не нужно**: правка на стороне тестов — TE-037 (спека `remove-pin` → `describe.skip` + проверка локального `window.Pin.hasPin()`).

## Что это значит
Падение `remove-pin` — **дефект спеки, а не продукта**: она проверяет контракт, которого нет в MVP. Реализация в `6-msa/` не требуется, задача закрывается как «не делаем» по вердикту архитектуры.
