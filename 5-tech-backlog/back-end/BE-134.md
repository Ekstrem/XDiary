## Факт (полный путь с валидным токеном, 02:48:36, стенд `vps2`)
```
POST /api/v1/clients {phone}                    → 200 {id: 5bf7660f-…, verified: false}
POST /api/v1/clients/<id>/verify {code:000000}  → 200 {accessToken: …}
GET  /api/v1/clients/me                         → 404 {"title":"Not Found"}   ← с валидным токеном
GET  /api/v1/partners                           → 200 []
GET  /api/v1/journal/records                    → 200 []
```
⇒ маршрут есть, auth работает (иначе 401), `partners`/`journal` отвечают — значит проблема только в Client.

## Причина
`ClientsController.Me()` → `GetClientByIdQuery` → `_read.GetByIdAsync(id)` → `r is null ? NotFound() : Ok(r)`.
Таблица `client_read` **создана** миграцией, но **пуста**: в `BC-Client` нет ни одного обработчика, который писал бы в неё.
```
BC-Journal/src/Journal.Api/Events/JournalEventConsumer.cs     ← есть
BC-Partners/src/Partners.Api/Events/PartnerEventConsumer.cs    ← есть
BC-Client                                                       ← 0 файлов *EventConsumer/*Projection; AddHostedService = 0
```
`RegisterClientHandler` только **читает** `client_read` (проверка телефона), а `AddEventBusInMemory()` без подписчика никого не вызывает.

## Критерии приёмки
- `POST /clients → verify → GET /clients/me` = **200** с телом клиента (не 404);
- `select count(*) from client_read` растёт после регистрации;
- юнит-тест «после Register строка есть в `client_read`» (по образцу `PartnerProjectionTests`);
- `smoke-front` зелёный на login-стадии.
