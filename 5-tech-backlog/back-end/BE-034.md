# BE-034: `pin/remove` без `currentPin` удаляет PIN вместо 401

- **Статус:** Открыта
- **Приоритет:** P1 (защита PIN — обход подтверждения)
- **Источник:** CI `front-e2e` на `1c4219e` (аннотация спека `remove-pin`), прогон @TE 2026-11-05
- **Зависимости:** —

## Проблема
Спек `remove-pin`, шаг «негатив: `pin/remove` без `currentPin` → 401»:
- ожидалось: `401` и **PIN остаётся** на месте;
- фактически: `Error: PIN на месте после неудачного снятия — Expected: true, Received: false`

То есть запрос `POST/PUT /privacy/pin/remove` **без `currentPin`** не вернул `401`, а **снял PIN**. Это обход подтверждения: любой, кто получил device-токен, может снять PIN без знания текущего.

## Задача
- В BC-Privacy эндпоинте снятия PIN требовать `currentPin`; без него — `401`/`400` и **не менять состояние**.
- Проверить, что при неверном `currentPin` PIN тоже не снимается.
- Тест в `9-tests`: негативный кейс (без `currentPin`, с неверным `currentPin`).

## Критерии приёмки
- [ ] `pin/remove` без `currentPin` → `401`, PIN не снят.
- [ ] `pin/remove` с неверным `currentPin` → `401`, PIN не снят.
- [ ] Спек `remove-pin` зелёный.
