# BE-032: Garmin per-client — GarminSync(clientId, sourceId) + SingleSourcePerClient

- **Статус:** Закрыта
- **Приоритет:** P1 (блокер Фазы 3 / TE-026)
- **Источник:** @AR 2026-11-04 13:40 (пробел от PO); ADR-021 (multi-user)
- **Зависимости:** —

## Проблема
`GarminGateway` моделирует Garmin как **один глобальный источник** (`sourceId = "garmin"`). По ADR-021 система многопользовательская: **у каждого клиента свой Garmin-токен и свои данные**. Сейчас клиенты перетирают/видят чужие соматические данные.

## Задача
- `GarminSync`: идентичность = **`clientId`** (чей Garmin) + `sourceId`.
- Инвариант `SingleSourcePerClient` — у клиента один активный Garmin-источник.
- `clientId` брать из **JWT** (клиентский), не из глобального состояния.
- Проверить **Apple Health** на ту же модель (per-client), отписать в чат.
- Согласовать контракт с @AR (`03-ddd/`), чтобы read-model/агрегаты не смешивали клиентов.

## Критерии приёмки
- [x] Два клиента синкают Garmin независимо; данные не смешиваются.
- [x] `SingleSourcePerClient` enforced.
- [x] Apple Health проверен (per-client или явно зафиксировано исключение).
- [ ] CI зелёный.

## Результат
Garmin (e65812) + Apple Health (95c3168) per-client: clientId из JWT (sub), репозиторий по (clientId, sourceId), unique-индекс (ClientId, SourceId) + именованный SingleSourcePerClientValidator в Connect/Configure (db8d7fa). Миграции AddClientIdToGarmin/AddClientIdToApple.

## Уточнение (TL, 2026-11-05 20:30) — приёмка требует runtime-проверки
Моё «проверено по коду» относилось к наличию CurrentClientId()/SingleSourcePerClientValidator, но **не** к тому, что sub реально приходит: в сервисах нет JWT-middleware (см. **BE-038**), поэтому clientId был Guid.Empty и per-client не работал в рантайме. Задача остаётся закрытой (код на месте), но фактическое разделение данных по клиентам нужно подтвердить после BE-038 на dev (два клиента — свои точки).
