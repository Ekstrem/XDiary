# BE-071 — бэкфилл read-моделей: `partners_read`/`journal_read` пусты для существующих данных

- **Статус:** ToDo
- **Приоритет:** P1 (проверка «`200`» пройдёт на **пустом** списке — зелёный тест при пустом экране)
- **Источник:** @TE `2026-11-05 08:21` (риск приёмки) + @TL `08:22`: `partners_read` заполняется **только** проекцией событий, бэкфилла в репозитории нет
- **Зависимости:** `BE-069`, `BE-068` (маппинг + DDL + `partners_read`)
- **Проверяет:** @AR

## Задача

`Partners.Api/Events/PartnerEventConsumer.cs` пишет `PartnersReadModel` **только когда приходит событие**
(`IReadModelStore<IPartners, PartnersReadModel>`, `Project(IDomainEvent<…>)`). Значит после выкатки
`partners_read` пуст: партнёры, созданные **до** появления read-таблицы, в проекцию не попадут.

Следствие: `GET /api/v1/partners` вернёт **200 с пустым списком**, и формальная приёмка «200» пройдёт,
хотя данные существуют. Это тот же класс, что «зелёный `grep → 0`» и «`restarts = 0`»: **зелёное
утверждение при пустом результате**.

## Критерии приёмки

- есть **бэкфилл** read-моделей из источника истины (`partners` → `partners_read`,
  `records` → `journal_read`/`journal_defaults`): одноразовая команда или шаг старта, **идемпотентный**;
- критерий приёмки уточнён: `GET /api/v1/partners` изнутри → **200 И непустой список**, если в
  `partners` есть строки (число совпадает с `SELECT count(*)`);
- то же для `journal`: `GET /internal/journal/records` → **200 И** количество записей равно `records`;
- бэкфилл покрыт проверкой: «до бэкфилла — 0, после — N», и это записано в `## Результат`;
- если решено не делать бэкфилл (проекция только вперёд) — это **явное решение** с записью в ADR/ранбуке
  и с критерием «пустой список допустим для исторических данных», а не молчаливая дыра.
