# BE-004: Реализовать `catalog` (Каталог, агрегат CatalogItem)

- **Статус:** Выполнена (классический CEQRS, CI green, образ ghcr.io/ekstrem/xdiary-catalog)
- **Приоритет:** P1
- **Источник:** BC-Catalog (`03-ddd/BC-Catalog/*`), US Инк 4/5/8/9
- **Зависимости:** BE-001

## ✅ Переделано (классический CEQRS, без AbstractAggregate)
Архитектор: metadata-driven (AbstractAggregate) — неверный подход. Переделать на классический CEQRS по эталону 6-msa/BC-Journal (явные immutable VO + AnemicModel + Aggregate c BusinessOperationData + валидаторы + EF Core state-персистенс, без AbstractAggregate).

## Задача
Реализовать микросервис `catalog`:
- Агрегат **CatalogItem** (kind: costume/toy/fantasy/contraception; name, notes, photo, brand, archived, partner).
- Command API: CRUD элемента; архив игрушек.
- Query API: список по `kind`, деталь.

## Критерии приёмки
- [x] CRUD по всем `kind` (костюм/игрушка/фантазия/контрацепция) — валидация `kind` в handler'е.
- [x] Архив игрушек (archived) — поле в draft, меняется через UpdateItem.
- [x] Интеграционный тест Command → Query → Assert (доменные тесты CatalogItem; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `catalog` в `6-msa/BC-Catalog/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Command API: Create/Update/Delete Item; Query API: GetCatalogItemById/ListCatalogItems (Read Store); Event Sourcing + проекции.
CI: `.github/workflows/ci-catalog.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-catalog` (`single`, `latest`).
