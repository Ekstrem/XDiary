# BE-083: аналитика считает по ВСЕМ клиентам и отдаёт это любому пользователю (утечка между клиентами)

- **Статус:** Закрыта
- **Закрыта:** 2026-11-11 (@TL апрув — владелец 2026-11-06: апрув ревьюера = авто-закрытие)
- **В работе с:** 2026-11-06
- **Приоритет:** **P0 — приватность** (агрегаты по чужим записям видны пользователю; для дневника это недопустимо)
- **Источник:** проверка @TL по коду `2026-11-06 00:0x`
- **Проверяет:** @TL + @AR (архитектурная часть)

## Факты (по коду)

### 1. Данные собираются БЕЗ фильтра по клиенту

`AnalyticsPrecomputeService` (`Analytics.Api/Precompute/AnalyticsPrecomputeService.cs:29`):

```csharp
var records = await client.GetFromJsonAsync<List<JournalRecord>>($"{_journalUrl}/internal/journal/records", ct) ?? new();
```

Этот эндпоинт — `InternalJournalController` → `IJournalQueryRepository.ListAllAsync(...)` — отдаёт **все** записи
(`JournalReadRepository.cs:62-71`, `_read.GetAllAsync(new Paging(1, int.MaxValue))`), без `clientId`.

### 2. В модели нет клиента вообще

`JournalRecord` (`Precompute/JournalRecord.cs`) **не содержит** `ClientId`; `AnalyticsSnapshot` — единый глобальный снимок
(`AddSingleton<AnalyticsSnapshot>()`, `Program.cs:27`).

### 3. Ответ отдаётся без авторизации и без привязки к пользователю

`AnalyticsController` (`:7-41`): **нет** `[Authorize]`, все ручки возвращают `_snapshot` целиком:

```csharp
[HttpGet("summary")]      => Ok(_snapshot.GetSummary(period));
[HttpGet("correlations")] => Ok(_snapshot.Correlations);
[HttpGet("tops")] / ("distribution") / ("thresholds") / ("trends") / ("physio") — так же
[HttpPost("events")]      => принимает любые события и меняет снимок
```

Снаружи путь прикрыт APIM (401 без JWT — измерено), но **сервис не различает пользователей**: один и тот же
глобальный снимок получает любой аутентифицированный клиент.

## Почему это P0

Дневник интимных записей: даже агрегаты («топ позиций», «распределение», «корреляции») по **чужим** записям — это
раскрытие. И одновременно это **неверные числа** для каждого отдельного пользователя.

## Задача

1. **Разделить снимок по клиенту:** ключ — `sub` (clientId); предрасчёт строить на записях **только этого клиента**.
2. Для этого `internal/journal/records` должен принимать `clientId` (новый параметр) **или** аналитика должна брать данные
   из своего источника с фильтром; в `JournalRecord` добавить `ClientId`.
3. **`[Authorize]` на `AnalyticsController`** + брать `sub` из токена (как в `PartnersController.Register/List`).
4. `POST /api/v1/analytics/events` — закрыть авторизацией и **не** позволять менять чужой снимок.
5. `internal/journal/records` — не должен быть анонимным (defense-in-depth, ADR-008).

## Критерии приёмки

- два клиента с разными записями получают **разные** `summary`/`tops`/`trends`; числа соответствуют **только** своим записям;
- `GET /api/v1/analytics/summary` **без** токена → **401** с самого сервиса (не только от APIM);
- тест: клиент A не видит ни одного значения, выведенного из записей клиента B (unit или ApiTests);
- `(ii-c)` по `/internal/**` снаружи остаётся 401/403/404.

### Вердикт @TL 2026-11-10 19:25 — **принято по артефакту, с проверкой изоляции**

- Проверил в `origin`: `[Authorize]` на `AnalyticsController` — **есть**; разделение по клиенту — `AnalyticsSnapshot` (`Precompute/AnalyticsSnapshot.cs`) содержит `Dictionary<Guid, …>` (per-client снапшоты) — **есть**.
- Смысл правки — утечка между клиентами (аналитика считалась по ВСЕМ и отдавалась любому). Теперь все GET и `POST events` берут `ClientId` из токена. Это тот же класс, что PII-инцидент: данные одного видны другому.
- Остаток для гейта: «аналитика без `ClientId` в запросе» должна краснеть — сейчас это держится кодом, но не проверкой; предложение в `AWAIT` уже есть (`attrs ⊆ codes` и `ClientId` в каноне).

## Результат

- `AnalyticsSnapshot` разделён по клиенту (`Dictionary<Guid, ClientSnapshot>`), все GET/`POST events` берут `clientId` из `sub`; `AnalyticsPrecomputeService` группирует записи по `ClientId` (null — никому);
- `[Authorize]` на `AnalyticsController` + `JournalRecord.ClientId`;
- `internal/journal/records` → `[Authorize]` (ADR-008) + precompute ходит с подписанным сервис-токеном (`sub=analytics`);
- тест изоляции `Snapshot_PerClient_DoesNotLeakAcrossClients` (клиент A видит только свои записи);
- сборка Analytics зелёная; runtime «два клиента → разные числа» — @DO.
