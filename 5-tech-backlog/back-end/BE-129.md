## Где искать (по коду `main` = `e5b19964c`)

`6-msa/BC-Journal/src/Journal.Api/Controllers/JournalController.cs`:

```
32-40| EnsureOwns:  _mediator.Send(new GetRecordByIdQuery(id)); если null — fallback на _anemic.GetById
42-47| WithOwner:   TryClientId -> EnsureOwns -> guard ?? await action()
61-66| SpecifyWhen / AddPartner: WithOwner(id, () => Respond(await _mediator.Send(c with { AggregateId = id })))
118-125| Get:        тот же GetRecordByIdQuery, но БЕЗ WithOwner
```

**Что уже доказано этим воспроизведением:**
1. `GetRecordByIdQuery` **работает** — `GET /records/{id}` (строка 122, тот же запрос) отвечает **200** ⇒ `EnsureOwns` проходит, владелец совпадает, дело **не** в guard'е и не в read-модели списка;
2. `POST /records` (создание) тоже **200** ⇒ маршрут, `[Authorize]`, `sub` из токена — в порядке;
3. ⇒ падает **внутри обработчика команды** после guard'а: `AddPartnerHandler.Handle` (`Journal.Application/Commands/JournalHandlers.cs:63-69`) — первым делом `_provider.GetAggregateAsync(r.AggregateId, ct)`, т.е. **реконструкция агрегата из event store**.

**Наиболее вероятные причины (проверить в этом порядке):**
- десериализация `ChangedValueObjectsJson` при реконструкции (в Partners для этого добавлен `IValueObjectJsonConverter` — `PartnerEventConsumer.cs:58-61`; в Journal такого может не быть);
- `IAnemicModelRepository`/`IEventStoreRepository` бросает исключение на записи без полного набора VO;
- `IObserver`-подписка (строка 67) кидает при первом `Observe`.

**Как читать ответ:** 500 приходит **с пустым телом** — это не `Respond(...)` (он даёт `400` с текстом) и не guard (даёт `404`/`401`), значит необработанное исключение.

## Критерии приёмки

1. `POST /journal/records/{id}/when {startedAt}` → **200**, `startedAt` в `GET /records/{id}` меняется;
2. `POST /journal/records/{id}/partners {partnerId}` → **200**, в `GET /records` у записи `partners` содержит id;
3. `smoke-api` шаг «Контракт журнала (Journal.ApiTests → PartnerSoftDelete)» — **зелёный**;
4. ни один из маршрутов `POST /journal/records/{id}/*` не отвечает `5xx` на валидном теле владельца.

- **не** `partners_read`/`partners_directory` (это отдельный дефект `BE-128`; здесь запись журнала создаётся и читается);
- **не** `lock`/выкатка: `deploy-dev` подтверждённо выкатил `partners`/`journal` из `single-378a56c` (лог `deploy-dev` 09:36:41: `partners single-378a56c`);
- **не** фронт: `8-front/js/api.js` шлёт `{startedAt}` в `/when` и `{clientId}` в `link-client` — по канону (проверено @TL 12:05).
