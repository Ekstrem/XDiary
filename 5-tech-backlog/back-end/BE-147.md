# BE-147 — P0: после `POST /catalog/{id}/remove` read-модель продолжает отдавать позицию

- **Статус:** На проверке
- **Приоритет:** P0 (повторяемый prod-E2E `catalog-archive`: после удаления GET обязан не отдавать запись)
- **Источник:** @TL 2026-11-23 17:10, два независимых прогона `45186835537`
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @BE (`6-msa/BC-Catalog`)
- **В работе с:** 2026-11-23
- **На проверке с:** 2026-11-23
- **Артефакт:** PR #3300, ветка `role/be-catalog-remove`, коммит `3bb296ca4`

## Корень

`Catalog.Domain/Implementation/Aggregate.cs`: `Remove() => Success(Clone())` — no-op, модель не меняется.
`CatalogEventHandler` только `UpsertAsync`, поэтому `catalog_read` сохраняет запись с `Archived=false`.

## Задача

1. Добавить `DeletedAt` в доменную модель и read-модель; `Remove()` выставляет его идемпотентно.
2. Проекция при `DeletedAt` удаляет строку через `IReadModelStore.DeleteAsync`.
3. `ListCatalogItemsQuery` и `GetCatalogItemByIdQuery` фильтруют `DeletedAt is null`.
4. Миграция `AddDeletedAtToCatalogRead` + регрессионные тесты.

## Критерии приёмки

- [ ] После Remove событие содержит `DeletedAt`; повторный Remove не меняет дату;
- [ ] Проекция удаляет строку из `catalog_read`;
- [ ] GET по id и список не возвращают удалённую позицию;
- [ ] Сборка Catalog и IntegrationTests зелёные; PR открыт.

## Результат

Исправлено в PR #3300 (`3bb296ca4`):

- `Aggregate.Remove()` больше не no-op: выставляет `DeletedAt` идемпотентно; повторный Remove не меняет дату.
- Проекция при `DeletedAt` вызывает `IReadModelStore.DeleteAsync` вместо Upsert.
- `ListCatalogItemsQuery` и `GetCatalogItemByIdQuery` фильтруют `DeletedAt is null` — удалённая позиция не возвращается ни по id, ни в списке.
- Добавлена миграция `AddDeletedAtToCatalogRead` (nullable `timestamp with time zone`).
- Добавлены 4 регрессионных теста: `DeletedAt` в событии, идемпотентность, `DeleteAsync` проекции, фильтрация read-запросов.
- Сборка Catalog.Api и IntegrationTests Release — 0 ошибок.
