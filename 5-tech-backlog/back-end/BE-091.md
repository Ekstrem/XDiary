## Два дефекта

1. **Precompute, вероятно, падает на первой же итерации:** запрос к `/api/v1/daily-metrics/series` идёт с **сервисным** токеном
   (`CreateServiceToken()`), у которого нет `sub` клиента ⇒ `ClientId()` = `null` ⇒ **401**. `GetFromJsonAsync` на 401 **бросает
   исключение** (не возвращает `null`), а внешний `try/catch` в цикле только логирует `Analytics precompute failed` ⇒
   **снимки не пересобираются вообще**. Проверить на dev: лог `Analytics precompute failed` каждые 2 минуты или пустые снимки.
2. **Если бы ответ приходил — он был бы общим для всех:** `metricInputs` — один список на всех, и `Rebuild(group.Key, …, metricInputs)`
   передаёт его каждому клиенту. `AnalyticsSnapshot.cs:50` — `_metrics = metrics.ToList()` без фильтра по `clientId`.

Плюс замечание @AR (`12:20`, отдельно):

3. **`/internal/journal/records` без арендатора** — внутренний эндпоинт отдаёт записи **всех** клиентов; по канону Analytics — отдельный BC
   и его источник — **события** Journal, а не внутренний HTTP-эндпоинт. Для MVP допустима временная форма, но она **обязана** принимать
   `clientId` и отдавать только его строки.

## Что сделать

1. **Минимум (чтобы аналитика вообще работала):** дать Analytics способ получать метрики per-client — либо `series?clientId=…`
   для сервисных вызовов (с проверкой «сервисный токен ⇒ можно указать любого клиента»), либо событийная проекция.
2. **Обязательно:** фильтровать метрики по `clientId` **до** `Rebuild` (или передавать в `MetricInput` поле `ClientId` и фильтровать
   в `ClientSnapshot.Rebuild`), чтобы «общий список» никогда не попадал в снимок клиента.
3. **`/internal/journal/records`** — добавить обязательный `clientId` (и в Analytics передавать `group.Key`, а не тянуть всех).
4. Тест: два клиента с разными метриками ⇒ `GET /api/v1/analytics/summary` для A не меняется от данных B; и тест
   «precompute не логирует `failed` на чистом стенде».

## Критерии приёмки

- на dev в логах Analytics **нет** `Analytics precompute failed` при штатной работе;
- снимок клиента A строится **только** из записей и метрик A (тест);
- `/internal/journal/records` без `clientId` → **400/401**, а не «все записи»;
- `## Результат` — прогон с числами (сколько снимков пересобрано, за какой период).

## Результат

- Analytics precompute per-client: `internal/journal/client-ids` → `records?clientId=X` → `internal/daily-metrics/series?clientId=X` → `Rebuild(cid, records, metricInputs)` — «общий список» метрик не попадает в снимок;
- новый внутренний эндпоинт `internal/daily-metrics/series` (сервис-токен `sub=analytics` + обязательный `clientId`); Analytics **не ходит** в клиентские `/api/v1/*`;
- не-2xx → `LogWarning` (не `new()` молча);
- `internal/journal/records` — обязательный `clientId` (без → 400), добавлен `internal/journal/client-ids` (`GetClientIdsAsync`);
- Journal + DailyMetrics + Analytics собираются (`Ошибок: 0`); «нет `precompute failed`» и числа — @DO на dev.
