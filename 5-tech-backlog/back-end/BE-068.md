# BE-068 — `ListAll` 500: read-модель не сконфигурирована в `AddReadStorePostgres`

- **Статус:** ToDo
- **Приоритет:** P1
- **Источник:** `(ii-b)` замер `REF=c48a18be` + триаж @DO `03:39` (`REF=b14aff18`)
- **Зависимости:** `BE-067` (закрыт), `BE-066` (двойная регистрация `ReadDbContext`, закрыт)
- **Проверяет:** @AR

## Задача

`GET /internal/journal/records` (`Journal.ListAll`) стабильно отдаёт **500**:

```
InvalidOperationException: Cannot create a DbSet for 'JournalReadModel'
because this type is not included in the model for the context
  → PostgresReadRepository<...>.GetAllAsync(IPaging, CancellationToken)
```

Причина: `Journal.Api/Program.cs:41-43` вызывает
`AddReadStorePostgres<IJournal, JournalReadModel, ReadDbContext>(cs, null)` — **третий аргумент `null`**,
то есть **конфигуратор модели не передан**, и тип `JournalReadModel` не попадает в EF-модель.
Библиотечный `PostgresReadRepository.GetAllAsync` делает `Set<JournalReadModel>()` и падает.

**Дефект старше сегодняшних правок:** до моста ручка падала на `NullReferenceException` (`Paging`),
после — на отсутствующей модели. То есть `ListAll` не работал и раньше; сегодняшние фиксы
(`BE-067`, `BE-066`) открыли следующую причину, а не создали её.

## Критерии приёмки

- `GET /internal/journal/records` изнутри контура → **200** (сейчас `500`);
- `Cannot create a DbSet` = 0 в логе, `restarts` не растёт 30 с, `/health` = 200;
- в квитанции `(ii-b)` операция `Journal.ListAll` даёт измеримый ответ (`401`/`200`), а не `500`;
- критерий «остальные 9 сервисов не тронуты»: `git diff --name-only` не содержит
  `AppleHealth`, `Catalog`, `Client`, `DailyMetrics`, `Garmin`, `Portability`, `Privacy`, `SomaticSeries`.
