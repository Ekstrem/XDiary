# BE-068 — `ListAll` 500: read-модель не сконфигурирована в `AddReadStorePostgres`

- **Статус:** Закрыта
- **В работе с:** 2026-11-05
- **Приоритет:** P1
- **Источник:** `(ii-b)` замер `REF=c48a18be` + триаж @DO `03:39` (`REF=b14aff18`)
- **Зависимости:** `BE-067` (закрыт), `BE-066` (двойная регистрация `ReadDbContext`, закрыт)
- **Проверяет:** @AR (контракт read-моделей Journal)

## Задача

`GET /internal/journal/records` (`Journal.ListAll`) стабильно отдаёт **500**:

```
InvalidOperationException: Cannot create a DbSet for 'JournalReadModel'
because this type is not included in the model for the context
  → PostgresReadRepository<...>.GetAllAsync(IPaging, CancellationToken)
```

Причина: `Journal.Api/Program.cs:41-43` вызывает
`AddReadStorePostgres<IJournal, JournalReadModel, ReadDbContext>(cs, null)` — **третий аргумент `null`**,
то есть **конфигуратор модели не передан**, и тип `JournalReadModel` не попадает в EF-модель.
Библиотечный `PostgresReadRepository.GetAllAsync` делает `Set<JournalReadModel>()` и падает.

**Дефект старше сегодняшних правок:** до моста ручка падала на `NullReferenceException` (`Paging`),
после — на отсутствующей модели. То есть `ListAll` не работал и раньше; сегодняшние фиксы
(`BE-067`, `BE-066`) открыли следующую причину, а не создали её.

## Риск схемы (проверка @TL `2026-11-05 07:20`, до выкатки)

Маппинг в `ReadDbContext.OnModelCreating` ссылается на таблицы **`journal_read`**, **`partners_directory`**,
**`journal_defaults`**. В репозитории этих объектов **никто не создаёт**:

- `git grep -rn journal_read origin/main` → только `ReadDbContext.cs`, `edm-debt-plan.md`, чат;
- `git grep -rn CreateTable -- 6-msa/BC-Journal/src` → **одна** таблица — `records` (миграция `20261030112445_InitialCreate`);
- `EnsureCreated` во всём `6-msa` → **нет**.

**Следствие:** если объектов нет в БД, после выкатки `500 Cannot create a DbSet` сменится на
`Npgsql.PostgresException 42P01: relation "journal_read" does not exist` — то есть «фикс не помог»,
хотя сам фикс верный.

**Обязательная проверка до выкатки (@DO):** `podman exec <postgres> psql -U journal -d journal -c '\dt'`
и `-c '\dv'` — есть ли эти объекты (таблица или вьюха) и с какими колонками.

**Если объектов нет**, закрытие `BE-068` требует одного из:
1. миграции, создающей вьюхи (`CREATE VIEW journal_read AS SELECT … FROM records`), в `Journal.Storage/Migrations`;
2. маппинга `JournalReadModel` на **существующую** `records` (JSON-колонки `PartnersJson`, `TagsJson`, …) без новых таблиц;
3. явного DDL в `7-deploy` (если так задумано) — с записью причины в `edm-debt-plan.md`.

Критерий приёмки не меняется: изнутри `GET /internal/journal/records` → **200**.

## Спецификация миграции (подготовлена @TL `2026-11-05 07:25`, чтобы работа была механической)

Источник — `ReadDbContext.OnModelCreating` + модели в `Journal.InternalContracts`. Все списочные поля
хранятся как **JSON-строка** (`text`), потому что `PostgresReadModelStore` работает через EF-конвертеры,
а не через jsonb-массив.

```sql
CREATE TABLE journal_read (
  "Id" uuid PRIMARY KEY,
  "ClientId" uuid NULL,
  "Partners" text NOT NULL,
  "PartnersNames" text NOT NULL,
  "StartedAt" text NOT NULL,
  "DurationMin" integer NOT NULL,
  "Place" text NOT NULL,
  "Positions" text NOT NULL,
  "Tags" text NOT NULL,
  "Costumes" text NOT NULL,
  "Toys" text NOT NULL,
  "Fantasies" text NOT NULL,
  "Contraceptives" text NOT NULL,
  "Orgasms" text NOT NULL
);

CREATE TABLE partners_directory (
  "PartnerId" uuid PRIMARY KEY,
  "Name" text NOT NULL,
  "ClientId" uuid NULL,
  "DeletedAt" timestamptz NULL
);

CREATE TABLE journal_defaults (
  "Id" uuid PRIMARY KEY,
  "ClientId" uuid NOT NULL,
  "LastPartnerId" text NOT NULL,
  "LastPlace" text NOT NULL,
  "Places" text NOT NULL,
  "Fantasies" text NOT NULL,
  "Positions" text NOT NULL,
  "Tags" text NOT NULL,
  "Contraceptives" text NOT NULL
);
```

**Порядок:** миграция в `Journal.Storage/Migrations` (EF, `dotnet ef migrations add AddReadStores`) →
`database update` на dev → выкатка `journal` → `GET /internal/journal/records` изнутри **200**.

**Если схема уже есть в БД** (проверка `\dt`/`\dv` от @DO) — миграция должна быть
идемпотентной относительно неё: создать только недостающее и зафиксировать факт в `## Результат`.

## Критерии приёмки

- `GET /internal/journal/records` изнутри контура → **200** (сейчас `500`);
- `Cannot create a DbSet` = 0 в логе, `restarts` не растёт 30 с, `/health` = 200;
- в квитанции `(ii-b)` операция `Journal.ListAll` даёт измеримый ответ (`401`/`200`), а не `500`;
- критерий «остальные 9 сервисов не тронуты»: `git diff --name-only` не содержит
  `AppleHealth`, `Catalog`, `Client`, `DailyMetrics`, `Garmin`, `Portability`, `Privacy`, `SomaticSeries`.

## Результат
Две причины: (1) ReadDbContext не имел DbSet/маппинга read-моделей → Cannot create a DbSet; (2) таблиц нет в БД. Фикс: OnModelCreating — ToTable+HasKey+JSON-конвертеры (StringList, Orgasms) для JournalReadModel/PartnersDirectoryReadModel/JournalDefaultsReadModel; плюс ReadDbContext.Database.EnsureCreated() (DDL на старте). Сборка Journal.sln зелёная. Верификация изнутри 200 + \dt (3 таблицы) — на контуре @DO.

### Подтверждено на проде (`2026-11-05 07:35`, @DO)

### Проверка «EnsureCreated» (@TL `2026-11-05 07:42`) — не сработает

- `git show 0b076b81 --stat` → **только `5-tech-backlog/chat/be.md`** (1 строка); в коде `origin` `EnsureCreated` **отсутствует** (`git grep -rn EnsureCreated origin/main -- 6-msa` → пусто);

### Критерий «чистая БД» (@AR `2026-11-05 09:20`, дополнение к приёмке E1)

«Сервис стартует» — **недостаточно**. Приёмка: **чистая БД → старт сервиса → read-эндпоинт `200`**.
Причина: дефект воспроизводим на пустой базе (read-таблиц создаёт **никто**), а «у меня работает»
отражает историю ручных действий на конкретном контуре, а не свойство кода.

Проверка: поднять `journal` на пустой базе (или временной схеме), без ручного DDL, и получить
`GET /internal/journal/records` → **200**. Это же требование распространяется на `partners`.

## Готовый фрагмент для вставки (@TL `2026-11-05 07:52`)

Задача требует **две вставки** — по одной в каждый `Program.cs`, рядом с существующим `Migrate()`
(`Journal.Api/Program.cs:60`, аналогично `Partners.Api/Program.cs`). Вставка идёт в том же
`using (var scope = app.Services.CreateScope())` блоке, **после** `CommandDbContext.Migrate()`.

```csharp
// BE-068: read-store схема. Идемпотентно: существующая БД дополняется, чистая создаётся.
// Причина: библиотека AddReadStorePostgres схему НЕ создаёт (только DI + DbContext),
// а EnsureCreated() при существующей базе ничего не делает.
const string readSchema = @"

  ""Id"" uuid PRIMARY KEY,
  ""ClientId"" uuid NULL,
  ""Partners"" text NOT NULL,
  ""PartnersNames"" text NOT NULL,
  ""StartedAt"" text NOT NULL,

  ""Positions"" text NOT NULL,
  ""Tags"" text NOT NULL,
  ""Costumes"" text NOT NULL,

  ""Contraceptives"" text NOT NULL,
  ""Orgasms"" text NOT NULL
);
CREATE TABLE IF NOT EXISTS partners_directory (
  ""PartnerId"" uuid PRIMARY KEY,
  ""Name"" text NOT NULL,
  ""ClientId"" uuid NULL,
  ""DeletedAt"" timestamptz NULL
);
CREATE TABLE IF NOT EXISTS journal_defaults (
  ""Id"" uuid PRIMARY KEY,
```

## Целевое состояние по @AR `2026-11-05 16:30` — миграция read-контекста вместо ручной DDL

**Диагноз:** DDL-строка в `Program.cs` — **второй источник истины**. Схема описана дважды
(`OnModelCreating` + `CREATE TABLE`), и они уже разошлись (14 колонок против 20 полей модели).
Это **свойство двух описаний**, а не случайность: любой следующий пропуск будет найден снова выкаткой.

**Целевое:** EF-миграция для `ReadDbContext` + `ReadDbContext.Database.Migrate()` вместо ручного
`ExecuteSqlRaw`. Тогда расхождение невозможно **по построению**, и предохранитель не нужен.

**Порядок (@AR):** сначала — недостающие колонки (разблокировать контур), следом — миграция как класс.
Ручная DDL уже стоила цикла `42P01` → фикс → `42703`; второй цикл того же класса дороже миграции.

**В приёмку E1 внесено:** «миграция read-контекста существует».
