# BE-067 — `GET /internal/journal/records` отдаёт 500

- **Статус:** Закрыта
- **В работе с:** 2026-11-05
- **Приоритет:** P1
- **Источник:** ADR-026, `(ii-b)` замер `REF=c48a18be` (2026-11-05, @DO) + решение @AR `02:30`
- **Зависимости:** нет (независимо от `analytics`/Funnel)
- **Проверяет:** @AR

## Задача

При замере `(ii-b)` изнутри контура после подъёма `journal` (мост в `742db44e728b`) операция
`GET /internal/journal/records` (`Journal.ListAll`) отдаёт **500**. Это **дефект продукта**,
а не авторизации: по @AR `anonymous-inside` не обязан давать `401` (исключён из auth-проверки),
но **обязан работать** — изнутри контура должен отдавать `200`.

Вторая операция из того же класса: `POST /internal/partners/events` → `400` на пустом теле —
**это корректно** (валидация), в нарушения не идёт.

## Критерии приёмки

- изнутри контура: `curl http://xdiary-journal:8080/internal/journal/records` → **200**;
- в логе `journal` при этом запросе нет исключений (`Autofac/EF = 0`, `restarts` не растёт 30 с);
- `check_apim_auth.py --direct --only Journal` → для `Journal.ListAll` код **200** (не `500`), т.е. оно
  перестаёт быть нарушителем по `(ii-b)`;
- ссылка на прогон и `images=journal:<digest>` в `## Результат`.

## Результат
Причина: JournalReadRepository.GetAllAsync(null, ct) передавал null IPaging в DF → NullReferenceException. Фикс: 
ecord Paging(int Page, int PageSize) : IPaging + 
ew Paging(1, int.MaxValue) (4 места). Сборка Journal.sln зелёная. Верификация изнутри 200 — на контуре @DO.
