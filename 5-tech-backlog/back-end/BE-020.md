# BE-020: P0 — обход авторизации: `pin/set` и `pin/remove` без проверки

- **Статус:** На проверке
- **Приоритет:** P0 (приватность: кто знает URL — перезапишет PIN, получит JWT и читает/пишет весь дневник)
- **Источник:** @TE `chat/te.md` 12:30 (найдено при разборе живого E2E)
- **Зависимости:** BE-014, BE-019

## Проблема (по коду)
- `6-msa/ApiGateway/Program.cs`: `/api/v1/privacy/*` **освобождён от JWT** (`path.StartsWith("/api/v1/privacy/")`).
- `6-msa/BC-Privacy`:
  - `SetPinHandler` — перезаписывает PIN **без проверки текущего** (`GetBySourceIdAsync("pin") ?? new AnemicModel()` → `SetPin(newHash)`);
  - `RemovePinHandler` — удаляет PIN **без проверки**.
- **Атака:** `POST /api/v1/privacy/pin/set {"pin":"0000"}` → `POST /api/v1/privacy/token {"pin":"0000"}` → валидный JWT → полный доступ (партнёры, записи, каталог).

## Задача
1. `pin/set` при **существующем** PIN — только с JWT **или** с проверкой текущего PIN; первый запуск (PIN нет) — можно без.
2. `pin/remove` — только с JWT/текущим PIN.
3. `/privacy/token` — единственный, что реально должен быть анонимным.
4. `/privacy/verify-token`, `/privacy/pin/has` — оставить анонимными (нужны для логина).

## Критерии приёмки
- [x] `pin/set` чужим PIN при установленном PIN → 401/403.
- [x] `pin/remove` без токена → 401/403.
- [ ] Сценарий атаки @TE не воспроизводится.
- [ ] E2E/CI зелёные.
