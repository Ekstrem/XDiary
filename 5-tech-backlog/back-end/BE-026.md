# BE-026: Analytics MV — summary/tops/distribution/trends/correlations от событий

- **Статус:** Открыта
- **Приоритет:** P1 (директива PO: агрегаты на MV, клиент не считает)
- **Источник:** PO 2026-11-03 13:20; @AR `chat/ar.md` 13:30 (`BC-Analytics/05-materialized-views.md`)
- **Зависимости:** AR-005

## Проблема
`BC-Analytics` считает `summary`/`tops`/`distribution`/`trends`/`correlations` «на лету»; по директиве PO — это **MV от событий** соседних сервисов. Сейчас клиент (тренды/корреляции) ходит в `daily-metrics`/`somatic-series` и агрегирует у себя — так быть не должно.

## Задача
- MV `summary`/`tops`/`distribution`/`trends`/`correlations` — инкрементально от событий (Journal/Somatic).
- Query API читает готовое; клиент не считает агрегаты.
- Контракт уже обновлён @AR (`BC-Analytics/05-materialized-views.md`).

## Критерии приёмки
- [ ] MV обновляются от событий.
- [ ] Query API отдаёт готовые агрегаты.
- [ ] Клиент не считает агрегаты (FE-012/013 перепроверить: тренды/корреляции — только рендер).
- [ ] CI зелёный.
