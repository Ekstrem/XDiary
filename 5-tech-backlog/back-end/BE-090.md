# BE-090: `POST /api/v1/clients` возвращает `otpCode` — вход в ЧУЖОЙ дневник по одному номеру телефона

- **Статус:** ToDo
- **Приоритет:** **P0 — безопасность/приватность, живой прод** (для дневника интимных записей это раскрытие всего)
- **Источник:** прогон @DO `2026-11-06 09:10` + проверка @TL `13:0x`
- **Проверяет:** @TL + @AR

## Факт (воспроизведено @DO с внешней машины)

```
POST /api/v1/clients  {"phone":"+7…"}   → 200
тело ответа содержит "otpCode":"<6 цифр>"
POST /api/v1/clients/{id}/verify        → 200, client-JWT (237 символов)
GET  /api/v1/partners  (с этим JWT)     → 200
```

То есть **телефон и Telegram не нужны**: знаешь номер — читаешь код из ответа и входишь в чужой дневник.

## Причина в коде

`6-msa/BC-Client/src/Client.Api/Controllers/ClientsController.cs`:

```csharp
:22  private IActionResult Respond(AggregateResult<IClients, IClientAnemicModel> r)
         => r.IsSuccess() ? Ok(r.Model()) : BadRequest(r.ErrorMessage());   // ← отдаёт модель целиком
:24  [HttpPost]
:25  [AllowAnonymous]
:26  public async Task<IActionResult> Register([FromBody] RegisterClientCommand c, CancellationToken ct)
         => Respond(await _mediator.Send(...));
```

А модель содержит OTP-поля (`6-msa/BC-Client/src/Client.Domain/Abstraction/IClientAnemicModel.cs`):

```
:9   string OtpCode { get; }
:10  DateTime? OtpExpiresAt { get; }
:11  int OtpAttempts { get; }
```

⇒ `Register` (анонимный!) сериализует `OtpCode` в ответ.

## Что сделать (рекомендация @BE из его же `09:35` — согласен)

Вернуть **явную проекцию** вместо модели:

```csharp
return Ok(new { id = r.Model().Id, version = r.Model().Version, phone = r.Model().Phone,
                otpExpiresAt = r.Model().OtpExpiresAt, verified = r.Model().Verified });
```

**Почему проекция, а не `[JsonIgnore]`:** `[JsonIgnore]` скрывает поле везде (включая места, где оно нужно), и легко
забыть про новый DTO. Whitelist-проекция — «что явно перечислено, то и уходит».

Дополнительно: `Verify` тоже возвращает модель? — проверить и закрыть тем же способом (`:29-32`).

## Почему это НЕ «потом»

Это единственный дефект из найденных, который **уже сейчас даёт доступ к чужим данным на проде** (образ `client` от
4 ноября, `885997ae` — по прогону @DO). Пока он жив, любой, кто знает номер, входит в дневник.

## Критерии приёмки

- `POST /api/v1/clients` → в ответе **нет** `otpCode`, нет `otpAttempts`; есть только `id`, `phone`, `otpExpiresAt`, `verified`;
- `POST …/verify` → нет утечки OTP-полей;
- тест: сериализованный ответ **не содержит** подстрок `otpCode`/`OtpCode` (падает на текущем коде);
- `## Результат`: подтверждение прогоном (как у @DO: `POST` → нет кода в теле → `verify` с кодом **из лога** работает).
