# BE-117 — P1: OTP rate-limit (BE-092) валит E2E-регистрацию: `429 /api/v1/clients` → `partnersCount: 0`

- **Статус:** ToDo
- **Приоритет:** P1 (единственный блокер браузерных квитанций фронта и тестов; три роли упёрлись в него независимо)
- **Источник:** замер @DO 2026-11-16 13:49 + мои прогоны `43845569210`, `43849004210`
- **Зависимости:** нет
- **Проверяет:** @TL
- **Исполняет:** @BE (`6-msa/BC-Client`)

## Что происходит (цепочка, проверена по коду и логам)

1. E2E переиспользует один телефон в `seedSession`.
2. `6-msa/BC-Client/src/Client.Application/Security/OtpRateLimiter.cs` — in-memory, singleton, ключ = телефон:
   - `private const int MaxPerHour = 5;`
   - `private static readonly TimeSpan MinInterval = TimeSpan.FromSeconds(60);`
   - `private static readonly TimeSpan Window = TimeSpan.FromHours(1);`
   - в шапке прямо записано: «BE-092: in-memory rate limiter. Ключ — телефон… не более 5 в окне».
3. За прогон телефон регистрируется больше 5 раз ⇒ **`429` на `/api/v1/clients`**.
4. В `seedSession` это видно как `partnersCount: 0, partnerCreated: false` — партнёр **не создан**.
5. Спеки, которым нужны данные созданного партнёра, падают «без данных»: `catalog-archive`, `csv`, `partner-client-link`, `partner-edit`; `stale-note` — каскад (пустой кэш ⇒ нет `fromCache` ⇒ нет бейджа).

**Подтверждения:** `429` в `43845569210` (дважды) и `43849004210`; `toast-reason` при этом зелёный (`"Укажите имя"`), то есть фронт не при чём. Перезапуск `xdiary-client` сбрасывает in-memory, но лимит исчерпывается заново **в том же прогоне** — это и объясняет, почему «стенд здоров, а прогон красный».

## Что нужно (выбор @BE, я не решаю за него)

- **(а)** dev-конфиг: не включать лимит в `Development` (или отключаемый флаг, например `Otp:RateLimit:Enabled=false` для dev) — самое чистое: тогда E2E не зависит от кода лимита;
- **(б)** если менять лимит нельзя — тогда `@TE` делает уникальный телефон на сценарий (это его зона, но решает проблему только «в тестах», а не в дев-среде).

## Критерии приёмки

- [ ] прогон `front-e2e-repeat` на dev: **нет ни одного `429` на `/api/v1/clients`**, в `seedSession` `partnersCount > 0`, `partnerCreated: true`;
- [ ] каскад `catalog-archive`/`csv`/`partner-client-link`/`partner-edit`/`stale-note` уходит из падений;
- [ ] поведение лимита в проде **не меняется** (проверка: описание флага + что он выключен вне `Development`);
- [ ] в логе при срабатывании лимита в dev — явный текст, что это конфиг, а не дефект спеки.

## Почему карточка, а не строка в чате

Из-за этого класса красные квитанции получали **две** роли (`@FE`, `@TE`), а причина три раза переписывалась: «стенд», «деплой в окне», «лимит стенда». Код-источник — здесь, поэтому фиксируем задачей с критерием «0 → 429» в прогоне.
