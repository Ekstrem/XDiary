# BE-070 — изоляция тестов: убрать вложенные csproj из тестовых проектов (ADR-028)

- **Статус:** ToDo
- **Приоритет:** P1 (валит блокирующий гейт `ci-guards`: `check_test_isolation` `rc=1`)
- **Источник:** `ci-guards` (шаг `check_awaits --strict` → висящее решение @BE) + прогон `tools/check_test_isolation.py` от @TL `2026-11-05` → `rc=1`, **3 нарушения** в 2 проектах
- **Зависимости:** нет (`ADR-028 §1.1/§3.1`)
- **Проверяет:** @AR (границы тестов — архитектурное правило)

## Задача

`python tools/check_test_isolation.py` на `origin/main` даёт:

```
::error::(11) 6-msa/ApiGateway.Tests/ApiGateway.Tests.csproj: вложенный csproj внутри тестового проекта:
             6-msa/ApiGateway.Tests/GatewaysApi.IntegrationTests/GatewaysApi.IntegrationTests.csproj
::error::(11) 6-msa/BC-Analytics/src/Analytics.ApiTests/Analytics.ApiTests.csproj: вложенный csproj внутри тестового проекта:
             6-msa/BC-Analytics/src/Analytics.ApiTests/AnalyticsPrivacy.IntegrationTests/AnalyticsPrivacy.IntegrationTests.csproj
rc=1, нарушений 3 (2 проекта)
```

`ADR-028 §1.1/§3.1`: общих тестовых папок нет; тест сервиса — в папке сервиса (`*Domain.Tests`, `*IntegrationTests`,
`*ApiTests`), тест пары — у потребителя. Вложенный проект внутри тестового проекта нарушает границу: он не
принадлежит ни одному BC по имени пути и не виден гейту путей роли.

## Критерии приёмки

- `python tools/check_test_isolation.py` → **`rc=0`**, нарушений **0**;
- вложенные проекты либо переименованы в самостоятельные папки по карте ADR-028, либо слиты в родительский тестовый проект (выбор — @BE и @AR);
- после переноса: `dotnet build` каждого затронутого `*.ApiTests`/`*.Tests` — `0 Error(s)`; `ci-guards` зелёный **сам**, без `continue-on-error`;
- висящая строка в `5-tech-backlog/tl/AWAIT.md` (`изоляция: HTTP-переписывание 3 пар…`) получает подтверждение — иначе `check_awaits --strict` останется красным.

## Вердикт @AR `2026-11-05 13:45` — раскладка по домену (заменяет часть §3.0.2 ADR-028)

**Факт по содержимому, а не по имени:** `Gateways.IntegrationTests` содержит `AppleHealthGatewayTests` и
`GarminGatewayTests` — это **доменные** тесты (`Aggregate.CreateInstance`, без БД и HTTP), и проект
ссылается на **два** BC (`BC-GarminGateway/src/*`, `BC-AppleHealthGateway/src/*`).
`GatewaysApi.IntegrationTests` (`GatewayBehaviorTests`) — HTTP по стенду, ссылок на BC нет.

**Что делать:**

1. **Разделить**, а не только перенести: `Gateways.IntegrationTests` → два проекта в своих BC
   (`BC-GarminGateway/src/GarminGateway.Domain.Tests`, `BC-AppleHealthGateway/src/AppleHealthGateway.Domain.Tests`).
   Причина: правило **(б)** ADR-028 запрещает тесту ссылаться на чужой BC, и сейчас оно **молчит** только
   потому, что папка не внутри `BC-*` (`bc_of()` → `None` → проверка пропускается). Перенос без разделения
   сделает (б) красным — и это будет правильный красный.
2. **Переименовать**: это `Domain.Tests`, а не `IntegrationTests` (ADR-028 §3: `<S>.Domain.Tests` —
   агрегат/инварианты/VO; `<S>.ApiTests` — по HTTP).
3. `GatewaysApi.IntegrationTests` (`GatewayBehaviorTests`, HTTP по стенду) — оставить как HTTP-тесты,
   определить место по §3.0.3 после объединения шлюзов.
4. Проверка после правок: `check_test_isolation` → **`rc=0`**; красный контроль на правиле (б):
   тест внутри `BC-*`, ссылающийся на чужой BC, должен давать `rc=1`.

## Блокер приёмки: ручной список файлов в csproj (@TE `2026-11-05 14:17`)

После правильной раскладки в **обеих** тестовых сборках группы осталось:

```xml
<EnableDefaultCompileItems>false</EnableDefaultCompileItems>
<ItemGroup><Compile Include="GatewayRoutesTests.cs" /></ItemGroup>
```

Факт по `origin`: `ApiGateway.Tests/ApiGateway.Tests.csproj` и `ApiGateway.ApiTests/ApiGateway.ApiTests.csproj`
содержат этот хак, при этом в папке `ApiGateway.Tests/ApiGateway.Tests/` **ровно один** `.cs`
(`GatewayRoutesTests.cs`) — то есть глоб по умолчанию собрал бы его сам.

**Почему это блокер, а не косметика:** пока `EnableDefaultCompileItems=false`, **любой новый** `.cs`,
положенный в папку, **не попадёт в сборку**. CI и гейт останутся зелёными, а тест будет «написан,
но не выполняется». Это ровно класс «зелёное на непроверенном», только на уровне компиляции.

**Требование:** убрать `EnableDefaultCompileItems=false` и `Compile Include` из **обеих** тестовых
сборок; после правки `dotnet build` каждого csproj проходит, и в папке остаётся ожидаемое число `.cs`.
Если хак по какой-то причине нужен — **объяснить в карточке**, что именно он исключает.
