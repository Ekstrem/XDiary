## Замер (стенд, 2026-11-19)
```
POST /api/v1/journal/records                        → 200 (id 701287da-…)
POST /api/v1/journal/records/<id>/when {startedAt}  → 200, в ответе команд root.startedAt = "2026-11-02T05:16:00"  ← домен принял
POST /api/v1/journal/records/<id>/complete          → 200
GET  /api/v1/journal/records/<id>                   → 200
  { "startedAt": "0001-01-01T00:00:00.0000000+00:00", "durationMin": 0, "place": "",
    "positions": [], "partners": [], "state": 0, "version": 1795066210997 }
```
То есть команды принимаются, а read-модель **не двигается вообще**, и `version` = **ms-таймстамп** — тот же признак, что в `BE-131`.

## Корень (по коду)
`6-msa/BC-Journal/src/Journal.Api/Events/JournalEventConsumer.cs:72`:
```csharp
if (existing.Version >= domainEvent.Version) return;   // без пола
```
У legacy-строк `Version` — ms-таймстамп (`AnemicModel.Version`), у события — номер (1,2,3…), значит условие **всегда истинно**, и все последующие события отбрасываются: read-модель навсегда остаётся в состоянии «сразу после создания».

## Задача
Добавить тот же пол, что в `BC-Client`/`BC-Partners`:
```csharp
const long LegacyTimestampFloor = 1_000_000_000_000L;
if (existing.Version >= domainEvent.Version && existing.Version < LegacyTimestampFloor) return;
existing.Version = domainEvent.Version;
```
Плюс проверить остальные BC на этот же шаблон (`git grep "existing.Version >= domainEvent.Version"`).

## Критерии приёмки
- `POST …/when` → `GET /journal/records/{id}` отдаёт **переданный** `startedAt` (не `0001-01-01`);
- то же для `place`, `durationMin`, `positions`, `partners`;
- `smoke-front`: тесты `wizard-record` проходят (запись находится по времени, партнёр выбран по умолчанию);
- регресс-тест: событие с legacy-`Version` не блокирует последующие.
