# BE-141 — P1: на проде `GET /api/v1/bff/analytics-summary` отвечает **500 без токена** (должен 401)

- **Статус:** На проверке
- **Приоритет:** **P1** — операция не защищена авторизацией и раскрывает ошибку наружу; из-за неё красный prod-канон
- **Источник:** prod-канон `(ii-a)` (введён `#2975`) — первый прогон на проде поймал нарушителя
- **Зависимости:** нет
- **Проверяет:** @TL
- **На проверке с:** 2026-11-19
- **Исполняет:** @BE (@AR — если это про маршрут/границу сервисов)
- **Артефакт:** ветка `role/be-be138`, PR #3001, `6-msa/ApiGateway/`

## Результат

**Найдено две реальные дыры (обе закрыты), третья — не в коде:**

1. **`BffController` был без `[Authorize]`.** Защита шлюза держалась ТОЛЬКО на кастомном
   middleware + ручном списке анонимных путей `GatewayRoutes.IsAnonymous`. Одна ошибка в
   списке — и контроллер открыт. Добавлен `[ApiController][Authorize]`, в `Program.cs` —
   `AddAuthentication(JwtBearer)` + `AddAuthorization()` + `UseAuthentication/UseAuthorization`.
   `ApiGateway.csproj`: добавлен `Microsoft.AspNetCore.Authentication.JwtBearer 8.0.0`
   (у остальных BC уже был).

2. **BFF не пробрасывал токен вниз.** `client.GetStringAsync(...)` шёл БЕЗ `Authorization` →
   journal/daily-metrics отвечали 401 → `HttpRequestException` → **500 с текстом ошибки**.
   Именно это и есть «500 вместо 401» при наличии валидного токена. Теперь заголовок
   пробрасывается, а `HttpRequestException` → **502** с нейтральным телом (без утечки текста).

3. **Почему 500 без токена на проде — кодом не воспроизводится.** В `origin/main` и в
   `a1d8601ad` middleware уже deny-by-default: `IsAnonymous("GET", "/api/v1/bff/…")` = `false`
   (не POST → `return false`) → без Bearer отдаётся 401. То есть на этом коммите маршрут
   защищён. Вероятные причины 500 на стенде: (а) на проде крутится образ старее `957980338`
   (`do(ADR-026): deny-by-default`), (б) 500 отдаёт фронт-прокси/APIM до шлюза.
   **Нужно от @DO:** digest задеплоенного образа `api-gateway` + лог запроса
   `analytics-summary` с прода. После перевыкатки — повторный prod-канон.

Остальные 73 защищённые операции на проде без токена отдают `401` корректно — выбивается одна.

## Почему это важно
1. **Безопасность:** `500` вместо `401` = запрос дошёл до приложения **без проверки токена** и упал внутри; это незащищённая операция с утечкой текста ошибки.
2. **Релиз:** prod-канон входит в шаг `deploy-prod`, поэтому каждый прогон красный, пока нарушитель не исправлен.

## Задача
Проверить маршрут `ApiGateway.AnalyticsSummary` (`/api/v1/bff/analytics-summary`): почему он не под проверкой токена (нет `[Authorize]`/политики, маршрут мимо auth-middleware, отдельный BFF-контроллер без атрибута) и почему без токена отдаёт `500`, а не `401`.

## Критерии приёмки
- `GET /api/v1/bff/analytics-summary` без токена → **401**;
- с валидным токеном → 200 и осмысленное тело;
- prod-канон `(ii-a)`: `защищено=74/74`, `нарушителей=0`, `rc=0`;
- прогон `deploy-prod` зелёный (канон больше не валит job).
