# BE-021: `ChangePin`/`RemovePin` без проверки текущего PIN

- **Статус:** На проверке
- **Приоритет:** P1 (остаток P0-дыры после BE-020)
- **Источник:** @TE `chat/te.md` 14:30 (проверка по коду)
- **Зависимости:** BE-020

## Проблема (по коду)
- `PrivacyHandlers.cs:30` `ChangePinHandler` → `Aggregate.CreateInstance(m).ChangePin(salt, hash, iter)` — **без проверки** текущего PIN.
- `PrivacyHandlers.cs:43` `RemovePinHandler` → `.Remove()` — **без проверки**.
- `ChangePinCommand(string Pin)` / `RemovePinCommand` — без поля `CurrentPin`.
- Шлюз требует JWT для `pin/change`/`pin/remove`, но при валидном токене смена/снятие PIN не требуют знания текущего: можно сменить PIN и «запереть» владельца (или снять PIN и открыть доступ через device-токен).

## Задача
- `ChangePinCommand` / `RemovePinCommand` — добавить `CurrentPin`, проверять как в `SetPinHandler` (`PrivacyHandlers.cs:22`).
- `/privacy/pin/change`, `/privacy/pin/remove` — только с JWT **и** верным текущим PIN.

## Критерии приёмки
- [x] `pin/change`/`pin/remove` без/с неверным текущим PIN → 401.
- [x] С верным текущим PIN → работает.
- [ ] E2E (сценарий «сменить PIN» @TE) зелёный; CI зелёный.
