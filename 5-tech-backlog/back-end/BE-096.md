# BE-096: Analytics ходит в клиентские API и молча деградирует при 401

- **Статус:** Отклонена
- **Причина:** премиса не подтвердилась в `origin`: `AnalyticsPrecomputeService.cs` уже использует `WithAuth` на всех трёх вызовах (`:54` журнал, `:61` метрики, `:71` `client-ids`), а не-2xx считаются и логируются (`_non2xx.Add(...)` + `LogWarning`, `:55`, `:62`, `:72`). Описание «токен только на `/internal/journal/records`» относилось к более ранней версии файла. Задача заведена по утверждению из чата без проверки кода — это моя ошибка постановки (класс `ERRATA` №33/№36)
- **Приоритет:** P1 (метрики «пустые» неотличимы от «не смогли получить»)
- **Источник:** @AR `2026-11-16 07:00` (`chat/ar.md`: `AnalyticsPrecomputeService.cs:44-48` — сервисный токен только на `/internal/journal/records`; после `401` метрики пустеют молча, `new()`); остаток `BE-091` (карточка закрыта)
- **Зависимости:** нет
- **Проверяет:** @TL (код); критерий сформулирован @AR

## Задача

Analytics читает данные клиентскими маршрутами `/api/v1/*`, а при `401` не падает и возвращает пустой результат (`new()`), поэтому «нет данных» и «не смогли получить» неразличимы.

Нужно: (1) Analytics **не ходит** в клиентские `/api/v1/*`; (2) чтение — через **внутренний** эндпоинт с **обязательным** `clientId` (контур `jwt-service`, как `Journal.IngestPartnerEvent`); (3) при недоступности источника — **явная ошибка**, а не `new()`; (4) в квитанции/логе — **какой** источник не ответил (адрес + код).

## Критерии приёмки

- [ ] `git grep -n "api/v1/" -- 6-msa/BC-Analytics` → **0** обращений из precompute к клиентским путям.
- [ ] Внутренний эндпоинт: `auth: jwt-service`, `clientId` обязателен, в каноне `internal: true` с кодами.
- [ ] При недоступном источнике нет пустоты: в логе и квитанции `источник <url> → <код>`.
- [ ] Кейс различения: «пусто по данным» ≠ «источник недоступен» (разные строки квитанции).
- [ ] §5.4 в обе стороны: источник отвечает `401` → видно `401`, тихого `new()` нет; норма → метрики считаются.
