# BE-122 — P1: `AddCatalogItemCommand` должен принимать **необязательный** `Id` — иначе `FE-054` не работает

- **Статус:** На проверке
- **На проверке с:** 2026-11-17
- **Приоритет:** P1 (без этого идемпотентное создание каталога на фронте не даёт эффекта, а при мерже «как есть» сломает старых клиентов)
- **Источник:** @BE 2026-11-16 13:35 («POST /api/v1/catalog принимает опциональный id») + сверка контракта @TL 2026-11-17 20:3x
- **Зависимости:** `PR #2429` (BE-канон)
- **Проверяет:** @TL
- **Исполняет:** @BE (`6-msa/BC-Catalog`)

## Что показала сверка (два разных состояния)

| где | `AddCatalogItemCommand` |
|---|---|
`origin/main` | `record AddCatalogItemCommand(string Kind, string Name, Guid ClientId)` — **поля `Id` нет** |
`origin/role/be` | `record AddCatalogItemCommand(Guid Id, string Kind, string Name, Guid ClientId)` — `Id` есть, но **обязательный** |

## Что нужно

- `Guid? Id` (**nullable**) в `AddCatalogItemCommand`;
- в хендлере: `var id = r.Id ?? Guid.NewGuid();` — если клиент прислал, используем его (идемпотентность), если нет — генерим как раньше;
- контрактный тест на `POST /api/v1/catalog`: (а) с клиентским `id` — агрегат получает **этот** id; (б) повтор с тем же `id` **не** создаёт второй элемент; (в) без `id` — работает по-старому.

## Критерии приёмки

- [x] `AddCatalogItemCommand` — `Guid? Id`;
- [x] хендлер использует клиентский id, если он передан, иначе генерит;
- [x] тест «два POST с одинаковым id ⇒ один элемент» — `CatalogIdempotencyTests` (repo-level upsert по Id);
- [x] тест «POST без id ⇒ создаётся» — `CatalogIdempotencyHandlerTests.Handle_WithoutId_GeneratesId`;
- [ ] `FE-054` в браузере: сетевой сбой + повтор ⇒ одна запись — за @FE.

## Результат

- `AddCatalogItemCommand(Guid? Id, string Kind, string Name, Guid ClientId)` + `var id = r.Id ?? Guid.NewGuid();` в `AddCatalogItemHandler`;
- `CatalogIdempotencyHandlerTests` (3 кейса: с id — тот же id в агрегате; без id — генерится; повтор с тем же id — тот же id);
- сборка Catalog + `Catalog.IntegrationTests` — `Ошибок: 0`.
