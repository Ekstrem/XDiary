# BE-122 — P1: `AddCatalogItemCommand` должен принимать **необязательный** `Id` — иначе `FE-054` не работает

- **Статус:** ToDo
- **Приоритет:** P1 (без этого идемпотентное создание каталога на фронте не даёт эффекта, а при мерже «как есть» сломает старых клиентов)
- **Источник:** @BE 2026-11-16 13:35 («POST /api/v1/catalog принимает опциональный id») + моя сверка контракта 2026-11-17 20:3x
- **Зависимости:** `PR #2429` (BE-канон) — сейчас блокирован гейтами, см. `DO-138`
- **Проверяет:** @TL
- **Исполняет:** @BE (`6-msa/BC-Catalog`)

## Что показала сверка (два разных состояния)

| где | `AddCatalogItemCommand` |
|---|---|
`origin/main` | `record AddCatalogItemCommand(string Kind, string Name, Guid ClientId)` — **поля `Id` нет** |
`origin/role/be` | `record AddCatalogItemCommand(Guid Id, string Kind, string Name, Guid ClientId)` — `Id` есть, но **обязательный** |

А фронт (@FE, `FE-054`) уже отправляет `{ id, kind, name }` и переиспользует id при retry — тест `FE-054-catalog-idempotent-test.js` я прогнал в его ветке: **9/9, rc=0**, включая контроль «id уходит в add».

**Следствия:**
1. на `main` сервер **игнорирует** `id` (лишнее поле в JSON) и генерит свой ⇒ повтор после сетевой ошибки всё равно создаёт **дубль**, то есть `FE-054` пока не даёт эффекта;
2. если влить `role/be` как есть (`Guid Id` без `?`), старые вызовы **без** `id` начнут получать `400` — это регресс публичного контракта.

## Что нужно

- `Guid? Id` (**nullable**) в `AddCatalogItemCommand`;
- в хендлере: `var id = r.Id ?? Guid.NewGuid();` — если клиент прислал, используем его (идемпотентность), если нет — генерим как раньше;
- контрактный тест на `POST /api/v1/catalog`: (а) с клиентским `id` — агрегат получает **этот** id; (б) повтор с тем же `id` **не** создаёт второй элемент; (в) без `id` — работает по-старому.

## Критерии приёмки

- [ ] `AddCatalogItemCommand` — `Guid? Id`;
- [ ] хендлер использует клиентский id, если он передан, иначе генерит;
- [ ] тест «два POST с одинаковым id ⇒ один элемент, второй — идемпотентный ответ»;
- [ ] тест «POST без id ⇒ создаётся, ответ 2xx» (совместимость);
- [ ] `FE-054` в браузере: сетевой сбой + повтор ⇒ **одна** запись в каталоге.
