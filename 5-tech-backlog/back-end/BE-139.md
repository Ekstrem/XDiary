# BE-139 — P2 (техдолг): разделить БД на Command DB и Read DB (профиль `Cqrs`)

- **Статус:** Идея
- **Приоритет:** P2 (техдолг; не блокирует функционал, но ограничивает CQRS)
- **Источник:** владелец 2026-11-19: «базы должно было быть две — это и есть CQRS» (по факту `__EFMigrationsHistory` общая на `EventStoreDbContext` и `ReadDbContext`)
- **Зависимости:** решение @AR (ADR-002/ADR-034), провижининг @DO
- **Исполняет:** @BE (конфигурация) после решения @AR + работ @DO
- **Проверяет:** @AR

## Что сейчас

- `deploy.sh:67-77`: для всех 11 BC `CommandDb = ReadDb = Database=<bc>` — **одна БД на BC**.
- Внутри: схема `Commands` (`AggregateStates`, `DomainEvents`, `Snapshots`) + `public` (`<bc>_read`, `__EFMigrationsHistory`).
- `EventStoreDbContext` и `ReadDbContext` оба вызывают `Database.Migrate()` в одной БД — **общая `__EFMigrationsHistory`**.
  Работает, пока ID миграций уникальны; при пересечении/откате — неочевидный конфликт.
- Нельзя независимо пересобрать read-модель из событий и независимо масштабировать read-сторону.

## Чьё решение

Раскладка «одна БД + три схемы» — решение **@AR** (ADR-034, принят 2026-11-05; владелец — финальный согласующий).
ADR-002 фиксирует профиль **`Single`** и путь эволюции `Single → BudgetCqrs → Cqrs → Ceqrs`.
Переход на две БД = профиль **`Cqrs`**, то есть **смена архитектурного решения** — зона @AR, не @BE.

Канон DTF (цитата из ADR-034): «Command DB и Read DB — **разные базы** (или как минимум разные схемы)». Сейчас реализован минимум.

## Что нужно сделать (по ролям)

1. **@AR:** обновить ADR-002/ADR-034 — переход `Single → Cqrs`; зафиксировать, что `__EFMigrationsHistory` разделяется по БД.
2. **@DO:** провижининг второй БД на каждый BC (`<bc>` → `<bc>` + `<bc>_read`), отдельные пользователь/права;
   `deploy.sh`: `ReadDb` → отдельная строка подключения; обновить `recreate-service.sh`/`rotate-db-password.sh`.
3. **@BE:** `appsettings.json` каждого BC — `ReadDb` на отдельную БД; проверить, что миграции read-контекста
   идут в свою историю; прогнать `DatabaseCreationTests` на двух БД.

## Критерии приёмки

- [ ] ADR обновлён (@AR) и профиль зафиксирован;
- [ ] для каждого BC две БД, у каждой своя `__EFMigrationsHistory`;
- [ ] `EventStoreDbContext.Migrate()` и `ReadDbContext.Migrate()` пишут в **разные** истории;
- [ ] read-модель BC можно пересобрать (drop + replay из events) без остановки command-стороны;
- [ ] `deploy-dev`/`deploy-prod` зелёные, `DatabaseCreationTests` на двух БД проходят.
