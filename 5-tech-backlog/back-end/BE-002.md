# BE-002: Переделать `journal` (Журнал, агрегат Record) — с нуля

- **Статус:** В работе
- **Приоритет:** P0
- **Источник:** BC-Journal (`03-ddd/BC-Journal/*`), US-01..09, ADR-001
- **Зависимости:** BE-001

## ⚠️ Переделка
Архитектор допустил ошибку — микросервис `journal` сделан неверно. Требуется **полностью переделать с нуля**. Канвас уже исправлен архитектором, старый код `6-msa/BC-Journal/` удалён.

## Задача
Реализовать Core-микросервис `journal` по исправленному канвасу `03-ddd/BC-Journal/02-aggregate-canvas.md`:
- **Сущность Record = признаки «кто + во сколько»:** `partnerId` (uuid) + `startedAt` («YYYY-MM-DDTHH:mm»).
- **Идентификатор (DF) — технический, НЕ в сущности:** составной `<guid, long>` (guid — агрегат, long — версия), только для быстрого поиска.
- **Команды — именованные методы по экранам визарда:** `StartManualEntry`, `SpecifyWhen`, `ChoosePartner`, `SpecifyPlace`, `AddPositions`, `AddAccessories`, `RecordContraception`, `SpecifyDuration`, `RecordOrgasms`, `Complete`, `Delete`.
- **События — от каждого метода** (`ManualEntryStarted`, `WhenSpecified`, `PartnerChosen`, …, `RecordCompleted`, `RecordDeleted`).
- Command API / Query API / MV — по `03-ddd/BC-Journal/03/04/05-*-api.md`.

## Критерии приёмки
- [ ] Сущность Record без технического id (идентичность = partnerId + startedAt; DF = `<guid, long>`).
- [ ] Команды и события соответствуют канвасу (именованные, по экранам визарда).
- [ ] Терминология «партнёр» (не «клиент»).
- [ ] Интеграционный тест: Command → Query → Assert.
