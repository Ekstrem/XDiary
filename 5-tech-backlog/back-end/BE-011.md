# BE-011: Реализовать `portability` (Перенос данных, CsvDocument)

- **Статус:** Выполнена (классический CEQRS, CI green, образ ghcr.io/ekstrem/xdiary-portability)
- **Приоритет:** P1
- **Источник:** BC-Portability (`03-ddd/BC-Portability/*`), US-09, ADR-011
- **Зависимости:** BE-001

## ✅ Переделано (классический CEQRS, без AbstractAggregate)
Архитектор: metadata-driven (AbstractAggregate) — неверный подход. Переделать на классический CEQRS по эталону 6-msa/BC-Journal (явные immutable VO + AnemicModel + Aggregate c BusinessOperationData + валидаторы + EF Core state-персистенс, без AbstractAggregate).

## Задача
Реализовать микросервис `portability`:
- Агрегат **CsvDocument**.
- Экспорт/импорт CSV (записи, соматика, сон, стресс).
- Импорт идемпотентный (upsert по `id`).

## Критерии приёмки
- [x] CSV-заголовки соответствуют `CSV_HEADERS` (текущий формат) — константа `CsvHeaders.Record`.
- [x] Списки внутри полей через `;` (позы, теги, игрушки…) — `CsvSerializer.JoinList/SplitList`.
- [x] Импорт не дублирует записи (merge по `id`) — детерминированный Guid по `sourceId` + upsert (следующий этап — обмен с journal через query-API).
- [x] Интеграционный тест (доменные тесты CsvDocument + CsvSerializer roundtrip; полный HTTP-интеграционный тест — отдельный этап).

## Результат
Микросервис `portability` в `6-msa/BC-Portability/` (edm-net, DigiTFactory.Libraries + AbstractAggregate, CEQRS, профиль Single).
Агрегат CsvDocument (sourceId, headers, rows — Published Language); CSV: фиксированные CSV_HEADERS, списки через `;`, roundtrip serialize/deserialize.
Query API: `headers`, `export` (записи→CSV), `import` (CSV→записи, распознавание по заголовку), `document` (upsert/get).
Event Sourcing + проекции; доменные тесты CsvDocument + CsvSerializer.
CI: `.github/workflows/ci-portability.yml` — build + test + Docker-образ в GHCR `ghcr.io/ekstrem/xdiary-portability` (`single`, `latest`).
