# BE-038: Нет JWT-аутентификации в сервисах → `sub` всегда пуст, per-client не работает

- **Статус:** Открыта
- **Приоритет:** **P0** (ломает вход по PIN и изоляцию данных; отменяет приёмку BE-032/BE-036)
- **Источник:** @BE 2026-11-05 11:44; проверено по коду
- **Зависимости:** ADR-021 (общий `Jwt:SigningKey`), BE-032 (per-client Garmin/Apple), BE-036 (PIN per-client)

## Факты (проверено)
`Program.cs` сервисов содержит **только** `app.UseAuthorization()`:
- `6-msa/BC-Privacy/src/Privacy.Api/Program.cs:35`
- `6-msa/BC-GarminGateway/.../Program.cs:33`
- `6-msa/BC-AppleHealthGateway/.../Program.cs:33`
- `6-msa/BC-Client/src/Client.Api/Program.cs:35`

**Нет** `AddAuthentication(...)`, `UseAuthentication()`, `AddJwtBearer(...)`. Значит `HttpContext.User` никогда не заполняется, `User.FindFirst("sub")` = `null`, `CurrentClientId()` = `Guid.Empty`.

Следствия:
1. **Вход по PIN сломан:** BE-036 сделал `/privacy/token` c `Unauthorized` при пустом `sub` → **401 всегда**, на любом стенде.
2. **Per-client изоляция не работает:** BE-032 (Garmin/Apple) писал/читал по `clientId = Guid.Empty` — данные не разделялись.
3. Тесты не ловили: `pin/has`, `pin/verify` и гейтвеи проверялись без JWT.

## Задача
1. В per-client сервисах (`Privacy`, `Client`, `GarminGateway`, `AppleHealthGateway`) добавить JWT bearer:
   ```csharp
   builder.Services.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
     .AddJwtBearer(o => { o.TokenValidationParameters = ... Jwt:SigningKey ... });
   app.UseAuthentication();   // ДО UseAuthorization
   ```
2. Единый `Jwt:SigningKey`/issuer/audience — как в ApiGateway (ADR-021), конфиг из `.env`.
3. Отдельно решить (с @AR): шлюз пробрасывает `X-Client-Id`, или каждый сервис валидирует JWT сам. Предпочтительно — валидация в сервисах (не доверять заголовку без подписи).
4. `CurrentClientId()` при пустом `sub` — `401`, но **не** ломать анонимные эндпоинты (`/clients` POST, `/clients/{id}/verify`).

## Критерии приёмки
- [ ] `GET /privacy/pin/has` с валидным JWT → отвечает по клиенту; без JWT → 401.
- [ ] `POST /privacy/token` с client-JWT и верным PIN → 200; с чужим PIN → 401.
- [ ] Garmin/Apple: два клиента видят только свои точки (проверить на dev).
- [ ] E2E `pin-first-login`, `onboarding`, `garmin-somatic` — зелёные.
- [ ] `test` зелёный.

## Контракт (вердикт @AR 2026-11-05 20:50, ADR-008)
- **Валидация JWT в каждом сервисе:** `AddJwtBearer` с **общим** `Jwt:SigningKey`, issuer = `xdiary`, audience — из конфига (тот же, что у ApiGateway).
- Сервис берёт **`sub` = `clientId`**.
- Заголовок `X-Client-Id` **не доверяем** — подделает любой во внутренней сети.
- Defense-in-depth: шлюз режет невалидный JWT на краю, сервис **дополнительно** валидирует сам.
