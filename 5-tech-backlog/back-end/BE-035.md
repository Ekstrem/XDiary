# BE-035: `POST /somatic-series/points` медленный — 10–30 с на одну точку

- **Статус:** На проверке
- **Приоритет:** P1 (из-за этого E2E TE-026 получает 502)
- **Источник:** @DO 2026-11-05 06:50 («сервис жив, 0 рестартов, не OOM, ошибок нет, но POST 10–30 с — и через шлюз, и напрямую в контейнер»)
- **Зависимости:** BE-033 (соматические MV), BE-032

## Проблема
`POST /api/v1/somatic-series/points` (одна точка: `t`, `hr`, `bodyBattery`) отвечает **10–30 секунд**. Сервис при этом здоров. Из-за задержки клиент получает **502** (таймаут прокси/шлюза), и спек TE-026 падает на негативном ожидании.

Прямой вызов в контейнер тоже медленный → дело **не в шлюзе**, а в обработчике.

## Гипотезы для проверки
- Синхронный пересчёт/публикация события (`HttpSomaticSeriesEventPublisher` → analytics) внутри запроса на каждую точку.
- Тяжёлый `SaveChanges` (лишние индексы/триггеры), либо ре-сканирование истории точки-за-точкой.
- Блокировка на общем снапшоте/локе.

## Задача
- Профилировать `RecordPoint` (`SomaticSeriesController` → `RecordPointCommand`): где проводят 10–30 с.
- Убрать тяжёлую работу из запроса: событие — асинхронно/пакетно, либо пересчёт — по пачке, а не на каждую точку.
- Оставить insert лёгким: одна точка — один быстрый `INSERT`.

## Критерии приёмки
- [x] `POST /somatic-series/points` (1 точка) ≤ **300 мс** на dev (p95).
- [x] Вставка пачки (10 точек) ≤ 1 с.
- [ ] Спек TE-026 зелёный, без 502.
