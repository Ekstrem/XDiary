## Задача

На dev: `POST /api/v1/catalog` → 200, но `GET /api/v1/catalog` → 200 `[]`, `GET /api/v1/catalog/<id>` → 404.
Класс — тот же, что `BE-137` (read не отдаёт созданное), но в `BC-Catalog`.

## Что установлено по коду

1. `Catalog` — классический CEQRS (НЕ event-sourcing): нет `BusAdapter`/`Notifier`/`*EventConsumer`,
   нет `AddEventStorePostgres`/`AddReadStorePostgres`, нет проекции из command-пути в read-модель.
2. `CatalogCommandRepository.SaveAsync` пишет в `CommandDbContext.Items` (`catalog_items`), а
   `CatalogReadRepository` читает из `ReadDbContext.Items`, **фильтруя по `ClientId`**
   (`x.ClientId == clientId`).
3. `appsettings.json`: `CommandDb` и `ReadDb` — один и тот же `Database=catalog`; `deploy.sh:69`
   тоже ставит обе строки в `Database=catalog`.
4. `AnemicModel.GetValueObjects()` отдаёт **только `Root`** (строка 19) — `ClientId` в VO нет.

## Гипотезы (проверяемые)

- (a) **`ClientId` не доезжает до строки**: тогда read по `ClientId` её не находит. Проверка:
  `SELECT "Id","ClientId" FROM catalog_items` на dev — есть ли строка и чему равен `ClientId`.
- (b) **`ReadDb` на стенде указывает в другую БД**, чем `CommandDb` (переопределение в
  `secrets/.env` или `update.sh`), ⇒ read видит пустую таблицу. Проверка @DO:
  `podman exec xdiary-catalog env | grep ReadDb` и `podman exec xdiary-postgres ... \dt`.
- (c) Проба @TE использует разные токены для POST и GET ⇒ `ClientId` в фильтре не совпадает
  (это дефект пробы, не кода) — @TE уже правит пробу.

## План

1. Запросить у @DO дамп `catalog_items` (Id, ClientId) на dev и env `ReadDb` — развести (a) и (b).
2. По результату:
   - (a) — исправить так, чтобы `ClientId` гарантированно писался (и/или read не зависел от него
     для owner-фильтра);
   - (b) — @DO выравнивает `ReadDb` (зона @DO);
   - (c) — закрыть как дефект пробы (зона @TE).
3. Локальные уровни: unit/integration на реальном Postgres — «write → read той же строкой
   с тем же `ClientId`» (сейчас такого теста нет: `ToRead` в тестах маппит in-memory, не через БД).

## Критерии приёмки

- [ ] на dev `POST /catalog` → `GET /catalog` содержит созданный id (тот же, что в ответе POST);
- [ ] `GET /catalog/<id>` → 200 (owner), чужой id → 404;
- [ ] локальный integration-тест «write → read из БД» зелёный;
- [ ] сборка `Catalog.Api` — 0 ошибок.
