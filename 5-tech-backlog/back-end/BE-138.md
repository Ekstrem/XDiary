## Корень (по коду, подтверждён дампом)

Catalog на `main` — **event-sourced**:

- `Catalog.DomainServices`: `BusAdapter` + `Notifier` + `AggregateProvider` (публикация в in-memory шину);
- `Catalog.Storage`: `CatalogEventSourcingRepository` + `CatalogEventReplay` + `EventStoreDbContext` (схема `Commands`);
- `Catalog.Api/Program.cs`: `AddEventStorePostgres` + `AddEventBusInMemory` + `AddReadStorePostgres<…, ReadDbContext>`;
- `ReadDbContext.cs:9` → `ToTable("catalog_read")` — **единственный read-путь**.

**Не хватало консьюмера событий и хендлера проекции** (в `Catalog.Api` не было папки `Events/`). События писались в `Commands."DomainEvents"`, но `public.catalog_read` никогда не заполнялась — отсюда `404` и `[]`. Это класс `BE-134` (Client: запись есть, проекции нет).

### История двух неверных гипотез (для честности; обе сняты фактами)

1. **«`ClientId = NULL` в `catalog_items`» (@TL, 11:24 по дампу @DO).** Снята @BE: `grep 'catalog_items'` по всему `6-msa/BC-Catalog` → **0 вхождений** в коде; в `origin/main` нет миграции, создающей эту таблицу (есть только `AddEventStore` + `AddReadStores`). Таблица — остаток старого «классического CEQRS» (коммиты `941c91d8c` → `737e2bdc2`), `GET /catalog` её **не читает**. Дамп относился к мёртвому артефакту.
2. **«Проекции нет вовсе, поэтому таблица пуста» (@TL, первый разбор).** По сути верно (консьюмера не было), но формулировка «read-таблица никем не наполняется» была верна лишь для `catalog_read`; уточнено выше.

⇒ Правильный корень — **отсутствие консьюмера/хендлера проекции в `catalog_read`**, а не привязка к клиенту.

## Что сделано (PR `#3001`)

1. `Catalog.Api/Events/CatalogEventConsumer.cs` — `CatalogEventConsumer` (`BackgroundService`, подписка на `IEventBusConsumer`) + `CatalogEventHandler` (`IDomainEventHandler<ICatalog>`, `IObserver<…>`) + `CatalogProjection.ApplyVos` (per-field: `Root`→Kind/Name, `ClientId`, `Photo`, `Notes`, `Brand`, `Archived`, `FantasyPartner`). Хендлер держит только `IServiceScopeFactory` (класс `BE-134`).
2. `Program.cs`: `AddHostedService<CatalogEventConsumer>()` + `AddSingleton<CatalogEventHandler>()`.
3. `CatalogReadModel.Version` (нужен для stale-skip QG-305).
4. Миграция `AddVersionToCatalogRead`: `AddColumn Version` + `IX_catalog_read_ClientId` (таблица не пересоздаётся).
5. Stale-skip с `LegacyTimestampFloor` (класс `BE-137`): `existing.Version >= domainEvent.Version && existing.Version < 1e12`.
6. Тем же шаблоном закрыты ещё 5 BC: SomaticSeries, AppleHealthGateway, Portability, DailyMetrics, GarminGateway, Privacy (у каждого `AddHostedService` + handler + проекция + `Version` + миграция + stale-skip).
