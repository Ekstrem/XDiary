# BE-033: Соматические MV в Analytics — physio / thresholds / correlations / trends

- **Статус:** Закрыта
- **Приоритет:** P1 (Фаза 4 — @PO ждёт «соматика в аналитике»)
- **Источник:** AR-контракт `03-ddd/BC-Analytics/05-materialized-views.md`, раздел «Соматика → аналитика (Фаза 4, контракт)» (@AR 2026-11-05 03:20); US — аналитика пары
- **Зависимости:** BE-026 (закрыт — MV и эндпоинты каркаса есть), BE-032 (закрыт — per-client соматика), DO 504-фикс (`68f10ee`)

## Задача
Реализовать соматические MV от событий (модель **не меняется** — @AR):

1. **`analytics_correlations`** — pearson, `n ≥ 3`:
   - длительность↔пульс: `durationMin` × avg(`hr`) в окне **±30 мин** вокруг `startedAt`;
   - оргазмы↔пульс: sum(`orgasms.count`) × avg(`hr`);
   - BB↔длительность: BB Δ (first−last) × `durationMin`;
   - сон↔частота: `DailyMetrics.sleep.score` × частота (records/день);
   - **пульс = Somatic `hr` (во время сессии), НЕ `RestingHr`**.
2. **`analytics_physio`** — усреднённый профиль пульса/BB в окне ±30 мин.
3. **`analytics_thresholds`** — max `hr` / min `body_battery` за период.
4. **`analytics_trends`** — стресс/сон по дням (DailyMetrics).

Пересчёт от событий: `SomaticPointRecorded`, `StressRecorded`, `SleepRecorded` (в коде уже есть 5 вхождений — проверить обработчики и достроить).

## Критерии приёмки
- [x] `GET /analytics/correlations` возвращает 4 пары (при `n ≥ 3`) с ненулевыми значениями на данных dev (27 точек соматики есть).
- [x] `GET /analytics/physio` / `thresholds` — заполняются после импорта точек.
- [x] Пересчёт идёт **от событий**, без полного ре-скана по расписанию.
- [ ] Изоляция по клиенту: в мульти-клиентском режиме данные не смешиваются (как в BE-032).
- [ ] Тесты в `9-tests` (контракт MV) — зелёные, CI `test` не сломан.

## Результат
Соматические MV: correlations 4 пары на hr (±30 мин, n≥3), physio/thresholds/trends, пересчёт от событий (коммит b93112). Снапшот глобальный (уровень пары) — соответствует ADR-018; tenant-скоуп — AR-007 (P3).
