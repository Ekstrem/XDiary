# AR-163 — Проработка: `Connect` в BC-GarminGateway = ввод токена (серверный прокси), снять ограничение «без UI подключения»

- **Статус:** На проработке
- **Приоритет:** P1 (блокирует FE-057/BE-142: без уточнения канваса фронт не знает, что допустимо)
- **Прорабатывает:** @AR
- **Источник:** владелец 2026-11-20 («в настройках нужна кнопка для диалога ввода токена пользователя Garmin»); текущий канвас `03-ddd/BC-GarminGateway/02-aggregate-canvas.md:13` говорит «Connect = выбор источника + импорт CSV/прокси, **не OAuth-UI**»; backlog `G-01` — статус «без UI подключения»
- **Зависимости:** `G-01`, `G-02`, `G-06`, ADR-012

## Задача
**Контракт сначала в Gravitee (APIM), потом фронт.** Цепочка: `04-architecture/api-index.yaml` (источник) -> `openapi/garmin-gateway.json` (спека) -> Gravitee (import/publish) -> FE читает опубликованный контракт.
1. Обновить канвас: **Connect = ввод токена пользователем в настройках** (токен хранится серверно в `Credentials`), синк — серверный прокси. Снять/переформулировать «не OAuth-UI» (ограничение было про браузерный OAuth-redirect, не про вставку токена).
2. Обновить `01-user-stories/backlog.md` (G-01: «без UI подключения» → сценарий подключения по токену).
3. **Дополнить `04-architecture/api-index.yaml` полями DTO** (сейчас там только тип): `CredentialsDto` = apiKey/oauthToken/tokenExpiry (+формат/обязательность), `SyncConfigDto` = metrics[]/windowDays, ответ `state` = поля `GarminSync` (credentials, syncConfig, lastSync); коды/поведение при истечении (`ReauthOnExpiry`). Это источник для спек и для проверки дрейфа.
4. Согласовать с @DO порядок публикации в Gravitee и что считается «контракт опубликован» (API запущен, план опубликован, спека видна).

## Критерии приёмки
- Канвас и backlog без противоречия «не OAuth-UI» vs «диалог токена»; ссылка на решение владельца 2026-11-20.
- @FE и @BE имеют однозначный контракт (поля/коды/истечение) в одном месте.
- Согласовано с владельцем (это изменение принятого решения).
