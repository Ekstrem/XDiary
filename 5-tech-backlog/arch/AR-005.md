# AR-005: TechDebt — «последние/подсказки» считаются во фронте, а не в read-model

- **Статус:** На проверке (arch: Query/MV готовы; реализация — BE-024/FE-014)
- **Приоритет:** P1 (решение перф-проблемы визарда, PO 2026-11-03 11:30)
- **Источник:** PO 2026-11-03; EDM/DF (read-model из событий, API отдаёт готовое); `8-front/js/app.js`
- **Зависимости:** —

## Контекст
Фронт вычисляет «последнее/подсказки» **клиентски**, сканируя все записи в `8-front/js/app.js`:
- `lastPartnerName(records)` — последний партнёр (сортировка по `startedAt` + первый с `partner`).
- `historyPlaces(records)[0]` — последняя локация.
- `fillDatalist("place-suggest"/"partner-suggest")` — списки уникальных мест/партнёров.

По EDM/DF эти результаты должны быть **готовы в read-model** (проекция событий `RecordCompleted`/`PartnerAdded`) и отдаваться из **Query API** — фронт не должен сканировать записи для представления.

## Задача
1. **Архитектор:** описать в `03-ddd` Query API + MV:
   - `GET /api/v1/journal/recent` → `{ lastPartner, lastPlace }` (проекция `RecordCompleted`).
   - уникальные места — проекция (для `place-suggest`); партнёры — уже `GET /api/v1/partners`.
2. **Бэкенд:** реализовать Query + MV (проекция событий).
3. **Фронт:** убрать `lastPartnerName`/`historyPlaces`/сканирование в `fillDatalist`, брать готовое из API.

## Критерии приёмки
- [x] `03-ddd` (Query API/MV) описывают «recent + подсказки» (из событий).
- [ ] `6-msa` отдаёт готовые результаты; `8-front` не сканирует записи для «последнего».
- [ ] CI green.

- **BE (BE-024):** реализовать Query; **FE (FE-014):** убрать клиентский скан.
