# AR-003: TechDebt — 6-msa использует PUT/DELETE вместо POST-only (расхождение с EDM/DF)

- **Статус:** Закрыта
- **Приоритет:** P1
- **Источник:** edm-net (Command API — только POST); статья «Тактические паттерны» (запрет PUT/DELETE для агрегата); ADR-006, ADR-013
- **Зависимости:** —

## Контекст
Аудит контроллеров `6-msa` выявил **PUT (4) и DELETE (5)** наряду с POST (37):
- Catalog: 2×Put + 1×Delete; Journal: 3×Delete; Partners: 2×Put + 1×Delete; Privacy: 1×Delete.

По конвенции EDM/DF команды идут **только через POST** (идемпотентные операции; статья прямо запрещает PUT/DELETE для модификации агрегата). PUT/DELETE в коде — расхождение.

Причина: Command API (`03-ddd`) не зафиксировал явные POST-эндпоинты — бэкенд по инерции сделал CRUD.

## Задача
1. **Архитектор (эта часть делается сейчас):** расписать явные POST-эндпоинты во всех `03-ddd/*/03-command-api.md` (без PUT/DELETE) + уточнить MV (INSERT/UPDATE/DELETE как БД-операции).
2. **Бэкенд:** переписать контроллеры `6-msa` на POST-only (`[HttpPut]`/`[HttpDelete]` → `[HttpPost]` с действием в URL).

## Критерии приёмки
- [x] Command API (10 контекстов) содержат явные POST-эндпоинты; PUT/DELETE отсутствуют.
- [x] В `6-msa` нет `[HttpPut]`/`[HttpDelete]` — все команды `[HttpPost]`.
- [x] Шлюз (YARP-роуты) и фронт (`8-front`) согласованы с новыми маршрутами (FE/DO: `d379e5e`, `3e572db`).

## Результат
- **Арх. часть (выполнена):** Command API (9 файлов) пересинхронизирован с кодом — все эндпоинты POST (⚠️-пометки сняты); правило «только POST» в `03-ddd/README.md`.
- **Код (выполнено, BE-018):** бэкенд перевёл 9 PUT/DELETE → POST (`.../name`, `.../remove`, `.../delete`); в `6-msa` остались только `[HttpPost]` (46) и `[HttpGet]` (13).
- **Синхронизация (выполнено):** `8-front`/`9-tests` обновлены (`d379e5e`, `3e572db`); CI `4cd0ce2` — 6 чеков green.
