## Факт

`git grep -l AddAuthentication origin/main -- "6-msa/**/Program.cs"` → **11** BC:
`Analytics, AppleHealthGateway, Catalog, Client, DailyMetrics, GarminGateway, Journal, Partners, Portability, Privacy, SomaticSeries`.

Гейт `check_api_index` печатает по каждому из них:

```
##[notice]BC-<X>: добавлен auth-стек — обнови область в ADR-026 (гейт ждёт 6 BC, станет 11)
```

То есть **ADR-026 описывает 6 BC с auth-стеком, а в коде их 11**.

## Важно для приёмки (и почему это не блокер)

Это строки `##[notice]`, а **не** `##[error]`. Красный `check-chat` на PR #2439 давали другие шаги: порядок строк в `chat_lint` (уже исправлен в `main`) и `нужен pyyaml` в шаге API-реестра (`DO-138`). Поэтому:
- карточка **не** про «гейт блокирует», а про «документ отстал от кода»;
- закрывать её можно независимо от `DO-138`.

## Что нужно

Обновить область ADR-026: перечислить 11 BC (или сформулировать правило «все сервисы, у которых есть `AddAuthentication`, обязаны быть в области», чтобы документ не отставал снова), и указать дату/источник изменения.

## Критерии приёмки

- [ ] в ADR-026 область auth-стека = фактический список из 11 BC (или правило, из которого он выводится);
- [ ] `check_api_index` на чистом `main` больше **не** печатает notice про ADR-026;
- [ ] в ADR указано, **почему** область расширилась (какие BC и когда получили auth-стек) — чтобы это не выглядело правкой ради тишины в логе.

   область периметра): таблица теперь «**11 BC** = **6** в `AUTH_BCS` с fallback + **5** с auth-стеком вне списка

   «два BC» на «пять», с командой замера `git grep -l AddAuthentication … → 11`.
2. **Тело `ADR-026` не правится** — по правилу §14 («у старых ADR меняется только статус; перечень BC меняется
   вместе с кодом, поэтому живёт в каноне») и по норме «содержание принятого ADR заморожено».
3. **Остаток — не в моей зоне:**
   - `AUTH_BCS` в `tools/check_api_index.py` всё ещё **6** ⇒ notice будет печататься и дальше;
   - итоговая строка гейта `без auth по ADR-008: 5` считает `11 − 6 − 0`, то есть **те же пять** вне `AUTH_BCS`,
     а не BC без auth (фактически их **0**) — это дефект печати, зона `tools/` (@DO/@LM). Зафиксировано в §14.
4. **Почему это не блокер (проверено):** `check_api_index` печатает `::notice::`, в счёт `bad` не входит;
   красный в шаге DO-064 даёт `gen_openapi.py --check` → `rc=2` «нужен pyyaml» (`DO-138` дефект 3).
