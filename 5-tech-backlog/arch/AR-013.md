# AR-013: обновить доменные доки после принятия ADR-024 («я» ≠ партнёр)

- **Статус:** На проверке
- **Приоритет:** P2 (нужно до BE-054, иначе код и `03-ddd` разъедутся)
- **Источник:** `04-architecture/edm-debt-plan.md` §3 (@AR 2026-11-09); ответы владельца на §5 `01-entity-map.md`
- **Зависимости:** ADR-024 переводится в «Принято» (решает владелец)
- **Прорабатывает:** @AR
- **Проверяет:** @TL (связность доков)

## Задача

После принятия ADR-024 обновить **в одном коммите** (зона @AR, `03-ddd/`):

1. `00-context-map.md` — `Privacy` → часть `Client`; связь `Client → Partners` = **scope владения** («мои партнёры»), а не «партнёр-«я»».
2. `BC-Client/02-aggregate-canvas.md` — добавить профиль (`displayName`, `gender`, `photo?`), **удалить `LinkedPartnerId`** и переходы `Linked`/`Unlinked`.
3. `BC-Privacy/*` — пометка «часть контекста `Client`»: где живёт политика приватности/PIN (BC не удаляем физически, но роль меняется).
4. `BC-Partners/02-aggregate-canvas.md` — `clientId` = владение, **опционален** (партнёр может стать клиентом; база для будущего взаимодействия).
5. `BC-Journal/02-aggregate-canvas.md` — `orgasms` = **словарь участник→оргазмы**, ключ `"me"` законен.
6. `01-entity-map.md` §4 — дельта помечена «внесено».
7. `TECHDEBT.md` п.15 — перевести в «СНЯТО» со ссылкой на коммит.

## Критерии приёмки

- [x] Шесть файлов обновлены, расхождений «док ↔ код» по этим пунктам нет (проверка `git grep` по `LinkedPartnerId` — остались только пометки «удалён»).
- [x] ADR-024 в статусе «Принято» (решение делегировано владельцем 2026-11-03: «реши по ограниченным контекстам сам»); протокол фиксирует делегирование.
- [x] `TECHDEBT` п.15 закрыт ссылкой на ADR-024.
