# AR-006: TechDebt — Analytics MV: schedule → event-driven проекция

- **Статус:** Открыта
- **Приоритет:** P2 (техдолг; schedule — временная заглушка)
- **Источник:** директива PO (MV по событиям); TL 2026-11-03 20:00; BE-026
- **Зависимости:** BE-026 (schedule-заглушка)

## Контекст
BE-026 реализует Analytics MV как `AnalyticsPrecomputeService` (HTTP pull каждые 2 мин). По директиве PO **MV должны обновляться по событиям**; расписание — техдолг (маскирует задержку и потерю событий).

## Задача (переход к event-driven)
1. **События:** `RecordCompleted`/`RecordDeleted` (Journal), `SomaticPointRecorded` (SomaticSeries), `StressRecorded`/`SleepRecorded` (DailyMetrics).
2. **Доставка:** outbox-таблица (Single-профиль, без внешнего bus) → целевое — реальный bus (эволюция Cqrs/Ceqrs).
3. **Проекция:** подписчик → инкрементальное обновление MV по событию.
4. **Расписание** (`AnalyticsPrecomputeService`) — только fallback-страховка, не основной путь.

## Схема outbox (Single-профиль)
1. **Outbox** (в Command DB каждого пишущего сервиса): `outbox_events { id, eventType, aggregateId, payload(json), occurredAt, processed }` — пишется в той же транзакции, что и изменение агрегата.
2. **Доставка:** событийный фид `GET /api/v1/{context}/events?since=<checkpoint>` (из outbox) — Analytics тянет **только новые** события (чекпоинт), обновляет MV инкрементально.
3. **Fallback:** `AnalyticsPrecomputeService` (полный пересчёт по расписанию) — страховка на случай пропуска, не основной путь.

## Критерии приёмки
- [ ] MV обновляется инкрементально от событий (не по расписанию).
- [ ] Расписание — fallback (страховка), не основной механизм.
- [ ] Outbox → bus план зафиксирован (эволюция профиля).
