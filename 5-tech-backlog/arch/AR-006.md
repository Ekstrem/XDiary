# AR-006: TechDebt — Analytics MV: schedule → event-driven проекция

- **Статус:** Открыта
- **Приоритет:** P2 (техдолг; schedule — временная заглушка)
- **Источник:** директива PO (MV по событиям); TL 2026-11-03 20:00; BE-026
- **Зависимости:** BE-026 (schedule-заглушка)

## Контекст
BE-026 реализует Analytics MV как `AnalyticsPrecomputeService` (HTTP pull каждые 2 мин). По директиве PO **MV должны обновляться по событиям**; расписание — техдолг (маскирует задержку и потерю событий).

## Задача (переход к event-driven)
1. **События:** `RecordCompleted`/`RecordDeleted` (Journal), `SomaticPointRecorded` (SomaticSeries), `StressRecorded`/`SleepRecorded` (DailyMetrics).
2. **Доставка:** Outbound Handler (Saga/HTTP) в Single-профиле → целевое — реальный bus (эволюция Cqrs/Ceqrs).
3. **Проекция:** подписчик → инкрементальное обновление MV по событию.
4. **Расписание** (`AnalyticsPrecomputeService`) — только fallback-страховка, не основной путь.

## Фазы (PO 2026-11-03)
1. **Сейчас:** `RecordCompleted`/`RecordDeleted` (Journal) → `analytics_summary`/`tops`/`distribution`.
2. **Отложено (соматика):** `SomaticPointRecorded`/`StressRecorded`/`SleepRecorded` → `physio`/`thresholds`/`correlations`/`trends`. После: (а) идентификация/аутентификация (AR-004), (б) проверка загрузки соматики с Garmin.

## Схема (событие = источник истины, по edm-skill)
1. **Command** → `Aggregate.BusinessMethod()` → `IEventBus.Publish(событие)` — команда **не пишет напрямую в БД**.
2. **Event Consumer (IHostedService)** — на каждое событие:
   - Command DB Projector (`SaveEventAsync`) → **Event Store** (источник истины);
   - Read Model Projector (`UpsertAsync`) → локальная MV;
   - **Outbound Handler (Saga/HTTP)** → доставка события соседним сервисам (интеграционное событие).
3. **Analytics** — получает интеграционные события `RecordCompleted`/`RecordDeleted`/`SomaticPointRecorded`/`StressRecorded`/`SleepRecorded` (HTTP) → свой Event Consumer → Read Model Projector → инкрементальное обновление MV.
4. **Fallback:** `AnalyticsPrecomputeService` (schedule) — страховка, не основной путь.
5. **Эволюция EventBus:** Single (InMemory) → Cqrs (Postgres Outbox) → Ceqrs (Kafka) — по таблице профилей edm-skill.

## Payload событий (для проекции Analytics)
| Событие | Payload |
|---|---|
| `RecordCompleted` | `startedAt`, `partners[]` (uuid), `place`, `positions[]`, `tags[]`, `costumes[]`, `toys[]`, `fantasies[]`, `contraceptives[]`, `contraceptiveCount`, `durationMin`, `orgasms[]` `{participant, count, types[], rating}`, `garmin`, `garminId` |
| `RecordDeleted` | `id` (uuid), `startedAt`, `place` |
| `SomaticPointRecorded` | `t`, `hr`, `body_battery` |
| `StressRecorded` | `date`, `stress` |
| `SleepRecorded` | `date`, `sleep` `{score, durationMin, deepMin, lightMin, remMin, awakeMin}` |

## Критерии приёмки
- [ ] MV обновляется инкрементально от событий (не по расписанию).
- [ ] Расписание — fallback (страховка), не основной механизм.
- [ ] Outbound Handler (Saga/HTTP) → bus план зафиксирован (эволюция профиля).
