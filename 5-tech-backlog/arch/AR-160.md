## Факт — корреляция 1:1, проверяемая командой

```
$ git ls-tree --name-only origin/main openapi/
$ for f in openapi/*.json; do jq -c '.servers' $f; done     # (или python)
```

| спек | `servers` |
|---|---|
**journal.json** | **`[{"url": "/"}]`** |
**partners.json** | **`[{"url": "/"}]`** |
api-gateway.json | `[{"url": "/"}]` |
catalog / client / privacy / analytics / daily-metrics / garmin / apple-health / portability / somatic-series | **отсутствует** |

Падают ровно `journal` и `partners` — то есть **те и только те** измеряемые API, у которых в спеке прописан `servers: "/"`. Остальные девять (без `servers`) отвечают корректно (401).

## Механизм

`7-deploy/apim/import.sh` отправляет спеку целиком в Gravitee (`POST …/apis/import`, `{"type":"BOTH","definition": <spec as string>}`). Gravitee берёт `servers[0].url` как базу/endpoint API. При `"/"` получается API без валидного backend-таргета: шлюз принимает запрос и не может проксировать в сервис, поэтому отдаёт `500` **своим** телом (`{"message":"Internal Server Error","http_status_code":500}`) и заголовками `X-Gravitee-*` — ровно то, что мы видим на живом проде.

Косвенно это уже было видно в `7-deploy/apim/import.sh` (комментарий про «definition» и про то, что v2-пути обязаны содержать контекст организации/среды, иначе 500) — то есть мы имеем дело с тем же классом: неверная метаинформация в спеке ломает весь API.

## Задача

1. Убрать `servers` из `journal.json`, `partners.json` и `api-gateway.json` (как в девяти остальных спеках), либо проставить корректный `servers[0].url`, если он нужен по канону;
2. Синхронизировать `_meta.json`/генератор, если `servers` появляется из генерации, а не вписан руками — иначе вернётся при следующей перегенерации;
3. После правки — **ре-импорт** в APIM (`bash 7-deploy/apim/import.sh`, зона @DO) и повторный замер канона.

## Доказательство дискриминатором (2026-11-13 23:3x)

Запрос **несуществующего** пути внутри API — самый чистый тест: корректный шлюз отвечает `401` (auth раньше маршрута) или `404`, но не `500`.

```
GET /api/v1/journal/nonexistent-xyz   → 500
GET /api/v1/partners/nonexistent-xyz  → 500
GET /api/v1/catalog/nonexistent-xyz   → 401
GET /api/v1/privacy/nonexistent-xyz   → 401
GET /api/v1/catalog                   → 401
```

`500` на любой путь внутри `journal`/`partners` = сломан **сам API в шлюзе** (не сервис: сервис отвечал бы 401/404). Совпадает с `servers: "/"` в этих двух спеках.
