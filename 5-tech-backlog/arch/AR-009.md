# AR-009: серверный PIN — legacy или живой контракт (ADR-021 п.3)

- **Статус:** Закрыта
- **Приоритет:** P1 (блокирует 2 задачи: BE-045 и правку спеки `remove-pin`; без решения они противоречат друг другу)
- **Источник:** ADR-021 п.3 (локальный PIN — канон, серверный `/privacy/pin/*` — legacy ADR-008); `ci-front` #10 (`7cbcd3a`) = 3 failed, из них `remove-pin` падает на серверном assert `pin/has = false`; @TL 2026-11-07 (разделение зон: решение — архитектура, реализация — BE, спека — TE)
- **Зависимости:** нет (само решение ни от чего не зависит)
- **Проверяет:** @TL (TechLead)

## Вопрос, который надо закрыть одним вердиктом
В MVP PIN живёт **локально** (`window.Pin`, IndexedDB). Серверный `/api/v1/privacy/pin/*` остался от ADR-008. Сейчас `remove-pin` (E2E) проверяет **серверный** `pin/has` и падает, потому что после снятия PIN серверное состояние не сбрасывается.

Нужно письменно зафиксировать **одно из двух**:

**A. Серверный PIN — живой контракт.** Тогда `DELETE /privacy/pin` и `GET /privacy/pin/has` обязаны быть согласованы (сброс по `deviceId`), это поведение продукта, и его надо держать в CI. → реализация у @BE в `6-msa/`, спека остаётся.

**B. Серверный PIN — legacy (вне MVP).** Тогда продукт на него не опирается, а спека `remove-pin` проверяет несуществующий контракт: её надо перевести в `describe.skip` с причиной и проверять **локальный** `window.Pin` (IndexedDB). → правка у @TE в `9-tests/` (задача TE-037 уже про локальный PIN), @BE ничего не меняет.

Рекомендация @TL: **B** — она соответствует ADR-021 п.3 и не заставляет продукт поддерживать второй источник правды для PIN. Но решение фиксирует @AR, а не исполнитель.

## Что должно быть на выходе (артефакт)
1. Строка в `04-architecture/` (ADR-021 §Решение или отдельный ADR), где явно написано: серверный PIN — **живой** или **legacy**, и что считать источником правды для PIN в MVP.
2. Ссылка на это решение в задачах BE-045 (если A) или TE-037 (если B).

## Вердикт @AR (2026-11-07)
- **B. Серверный PIN — legacy (вне MVP).** Источник правды для PIN — локальный `window.Pin` (IndexedDB); серверный `/privacy/pin/*` — наследие device-токена (ADR-008), продукт на него не опирается.
- `remove-pin` → `describe.skip` + локальная проверка `window.Pin.hasPin()` (TE-037); серверный `pin/has` не чиним (BE-045 → «не делаем»).

## Критерии приёмки
- [x] Вердикт записан в `04-architecture/` (ADR-021 §«PIN: серверный vs локальный»).
- [x] Сказано, что делать с `remove-pin`: **B** — `skip` + локальная проверка `window.Pin`.
- [x] BE-045 → «не делаем» (legacy, вне MVP).

## Результат
- Вердикт **B (legacy)** зафиксирован в ADR-021 §«PIN: серверный vs локальный». BE-045 → «Отклонена», TE-037 → P1 (remove-pin на локальный PIN). Принято TL 06:59.
