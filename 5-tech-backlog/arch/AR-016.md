## Задача

0. **Машиночитаемый индекс создан:** `04-architecture/api-index.yaml` — **79 операций** по 12 BC
   (`method`, `path`, `operationId` = имя действия, `auth`, `codes`, `internal`, `deprecated`).
   Источник: фактические маршруты `6-msa/BC-*/**/*Controller.cs`; `canvases` — ссылка на §2.2 как смысловую часть.
   **Статус:** `draft`; **10 операций `codes_status: verified`** (Client, Journal, Partners, Privacy — по ADR-026/BE-053/BE-064),
   остальные `baseline` (200/400/401 по общему правилу) — их надо сверить с контрактом и тестами.
   **Правило изменения:** правка индекса + гейт в одном коммите; гейт сверяет (1) набор операций == набор в коде,
   (2) у каждой есть `codes`, (3) анонимность только по allow-list (`GET /health` исключён: не контроллер).
1. **Пилот на одном BC** (`BC-Journal` — самый нагруженный): в `03-command-api.md`/`04-query-api.md` для каждого
   эндпоинта указать **`operationId`** из `openapi/journal.json` вместо пересказа полей.
2. Оставить в канвасе то, что OpenAPI не описывает: **бизнес-смысл операции** (зачем она), инварианты, порядок
   шагов визарда — то есть «почему», а не «какие поля».
3. Проверить, что ссылки разрешаются: скрипт/гейт (по договорённости с @DO) — каждый `operationId` из канвасов
   существует в реестре; отсутствующий = красный.
4. После пилота — раскатка на остальные BC (отдельные коммиты, чтобы откат был по компоненту).
