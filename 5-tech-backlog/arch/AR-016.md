# AR-016: канвасы `03-ddd/**` ссылаются на `operationId` реестра контрактов

- **Статус:** ToDo
- **Приоритет:** P2 (второй источник правды: канвас пересказывает поля API)
- **Источник:** ADR-025 §3 п.2 (контракт-first, 2026-11-10); драйвер владельца «расходились спеки архитектора, бэка и фронта»; AR-015
- **Зависимости:** BE-050 (`openapi/*.json` из кода) — без реестра ссылаться не на что; DO-056 (breaking-change гейт)
- **Прорабатывает:** @AR
- **Проверяет:** @TL (техника) + @PO (продуктовые формулировки не ломаются)

## Проблема

Сейчас `03-ddd/*/03-command-api.md` и `04-query-api.md` **пересказывают** поля DTO и пути эндпоинтов руками.
Пока код и канвас живут раздельно, они расходятся — это и есть исходная боль владельца («расходились спеки
архитектора, бэка и фронта»). ADR-023 этап 1 (OpenAPI из кода + drift-check) ловит «код vs APIM», но **не**
«канвас vs код».

## Задача

1. **Пилот на одном BC** (`BC-Journal` — самый нагруженный): в `03-command-api.md`/`04-query-api.md` для каждого
   эндпоинта указать **`operationId`** из `openapi/journal.json` вместо пересказа полей.
2. Оставить в канвасе то, что OpenAPI не описывает: **бизнес-смысл операции** (зачем она), инварианты, порядок
   шагов визарда — то есть «почему», а не «какие поля».
3. Проверить, что ссылки разрешаются: скрипт/гейт (по договорённости с @DO) — каждый `operationId` из канвасов
   существует в реестре; отсутствующий = красный.
4. После пилота — раскатка на остальные BC (отдельные коммиты, чтобы откат был по компоненту).

## Критерии приёмки

- [ ] `BC-Journal`: все эндпоинты канваса ссылаются на `operationId`; поля DTO **не** пересказываются вручную.
- [ ] Гейт «`operationId` из канвасов существует в реестре» — два прогона (найденный/отсутствующий), §5.4.
- [ ] Пилот проверен @TL: изменение контракта в коде → красный гейт **на коммите**, а не через сутки.
- [ ] Решено и записано: раскатываем на все BC (да/нет, в каком порядке).
