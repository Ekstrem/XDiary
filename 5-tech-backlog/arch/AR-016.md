# AR-016: канвасы `03-ddd/**` ссылаются на `operationId` реестра контрактов

- **Статус:** В работе
- **Приоритет:** P2 (второй источник правды: канвас пересказывает поля API)
- **Источник:** ADR-025 §3 п.2 (контракт-first, 2026-11-10); драйвер владельца «расходились спеки архитектора, бэка и фронта»; AR-015
- **Зависимости:** BE-050 (`openapi/*.json` из кода) — без реестра ссылаться не на что; DO-056 (breaking-change гейт)
- **Прорабатывает:** @AR
- **В работе с:** 2026-11-13
- **Проверяет:** @TL (техника) + @PO (продуктовые формулировки не ломаются)

## Проблема

Сейчас `03-ddd/*/03-command-api.md` и `04-query-api.md` **пересказывают** поля DTO и пути эндпоинтов руками.
Пока код и канвас живут раздельно, они расходятся — это и есть исходная боль владельца («расходились спеки
архитектора, бэка и фронта»). ADR-023 этап 1 (OpenAPI из кода + drift-check) ловит «код vs APIM», но **не**
«канвас vs код».

## Задача

0. **Машиночитаемый индекс создан:** `04-architecture/api-index.yaml` — **79 операций** по 12 BC
   (`method`, `path`, `operationId` = имя действия, `auth`, `codes`, `internal`, `deprecated`).
   Источник: фактические маршруты `6-msa/BC-*/**/*Controller.cs`; `canvases` — ссылка на §2.2 как смысловую часть.
   **Статус:** `draft`; **10 операций `codes_status: verified`** (Client, Journal, Partners, Privacy — по ADR-026/BE-053/BE-064),
   остальные `baseline` (200/400/401 по общему правилу) — их надо сверить с контрактом и тестами.
   **Правило изменения:** правка индекса + гейт в одном коммите; гейт сверяет (1) набор операций == набор в коде,
   (2) у каждой есть `codes`, (3) анонимность только по allow-list (`GET /health` исключён: не контроллер).
1. **Пилот на одном BC** (`BC-Journal` — самый нагруженный): в `03-command-api.md`/`04-query-api.md` для каждого
   эндпоинта указать **`operationId`** из `openapi/journal.json` вместо пересказа полей.
2. Оставить в канвасе то, что OpenAPI не описывает: **бизнес-смысл операции** (зачем она), инварианты, порядок
   шагов визарда — то есть «почему», а не «какие поля».
3. Проверить, что ссылки разрешаются: скрипт/гейт (по договорённости с @DO) — каждый `operationId` из канвасов
   существует в реестре; отсутствующий = красный.
4. После пилота — раскатка на остальные BC (отдельные коммиты, чтобы откат был по компоненту).

## Критерии приёмки

- [ ] `BC-Journal`: все эндпоинты канваса ссылаются на `operationId`; поля DTO **не** пересказываются вручную.
- [ ] Гейт «`operationId` из канвасов существует в реестре» — два прогона (найденный/отсутствующий), §5.4.
- [ ] Пилот проверен @TL: изменение контракта в коде → красный гейт **на коммите**, а не через сутки.
- [ ] Решено и записано: раскатываем на все BC (да/нет, в каком порядке).

## Прогресс

**2026-11-13 — пилот Journal выполнен, `3.5` из `10` BC** (счёт BC: 10 контекстов, из них 9 с собственным API):

| BC | Что сделано | Как выглядит |
|---|---|---|
| **Journal** | §2.2.1 «Как атрибут попадает в агрегат через API» — таблица `атрибут → operationId` | пути/коды **не дублируются**, ссылка на `api-index.yaml`; 19 операций Journal переведены в `codes_status: verified` по коду (`JournalController.cs`: класс `[Authorize]`, `WithOwner` → 401/404/403, `Respond` → 200/400) |
| Partners | §10 контракта создания (двухшаговый + запрет молчаливого игнора) | ссылки на `Partners.Register` / `UpdateProfile` |
| Остальные 8 BC | не начаты | нужен тот же шов: таблица `атрибут → operationId` + удаление пересказа DTO |

**Что именно убираем (риск, который закрываем):** в `03-command-api.md`/`04-query-api.md` пересказаны имена полей DTO.
Расхождение «поле есть в доке, нет в коде» мы ловили дважды; после AR-016 единственный источник полей — OpenAPI-реестр
(BE-050) + `api-index.yaml`, а канвас описывает модель и ссылается.
