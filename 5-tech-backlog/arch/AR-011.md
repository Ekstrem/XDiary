# AR-011: Онбординг — имя и пол вместо «создай партнёра» (продуктовое решение с @PO)

- **Статус:** В паузе
- **Приоритет:** **P1** (первый шаг после входа; владелец назвал «нелогичным» дважды)
- **Пауза:** ретро владельца (объявлена 2026-11-09) — работы не ведутся
- **Разблокирует:** решение владельца после ретро
- **Источник:** владелец 2026-11-09 03:5x: «на онбординге я опять должен добавлять партнёра вместо того чтобы написать просто имя и пол. Это не логично»
- **Прорабатывает:** @AR (совместно с @PO)
- **Зависимости:** BE-048/BE-049 (скоуп партнёров), FE-033 (экран «Кто ты?»), ADR-028 (модель «я» и «партнёр», если потребуется)
- **Проверяет:** @PO (продукт) + @TL (техника)

## Проблема
Сейчас после входа обязателен шаг «Кто ты?» → **создать карточку партнёра**, чтобы обозначить себя. Для владельца это нелогично: он ожидает «ввести имя и пол» (или хоть что-то простое) и продолжить. Кроме того, «я» и «партнёр» смешаны в одной сущности (`Partner` с `ClientId` = я), из-за чего возникают вопросы вроде «почему я вижу себя в партнёрах» (см. AR-012).

## Задача
1. **Согласовать модель с @PO:** нужно ли отдельное «профиль клиента» (имя, пол) или «я» остаётся партнёром с флагом `isSelf`.
2. **Дать решение в формате ADR/проектного ответа:** какие поля обязательны на онбординге, что спрашиваем один раз, что можно заполнить позже.
3. **Минимальный онбординг:** имя + пол (+ аватар опционально) → сразу журнал. Партнёр (второй человек) добавляется **позже**, отдельным действием, когда есть кого добавлять.
4. Зафиксировать, что происходит с уже созданными «эго»-партнёрами (миграция/переименование, без потери данных).

## Критерии приёмки
- [ ] Ответ от @PO по продукту (обязательные поля и порядок).
- [ ] Решение по модели «я vs партнёр» — 🟡 **черновик ADR-024, не принято**: бизнес-постановка не подтверждена владельцем.
- [ ] Онбординг проходится **без** создания партнёра; проверено владельцем.
