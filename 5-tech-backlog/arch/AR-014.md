# AR-014: актуализировать ADR-013 и ADR-007 после принятия ADR-023 (APIM)

- **Статус:** Закрыта
- **Приоритет:** P2 (доковый долг: три ADR описывают один контрактный слой по-разному)
- **Источник:** `04-architecture/edm-debt-plan.md`; TD-PROGRAM (владелец 2026-11-09 «закрыть все техдолги»)
- **Зависимости:** ADR-023 уже «Принято»
- **Прорабатывает:** @AR
- **Проверяет:** @TL (непротиворечивость ADL)

## Проблема

После ADR-023 (полный APIM, контракты из git → импорт в APIM) два старых ADR описывают **заменённый** слой:

- **ADR-013** «URL-версионирование `/v1` + OpenAPI как источник правды» — фактически **поглощён** ADR-023: источник правды и версии переезжают в APIM (индекс + lifecycle), а `/v1` остаётся внешним видом.
- **ADR-007** «API Gateway (YARP) + BFF» — при этапе 2 APIM встаёт в путь и маршрутизация меняется; роль YARP (BFF-агрегация vs транспорт) нигде не зафиксирована.

Итог: три ADR про один слой, и на вопрос «где источник правды для API» есть три ответа. Это класс «второй источник правды», который я же и должен ловить.

## Задача

1. **ADR-013** — поле `Заменяет`/`Статус: Заменено` с указанием ADR-023 и одной строкой, **что именно** осталось в силе (`/v1` как внешний путь, аддитивность — да; «OpenAPI в git как единственный источник» — нет, теперь APIM-индекс + drift-check).
2. **ADR-007** — сузить: YARP = **BFF-агрегация** (сводка аналитики), маршрутизация на этапе 2 переходит к APIM; дописать условие, при котором YARP выводится из пути.
3. Проверить, что `04-architecture/ADL/README.md` (таблица) отражает статусы.

## Критерии приёмки

- [x] ADR-013 помечен «Заменено» (с полем «Заменяет: —») и не противоречит ADR-023.
- [x] ADR-007 разводит маршрут и BFF: BFF — под мараторием владельца, YARP = маршрут + путь деградации, «единая точка входа» = край (Caddy/APIM).
- [x] `check_adr.py` на изменённых файлах — `проверено 3, старых с понижением 2, нарушений 0`, rc=0.

## Результат

ADR-013 → **Заменено** ADR-023 (что осталось: внешний `/api/v1` + аддитивность; что нет: «OpenAPI в git — единственный
источник правды»). ADR-007 → раздел «⛔ Мораторий владельца на BFF (2026-11-09)»: новых агрегатов не добавляем,
существующий `GET /api/v1/bff/analytics-summary` — мёртвый код (потребителей нет ни в `8-front`, ни в `9-tests`),
кандидат на удаление; агрегация — в контексте-владельце данных. Из ADR-023 убрано «YARP = BFF».

**Замечание @TL (2026-11-09 21:45) исправлено:** заголовок ADR-007 переименован «API Gateway / BFF» → **«API Gateway (YARP)»** —
чтобы первое, что читают, не противоречило мораторию. Ревью: **принято**.
