# PROD-CHECKLIST: сценарий приёмки на проде «как реальный пользователь» (@TL)

**Когда использовать:** после того как `deploy-prod` выкатит версию с закрытыми блокерами
(`PATCHES.md` п.1–4). Владелец проходит сценарий, @TL фиксирует результат в `FRONT-GREEN.md`.

**Стенд:** прод — `https://ekstrem.github.io/XDiary/` (фронт) → `https://xdiary-vps1.taile0b6ee.ts.net` (API).
Версия должна быть видна в подвале/настройках: **`APP_VERSION`** и `CACHE` в паре (`0.94` ↔ `xdiary-v94`).

## Перед началом (30 секунд)

- [ ] открыть прод-фронт в режиме инкогнито (чистый `localStorage`, чистый Service Worker);
- [ ] проверить `…/health` → **200**, `GET …/api/v1/catalog` **без токена** → **401** (значит защита на месте);
- [ ] в консоли нет красных ошибок на старте.

## Сценарий 1. Первый вход и PIN

- [ ] онбординг «Кто вы?» — имя и пол, профиль «я» сохраняется;
- [ ] установка PIN: ввод и подтверждение, вход после перезагрузки страницы;
- [ ] **негатив:** неверный PIN → понятная ошибка, данные не теряются;
- [ ] смена PIN; снятие PIN (если сценарий разрешён) — приложение остаётся работоспособным.

## Сценарий 2. Запись в журнал (базовый)

- [ ] «+» → мастер открывается **без пустых предзаполнений** (партнёр/место/позиции не подставлены ложно);
- [ ] заполнить поля, сохранить → запись **видна в списке** и в карточке;
- [ ] правка записи → изменения видны; удаление → запись исчезает, список не ломается;
- [ ] отключить сеть и открыть «+» → **видимая** ошибка чтения («Не удалось загрузить…»), а не пустая форма (п.1 `read-paths.md`).

## Сценарий 3. Партнёр (тот, что ломал CI)

- [ ] «Партнёры» → «+» → имя → **«Сохранить»** → **возврат в список**, партнёр в списке (сейчас падает: `FE-045`);
- [ ] правка имени/профиля → сохраняется;
- [ ] **удаление партнёра** → из списка исчезает; повторное удаление не даёт 5xx и не «залипает» (`BE-080`);
- [ ] привязка партнёра к профилю «я» (если используется) — без ошибок.

## Сценарий 4. Каталог, тренды, импорт

- [ ] каталог: добавить позицию по всем `kind` (костюм, игрушка, фантазия, контрацепция) → в списке; архив игрушек работает;
- [ ] тренды: графики строятся, пустые данные показываются как «нет данных», а не как ошибка;
- [ ] импорт CSV: корректный файл импортируется; битый — понятная ошибка разбора, без падения экрана.

## Сценарий 5. Возврат и офлайн

- [ ] перезагрузка вкладки → сессия сохраняется (токен/локальное состояние не теряются);
- [ ] самолётный режим → приложение открывается, явно показывает, что данных нет/они из кэша;
- [ ] выход из режима → данные подтягиваются без ручной очистки.

## Что делать при расхождении

1. Зафиксировать: **экран**, **шаг**, **что ожидалось / что получилось**, консольные ошибки (скрин + текст).
2. @TL заводит карточку с этим описанием (не «не работает», а «на шаге X ожидалось Y, получено Z»).
3. Если расхождение массовое — стоп-кран: фиксируем и останавливаем выкатки до разбора.

## Критерий «сценарий пройден»

Все пункты отмечены **и** ни одного 5xx в консоли/сети за проход. Частичный проход = **не пройден**.
