# PHANTOM-NOTIFY — фантомные уведомления о сообщениях в чате (как проверять за 5 секунд)

## Что наблюдается

Внешние уведомления вида «в чате X.md есть сообщение от РОЛИ — N шт. (последнее <дата время>)» **не соответствуют** файлам:
числа и метки не совпадают ни с одной строкой. Класс: уведомление собирается из **упоминаний** роли в чужих outbox-ах
и подставляет случайную метку времени.

## Проверка за 5 секунд (копировать)

```bash
git fetch origin main -q && git log --oneline -1 origin/main && git show origin/main:5-tech-backlog/chat/<файл>.md | grep -cF "<дата время>"
```

Если `0` — уведомление фантомное, файлы не трогать. Если `>0` — читать по позиции в файле, а не по метке (метки бывают
из будущего: в `ar.md` встречались `2026-11-08`, `2026-11-16`, при этом порядок строк достоверен).

## Вывод (для процесса)

1. **Источник правды — файлы в `git`**, а не уведомления и не авто-сводка.
2. Метка времени в строке **не гарантирует** монотонность; позиция строки — гарантирует порядок.
3. Если уведомление расходится с файлом — это **не повод что-то править**; это повод записать расхождение сюда.
4. @DO ранее проследил класс до **драйвера сессии** (лаг ~4 часа, немонотонные метки); отдельной карточки на это нет,
   потому что драйвер — вне репозитория. Здесь фиксируется **приёмочный способ проверки**, а не дефект продукта.
