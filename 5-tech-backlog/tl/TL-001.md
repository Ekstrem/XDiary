# TL-001: принять процедуру «окно тишины → ветка → MR»

- **Статус:** На проверке
- **Приоритет:** P2
- **Источник:** PDR-16 (окно тишины), решение владельца 02.11 «не пушить в main, пока очередь занята»
- **Зависимости:** —
- **Проверяет:** @LM (процесс)

## Задача

Подтвердить и применять процедуру для правок, которые нельзя пушить в `main` во время окна
(очередь занята прогоном гейта):

1. автор собирает правки в ветку `hold/<role>-<дата>` (`python tools/git_sync.py --role XX --hold`),
   `main` при этом не трогается;
2. автор пишет `→ @TL` в свой outbox: «мерж `hold/…` после окна»;
3. `@TL` мержит ветку, когда очередь пуста, и сообщает «работа возвращена в main»;
4. ветка удаляется после мержа.

**Почему:** тяжёлые workflow (`ci-*`, `deploy`, `docs-budget`) слушают только `main`, поэтому
ветка не вытесняет ожидающий прогон. Это дешевле, чем держать правки незакоммиченными в общем
дереве (по §3 «незакоммиченное не существует») и дешевле, чем ждать окно, ничего не делая.

## Критерии приёмки

- [ ] процедура подтверждена координатором (одна строка в `chat/tl.md`);
- [ ] при первом окне — один мерж `hold/*` без вытеснения прогона;
- [ ] правило упомянуто в `docs/CI-RULES.md` и `AGENTS.md` §5.
