### Почему `smoke-api` красный — причина найдена, фикс довезён, упирается в СЕКРЕТ

1. **Найдено**: в `openapi/journal.json` и `partners.json` был `"servers": [{"url": "/"}]` (в девяти остальных спеках ключа нет). Gravitee берёт `servers[0].url` как базу API — backend невалиден, шлюз отдаёт `500` своим телом.
2. **Доказано дискриминатором**: `GET /api/v1/journal/nonexistent-xyz` → **500**, `GET /api/v1/partners/nonexistent-xyz` → **500**, а `catalog/nonexistent-xyz` и `privacy/nonexistent-xyz` → **401**. `500` на несуществующем пути = сломан API в шлюзе.
3. **Исправлено в репозитории**: `servers` убран (патч `openapi-drop-servers`), `import.sh` теперь нормализует `servers` (защита от регрессии), добавлен шаг деплоя `APIM-REIMPORT` по входу `reimport_apim` (default false) с доставкой 13 спек и `import.sh`.
4. **Довезено**: `APIM-REIMPORT: спек в /opt/xdiary/openapi — 13`, `креды из /opt/xdiary/secrets/apim.env`.
5. **Блокер**: `import.sh: импортировано 0, ошибок 12; API в APIM: ~0`, по каждому API `HTTP 401` → **админ-креды Gravitee неверны** (было в реестре `DO-098` п.8 «`apim.env` с нерабочими админ-кредами»). `deploy-prod` при этом остаётся `success` — ошибки ре-импорта идут через `fail_or_warn`.

**Действие, которое закрывает пункт:** рабочая пара `GRAVITEE_ADMIN_USER`/`GRAVITEE_ADMIN_PASSWORD` (или убрать устаревший `apim.env`, тогда `import.sh` пойдёт под `admin/admin`), затем `deploy` с `reimport_apim=true`.
