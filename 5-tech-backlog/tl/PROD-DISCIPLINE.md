# Прод — не тестовый контур: правило и мои следы

Владелец `2026-11-06`: **«Для тестов тестовый контур. Почему проводится тестирование на проде?»** — вопрос по делу.

## Что я сделал не так

Для проверки дефекта возврата `otpCode` я делал **write-запросы на прод**: `POST /api/v1/clients` тестовыми номерами.
Мотивировка была: дефект проявлялся **именно на проде** (на dev канал-заглушка `000000` и другой образ), и нужно было
подтвердить фактическое тело ответа. **Это объяснение, а не оправдание:** проверка дефекта должна воспроизводиться на
тестовом контуре, а прод — только чтение.

## Мои следы на проде (номера, по которым созданы клиенты)

| Номер | Когда | Что осталось |
|---|---|---|
| `+79998681776` | 23:05 | клиент `unverified`, файлов/записей нет |
| `+79998765586` | 23:05 | клиент `unverified`, файлов/записей нет |
| `+79992350589` | 23:34 | клиент `unverified`, файлов/записей нет |
| ещё 1–2 | ~22:0x | из первой проверки, номера не записал — **это тоже дефект метода** |

Побочный эффект: при живом канале на каждый такой запрос уходил код **в личный Telegram владельца**
(`ChatIdMap` пуст ⇒ все OTP идут админу — штатно по `runbook/otp-delivery.md`).

## Правило (предлагаю в `AGENTS`, зона @LM)

1. **Тестовый контур — dev.** Дефект воспроизводится там; прод для этого не используется.
2. **На проде разрешено только чтение:** `GET /health`, `OPTIONS`/CORS-preflight, проверка версии фронта, `GET`-запросы без записи.
3. **Любой write на проде** (`POST/PUT/DELETE`) — только с явного разрешения владельца, с названной целью и планом очистки;
   после — запись в карточке: что создано, какими номерами/ids, кто уберёт.
4. Если дефект **виден только на проде** — это признак расхождения контура (образ/конфиг), и чинится оно **сведением контуров**,
   а не тестами на проде.

## Что сделать с моими следами

- Клиенты без записей и без подтверждения — безвредны, но не должны оставаться «неучтёнными». Варианты:
  (а) оставить и зафиксировать здесь (номер/дата/кто) — минимум; (б) удалить вместе с OTP-полями —
  решение владельца, потому что удаление на проде тоже write.
- Коды, ушедшие в Telegram по этим номерам, — одноразовые и просрочены (TTL 5 минут), их можно игнорировать.

## Проверено

- Даты и номера выше — из моих собственных прогонов; тело ответа прода (`200`, whitelist) зафиксировано в `OTP-REPORT.md`.
