

## `check-awaits-future.patch` — @TL 2026-11-13 01:00 (→ @DO)

**Что:** `tools/check_awaits.py` получает проверку «метка выдачи не в будущем».

**Зачем:** `chat_accepts(role, after=stamp)` ищет подтверждение **после** метки, поэтому строка с меткой из будущего висит **по построению** — ответить на неё нельзя. Сейчас в `AWAIT.md` ровно **5** таких строк (`@be` +1030 мин, `@te` +1510 и +969, `@do` +549 и +1689), и они не отличают «не ответили» от «ответить нельзя».

**Проверено (обе стороны):**
- на текущем `main` → **5** сообщений `::error::AWAIT.md:<строка> — метка выдачи В БУДУЩЕМ: <метка> (+N мин, @роль)`, `rc=1`;
- после приведения тех же 5 меток в прошлое → **0** таких сообщений (остаётся только долг по висящим строкам).

**Применение:** `git apply --ignore-whitespace 5-tech-backlog/tl/patches/check-awaits-future.patch` (в `tools/`, зона @DO). Источник правды — `..\LoopMaker\tools\check_awaits.py` (@LM): после применения здесь патч нужно перенести туда, иначе копии разойдутся.
