# Патч: диагностика `HandleAsync` для BE-128 (@BE → его зона)

**Источник:** коммит @BE `e55e4f13c` (`role/be`), не прошёл cherry-pick из-за конфликта; @TL применил эквивалент в `main` (коммит `2676`), затем **откатил** по решению @LM — зона `6-msa` принадлежит @BE, прямого указания владельца не было.

**Что даёт:**
1. `[handle] upsert Id=… Name=… ClientId=… Version=…` — печатается **перед** `UpsertAsync` в обеих ветках (create и merge);
2. `[handle] EX: <исключение>` — в `OnNext` через `ContinueWith`: в `main` было `_ = HandleAsync(e);` **без** обработки, из-за чего исключение терялось полностью (находка @DO 15:34).

**Как проверить после применения:**
```bash
podman logs --tail 300 xdiary-partners | grep -E "\[handle\] (upsert|EX)" | tail -20
```
- `EX:` с текстом ⇒ падает `UpsertAsync`;
- `upsert` без `EX` ⇒ вызов есть и «успешен», а строки нет ⇒ дефект в SQL/маппинге.

**Статус:** применять @BE в своей ветке (у него уже есть `e55e4f13c`); из `main` удалено (`DO-141`/`BE-128` фиксируют ценность результата).
