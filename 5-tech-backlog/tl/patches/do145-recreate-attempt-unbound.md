**`journal` тут не виноват.** Новый readiness-цикл (`while ... __ok`), добавленный в `#2805`, оставил **мёртвый хвост старого цикла** (строки 351–380): `if true; then … say "попытка $attempt …"; attempt=$((attempt+1)); sleep 5; done`. При таймауте (`__ok=0`) управление уходит в этот хвост, а `$attempt` не инициализирован ⇒ `set -u` бросает `unbound variable` ⇒ скрипт выходит с ошибкой ⇒ `update.sh` печатает «не поднялся».

## Что делает патч

Убирает мёртвый хвост и оставляет один корректный блок «успех» (15 строк вместо 30):

```
if [ "$__ok" = "1" ]; then
  say "  OK: $CONTAINER пересоздан"
  check_hosts "$SVC" || exit 1
  if [ "$SVC" = "api-gateway" ]; then
    ... проверки /health и /api/v1/clients (200/401, POST 200/201/400/401) ...
  fi
  exit 0
fi
```

Ничего не добавляет по смыслу — только удаляет дублирующую/недостижимую ветку, из-за которой падал скрипт.
