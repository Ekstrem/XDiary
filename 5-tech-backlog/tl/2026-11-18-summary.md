## Главный результат

**Весь день не работала доставка кода на стенд.** Не из-за кода, а из-за двух независимых механических причин, и обе устранены:

1. **`lock-sync` не мог обновить `images.lock`** — при смене релизного тега `merge_digests` не переносит digest (другой тег) ⇒ 12 digest-строк → 0 ⇒ гейт `DO-113` откатывал lock. Фикс: шаг `gen_images_lock.py --fill-digests` перед Guard (PR `#2649`, автор @DO по нашему патчу; симуляция «без патча rc=1, с патчем rc=0» — в `tl/patches/lock-sync-fill-digests.md`).
2. **`GH006: Protected branch update failed`** — защита `main` не пускала пуш `github-actions[bot]`. Фикс: `lock-sync` переведён на **ветку + PR** (PR `#2682`, @DO), плюс `env: GH_TOKEN` (моего ревью не хватало — без него `gh pr create` падает).

После этого `lock` доехал до **`single-9b7f2fa`** (12 digest-строк), и фикс кода впервые оказался на стенде.

## `BE-128` — ЗАКРЫТ по факту (подтверждён замером)

Корень: **двойная запись события**. `BusAdapter.cs:33-34` уже делает `SaveEventAsync` + `PublishAsync`, а `PartnerEventHandler.HandleAsync:74` сохранял **то же событие второй раз** ⇒ дубликат ключа ⇒ исключение уходило в отброшенную задачу (`OnNext` был `_ = HandleAsync(e);` без `ContinueWith`) ⇒ до `UpsertAsync` управление не доходило.

Почему искали долго: все наблюдаемые симптомы (пустой `partners_read`, `GET /partners` = 0, `link-client` 404, «чистые логи») **совместимы** и с проекцией, и с фильтром, и с лагом. Развели только данные из БД (@DO) + локальный прогон на живой БД (@BE).

Фикс @BE: `5cb5b513e`, узким PR `#2688`. **Проверено на стенде:** `GET /partners` → 200 с **1 элементом** (весь день было 0), `GET /partners/{id}` → **200** (было 404).

**Корни двух оставшихся 500:**
1. **`BE-130`** — найден @DO из Kestrel-лога: `InvalidOperationException: The instance of entity type 'DomainEventEntry' cannot be tracked because another instance with the same key value for {'Id','Version'} is already being tracked` ⇒ EF-tracking в пути `LinkClient`; фикс — `AsNoTracking`/detach/без повторного attach + проверить инкремент `Version`.
2. **`BE-129`** — три слоя диагностики не дали текста (`[replay] EX`, `[journal] EX` = 0; лог `journal` чист). Причина слепоты найдена: в `BC-Journal` **два** `IAggregateProvider` (`RegisterDependencies.cs:17` → `AggregateProvider` с библиотечным `GetById`; `Program.cs:53` → `RecordAggregateProvider` с нашим `RecordEventReplay`). Остался один эксперимент: прямой вызов `journal` **с токеном** (без токена — 401): 200 ⇒ виноват APIM, 500 ⇒ сервис и нужен лог middleware.

**Три инфраструктурные причины красных прогонов, которые маскировались под «дефект кода»:**
`lock-sync` терял digest → `GH006` (бот не мог пушить) → `smoke-*` стартует раньше, чем контейнеры поднялись (`Up 4s` → 5xx). Все три закрыты или заведены карточками.
