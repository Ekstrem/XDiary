# 5-tech-backlog — технический бэклог (задачи)

Зона ответственности: этот агент. Задачи формируются из артефактов:
- `01-user-stories` + `02-cjm` (PO) — «что нужно пользователю».
- `03-ddd` (DDD) — ограниченные контексты, агрегаты, Command/Query API, MV.
- `04-architecture` (архитектура) — ADR, C4, размер ВМ.

## Структура
- `front-end/` — задачи фронтенда (PWA).
- `back-end/` — задачи бэкенда (10 микросервисов + шлюз YARP).
- `devops/` — задачи инфраструктуры (ВМ, podman, PostgreSQL, сеть, CI).
- `tester/` — задачи тестирования.
- `arch/` — задачи архитектору (пробелы/уточнения ADL).
- `chat/` — outbox-чат ролей (каждая роль пишет только в свой файл).

## Формат задачи
Каждая задача — отдельный `.md` с уникальным ID:
- `FE-xxx` — front-end
- `BE-xxx` — back-end
- `DO-xxx` — devops
- `TE-xxx` — tester

Обязательные поля: **Статус, Приоритет, Источник (трассировка), Задача, Критерии приёмки**.

## Статусы
`Открыта → В работе → На проверке → Закрыта` (или `Отклонена`).

## Процесс
1. Агент формирует задачи из артефактов 01/03/04 (трассировка в поле «Источник»).
2. Исполнители берут задачи, меняют статус, фиксируют результат.
3. Агент **раз в час** проверяет папку: сверяет закрытые задачи с критериями приёмки, координирует исполнителей, задаёт вопросы.

## Связь с артефактами (трассировка)
| Папка-источник | Что берём для задач |
|---|---|
| `01-user-stories` | US/инкременты (приоритет, «что» и «зачем») |
| `03-ddd` | BC-канвасы: агрегат, Command API, Query API, MV |
| `04-architecture` | ADR (сервисы, профиль, шина, шлюз, деплой), C4, vm-sizing |
