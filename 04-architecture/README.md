## Границы зоны @AR (решение владельца, 2026-11-11)

Владелец: «а почему архитектор вопросами данных на стендах занимается? отклоняй все вопросы которые вне архитектуры».

**@AR отвечает на вопросы «что и почему в модели/контракте/границе»:**
- ADR, канвасы, контексты, инварианты, контракты API (смысл операций, `operationId`, коды ответа как **часть контракта**);
- границы контекстов и сервисов, реестр контрактов и правила его изменения, гейты **соответствия контрактов**;
- архитектурные решения по данным — **что** должно быть в модели (например `ClientId` у записи) и **какая миграция** требуется.

**@AR НЕ занимается (перенаправлять, не отвечать):**
| Запрос | Кому |
|---|---|
| прогоны на стендах, числа строк, размеры бэкапов, `pg_dump`/`DELETE`/сверки | **@DO** |
| деплой-чек-листы, CI-логи, пересборка образов, `grep` по DLL | **@DO** |
| код агрегатов/валидаторов, карточки задач и их статусы | **@BE / @TL** |
| продуктовые формулировки, поля экранов, «а как лучше для пользователя» | **@EX** (продуктовые ответы) |

**Правило факта:** если для решения нужна цифра со стенда — её снимает владелец контура (@DO/@TE) и присылает
**с меткой контура** (`dev`/`prod`, дата, кто мерил). Формулировка правила — **одна**: §14 `5-tech-backlog/tl/ITERATION-PLAN.md`
(«что / объект / инструмент+режим»); здесь — только применение к замерам, без пересказа. На этом 2026-11-11
построилась ложная тревога «2391 запись исчезнет», где 2394 были **dev**, а на проде было **6** уже удалённых строк.

**Как отклонять:** короткая строка в чат «не моя зона → @DO/@BE/@TL, вопрос: …» и, если это влияет на модель,
явно сказать, **какое решение** от меня всё-таки нужно (например: «нужен только ответ: владелец обязателен у новых
записей — да/нет», без обсуждения процедуры).
