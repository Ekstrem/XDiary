## Границы зоны @AR (решение владельца, 2026-11-11)

Владелец: «а почему архитектор вопросами данных на стендах занимается? отклоняй все вопросы которые вне архитектуры».

**@AR отвечает на вопросы «что и почему в модели/контракте/границе»:**
- ADR, канвасы, контексты, инварианты, контракты API (смысл операций, `operationId`, коды ответа как **часть контракта**);
- границы контекстов и сервисов, реестр контрактов и правила его изменения, гейты **соответствия контрактов**;
- архитектурные решения по данным — **что** должно быть в модели (например `ClientId` у записи) и **какая миграция** требуется.

**@AR НЕ занимается (перенаправлять, не отвечать):**
| Запрос | Кому |
|---|---|
| прогоны на стендах, числа строк, размеры бэкапов, `pg_dump`/`DELETE`/сверки | **@DO** |
| деплой-чек-листы, CI-логи, пересборка образов, `grep` по DLL | **@DO** |
| код агрегатов/валидаторов, карточки задач и их статусы | **@BE / @TL** |
| продуктовые формулировки, поля экранов, «а как лучше для пользователя» | **@EX** (продуктовые ответы) |

**Чек-лист перед любым новым решением (мой собственный провал, 2026-11-14).** Прежде чем писать ADR или
архитектурный документ, три проверки — по порядку, с командой:

1. **Решение уже принято?** `git grep -n -i -e "<тема>" origin/main -- 04-architecture/ADL` — если есть ADR,
   то новое решение **не пишется**: либо работа идёт по нему, либо это **уточнение** с явной ссылкой.
2. **Отклонение уже описано?** `04-architecture/edm-verification.md` (EDM-скан), `03-ddd/TECHDEBT.md` — если пункт
   там есть, то моя работа — **ссылка + объём работ**, а не новый документ.
3. **Это gap в коде или в решении?** Gap в коде (код не соответствует ADR) → задача исполнителю (@BE/@DO).
   Gap в решении (вопроса действительно не решали) → ADR. **Смешивать нельзя** — именно это я и сделал.

**Четвёртая проверка — источник:** у ADR должен быть источник — **карточка** или **прямой вопрос владельца**. «Переписка ролей» и «я заметил в коде» источником не являются: сначала карточка (Идея/На проработке), потом ADR. ADR без источника — это решение, которое никто не заказывал.

**Как это выглядело 2026-11-14:** нашёл, что шина событий — заглушка, и написал «новое» решение про доставку.
При этом: **ADR-003** (Event Store = источник истины, `FullEventSourcing`) и **ADR-005** (шина InMemory, «межсервисные
связи через HTTP/шлюз») уже отвечали на вопрос, а **`edm-verification.md` п.1–3** (аудит от 2026-11-02) уже описывал
ровно это отклонение. Итог: два переписывания документа, удалённый дубль, три смены указаний у @TL. Цена — моя.

**СРОЧНОЕ требование владельца (2026-11-16): чек-лист архитектора на каждый раунд** — `04-architecture/round-checklist.md`.
Перед сдачей любого артефакта обязательны **два** блока проверок: (1) **EDM/DF skill** — нет своей инфраструктуры,
команда не пишет БД напрямую, Event Store реально используется, консьюмер+хендлер зарегистрированы, чтение через MV;
(2) **ADL** — гейт ADR зелёный, решение не дублируется, «Связанные решения» заполнены, **исключение живёт в ADR, а не
в инструменте** (урок `6-msa/Shared`), бюджет доков в норме. Результат — строкой в outbox: `чек-лист: EDM/DF — <команда → вывод>, ADL — <команда → вывод>`.
Красный пункт = артефакт не сдаётся.

**Правило факта:** если для решения нужна цифра со стенда — её снимает владелец контура (@DO/@TE) и присылает
**с меткой контура** (`dev`/`prod`, дата, кто мерил). Формулировка правила — **одна**: §14 `5-tech-backlog/tl/ITERATION-PLAN.md`
(«что / объект / инструмент+режим»); здесь — только применение к замерам, без пересказа. На этом 2026-11-11
построилась ложная тревога «2391 запись исчезнет», где 2394 были **dev**, а на проде было **6** уже удалённых строк.

**Как отклонять:** короткая строка в чат «не моя зона → @DO/@BE/@TL, вопрос: …» и, если это влияет на модель,
явно сказать, **какое решение** от меня всё-таки нужно (например: «нужен только ответ: владелец обязателен у новых
записей — да/нет», без обсуждения процедуры).

| Гейт | Что ловит | Где в CI | Плечо на дефекте |
|---|---|---|---|
| `check_api_index.py` (+ `--require-request`) | коды/атрибуты/`auth`/`request_rule`/ссылки канвасов/копипасту `verification` | `ci-guards.yml:146` | `POST` без `request` ⇒ `rc=1`, ровно 1 `::error::(AR-022)` |
| `check_apim_drift.py --specs-only` | состав и коды индекса против `openapi/` (внутренние маршруты исключены с обеих сторон) | `apim-drift.yml` | — (проверено @DO) |
| `gen_openapi.py --check` | **валидность YAML** канона + дрейф `openapi/` | `ci-guards.yml:147` | незакрытая кавычка в `verification` ⇒ `ParserError`, `rc=1` |
| `check_paths.py --range` | выход роли из зоны (`loop.config.json`) | `guard-paths.yml:76` | коммит вне зоны ⇒ `rc=1` с именем файла |

### Гейты, которые **не удерживают** своё состояние (замер 2026-11-11 01:45, REF `60aed4750`)

Три случая, где гейт зелёный, а инвариант не удерживается. Они не «в CI», а рядом с CI — и потому не видны в таблице выше.

| Что | Факт | Почему нельзя считать закрытым |
|---|---|---|
| неизменяемость образа (`ADR-027`, `ADR-035`, `DO-113`) | в `7-deploy/images.lock` сейчас **13** строк, `sha256:` — **0**, `commit=` — **0** | работа была сделана (`e45f95f1a`: 12 digest), но `lock-sync` (`e198a6bb9`, `61f16284c`, `12eb5aa86`) перезаписал файл: путь `--from-registry --write` (`tools/gen_images_lock.py:517`) не пишет ни `digest=`, ни `commit=`; `fill_digests()` — отдельный шаг, в `--write` не вызывается. Условие: **`--write` сохраняет поля или падает `rc=1`** |
| «не измерено ≠ ок» (`check_workflow_paths`) | `--selftest` **нет** (`rc=2`), без PyYAML → **`rc=0`** «пропускаю» | при отсутствии зависимости гейт не отличает «нарушений нет» от «не измерено». Образец правильной семантики в репозитории уже есть: `check_probe_freshness` без токена → **`rc=2`** «НЕ ИЗМЕРЕНО» (`AR-023`) |

| «предупреждение = перевод» (`check_edm`, критерий `BE-057`) | `tools/check_edm.py` → **`rc=0`** при «BC 11, **с маркером 0**, не переведены **11**, предупреждений 11» | гейт печатает «не переведены 11» как **warning**, поэтому критерий «все BC проходят `check_edm`» выполняется **при нуле переведённых**. Второй счётчик (регистрация `AddEventStorePostgres` в `Program.cs`) даёт **2 из 11** — числа расходятся, и карточка может закрыться по зелёному. Требование: «не переведены N>0» → `rc=1`, либо критерий мерить регистрацией, а не гейтом |

**Правило, которое из этого следует:** гейт проверяется не только «краснеет ли на дефекте», но и «**удерживается ли состояние, которое он подтвердил**». Иначе любой автогенератор отменяет вердикт через три минуты после коммита — и карточка закрывается «на момент коммита».

**Что это меняет для правки канона:** сломанный YAML или потерянный `request` теперь **не пройдут** CI — но только если правка идёт через CI. Локально их по-прежнему надо гонять самому
(`check_nul` ловит только управляющие символы и маркеры конфликта, **не** YAML).
