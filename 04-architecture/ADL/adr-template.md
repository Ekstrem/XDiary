# ADR — шаблон (минимальный скелет для проекта)

> **Полный канон:** `LoopMaker/templates/adr.md` (LoopMaker приватный — из XDiary недоступен).
> Скелет соответствует гейту `tools/check_adr.py` — «скопировал → заполнил → гейт зелёный».

## 0. ПЕРЕД РЕШЕНИЕМ — три команды, без них ADR не пишется

> Появилось после двух моих ошибок 2026-11-14: ADR-029 дублировал ADR-003/005 + `edm-verification.md`, а ADR-028
> не имел ни карточки, ни вопроса владельца. Причина одна — **писал из памяти/переписки, а не из документов**.

```bash
# Работает и в bash, и в PowerShell — используем git grep (git есть везде), не grep.
# 1) Решение уже принято? (ключевые слова темы, а не название ADR)
git grep -n -i -e "<термин>" -e "<синоним>" -- 04-architecture/ADL 04-architecture/edm-verification.md 03-ddd/TECHDEBT.md
#    нашлось → ADR НЕ пишем: работаем по нему либо делаем «уточняет ADR-XXX» с явной ссылкой

# 2) Отклонение кода уже описано? (EDM-аудит / реестр техдолга)
git grep -n -i -e "<термин>" -- 04-architecture/edm-verification.md 03-ddd/TECHDEBT.md
#    нашлось → это gap в КОДЕ: задача исполнителю (@BE/@DO), а не ADR

# 3) Источник решения существует?
git grep -n -e "AR-" -e "BE-" -e "DO-" -- 5-tech-backlog | grep -i "<термин>"
#    пусто → сначала карточка (Идея/На проработке) или прямой вопрос владельца, потом ADR
```

**Проверено на живом примере (2026-11-14), что команды ловят дубликат:** для темы «доставка событий» шаги 1–2 дают
`ADR-003`, `ADR-005`, `edm-verification.md` — то есть ADR-029 не надо было писать; а шаг 3 по той же теме даёт
**пусто** (карточки не было).

**Правило-итог:** если (1) пусто **и** (2) пусто **и** (3) есть — ADR пишется. Иначе — не пишется.
Не «переписка ролей» и не «я заметил в коде»: это не источник.

**Предусловия владельца (2026-11-14, `AGENTS` §5.2) — обязательны, отдельного разрешения не требуется:**
(1) **сверка с логом** — три команды выше, с результатом **в самом ADR** (что нашлось / чего нет);
(2) **поле «Связанные решения»** — если ADR того же типа существует: **почему меняется** и **соответствует ли
комплаенсу прошлого** (§3.3 старого ADR). Молча «улучшать» принятое решение нельзя. **Поле обязательно всегда:**
нет связанных решений — пишем `— (ADR того же типа нет)`; **пусто = ADR не пишется**; если сослаться не на что,
ADR идёт владельцу (это единственное исключение из свободы архитектора).
**Ревьюер — владелец:** его вердикт — **первая строка** протокола, остальные роли — после.

# ADR-NNN: {Название}
- **Статус:** Предложено
- **Дата:** 2026-11-09  ← **образец формата.** Подставь реальную дату решения в формате `YYYY-MM-DD`.
  Плейсхолдеры из шаблона (`YYYY-MM-DD`, `{…}`, `…`) **оставлять нельзя**: гейт `check_adr` справедливо покраснеет,
  и это не «гейт против шаблона», а незаполненный документ. Проверено тремя прогонами (2026-11-09): шаблон
  с **реальной** датой → `rc=0`; с литералом `YYYY-MM-DD` → `rc=1`, «поле «Дата» не в формате YYYY-MM-DD».
- **Источник:** {номер карточки `AR-/BE-/DO-/FE-/TE-NNN` ИЛИ цитата прямого вопроса владельца с датой}  ← обязательное поле
- **Связанные ADR:** {номера}  ← обязательное поле
- **Связанные решения:** {ADR-XXX → почему меняется → комплаенс прошлого (§3.3): соответствует/отступает и почему}  ← **обязательное поле всегда**; если ADR того же типа нет — писать `— (ADR того же типа нет)`; **пустое поле = ADR не пишется** (или идёт владельцу, если сослаться не на что)
- **Заменяет:** — (или ADR-XXX, если пересмотр)
- **Владелец решения:** @роль

### Протокол согласования — **итог: кворум собран / не собран**

| Роль | Принял | Отклонил | Комментарий, условие |
|---|---|---|---|
| @TL (координатор) | ✅ да, YYYY-MM-DD HH:mm | — | что именно он требует или чем обусловлен голос |
| @BE (сервисы) | ✅ да, YYYY-MM-DD HH:mm | — | зона ответственности, если голос её касается |
| @AR (архитектор) | ✅ да — выбранный вариант | варианты «нет» отклонены | автор документа |
| @EX (владелец) | ⏳ ждёт вердикта | — | финальный голос; после него статус `Принято` |
| **ИТОГ** | **N голоса «за» — кворум** | **0** | кворум = 3 из 5; голосуют только затронутые роли |

**Правило кворума (владелец, 2026-11-05):** голосуют **только роли, которых решение затрагивает**; роли вне домена
на кворум **не влияют**. **Кворум = 3 согласования из 5.** Их голоса, если даны, фиксируются в таблице, но кворум
не задерживают.

## 4. Последствия

### Влияние на другие ADR — только смена статуса

По правилу владельца (2026-11-05): старые ADR не переписываются — меняется только **статус**
(`Пересмотрен (дата)` / `Отменён (дата)`) и поле **`Последствия`**. Ниже — какой статус получит
каждый прошлый ADR после принятия этого ADR.

| Старый ADR | Статус после принятия | Что для читателя |
|---|---|---|
| ADR-XXX «…» | `Пересмотрен (дата)` / `Отменён (дата)` | … |

### Реестр задач — таблица с колонкой «Задача»

**Правило владельца (2026-11-05):** ADR несёт **реестр работ** — что делать, кем, по какому критерию,
от чего зависит. Колонка **«Задача»** есть в таблице **с самого начала**: до принятия она пустая,
после принятия в неё вписываются **номера карточек**. То есть место под задачи существует заранее —
номер не «придумывается потом», а вписывается на prepared место.

| # | Работа (что сделать) | Ответственный | Критерий приёмки | Зависит от | Задача |
|---|---|---|---|---|---|
| 1 | … | @DO | … | — | (после принятия: `DO-NNN`) |
| 2 | … | @BE | … | 1 | (после принятия: `BE-NNN`) |

**Порядок:** @AR пишет реестр в `Предложено` (колонка «Задача» пустая) → ADR принимается (кворум +
владелец) → задачи заводятся в доске → @AR вписывает номера в колонку «Задача» в том же коммите, где
уточняется `Последствия`.

**Признак «не заведено»:** у принятого ADR в колонке «Задача» пусто или `___`. Исключение — ADR, который
работ не порождает: тогда в таблице одна строка `— (работ не порождает)`, и это осознанное утверждение.
