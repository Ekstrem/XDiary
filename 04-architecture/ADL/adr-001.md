# ADR-001: Разбиение на микросервисы

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 002, 006, 007, 009
- **Бэклог:** Инк 1..9 (TOBE «микросервисы на основе DDD»)

## Контекст
Сейчас — монолитная PWA (IndexedDB + локальный прокси). Цель — микросервисы на .NET (EDM/CEQRS). В `03-ddd` выделено 10 ограниченных контекстов.

## Решение
**Один ограниченный контекст = один микросервис** — 10 микросервисов (имена — по домену, без `-svc`):

| Сервис | Контекст | Агрегат | Роль |
|---|---|---|---|
| `journal` | Журнал интимной активности | Record | Core / Execution |
| `partners` | Партнёры | Partner | Execution |
| `catalog` | Каталог и инвентарь | CatalogItem | Execution |
| `somatic-series` | Соматика — минутные точки | SomaticPoint | Execution |
| `daily-metrics` | Дневные метрики | DailyMetrics | Execution |
| `garmin-gateway` | Шлюз Garmin | GarminSync | Gateway |
| `apple-health-gateway` | Шлюз Apple Health | AppleImport | Gateway |
| `analytics` | Аналитика | — (read-only) | Analysis |
| `privacy` | Приватность и доступ | PinCredential | Execution (Gatekeeper) |
| `portability` | Переносимость данных | CsvDocument | Execution |

**Обоснование:** строгая изоляция по контекстам; профиль Single (ADR-002) делает каждый сервис лёгким (1 процесс, InMemory).

## Последствия
- **Плюсы:** изоляция, независимая деплойность, чёткая граница владения.
- **Риски:** 10 сервисов — больше координации; единая точка входа через шлюз (ADR-007).
