# ADR-001: Разбиение на микросервисы

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 002, 006, 007, 009
- **Бэклог:** Инк 1..9 (TOBE «микросервисы на основе DDD»)

## Контекст
Сейчас — монолитная PWA (IndexedDB + локальный прокси). Цель — микросервисы на .NET (EDM/CEQRS). В `03-ddd` выделено 10 ограниченных контекстов.

## Решение
**Один ограниченный контекст = один микросервис** — 10 микросервисов:

| Сервис | Контекст | Агрегат | Роль |
|---|---|---|---|
| `journal-svc` | Журнал интимной активности | Record | Core / Execution |
| `partners-svc` | Партнёры | Partner | Execution |
| `catalog-svc` | Каталог и инвентарь | CatalogItem | Execution |
| `somaticseries-svc` | Соматика — минутные точки | SomaticPoint | Execution |
| `dailymetrics-svc` | Дневные метрики | DailyMetrics | Execution |
| `garmin-gateway-svc` | Шлюз Garmin | GarminSync | Gateway |
| `applehealth-gateway-svc` | Шлюз Apple Health | AppleImport | Gateway |
| `analytics-svc` | Аналитика | — (read-only) | Analysis |
| `privacy-svc` | Приватность и доступ | PinCredential | Execution (Gatekeeper) |
| `portability-svc` | Переносимость данных | CsvDocument | Execution |

**Обоснование:** строгая изоляция по контекстам; профиль Single (ADR-002) делает каждый сервис лёгким (1 процесс, InMemory).

## Последствия
- **Плюсы:** изоляция, независимая деплойность, чёткая граница владения.
- **Риски:** 10 сервисов — больше координации; единая точка входа через шлюз (ADR-007).
