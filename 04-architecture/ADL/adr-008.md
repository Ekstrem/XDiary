# ADR-008: Аутентификация и авторизация

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 007, 009
- **Бэклог:** Инк 2 (US-11 PIN); F2 (PIN/биометрия)

## Контекст
Сейчас приватность — локальный PIN (PBKDF2-SHA256) на устройстве. С появлением бэка нужна защита API (контекст «Приватность и доступ»).

## Решение
**JWT** (краткоживущий access + refresh), два пользователя в одном issuer (простая identity-служба на шлюзе). Локальный **PIN остаётся** как дополнительный слой на устройстве.

**Обоснование:** серверной аутентификации достаточно JWT при приватном деплое; PIN сохраняет текущий UX (блокировка приложения).

## Последствия
- **Плюсы:** стандарт, stateless-проверка на шлюзе.
- **Риски:** хранение refresh-токенов, ротация секретов.

## Проверки
- Кросс-ссылка: текущий PIN — `app/js/pin.js` (Pin.setPin/verifyPin/removePin, store `meta.pin`); на бэке — контекст «Приватность и доступ».
- Согласовано с ADR-007 (шлюз проверяет JWT), ADR-009 (identity в контейнере шлюза).

## Уточнения (2026-11-01, по BE-019/BE-020)
- **PIN опционален:** JWT (device-токен) выдаётся и **без PIN** (`IssueDevice`); PIN — локальный замок (re-auth на Lock/Unlock), а НЕ условие выдачи токена.
- **Анонимные эндпоинты (без JWT, по `ApiGateway/Program.cs:39-44`):** `/health`, `/api/v1/privacy/token`, `/api/v1/privacy/verify-token`, `/api/v1/privacy/pin/has`, `/api/v1/privacy/pin/set`.
- **`pin/set` при уже установленном PIN:** шлюз пропускает (анонимно), но сервис требует `CurrentPin` — иначе 401 (BE-020).
- **Требуют JWT:** всё остальное `/api/v1/**`, включая `pin/change`, `pin/remove`, `pin/lock`, `pin/unlock`.

## Уточнение (2026-11-05, AR-008)
- **PIN per-client:** `PinCredential` хранит `clientId` (чей PIN) — один PIN на клиента, а не синглтон на развёртывание. Согласовано с ADR-021 (multi-user). Миграция: `pin_credential` + `client_id`.

## Уточнение (2026-11-05, BE-038)
- **JWT валидируется в каждом сервисе** (`AddJwtBearer`, общий `Jwt:SigningKey`, issuer `xdiary`, audience): сервис берёт `sub = clientId` для скоупа по клиенту (PIN/Garmin/Apple per-client).
- **Defense-in-depth:** шлюз режет невалидный JWT на краю (ADR-007/008), сервис валидирует сам для извлечения `sub` — заголовку `X-Client-Id` без подписи **не доверяем** (подделает любой во внутренней сети).
