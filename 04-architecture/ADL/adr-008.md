# ADR-008: Аутентификация и авторизация

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 007, 009
- **Бэклог:** Инк 2 (US-11 PIN); F2 (PIN/биометрия)

## Контекст
Сейчас приватность — локальный PIN (PBKDF2-SHA256) на устройстве. С появлением бэка нужна защита API (контекст «Приватность и доступ»).

## Решение
**JWT** (краткоживущий access + refresh), два пользователя в одном issuer (простая identity-служба на шлюзе). Локальный **PIN остаётся** как дополнительный слой на устройстве.

**Обоснование:** серверной аутентификации достаточно JWT при приватном деплое; PIN сохраняет текущий UX (блокировка приложения).

## Последствия
- **Плюсы:** стандарт, stateless-проверка на шлюзе.
- **Риски:** хранение refresh-токенов, ротация секретов.

## Проверки
- Кросс-ссылка: текущий PIN — `app/js/pin.js` (Pin.setPin/verifyPin/removePin, store `meta.pin`); на бэке — контекст «Приватность и доступ».
- Согласовано с ADR-007 (шлюз проверяет JWT), ADR-009 (identity в контейнере шлюза).
