# ADR-018: Отсутствие изоляции по пользователям — by design (пара = единое пространство)

- **Статус:** Принято
- **Дата:** 2026-11-01
- **Связанные ADR:** 008 (JWT/аутентификация), 001 (контексты)
- **Бэклог:** —

## Контекст
Тестировщик (@TE) отметил отсутствие `UserId`/`OwnerId` в `Partners`/`Journal` — нет изоляции данных между пользователями. Вопрос: это баг или by design.

## Решение
**Изоляции по пользователям НЕТ — это by design.** Приложение — приватный дневник **одной пары** (2 устройства, единое пространство данных):
- JWT/device-токен идентифицирует **инстанс (пространство пары)**, а не отдельных пользователей.
- `Partner` и `partners[]` (в Record) — **доменные данные** (кто участвовал в сессии), а НЕ учётные записи пользователей.
- Все данные (журнал, партнёры, каталог, метрики) — **общие** для пары.

## Обоснование
- US/CJM: пара ведёт общий дневник; данные не разделяются по партнёрам.
- Один JWT на инстанс (device-токен, ADR-008) + опциональный PIN (локальный замок) — достаточно.

## Последствия
- Нет мультитенантности, нет per-user разделения данных.
- Если появится вторая пара (многоарендность) — потребуется пересмотр: ввести `Tenant`/`Space` + скоупинг по нему.

## Проверки
- `Partners`/`Journal` не содержат `UserId`/`OwnerId` — осознанно, а не по недосмотру.
