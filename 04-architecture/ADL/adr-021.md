# ADR-021: Идентификация клиента — «я» = партнёр (онбординг)

- **Статус:** Принято
- **Дата:** 2026-11-04
- **Связанные ADR:** 018 (изоляция), 008 (JWT/PIN)
- **Бэклог:** AR-004

## Контекст
PO: сначала **идентификация** («кто я» = партнёр), потом **аутентификация** (PIN опционально). ADR-018 зафиксировал отсутствие изоляции (пара = одно пространство); теперь вводим явную идентификацию клиента (Фаза 1).

## Решение
- **«Я» = партнёр** — пользователь приложения = один из партнёров (участник сессии).
- **Онбординг (первый запуск):** идентификация — «кто я» (выбор/создание партнёра-я) → опциональный PIN.
- **Домен:** `Partner` получает признак `self` («это я» на устройстве); альтернатива — отдельный концепт «Член пары» (`Member`) — отложено (переоценить при второй паре).

## Последствия
- Клиентский путь: идентификация → аутентификация (PIN опц.).
- `Partners` BC: добавить «self»-концепт (какой партнёр = «я»).
- `Record`: автор = «я» (идентифицированный партнёр); `orgasms[].participant = "me"` теперь ссылается на явного партнёра.
