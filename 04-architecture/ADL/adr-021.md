# ADR-021: Идентификация и аутентификация клиента (многопользовательская, по номеру телефона)

- **Статус:** Принято (пересмотрено 2026-11-04)
- **Дата:** 2026-11-04
- **Связанные ADR:** 018 (изоляция), 008 (JWT/PIN), 001 (контексты)
- **Бэклог:** AR-004

## Контекст
Система **многопользовательская** (пара = 2 пользователя). Сейчас возможен только один пользователь (device-токен = инстанс, без персональной идентичности). Нужна идентификация + аутентификация — пока **по номеру телефона**.

## Решение
1. **Многопользовательская:** пользователи идентифицируются **номером телефона**.
2. **Идентификация:** «кто я» = номер телефона; верификация — **OTP**. Канал (`Otp:Channel = sms|telegram|log`): `SmsOtpSender` — целевой, `TelegramOtpSender` — MVP-упрощение, `LogOtpSender` — только dev/CI.
3. **Аутентификация:** номер телефона (OTP) + **опциональный PIN** — **локальный** `window.Pin` (IndexedDB, замок экрана). Серверный `/privacy/pin/*` — **legacy** (device-токен, ADR-008), в MVP не используется.
4. **Домен:** отдельный BC **«Клиент»** (аккаунт пользователя: номер, верификация, PIN) + связь с `Partner` (профиль участника).

## Последствия
- JWT идентифицирует **пользователя** (номер телефона), а не устройство.
- «Я» = пользователь (номер) → связанный профиль `Partner`.
- `Record.author` = пользователь; `orgasms[].participant = "me"` = связанный партнёр.
- Изоляция (ADR-018): данных между пользователями по-прежнему нет — пара = общее пространство (нет per-user данных).

## JWT (уточнение)
- client-JWT (от `/verify`) подписывается **тем же `Jwt:SigningKey`**, что валидирует ApiGateway — **один ключ** на Privacy + Client + Gateway (иначе токен отклоняется шлюзом).
- **Модель токена (как Privacy, ADR-008):** access **15 мин** + refresh **30 дней**; обновление — `POST /api/v1/clients/refresh`. PIN — локальный замок, НЕ условие выдачи токена.
- Ротация ключа — @DO (GitHub Secrets + `.env`), **не в git** (AGENTS.md §6).

## PIN: серверный vs локальный (решение AR-009)
- **Источник правды для PIN в MVP — локальный `window.Pin`** (IndexedDB, замок экрана, опционален).
- **Серверный `/privacy/pin/*` — legacy** (device-токен, ADR-008), вне MVP: продукт на него не опирается, CI его не проверяет.
- Следствие: E2E `remove-pin` → `describe.skip` + локальная проверка `window.Pin.hasPin()` (TE-037); серверный `pin/has` не чиним (BE-045 → «не делаем»).
