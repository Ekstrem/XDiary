# ADR-019: VPS-2 — тестовый контур (разделение prod/test)

- **Статус:** Принято
- **Дата:** 2026-11-01
- **Связанные ADR:** 016 (размещение PostgreSQL), 009 (две ВМ), 010 (compose)
- **Бэклог:** —

## Контекст
PO предложил отдать VPS-2 (сейчас только бэкап-таргет) под тестовый контур: тестировщику нужен выделенный стенд (E2E/нагрузка) без затрагивания прода.

## Решение
**VPS-2 = self-contained тестовый стенд + бэкап-таргет (две роли, изолированно):**
- **Тест-контур:** podman + 10 сервисов + шлюз + **локальный PostgreSQL** (свой, тестовые БД) — изолирован от прод VPS-1.
- **Свой Tailscale-хост/домен** для теста (напр. `xdiary-test-*.ts.net`), не пересекается с прод `xdiary-vps1.taile0b6ee.ts.net`.
- **Бэкап-роль сохраняется:** `pg_dumpall` с VPS-1 → **файлы** на VPS-2 (файлы ≠ тестовая БД, не конфликтуют).

## Обоснование
- TE нужен выделенный стенд (E2E 9/9 + front-e2e на живом шлюзе, не на проде).
- VPS-2 недогружен (только файлы бэкапа).

## Последствия
- Тест и прод изолированы (разные PostgreSQL, сети, Tailscale-хосты).
- VPS-2 несёт две роли: тестовая БД (running) + файлы бэкапа (dumps).
- Деплой теста — отдельный compose/tag (не путать с прод).

## Проверки
- Тест-стенд отвечает по своему DNSName; `/health` = 200.
- Бэкап (pg_dumpall VPS-1 → VPS-2) не затронут.
