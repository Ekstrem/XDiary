# ADR-019: VPS-2 — dev-стенд (разделение prod/dev)

- **Статус:** Принято
- **Дата:** 2026-11-01
- **Связанные ADR:** 016 (размещение PostgreSQL), 009 (две ВМ), 010 (compose)
- **Бэклог:** —

## Контекст
PO предложил отдать VPS-2 (сейчас только бэкап-таргет) под dev-стенд: тестировщику нужен выделенный стенд (E2E) без затрагивания прода.

**Терминология сред (PO, 2026-11-01):** VPS-1 = **прод**, VPS-2 = **dev-стенд** (не «тестовый»).

## Решение
**VPS-2 = self-contained dev-стенд + бэкап-таргет (две роли, изолированно):**
- **Dev-стенд:** podman + 10 сервисов + шлюз + **локальный PostgreSQL** (свой, dev-БД) — изолирован от прод VPS-1.
- **Свой Tailscale-хост/домен:** `xdiary-vps2.taile0b6ee.ts.net` (внутри tailnet; при необходимости — Funnel), не пересекается с прод `xdiary-vps1.taile0b6ee.ts.net`.
- **Бэкап-роль сохраняется:** `pg_dumpall` с VPS-1 → **файлы** на VPS-2 (файлы ≠ dev-БД, не конфликтуют).

## Обоснование
- TE нужен выделенный стенд (E2E 9/9 + front-e2e на живом шлюзе, не на проде).
- VPS-2 недогружен (только файлы бэкапа).

## Последствия
- Dev и прод изолированы (разные PostgreSQL, сети, Tailscale-хосты).
- VPS-2 несёт две роли: dev-БД (running) + файлы бэкапа (dumps).
- Деплой dev — отдельный compose/tag (не путать с прод).

## Проверки
- Dev-стенд отвечает по `xdiary-vps2.taile0b6ee.ts.net`; `/health` = 200.
- Бэкап (pg_dumpall VPS-1 → VPS-2) не затронут.
