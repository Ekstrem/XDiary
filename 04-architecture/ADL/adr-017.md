# ADR-017: Публичный доступ к API — Tailscale Funnel (без VPN-клиента)

- **Статус:** Отложено (не для MVP — VPN есть на устройствах пары)
- **Дата:** 2026-10-31
- **Связанные ADR:** 015 (меняет «частный VPN»), 008 (JWT), 009
- **Бэклог:** DO-012

## Контекст
ADR-015 предполагал доступ только через Tailscale-клиент (частный VPN, без публичного доступа). PO отказался ставить VPN-клиент и регистрировать новые сервисы (Cloudflare/DuckDNS/домены отпали). Нужен публичный HTTPS **без VPN-клиента**, без домена, без новых аккаунтов.

> **Отложено (2026-10-31):** VPN на устройствах пары **есть**, всё работает. Для MVP остаёмся на ADR-015 (частный VPN); Funnel — на потом, если понадобится публичный доступ.

## Решение
**Tailscale Funnel** на уже существующем tailnet:
```bash
sudo tailscale funnel --bg --https=443 http://127.0.0.1:8080
```
- Даёт публичный `https://xdiary-vps1.taile0b6ee.ts.net` — доступен **любому устройству без Tailscale**.
- Порт **8080 наружу не открываем** (Funnel проксирует только 443 → 127.0.0.1:8080).

## Обоснование
- PO не ставит VPN-клиент; PWA требует HTTPS (secure context для Service Worker).
- Без домена и без новых регистраций — Funnel использует уже существующий tailnet.
- Валидный Let's Encrypt-сертификат (Funnel даёт HTTPS с сертификатом Tailscale).

## Последствия (важно!)
- **API становится публично доступен** — это изменение ADR-015, где было «нет публичного доступа (приватность пары)».
- Единственная защита — **JWT** (ADR-008). Данные чувствительные.
- Обязательно: JWT на всех эндпоинтах, кроме `/health` и `/api/v1/privacy/*`; 8080 наружу не публиковать.

## Проверки
- `curl https://xdiary-vps1.taile0b6ee.ts.net/health` = 200 **с устройства без Tailscale**.
- Анонимный запрос к `/api/v1/journal` → **401**.
