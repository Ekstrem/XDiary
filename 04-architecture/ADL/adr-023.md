# ADR-023: Управление API-контрактами и версионирование

- **Статус:** Предложено
- **Дата:** 2026-11-08
- **Связанные ADR:** 006 (REST), 007 (шлюз YARP), 013 (версионирование /v1 + OpenAPI)
- **Бэклог:** техническая итерация (владелец 2026-11-08: «много релизов и расхождений контрактов»)

## 1. Контекст
ADR-013 декларирует `/api/v1` + OpenAPI, но исполнение не проверяется: контракт (`03-ddd`),
реализация (`6-msa`) и клиент (`8-front`) расходятся; версия `/v1` не защищена от ломающих
изменений. Нужно управление контрактами + версионирование.

## 2. Варианты решений

### Вариант A — Оставить YARP + дисциплина
| Аспект | Значение |
|---|---|
| Описание | Усилить ADR-013: версионная политика (breaking → `/v2`), deprecation, CI-валидация OpenAPI |
| Плюсы | дёшево, без нового компонента |
| Минусы | нет централизованного реестра контрактов; нет rate-limiting/аналитики (для 12 сервисов + 1 пары не нужны) |
| Соответствие целям | консистентность контрактов (частично) |

### Вариант B — Полноценный APIM (Kong / Tyk / Azure APIM)
| Аспект | Значение |
|---|---|
| Описание | Отдельный APIM-слой перед YARP: версии, rate limiting, auth, аналитика, портал |
| Плюсы | полный набор APIM-функций |
| Минусы | высокая цена (новый компонент + ops + обучение); вне стека EDM/DF (там шлюз = YARP, ADR-007) |
| Соответствие целям | избыточно для размера |

### Вариант C — Контракт-first реестр (YARP + OpenAPI-реестр + версионные маршруты + CI-гейт)
| Аспект | Значение |
|---|---|
| Описание | YARP остаётся; добавляется: (1) центральный OpenAPI-реестр (источник правды), (2) версионные маршруты `/v1`→сервисы с явной политикой, (3) CI-гейт breaking-change |
| Плюсы | бьёт в корень (контрактный дрейф), без тяжёлого APIM; версии управляемы |
| Минусы | нужна дисциплина ведения реестра |
| Соответствие целям | единый источник правды контрактов, версии без поломок |

## 3. Выбранное решение
**Вариант C** — контракт-first реестр + версионирование, без полного APIM. Полный APIM (B)
избыточен для 12 микросервисов и одной пары и вне стека EDM/DF; дисциплина без реестра (A)
не даёт единого источника правды — ровно из-за его отсутствия контракты и разъезжаются.

|---|---|

| Как проверяется | breaking-change гейт в CI; аддитивные правки не ломают `/v1` |
| Кто проверяет | @AR (контракты) + @DO (гейт) |

## 4. Последствия
- **Плюсы:** единый источник правды контрактов, версии без поломок, без нового тяжёлого компонента.
- **Риски:** дисциплина ведения реестра; накопление версий (чистить по ADR-013).
