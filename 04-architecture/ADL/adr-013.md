# ADR-013: Версионирование API и контракты

- **Статус:** Заменено
- **Дата:** 2026-10-29
- **Заменяет:** — (**этот ADR заменён на ADR-023**)
- **Связанные ADR:** 006, 023 (полный APIM)
- **Бэклог:** кросс-кат (контракты API)

> **Заменено ADR-023 (2026-11-09).** Что осталось в силе: **внешний путь `/api/v1`** и аддитивность изменений
> внутри версии. Что изменилось: **«OpenAPI в git — единственный источник правды» больше не действует** —
> источником правды остаётся git, но версии и жизненный цикл управляются **APIM (Gravitee, этап 1 — control plane)**,
> а расхождение ловится drift-check (`DO-056`), а не только ревью. Новые ADR по контрактам — только в ADR-023.

## Контекст
Фронт (PWA) и бэк развиваются независимо. Нужны контракты и правила совместимости.

## Решение
**URL-версионирование** (`/api/v1/...`) + **OpenAPI** как единый источник правды (генерация клиента при необходимости). Аддитивные изменения, без ломающих в рамках одной версии.

**Обоснование:** просто и однозначно; OpenAPI фиксирует DTO.

## Последствия
- **Плюсы:** явные версии, автодокументация.
- **Риски:** накопление версий — чистить по мере.
