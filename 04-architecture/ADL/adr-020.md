# ADR-020: CD pipeline (prod/dev)

- **Статус:** Принято
- **Дата:** 2026-11-02
- **Связанные ADR:** 019 (prod/dev), 010 (compose), 013 (контракты API)
- **Бэклог:** DO-015

## Контекст
Есть CI (сборка + тесты) и крон-деплой (`update.sh` + cron 15 мин). Нужен CD: доставка в **dev** и продвижение в **prod**. PO указал, что pull-based деплой уже работает — SSH-секреты не нужны.

## Решение (pull-based cron, вариант B)
1. **CI (push/PR в `main`):** сборка образов → push в GHCR с тегом `single-<SHA>` (+ `latest`).
2. **Deploy dev (авто):** cron на VPS-2 (`update.sh`) подхватывает `single-<SHA>`/`latest` → recreate → `/health` 200.
3. **Smoke/E2E dev (авто, против dev `XDIARY_E2E_BASE_URL=https://xdiary-vps2.taile0b6ee.ts.net`):** blocking — `/health` 200 + API-E2E 9/9 + ключевые UI; неблокирующие — остальное.
4. **Deploy prod (гейт):** cron на VPS-1 деплоит **только по релиз-тегу `v*`** (или флаг `/etc/xdiary/prod-release`); без гейта `update.sh` ничего не меняет.
5. **Post-deploy:** stats / guard / sync.

## Ключевые решения
- **Pull-based:** VPS сами тянут образы из GHCR (cron); **SSH-секреты и GitHub Environments не нужны**.
- **Теги:** `single-<SHA>` (или `latest`) для dev; релиз-тег `v*` для prod.
- **Гейт prod:** релиз-тег `v*` или флаг `/etc/xdiary/prod-release`.

## Последствия
- dev обновляется автоматически (merge → cron подхватывает).
- prod обновляется только по релиз-тегу/флагу (явный контроль релиза).

## Проверки
- Merge в `main` → dev обновлён (cron), E2E зелёный.
- Релиз-тег `v*` → prod обновлён, `/health` 200.
