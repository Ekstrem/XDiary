# ADR-020: CD pipeline (prod/dev)

- **Статус:** Предложено
- **Дата:** 2026-11-02
- **Связанные ADR:** 019 (prod/dev), 010 (compose), 013 (контракты API)
- **Бэклог:** —

## Контекст
Есть CI (сборка + тесты в `ci-tests.yml`) и ручной/крон-деплой (`update.sh` + cron 15 мин). Нужен CD: автоматическая доставка в **dev** и продвижение в **prod**.

## Решение (pipeline, GitHub Actions)
1. **CI (push/PR в `main`):** сборка образов → push в GHCR → unit/integration тесты.
2. **Deploy dev (авто, на `main`):** SSH на VPS-2 → `update.sh` (pull + recreate) → `/health` = 200.
3. **Smoke/E2E dev (авто, против dev `XDIARY_E2E_BASE_URL=https://xdiary-vps2.taile0b6ee.ts.net`):** **blocking** — `/health` 200 + API-E2E 9/9 + ключевые UI-сценарии; **неблокирующие** — остальное. **prod-деплой — только на зелёном smoke.**
4. **Deploy prod (manual approval / tag):** promotion dev→prod теми же образами → SSH на VPS-1 → `update.sh` → `/health` = 200.
5. **Post-deploy:** stats / guard / sync.

## Ключевые решения
- **Теги образов:** `:<commitSHA>` (иммутабельный, для promotion) + `:latest` (мутабельный, удобство). Deploy dev и prod — **один и тот же `:<commitSHA>`** (проверено на dev → в prod), НЕ `:latest`.
- **update.sh:** режим `deploy <tag>` (не только «pull latest»).
- **Trigger prod:** GitHub Environment `prod` с approval; `dev` — без approval.
- **Деплой:** SSH из GitHub Secrets → VPS.
- **Секреты:** `DEV_SSH_HOST/USER/KEY`, `PROD_SSH_HOST/USER/KEY`.

## Последствия
- dev получает каждый merge в `main`; prod — только по approval/tag.
- Один источник образов (GHCR), promotion dev→prod без пересборки.

## Проверки
- Merge в `main` → dev обновлён, E2E зелёный.
- Approval → prod обновлён, `/health` = 200.
