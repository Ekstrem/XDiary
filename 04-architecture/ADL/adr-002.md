# ADR-002: Профиль деплоймента CEQRS

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 001, 003, 004, 005

## Контекст
EDM предлагает 4 профиля: Single (1 процесс), BudgetCqrs (1 процесс, Cmd DB + Read DB в одной БД), Cqrs (Cmd+Qry раздельно), Ceqrs (Cmd+Evt+Qry). Два пользователя, минимальная нагрузка.

## Решение
**BudgetCqrs** — один процесс на сервис; Command DB и Read DB живут в одной Postgres, ReadModel вынесена в отдельную схему. Событийная шина — внутри процесса (см. ADR-005).

**Обоснование:** сохраняет разделение записи/чтения (CEQRS) без лишних процессов; самый дешёвый путь с возможностью эволюции.

## Последствия
- **Плюсы:** один контейнер на сервис, простота эксплуатации.
- **Путь эволюции:** BudgetCqrs → Cqrs (разделить Cmd/Qry процессы) → Ceqrs (добавить выделенный Event процесс) при росте нагрузки.

## Проверки
- Согласовано с ADR-003/004 (одна Postgres), ADR-005 (шина внутри процесса/Outbox).
- Кросс-ссылка: профили описаны в edm-net (DigiTFactory deployment profiles).
