# ADR-005: Event Bus

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 002, 009
- **Бэклог:** кросс-кат (событийная шина)

## Контекст
Команда публикует доменное событие в `IEventBus`; потребители (Projectors, Saga, Outbound Handler) читают из шины.

## Решение
**InMemory** (`AddEventBusInMemory`) — события внутри процесса (профиль Single).

**Обоснование:** Single — один процесс на сервис; внешний брокер не нужен при двух пользователях.

## Последствия
- **Плюсы:** нулевая инфраструктура, простота.
- **Риски:** события не переживают рестарт и не доставляются между сервисами — для межсервисных связей используется HTTP/шлюз.

## Уточнение (2026-11-14)
Гарантии межсервисной доставки (этот ADR говорил только «HTTP/шлюз») **не зафиксированы отдельным принятым ADR**: `ADR-029`
**отклонён (2026-11-14)** — «вопрос уже решён `ADR-003` и `ADR-005`». Решение о доставке — `ADR-003` (Event Store = источник
истины) и этот ADR; проверяемые требования к доставке (**из Event Store через Outbound Handler**, at-least-once, идемпотентный
приём) живут как **приёмка долга E1/E5** в `04-architecture/edm-debt-plan.md`, а не как принятое решение. Шина остаётся **InMemory**
для внутрипроцессных подписчиков — межсервисных доставок через неё нет и не планируется.

> статус `Принято` не тронут, причина названа). Было: «зафиксированы в `ADR-029`» — ссылка из **принятого** ADR в **отклонённый**.
