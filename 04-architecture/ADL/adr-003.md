# ADR-003: Command Store (Event Store)

- **Статус:** Принято
- **Дата:** 2026-10-29
- **Связанные ADR:** 002, 004, 009
- **Бэклог:** кросс-кат (Event Sourcing)

## Контекст
EDM: команда → шина → Command DB Projector (`SaveEventAsync`). Event Sourcing требует event store. План — Postgres на отдельной ВМ.

## Решение
**PostgreSQL (Event Sourcing)** — `AddEventStorePostgres`, стратегия `FullEventSourcing`.

**Обоснование:** одна СУБД на всё (проще для двух ВМ), согласуется с ADR-009 (ВМ с Postgres).

## Последствия
- **Плюсы:** единый стек хранения; event store и read-модель в одной БД (профиль Single).
- **Риски:** объём событий и снапшоты — настроить при росте.

## Проверки
- Согласовано с ADR-004 (Read Store тоже Postgres), ADR-002 (Single).
- Кросс-ссылка на код: текущие данные в IndexedDB (`records`, `catalog`, …) — при миграции станут событиями/снапшотами (ADR-011).
